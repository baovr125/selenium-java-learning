09 · Kế hoạch học căn bản Selenium + Java (đã có nền OOP, cần ôn lại; chuẩn bị cho Playwright)

Quay lại README đánh giá · Thay thế bản trước (giả định Java từ đầu) và file 08 (giả định Java vững). Phiên bản này dựa trên: đã học OOP Java ở đại học nhưng quên nhiều, còn nhớ sơ sơ · đã có Testing/API/SQL · chỉ có ~2 tuần · mục tiêu căn bản Selenium + Java · sau này học Playwright.

1. Điều chỉnh vì bạn đã học OOP

Trước (Java từ đầu) Bây giờ (ôn lại)
~12–14 giờ cho Java, học từng bài ~8–9 giờ — ôn nhanh (nhớ lại nhanh hơn học mới)
Học OOP như kiến thức mới OOP chỉ cần ôn + gắn vào code Selenium (WebDriver là interface, BaseTest là kế thừa, Page là đóng gói)
POM nhập môn (chỉ Login) POM đầy đủ hơn (BasePage + DriverFactory + Config) vì nền OOP cho phép
Chạm Selenium ngày 3 Chạm Selenium ngày 2
Java là điểm yếu nhất Điểm yếu chuyển sang phần Java ngoài OOP: Collections, Generics, Lambda, Exceptions — các môn OOP đại học thường dạy ít hoặc không dạy (giả định của tôi, hãy kiểm chứng ở bài chẩn đoán Ngày 1)

Thời gian giả định: ~2,5–3 giờ/ngày trong tuần, ~4 giờ/ngày cuối tuần ≈ 40 giờ / 14 ngày; mục ★ là lộ trình tối thiểu (~24 giờ).

2. Bài chẩn đoán Java (Ngày 1, 45 phút, không tra cứu)

Viết bằng tay hoặc trong IDE tắt gợi ý:

# Yêu cầu Kiểm tra
1 class Account: field private, constructor, getter, deposit(amount) ném IllegalArgumentException nếu âm Đóng gói, constructor, exception
2 SavingsAccount extends Account ghi đè toString(); gọi super(...) Kế thừa, super, override
3 interface Notifier { void send(String msg); } + 2 lớp cài đặt; List<Notifier> duyệt và gọi send Interface, đa hình, List
4 Đếm số lần xuất hiện của từng từ trong một String bằng Map<String,Integer> Collections, String.split
5 Integer.parseInt("abc") bọc trong try/catch/finally; giải thích finally Exceptions

Cách đọc kết quả:

Kết quả Việc làm
5/5 hoặc 4/5 Đi nhanh: bỏ phần "ôn OOP" ở Ngày 3, dùng thời gian đó cho Selenium
2–3/5 Làm đúng kế hoạch bên dưới
0–1/5 Tuy bạn nói đã học OOP nhưng thực tế cần học lại: thêm 2 ngày Java (xem 07 Classes, 08 OOP đầy đủ + Exercise 1–3) trước khi sang Ngày 3

Ghi lại danh sách chỗ quên — đó là danh sách ôn của bạn, không cần ôn những gì đã nhớ.

3. Cách học (mỗi ngày)

  1. Ôn Java bằng cách gõ lại: đọc Syntax + 1–2 ví dụ (~15–20 phút/bài), rồi làm Exercise 3 (Practical); mở lời giải sau khi chạy. Chỉ đọc kỹ chỗ bài chẩn đoán cho thấy bạn quên.
  2. Mỗi chủ đề Java phải xuất hiện trong code Selenium bạn tự gõ cuối buổi.
  3. Bỏ qua: Knowledge Check (đáp án lệch: 135/180 câu là B), Interview Corner cuối bài, Lesson Summary.
  4. Mỗi buổi commit lên GitHub (repo riêng selenium-java-basics).
  5. Mỗi 3–4 ngày có Checkpoint tự kiểm không nhìn tài liệu.

Đường dẫn bài: thư mục docs/selenium-learning/.

4. Bản đồ OOP → Selenium (ôn xong phải giải thích được)

Khái niệm OOP Xuất hiện ở đâu trong Selenium/dự án Bạn phải nói được
Class, object, constructor new LoginPage(driver); new WebDriverWait(driver, …) Constructor nhận driver để làm gì
Đóng gói (private, getter) Page: private By username; method công khai loginAs(...) Vì sao giấu locator trong Page
Kế thừa (extends, super) Exercise01_LoginTest extends BaseTest; LoginPage extends BasePage Test dùng lại driver/wait từ lớp cha
Đa hình + Interface WebDriver driver = new ChromeDriver() Vì sao khai báo kiểu WebDriver, đổi trình duyệt không đổi test
Abstract class BasePage/BaseTest có thể abstract Khác interface ở đâu
static, final Hằng số URL; DriverFactory.create(...); ThreadLocal (khái niệm) Khi nào dùng static, vì sao driver không nên là static khi song song
Overloading click(By) và click(WebElement) trong BasePage Khác overriding
Package, access modifier base/, pages/, tests/; protected WebDriver driver Vì sao protected
Generics, lambda (thường chưa học) List<WebElement>; wait.until(d -> …) Hiểu cú pháp đọc được

6. Chuẩn bị cho Playwright

Là kiến thức chung của tôi, chưa kiểm chứng trên máy bạn; khi học hãy đối chiếu tài liệu chính thức của Playwright (bản Java/TS/Python), vì API đổi theo phiên bản.

Kiến thức học bây giờ Trong Playwright
Locator (CSS/XPath, ổn định) Vẫn dùng được; khuyến khích locator theo ngữ nghĩa (role, text, label, test-id) — cùng tư duy
Wait & đồng bộ hoá Playwright tự chờ trước hành động và có assertion tự thử lại; bạn hiểu vì sao cần cơ chế đó và biết ca nào vẫn cần điều kiện riêng
POM, BasePage, kế thừa, interface Dùng nguyên (và nền OOP của bạn dùng được ngay)
Test độc lập, assert ở test, chẩn đoán flaky Y hệt
Java, Maven, TestNG/JUnit Dùng lại 100% nếu học Playwright bản Java; nếu chọn TypeScript/Python thì chỉ còn khái niệm
Alert/Frame/Window/Actions/JS Có tương đương (dialog, frame locator, page/context, hover/drag, evaluate); cú pháp khác

Thói quen nên có ngay: không Thread.sleep, không Implicit Wait, không XPath tuyệt đối; locator trong Page, assertion trong test; ghi lại nguyên nhân mỗi lần test fail. Không đầu tư sâu: PageFactory/@FindBy, Selenium Grid, helper wait tự chế phức tạp, trường hợp biên của Actions, Maven Profile/Failsafe. Chuyển tiếp hiệu quả nhất: viết lại 10 Exercise của Selenium1 bằng Playwright để so sánh số dòng code, số chỗ chờ thủ công, độ ổn định. Chọn ngôn ngữ Playwright dựa trên JD, chưa cần quyết bây giờ; còn phân vân thì giữ Java để tận dụng nền hiện có. Đọc thêm JUnit 5 khoảng 1 giờ (nhiều ví dụ Playwright Java dùng JUnit).

9. Rủi ro

  1. Tự tin quá về OOP: "đã học" ≠ "viết được". Dựa vào kết quả bài chẩn đoán, không dựa vào cảm giác.
  2. Collections/Generics/Lambda bị bỏ sót vì tưởng thuộc OOP — đây là các mảng dễ vướng nhất khi đọc code Selenium.
  3. Đọc nhiều, gõ ít: giữ ≥ 60% thời gian là gõ và chạy.
  4. Ước lượng giờ có thể lệch: đo giờ thực ở Ngày 1–3; nếu chậm hơn 30%, chuyển mục không ★ sang tuần 3.
