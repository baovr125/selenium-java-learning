3.2. Tiêu chí 4 mức

Mức Điều kiện (tất cả phải thoả)
1. Chưa sẵn sàng ứng tuyển Bất kỳ: Testing < 2, Java < 2, Selenium < 3, Wait < 2, hoặc chưa tự chạy được dự án bằng mvnw ba lần liên tiếp xanh, hoặc không có repo Git thật
2. Có thể ứng tuyển Fresher Testing ≥ 2, Java ≥ 2, Selenium ≥ 3, Locators ≥ 3, Wait ≥ 3, Maven ≥ 2, TestNG ≥ 2, POM ≥ 2, Git ≥ 2, Interview ≥ 2; có repo GitHub với framework POM chạy xanh + README; trả lời ≥ 60% bộ câu mô phỏng; không có nhóm nào < 2
3. Có thể ứng tuyển Junior Automation Tester Mức 2 + Testing ≥ 3, Java ≥ 3, Exception ≥ 3, Maven ≥ 3, TestNG ≥ 3, POM ≥ 3, Git ≥ 3, Debugging ≥ 3, Interview ≥ 3; Capstone ≥ 70% rubric (có bug report, PR, CI); Exit Exam ≥ 70%; qua ≥ 2 buổi mock liên tiếp
4. Tự thực hiện nhiệm vụ Automation cơ bản trong dự án Mức 3 + Wait = 4, Debugging = 4, Framework ≥ 3, API cơ bản ≥ 2; chứng minh được: (a) nhận 1 test case thủ công → script ổn định 5/5 xanh trong ≤ 1 ngày; (b) chẩn đoán–sửa 1 test flaky có kèm nguyên nhân; (c) thêm Page/Test vào framework có sẵn qua PR được review; (d) báo bug đúng chuẩn

Nguyên tắc: không xét "đã đọc hết tài liệu". Bằng chứng gồm: repo, kết quả chạy 3/3, PR, bug report, bản ghi âm mock, điểm Exit Exam.

4.1. Software Testing (15)

# Question Ý chính cần có
ST1 Explain the 7 testing principles. Pick two and give an example. Testing shows presence of defects; exhaustive testing impossible; early testing; defect clustering; pesticide paradox; context-dependent; absence-of-errors fallacy
ST2 What is the difference between SDLC and STLC? Where does testing start? STLC là chuỗi hoạt động test trong SDLC; test bắt đầu từ phân tích requirement (shift-left)
ST3 Verification vs validation? "Build the product right" vs "build the right product"; review/static vs chạy/động
ST4 What are the test levels and test types? Unit/Integration/System/Acceptance; functional/non-functional/regression/confirmation; level ≠ type
ST5 Smoke vs sanity vs regression vs retesting. Smoke = build có đủ ổn để test tiếp; sanity = kiểm nhanh vùng vừa sửa; regression = không hỏng phần cũ; retest = xác nhận bug đã sửa
ST6 Test scenario vs test case vs test plan. Mức trừu tượng khác nhau; test case có precondition/bước/dữ liệu/kết quả mong đợi
ST7 A field accepts ages 18–60. Which values do you test with BVA? 17, 18, 19, 59, 60, 61 (+ biên của kiểu dữ liệu/rỗng)
ST8 Apply equivalence partitioning to a discount field (0–100%). Phân vùng hợp lệ (0–100), không hợp lệ (<0, >100, không phải số, rỗng); 1 đại diện/phân vùng
ST9 Build a decision table for login with valid/invalid user, valid/invalid password, and captcha. Liệt kê điều kiện × hành động; gộp luật; kỳ vọng từng luật
ST10 Describe state transition testing using "account locked after 3 failed logins". Trạng thái, sự kiện, chuyển; test chuyển hợp lệ & không hợp lệ
ST11 Describe the defect lifecycle. When is a bug Rejected, Deferred, Reopened? New → Assigned → Open → Fixed → Retest → Closed/Reopened; Rejected (không phải bug), Deferred (hoãn)
ST12 Severity vs priority — give four examples (high/low combinations). Severity = mức ảnh hưởng kỹ thuật; priority = thứ tự xử lý theo nghiệp vụ; ví dụ logo sai ở trang chủ (low sev/high prio)
ST13 What makes a good bug report? Write one for "Login button does nothing on Firefox". Tiêu đề, môi trường, bước tái hiện, kỳ vọng/thực tế, bằng chứng, severity/priority, tái hiện được không
ST14 Explain Scrum roles/events. What does a QA/automation engineer do in a sprint? PO/SM/Dev; planning/daily/review/retro; tham gia refinement, viết test cùng sprint, regression tự động
ST15 How do you decide what to automate? What is the test pyramid? Lặp lại, ổn định, giá trị cao, ROI/bảo trì; nhiều unit/API, ít UI; không tự động hoá kiểm tra một lần/chủ quan

4.4. Wait Mechanisms (15)

# Question Ý chính cần có
W1 Why do we need waits? Ứng dụng bất đồng bộ; Selenium chạy ngay; đồng bộ theo điều kiện
W2 Implicit vs explicit vs fluent. Phạm vi toàn cục vs một điều kiện vs tuỳ biến polling/ignore
W3 What is wrong with implicit wait when findElements returns empty? Vẫn chờ hết timeout (đo thật: 17 ms vs 3050 ms)
W4 Why not mix implicit and explicit waits? Thời gian chờ khó đoán, cộng dồn
W5 Defaults of WebDriverWait? Polling 500 ms; bỏ qua NotFoundException; TimeoutException mô tả điều kiện
W6 Presence vs visibility vs clickability — when each? Có trong DOM / hiển thị / hiển thị + enabled
W7 Why avoid Thread.sleep? Is it ever acceptable? Chờ cố định, chậm hoặc flaky; chỉ khi debug/không có điều kiện quan sát được
W8 How do you choose timeout and polling interval? 10–20 s UI thường; wait trả ngay khi đúng; polling 250–500 ms
W9 How do you handle StaleElementReferenceException? Tìm lại element, refreshed/stalenessOf, dùng By thay vì lưu WebElement
W10 A spinner blocks the button. What do you wait for? invisibilityOfElementLocated rồi elementToBeClickable; chờ spinner xuất hiện trước
W11 An old message is still visible while waiting for a new one. textToBe/điều kiện đặc trưng trạng thái mới
W12 Write a custom wait: wait until item count increases. Lambda d -> d.findElements(...).size() > before; FluentWait nếu cần ignore/polling
W13 How do you synchronize with AJAX-heavy pages? Chờ theo điều kiện UI cụ thể; (thêm) document.readyState/request đã xong
W14 TimeoutException vs NoSuchElementException. Điều kiện chờ không đạt trong hạn vs tìm không thấy ngay
W15 A test is flaky. Walk me through your diagnosis. Chạy lặp, đọc exception, DevTools, thay sleep bằng điều kiện đặc trưng; không chỉ tăng timeout/retry

SC8 Requirement says "users can buy products". Design tests. Hỏi làm rõ; EP/BVA; luồng chính/phụ/âm; chọn automation
SC9 The regression suite takes 40 minutes. Song song, bỏ UI thừa → API, tag smoke, tối ưu đăng nhập, headless
SC10 In code review you see Thread.sleep, absolute XPath and assertions in Page classes. Nêu từng vấn đề + thay thế + giọng nhận xét tôn trọng
