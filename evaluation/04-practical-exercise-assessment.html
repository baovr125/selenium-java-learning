2. Chất lượng bài tập cuối bài (180 bài)

Vấn đề Bằng chứng Hệ quả
Yêu cầu quá ngắn, "Expected Output" mơ hồ. 140/180 bài tập có Expected Output dạng văn xuôi ("3 cặp", "Bảng + 1 khoảng trống", "Click thành công hoặc ném lỗi") thay vì kết quả kiểm chứng được. Quét **Expected Output:**; ví dụ 10-selenium-exceptions Ex1/Ex3, 08/01 Ex1–3 Người học không tự chấm được → dễ "tưởng đã làm"
Basic/Intermediate/Practical chênh nhau ít. Ví dụ 04-control-flow: "tổng 1–5" → "switch tên driver" → "đếm PASS/FAIL" (cả ba < 10 dòng code). Mức "Practical" vẫn là bài tập đồ chơi. 01-java-fundamentals/04-control-flow.md Practice Exercises Không có bước nhảy lên kỹ năng thật
Không có bài "sửa test hỏng cho sẵn". Không tìm thấy bài nào đưa một test đang fail/flaky và yêu cầu chẩn đoán–sửa (quét 03/, 04/, 08/). Quét từ khoá Debugging chỉ là đọc quy trình 8 bước, không phải kỹ năng — mà đây là điều interviewer hỏi nhiều nhất
Lời giải ngay cuối file. Cấu trúc 60/60 bài Dễ mở sớm
Quiz lệch đáp án (135/180 = B). Script Mất giá trị tự kiểm tra
Bài tập Selenium cuối bài khó chạy độc lập (cần site/locator giả định); UPDATE_REPORT §7 thừa nhận 7/36 lời giải Selenium "không chạy độc lập". UPDATE_REPORT §7 Người học không chắc mình sai ở đâu

Điểm tốt: bài Java có ví dụ + lời giải đã chạy thật (93/93); bài tập Wait có tình huống đo thời gian thật; mỗi bài đều có Hint.

3. Đánh giá theo cấp độ (Level 1–5)

Level Yêu cầu của bạn Hiện có Đánh giá
1 – Basic Java Variables, điều kiện/vòng lặp, methods, class/object, Collections, Exceptions Bài 02–10, 3 bài tập/bài, có lời giải chạy thật Đủ về số lượng; thiếu mini-project. Không có bài Java nào mô hình hoá Selenium (ví dụ: lớp TestCase + List<TestCase> + đọc CSV + in báo cáo PASS/FAIL).
2 – Basic Selenium WebDriver, tìm phần tử, WebElement, Login, Dropdown/Alert/Frame Lab 01, 02, 05; 10 Exercise của source Tạm đủ. Nhưng Lab nằm ở Phase 8 (tuần 9–10). Alert/Frame/Window chưa có bằng chứng thực hành trong source (00-project-analysis.md:225). Mọi thứ trên một site.
3 – Intermediate Selenium Explicit Wait, dynamic elements, Selenium exceptions, POM, TestNG, chạy bằng mvnw Lab 03, 06, 07; Exercise 6/7/8/10 Tốt nhất ở phần Wait (Lab 03: không chờ vs chờ đúng, đo thời gian, 3 thử nghiệm bắt buộc). Thiếu kỹ năng xử lý Stale/Intercepted bằng bài tập cho sẵn lỗi; Lab 06 (POM) làm trên chính trang Login đã quen.
4 – Automation Framework Cấu trúc, DriverFactory, Config, Test Data, Reusable, Report, Debug/bảo trì Lab 08 (khung + code Config, BaseTest) Đúng hướng, nhưng đưa sẵn quá nhiều code (Config, BaseTest đầy đủ; DriverFactory/BasePage/Screenshots ở bài khác); không có "bảo trì thật" (đổi giao diện → sửa 1 chỗ) ngoài thí nghiệm đổi một locator ở Lab 06.
5 – Project Simulation 11 bước như thực tế Phase 8: 3 bài + Lab 08 Chưa đạt — xem §4.

4. Phase 8 có phải "mô phỏng dự án thật" không?

Đối chiếu 11 bước bạn nêu:

# Bước Hiện có Nhận xét
1 Nhận Requirement Có, nhưng tự rút ngược từ de.md: "R1–R10 (rút từ 10 bài tập của dự án)" (01-requirements:62) Không có tài liệu yêu cầu từ "stakeholder", không mơ hồ/thiếu sót cần hỏi lại
2 Phân tích chức năng Một phần (bảng R1–R10) Chưa có phân tích rủi ro/ưu tiên theo nghiệp vụ
3 Thiết kế Test Cases Có, 6 test case mẫu Không dùng BVA/EP/Decision Table (chưa được dạy); không có test case âm cho đa số chức năng
4 Chọn Scenario cần automation Tốt (bảng S1–S12, tiêu chí chọn) Giữ
5 Thiết kế Framework Có (M1–M6) Giữ; thêm tiêu chí thiết kế
6 Viết Scripts Có Giữ
7 Thực thi Test Có (mvnw clean test, 3 lần xanh) Giữ
8 Phân tích kết quả Một phần (bài 03: đọc Tests run, 8 bước debug) Không có kết quả fail thật để phân tích (mọi thứ nhắm đến "xanh")
9 Báo cáo Defect Không có (bước 11 của giáo trình là báo cáo kết quả chạy: mẫu Markdown "12 chạy, 0 fail") Thiếu hoàn toàn; không có mẫu bug report, không có bug để báo vì AUT ổn định
10 Commit & Push git init -b main + commit cục bộ (03:92-100); không có push, không remote, không PR Giả lập
11 Review & bảo trì Có checklist review PR (Git bài 03), nhưng không có "người review", không có thay đổi yêu cầu giữa chừng Thiếu tình huống bảo trì

Vấn đề gốc: AUT của Capstone là chính site demo công khai — trang người học đã tự động hoá 10/10 ở Phase gốc. Bản dựng lại thêm POM/Config/DataProvider nhưng không thêm độ phức tạp nghiệp vụ, không có lỗi để tìm, không có CV-able artifact khác biệt (hàng nghìn ứng viên có cùng project này). Kết luận: Phase 8 là "refactor lab", chưa phải "project simulation".

6. Đề xuất hệ thống bài tập mới

6.1. Thang bài tập

Level Bài tập Tiêu chí hoàn thành (đo được)
1 Java 15 kata (chuỗi, List/Map, equals, exception) + 2 mini-project: (a) TestCase/TestResult + đọc CSV + in tóm tắt; (b) Retry.run(action, n) có test Mỗi kata có main + test TestNG tự kiểm; mini-project chạy mvnw test xanh
2 Selenium cơ bản 12 "kata" trên 3 site: site demo hiện dùng + 1 site có form/giỏ hàng (một site demo công khai khác, ví dụ trang có giỏ hàng — kiểm tra site còn hoạt động) + 1 site có bảng/phân trang 12 test xanh 3 lần liên tiếp; không Thread.sleep
3 Selenium trung cấp "Flaky Clinic" (6 test cho sẵn lỗi: sleep, stale, overlay, message cũ, iframe, tab mới) + "Locator Refactor" (10 locator giòn → ổn định) Mỗi ca ghi: triệu chứng → nguyên nhân → sửa → bằng chứng chạy 5/5
4 Framework Refactor 10 Exercise gốc → POM + DriverFactory + Config + Screenshot + DataProvider; không cho sẵn code (chỉ spec + tiêu chí) Tests run ≥ 15; mọi By nằm trong Page; -Dheadless=true; screenshot tự sinh khi fail
5 Capstone Xem §6.2 Xem rubric

6.2. Capstone đề xuất — "Test Automation cho một ứng dụng web có nghiệp vụ"

Bối cảnh: nhận Requirement Document 1 trang (có cố ý mơ hồ/thiếu) cho một ứng dụng có luồng: đăng nhập → danh mục sản phẩm → giỏ hàng → thanh toán → lịch sử đơn (dùng demo site công khai hoặc app tự host; kiểm tra site còn hoạt động trước khi chọn).

Bước Deliverable Gắn với 11 bước của bạn
1. Phân tích Danh sách câu hỏi làm rõ requirement (≥ 5) + giả định 1, 2
2. Thiết kế ≥ 25 test case áp dụng BVA, EP, Decision Table (bảng Excel/Markdown) + RTM 3
3. Chọn automation Bảng lý do (tiêu chí ROI) → ~12–15 test tự động, còn lại thủ công 4
4. Framework POM + BasePage + DriverFactory + Config + Logging (SLF4J) + Screenshot + TestNG groups (smoke, regression) 5, 6
5. Thực thi ./mvnw clean test + -Dgroups=smoke; chạy trên GitHub Actions 7
6. Phân tích Báo cáo kết quả: ≥ 1 lỗi thật hoặc lỗi cố ý do người khác/AI cài vào để bạn tìm 8
7. Defect ≥ 3 bug report chuẩn (tiêu đề, môi trường, bước, kỳ vọng/thực tế, severity/priority, ảnh) 9
8. Git Repo GitHub thật, nhánh feature, ≥ 4 PR, commit message chuẩn, .gitignore, mvnw mode 100755 10
9. Review & bảo trì Một thay đổi UI/requirement giữa chừng → sửa test; 1 PR được review (người/AI) và sửa theo góp ý 11
10. Trình bày README + sơ đồ + video/ghi chú 5 phút giải thích bằng tiếng Anh Giao tiếp

Rubric chấm Capstone (đủ để đưa vào CV): cấu trúc framework (20%) · chất lượng test case & bao phủ (20%) · độ ổn định (3/3 lần xanh, không sleep) (20%) · Git/PR/CI (15%) · bug report (10%) · README & giải thích (15%).

7. Kết luận

  • Giữ: 180 bài tập Java/Selenium ở dạng "kata" nhưng viết lại Expected Output cụ thể và xáo đáp án quiz.
  • Chuyển: Labs từ Phase 8 về cuối từng Phase tương ứng (Lab 01/02 → Phase 2; 05 → Phase 3; 03 → Phase 4; 07/04 → Phase 5; 06/08-lite → Phase 6).
  • Thêm: Flaky Clinic, mini-project Java, 3 site thực hành, bài debug có lỗi cài sẵn, bug report, Capstone có nghiệp vụ + PR + CI.
  • Bỏ: việc đưa sẵn code đầy đủ của Lab 08 (chỉ giữ spec + tiêu chí); Lab 08 hiện còn như đáp án.
