Assertions và Verification

Liên quan: Mục lục · Trước: JUnit · Sau: Setup/Teardown

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Dùng Assert.assertEquals/assertTrue/assertFalse/assertNotEquals đúng thứ tự
  • Phân biệt Hard Assert và SoftAssert
  • Viết assertion có message và kiểm chứng trước/sau
  • Kiểm tra exception mong đợi

📋 Prerequisites

  • TestNG Fundamentals
  • Java Strings

1. Assertion là gì?

Assertion là phép kiểm tra "kết quả thực tế có đúng kỳ vọng không". Sai ⇒ ném AssertionError ⇒ test fail. Không có assertion ⇒ test chỉ kiểm tra "không crash" — không phải kiểm thử thực sự.

2. org.testng.Assert — từng method làm gì

Các method của Assert đều static (gọi Assert.xxx(...)) và trả về void. Khi đúng → không có gì xảy ra, test chạy tiếp. Khi sai → ném AssertionError → test fail ngay tại dòng đó, các dòng sau không chạy.

⚠️ Tham số message luôn nằm cuối và là tuỳ chọn. Thứ tự của TestNG: assertEquals(actual, expected) — giá trị thực tế trước, kỳ vọng sau. JUnit ngược lại (expected, actual).

2.1. assertEquals(actual, expected[, message])

  • Làm gì: kiểm tra hai giá trị bằng nhau theo equals(). Có bản riêng cho String, số, boolean, mảng (so từng phần tử), List (so cả thứ tự), Set, Map.
  • Sai thì: ném AssertionError với thông báo dạng expected [Secure Area] but found [Login Page] (kèm message của bạn ở đầu nếu có).
  • 🧩 Dùng ở: Ex 3, 4, 5, 6, 8, 9, 10.
  • Ví dụ:
java
Assert.assertEquals(driver.getTitle(), "The Internet");                 // String
Assert.assertEquals(rows.size(), 4, "Bảng phải có 4 dòng");            // int
Assert.assertEquals(actualList, List.of("Smith", "John"));              // List: so cả thứ tự
  • Lưu ý: với số thực dùng bản có sai số assertEquals(actual, expected, delta), vì 0.1 + 0.2 != 0.3.

2.2. assertNotEquals(actual, unexpected[, message])

  • Làm gì: kiểm tra hai giá trị khác nhau.
  • Sai thì: ném AssertionError khi hai giá trị bằng nhau.
  • 🧩 Dùng ở: Ex 2.
  • Ví dụ: Assert.assertNotEquals(checkbox.isSelected(), stateBeforeClick, "click phải đổi trạng thái");
  • Lưu ý: chỉ nói "khác", không nói "khác thế nào" — nếu biết giá trị mong đợi, dùng assertEquals chặt hơn.

2.3. assertTrue(condition[, message])

  • Làm gì: kiểm tra biểu thức boolean là true.
  • Sai thì: AssertionError thông báo expected [true] but found [false] — không cho biết giá trị nào gây ra, nên message rất quan trọng.
  • 🧩 Dùng ở: Ex 1, 2, 5, 6, 7, 8, 10.
  • Ví dụ:
java
Assert.assertTrue(msg.contains("You logged into a secure area!"), "Thông báo thực tế: " + msg);
  • Lưu ý: nên ghi giá trị thực tế vào message. Nếu so sánh bằng, dùng assertEquals thay vì assertTrue(a.equals(b)) để có thông báo đầy đủ.

2.4. assertFalse(condition[, message])

  • Làm gì: kiểm tra biểu thức là false.
  • Sai thì: AssertionError khi biểu thức là true.
  • 🧩 Dùng ở: Ex 10.
  • Ví dụ: Assert.assertFalse(input.isEnabled(), "Ban đầu input phải bị khoá");

2.5. assertNull(object[, message]) / assertNotNull(object[, message])

  • Làm gì: kiểm tra đối tượng là / không là null.
  • Ví dụ:
java
Assert.assertNull(driver.manage().getCookieNamed("khong-co"), "Không được có cookie này");
Assert.assertNotNull(driver.manage().getCookieNamed("session"), "Phải có cookie phiên");
  • Lưu ý: getCookieNamed trả null khi không có — đây là dạng kiểm tra tự nhiên.

2.6. assertSame(actual, expected) / assertNotSame(...)

  • Làm gì: kiểm tra hai biến trỏ vào cùng một đối tượng trong bộ nhớ (so bằng ==), không phải "giá trị giống nhau".
  • Ví dụ:
java
String a = new String("hi"), b = new String("hi");
Assert.assertEquals(a, b);     // ✅ pass: nội dung bằng nhau
Assert.assertSame(a, b);       // ❌ fail: hai đối tượng khác nhau
  • Lưu ý: hiếm dùng trong Selenium. Chỉ dùng khi cần xác nhận "chính là đối tượng đó" (ví dụ singleton).

2.7. assertEqualsNoOrder(actual, expected[, message])

  • Làm gì: so hai mảng có cùng phần tử, bỏ qua thứ tự (cùng số lượng, trùng lặp vẫn phải khớp số lần).
  • Ví dụ:
java
Assert.assertEqualsNoOrder(new String[]{"b", "a"}, new String[]{"a", "b"});   // ✅
  • Lưu ý: với List, assertEquals so cả thứ tự; muốn bỏ qua thứ tự thì so hai Set (mục 8).

2.8. assertThrows(Class<T> expected, ThrowingRunnable code) / expectThrows

  • Làm gì: chạy đoạn code và kiểm tra nó ném đúng loại exception (hoặc lớp con) đã chỉ định. Không ném gì hoặc ném loại khác → fail.
  • Khác nhau: assertThrows trả void; expectThrows trả về chính exception để bạn kiểm tra thêm (ví dụ getMessage()).
  • Ví dụ:
java
Assert.assertThrows(NoSuchElementException.class, () -> driver.findElement(By.id("khong-ton-tai")));

NoSuchElementException e = Assert.expectThrows(NoSuchElementException.class,
        () -> driver.findElement(By.id("khong-ton-tai")));
Assert.assertTrue(e.getMessage().contains("khong-ton-tai"));
  • Lưu ý: chặt hơn @Test(expectedExceptions=...) vì chỉ bao đúng một dòng, không phải cả method.

2.9. fail(message)

  • Làm gì: ép test fail ngay với thông báo cho trước.
  • Ví dụ:
java
try {
    driver.findElement(By.id("must-not-exist"));
    Assert.fail("Phần tử không được tồn tại");     // đến đây nghĩa là findElement không ném lỗi
} catch (NoSuchElementException expected) { }
  • Lưu ý: dùng khi đường chạy "lẽ ra không bao giờ đến được".

2.10. Bảng so sánh các method dễ nhầm

Muốn kiểm tra Nên dùng Không nên dùng Vì sao
Hai giá trị bằng nhau assertEquals(a, b) assertTrue(a.equals(b)) assertEquals in cả hai giá trị khi sai
Hai chuỗi bằng nhau assertEquals(s1, s2) assertTrue(s1 == s2) / assertSame == so địa chỉ, không so nội dung
Cùng một đối tượng assertSame(a, b) assertEquals(a, b) assertEquals chỉ so nội dung
Chuỗi chứa một đoạn assertTrue(s.contains(x), msg) assertEquals(s, x) assertEquals đòi bằng toàn bộ
Có/không có phần tử assertTrue(list.isEmpty()) / assertFalse(...) assertEquals(list.size(), 0) Cả hai được; isEmpty rõ nghĩa hơn
Hai list bằng, bỏ qua thứ tự So hai Set, hoặc assertEqualsNoOrder (mảng) assertEquals(list1, list2) assertEquals(List, List) so cả thứ tự
Bắt exception ở một dòng assertThrows expectedExceptions expectedExceptions bao cả method

🧩 Thứ tự tham số khi sai: nếu viết assertEquals(expected, actual) (đảo), thông báo lỗi "expected [..] but found [..]" sẽ đảo nghĩa làm bạn debug sai hướng.

🧩 Phân tích assert trong dự án:

java
// Ex1 — assertTrue với message có giá trị thực tế
Assert.assertTrue(actualMessage.contains("You logged into a secure area!"),
        "Nội dung thông báo không đúng! Thực tế: " + actualMessage);

// Ex2 — assertNotEquals kiểm chứng click thật sự đổi trạng thái
Assert.assertNotEquals(checkbox.isSelected(), stateBeforeClick, name + ": click phải làm đổi trạng thái được chọn!");

// Ex3 — assertEquals so sánh cả List<String>
Assert.assertEquals(firstRow, Arrays.asList("Smith", "John", "jsmith@gmail.com", "$50.00", "http://www.jsmith.com"), "...");

// Ex1 — assertEquals giữa hai WebElement: so sánh theo element id nội bộ
Assert.assertEquals(other, reference, "Các bộ định vị của '" + elementName + "' phải cùng trỏ về một phần tử!");

3. Hard Assert và Soft Assert

Hard Assert (Assert) Soft Assert (SoftAssert)
Khi sai Dừng ngay test Ghi nhận và chạy tiếp
Báo lỗi Lỗi đầu tiên Tất cả lỗi, khi gọi assertAll()
Dùng khi Các bước phụ thuộc nhau (đăng nhập sai thì khỏi kiểm tra tiếp) Kiểm tra nhiều thuộc tính độc lập (nhiều trường trên một trang)
java
SoftAssert soft = new SoftAssert();
soft.assertEquals(firstRow.get(0), "Smith", "Last name");
soft.assertEquals(firstRow.get(1), "John",  "First name");
soft.assertEquals(firstRow.get(2), "jsmith@gmail.com", "Email");
soft.assertAll();       // ⚠️ BẮT BUỘC: không gọi thì không bao giờ fail!

⚠️ Quên assertAll() là lỗi kinh điển: test luôn pass.

3.1. new SoftAssert()

  • Làm gì: tạo đối tượng "ghi nhớ lỗi". Các method assertEquals, assertTrue, assertNotEquals... của nó có cùng chữ ký với Assert, nhưng khi sai chỉ ghi lại lỗi và cho test chạy tiếp.
  • Lưu ý: tạo SoftAssert mới cho mỗi test (đừng dùng static dùng chung — lỗi test này lọt sang test khác).

3.2. softAssert.assertAll()

  • Làm gì: tổng kết: nếu có ít nhất một lỗi đã ghi nhận, ném một AssertionError liệt kê tất cả lỗi; nếu không có thì không làm gì.
  • Thông báo khi sai (dạng điển hình):
text
java.lang.AssertionError: The following asserts failed:
	Last name expected [Smith] but found [Smyth],
	Email expected [jsmith@gmail.com] but found [x@y.com]
  • Lưu ý: phải gọi assertAll() ở cuối test. Bản assertAll(String message) thêm câu mô tả. Sau assertAll() đã ném lỗi thì các dòng bên dưới không chạy.

3.3. Ví dụ so sánh hai cách

java
// Hard Assert: dừng ở lỗi đầu tiên → bạn chỉ thấy "Last name" sai, chưa biết Email có sai không
Assert.assertEquals(row.get(0), "Smith");
Assert.assertEquals(row.get(2), "jsmith@gmail.com");      // không bao giờ chạy tới nếu dòng trên fail

// Soft Assert: thấy cả hai lỗi trong một lần chạy
SoftAssert soft = new SoftAssert();
soft.assertEquals(row.get(0), "Smith", "Last name");
soft.assertEquals(row.get(2), "jsmith@gmail.com", "Email");
soft.assertAll();

⚠️ Không dùng Soft Assert cho bước phụ thuộc: nếu đăng nhập sai mà vẫn tiếp tục kiểm tra trang sau, các lỗi tiếp theo chỉ là hệ quả gây nhiễu.

4. Verify ≠ Assert (khái niệm)

Trong tài liệu tester, verify thường nghĩa là kiểm tra nhưng không dừng test khi sai (soft); assert dừng. TestNG: Assert (hard), SoftAssert (verify). Đề bài de.md dùng chữ "Verify" cho nghĩa "kiểm chứng"; dự án hiện thực bằng hard assert.

5. Viết assertion tốt

Nguyên tắc Ví dụ xấu Ví dụ tốt
Có message mô tả + dữ liệu assertTrue(x) assertTrue(x, "Thông báo thực tế: " + actual)
Assert đúng thứ cần kiểm assertTrue(el.isDisplayed()) chỉ để "có gì đó" assertEquals(el.getText(), "...")
Dùng assertEquals thay vì assertTrue(a.equals(b)) Thông báo lỗi nghèo assertEquals in cả expected/actual
Một test — một ý chính 20 assert không liên quan Tách test
Không assert trên dữ liệu tạm Chờ trạng thái ổn định rồi assert
Kiểm chứng trước và sau hành động Click rồi tin 🧩 Ex2 clickAndVerifyToggled
Tránh so sánh quá chặt dữ liệu thay đổi Ngày giờ hiện tại Dùng pattern/contains

6. Assertion với Selenium

java
// Trạng thái phần tử
Assert.assertTrue(flash.isDisplayed(), "Flash phải hiển thị");
Assert.assertFalse(input.isEnabled(), "Ban đầu input phải bị khoá");        // 🧩 Ex10
Assert.assertTrue(checkbox.isSelected(), "Checkbox phải được chọn");        // 🧩 Ex2

// Nội dung
Assert.assertEquals(driver.getTitle(), "The Internet");                      // 🧩 EnvironmentCheckTest
Assert.assertTrue(driver.getCurrentUrl().endsWith("/secure"));               // 🧩 Ex1

// Số lượng
Assert.assertEquals(driver.findElements(By.xpath(ROW_PREFIX)).size(), 4);   // 🧩 Ex3

// Không tồn tại
Assert.assertTrue(driver.findElements(By.id("checkbox")).isEmpty());

⚠️ Không assert trước khi chờ với nội dung bất đồng bộ. Ví dụ đúng: wait.until(textToBe(...)) rồi mới assertEquals. 🧩 Ex10 làm đúng (chờ textToBe("It's enabled!") rồi đọc, rồi assert).

7. Kiểm tra exception mong đợi

java
@Test(expectedExceptions = NoSuchElementException.class)
public void shouldNotFindMissingElement() {
    driver.get(BASE_URL + "/");
    driver.findElement(By.id("khong-ton-tai"));
}

// hoặc TestNG 7:
Assert.assertThrows(NoSuchElementException.class, () -> driver.findElement(By.id("khong-ton-tai")));

8. So sánh danh sách, bản đồ

java
Assert.assertEquals(actualList, expectedList);                        // cả thứ tự
Assert.assertEqualsNoOrder(actualArray, expectedArray);                // bỏ qua thứ tự (mảng)
Assert.assertEquals(new HashSet<>(actual), new HashSet<>(expected));   // set

9. Các lỗi thường gặp

Lỗi Hậu quả Cách tránh
Test không có assertion Pass giả Luôn kiểm chứng kết quả
Quên softAssert.assertAll() Pass giả Gọi cuối test
Sai thứ tự actual/expected Thông báo lỗi đánh lừa TestNG: actual trước
assertTrue(a == b) với String So sánh tham chiếu assertEquals
catch (AssertionError) nuốt Che lỗi Không bắt
Assert quá sớm (trước Wait) Flaky Wait → assert

✅ Best Practices

  1. Mỗi assert có message có giá trị thực tế (🧩 dự án làm tốt).
  2. Dùng Hard Assert mặc định; Soft Assert cho kiểm tra nhiều trường độc lập, nhớ assertAll().
  3. Assert trạng thái trước/sau hành động.
  4. Gom assert lặp thành helper (🧩 assertSameElement).

💼 Interview Corner

1. Hard assert vs soft assert?

  • 🇻🇳 Dịch: Hard assert khác soft assert?
  • Suggested answer (EN): A hard assert stops at the first failure; a soft assert records failures and continues until assertAll(), which I must call at the end.
  • Giải thích (VI): Soft cho nhiều kiểm tra độc lập.
  • Follow-up: What is the pitfall?

2. What makes a good assertion?

  • 🇻🇳 Dịch: Assertion tốt là gì?
  • Suggested answer (EN): It checks the specific expected behavior, has a descriptive message with the actual value, and verifies state before and after an action rather than only that nothing crashed.
  • Giải thích (VI): Ví dụ clickAndVerifyToggled (Exercise02).
  • Follow-up: How do you assert something does not exist?

📌 Lesson Summary

Kiến thức cần nhớ

  • Hard Assert dừng ngay; Soft Assert gom lỗi + assertAll()
  • TestNG: (actual, expected)
  • Có message + dữ liệu thực tế

Method / lệnh cần biết

  • assertEquals/assertNotEquals/assertTrue/assertFalse/assertNull, SoftAssert.assertAll, expectedExceptions/assertThrows

Điểm dễ nhầm lẫn

  • actual/expected (TestNG) vs expected/actual (JUnit)
  • Verify ≠ Assert (khái niệm)
  • Assert trước khi chờ → flaky
