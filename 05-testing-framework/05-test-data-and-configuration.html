1. Dự án hiện làm gì?

Hiện tại, mọi dữ liệu và cấu hình đều hard-code trong test:

Loại Vị trí Ví dụ
URL Hằng private static final ở mỗi class LOGIN_URL = "https://the-internet.herokuapp.com/login"
Tài khoản Hằng ở Exercise01 tomsmith / SuperSecretPassword! (tài khoản demo công khai)
Dữ liệu kỳ vọng Trong assertEquals Dữ liệu bảng ở Ex3 (Smith, John...)
Timeout BaseTest Duration.ofSeconds(15), 30
Browser BaseTest new ChromeDriver()
Suite testng.xml 10 class
Thông số Maven pom.xml selenium.version, testng.version, release

Với 10 bài tập học tập, cách này đơn giản và dễ đọc là hợp lý. Khi dự án lớn lên, cần tách để dễ bảo trì.

2. Vì sao nên tách dữ liệu và cấu hình?

Hard-code Tách ra
Đổi URL ⇒ sửa nhiều file Sửa 1 chỗ
Không chạy được nhiều môi trường -Denv=staging
Mật khẩu thật lộ trong Git Biến môi trường / file không commit
Thêm bộ dữ liệu ⇒ viết thêm test Thêm 1 dòng dữ liệu

3. Các loại dữ liệu/cấu hình

Nhóm Ví dụ Lưu ở
Cấu hình môi trường base.url, browser, timeout, headless config.properties, -D, biến môi trường
Dữ liệu test user, product, expected message JSON/CSV/Excel hoặc @DataProvider
Bí mật mật khẩu, token Biến môi trường/ secret của CI; không commit
Cấu hình build phiên bản thư viện pom.xml
Cấu hình chạy test nào chạy testng.xml, -Dtest, groups

4. File config.properties

Đặt trong src/test/resources/config.properties:

properties
base.url=https://the-internet.herokuapp.com
browser=chrome
timeout.seconds=15
headless=false

Đọc bằng Java thuần:

java
public final class Config {
    private static final Properties PROPS = new Properties();

    static {
        try (InputStream in = Config.class.getClassLoader().getResourceAsStream("config.properties")) {
            if (in == null) throw new IllegalStateException("Không tìm thấy config.properties trong classpath");
            PROPS.load(in);
        } catch (IOException e) {
            throw new UncheckedIOException(e);
        }
    }

    private Config() {}

    /** Ưu tiên: -Dkey (command line) > file properties > giá trị mặc định. */
    public static String get(String key, String defaultValue) {
        return System.getProperty(key, PROPS.getProperty(key, defaultValue));
    }

    public static int timeoutSeconds() { return Integer.parseInt(get("timeout.seconds", "15")); }
    public static String baseUrl()     { return get("base.url", "https://the-internet.herokuapp.com"); }
    public static String browser()     { return get("browser", "chrome"); }
}

Chạy ghi đè: .\mvnw.cmd test "-Dbrowser=firefox" "-Dtimeout.seconds=30".

Nhờ cơ chế chuỗi ưu tiên (-D > file > mặc định) bạn có cùng mã nguồn cho local và CI.

⚠️ Chỉ khi Surefire chuyển system property sang JVM test thì System.getProperty thấy giá trị từ -D — mặc định Surefire sao chép property của Maven; hoặc khai báo tường minh qua systemPropertyVariables (maven/02). Hãy tự kiểm chứng bằng cách in giá trị ra.

Đọc config.properties rồi chồng config-<env>.properties. Hoặc dùng Maven Profile (maven/06).

6. Dữ liệu test: @DataProvider

Dữ liệu nhỏ, trong code:

java
@DataProvider(name = "dropdownOptions")
public Object[][] dropdownOptions() {
    return new Object[][] { {"Option 1", "1"}, {"Option 2", "2"} };
}

@Test(dataProvider = "dropdownOptions")
public void shouldSelectOption(String text, String value) {
    driver.get(Config.baseUrl() + "/dropdown");
    Select s = new Select(driver.findElement(By.id("dropdown")));
    s.selectByVisibleText(text);
    Assert.assertEquals(s.getFirstSelectedOption().getAttribute("value"), value);
}

Dữ liệu lớn, ngoài code: đọc file rồi trả Object[][].

CSV (không cần thư viện)

src/test/resources/login.csv:

csv
username,password,expected
tomsmith,SuperSecretPassword!,You logged into a secure area!
tomsmith,wrong,Your password is invalid!
java
@DataProvider(name = "csvLogin")
public Object[][] csvLogin() throws IOException {
    try (InputStream in = getClass().getClassLoader().getResourceAsStream("login.csv");
         BufferedReader br = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8))) {
        return br.lines().skip(1).map(l -> l.split(",", 3)).toArray(Object[][]::new);
    }
}

Lưu ý: dữ liệu có dấu phẩy phải dùng thư viện CSV thật (OpenCSV/Commons CSV) — thêm vào pom.xml sau khi tra phiên bản ổn định.

JSON / Excel

JSON ⇒ Jackson/Gson; Excel ⇒ Apache POI. Chỉ thêm khi cần; nhớ ghim phiên bản và xem dependency:tree (maven/05).

7. Mô hình dữ liệu (POJO / record)

java
public record LoginData(String username, String password, String expectedMessage) {}

Java 21 (🧩 dự án release 21) hỗ trợ record — ngắn gọn, bất biến. DataProvider có thể trả Object[][] chứa LoginData.

8. Quản lý bí mật

  • ❌ Không commit mật khẩu thật. (Tài khoản tomsmith là demo công khai của trang luyện tập nên chấp nhận được.)
  • ✅ Dùng biến môi trường: System.getenv("APP_PASSWORD").
  • ✅ Trên CI: secret của CI (GitHub Actions Secrets...).
  • ✅ File cấu hình cục bộ chứa bí mật: thêm vào .gitignore.

9. Thứ tự ưu tiên khuyến nghị

text
-D (command line)  >  biến môi trường  >  config-<env>.properties  >  config.properties  >  giá trị mặc định trong code

✅ Best Practices

  1. Một nguồn sự thật cho mỗi giá trị.
  2. Tách dữ liệu khỏi logic; test chỉ mô tả hành vi.
  3. Không commit bí mật.
  4. Giá trị mặc định hợp lý để test chạy "ngay" sau khi clone.
  5. Dữ liệu test độc lập và có thể dọn (không phụ thuộc dữ liệu có sẵn trên server).

⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
getResourceAsStream trả null File không nằm trong src/test/resources / sai tên Đặt đúng vị trí; chạy test-compile để copy resource
-Dbrowser=firefox không có tác dụng Property không tới JVM test / code không đọc In ra giá trị; dùng systemPropertyVariables
Tiếng Việt trong CSV bị lỗi Mã hoá Đọc bằng UTF-8
Dữ liệu kỳ vọng hard-code lệch khi web đổi Phụ thuộc trang ngoài Dùng trang test ổn định/mock

💼 Interview Corner

1. How do you manage test data and configuration?

  • 🇻🇳 Dịch: Quản lý dữ liệu và cấu hình test?
  • Suggested answer (EN): I keep configuration in config.properties with command line overrides and defaults, and data in data providers or CSV/JSON files, with secrets in environment variables.
  • Giải thích (VI): Không hard-code.
  • Follow-up: Where do you keep passwords?

2. Why separate data from test logic?

  • 🇻🇳 Dịch: Vì sao tách dữ liệu?
  • Suggested answer (EN): So adding cases means adding data not code, changing environments is one edit, and tests describe behavior only.
  • Giải thích (VI): DataProvider.
  • Follow-up: What is a risk of external data?

📌 Lesson Summary

Kiến thức cần nhớ

  • Dự án hiện hard-code (hợp lý cho học tập)
  • Config: -D > file > mặc định
  • Dữ liệu: DataProvider/CSV; bí mật: biến môi trường

Method / lệnh cần biết

  • Properties, System.getProperty, @DataProvider, getResourceAsStream

Điểm dễ nhầm lẫn

  • Cấu hình build (pom) ≠ cấu hình test (properties)
  • Property của Maven JVM ≠ JVM test (cần chuyển)
  • CSV có dấu phẩy cần thư viện CSV
