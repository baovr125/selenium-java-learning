Chạy test và báo cáo

🎯 Learning Objectives

  • Liệt kê các cách chạy test và nơi lưu báo cáo

📋 Prerequisites

1. Bốn cách chạy test trong dự án

Cách Lệnh/thao tác Qua Maven? Báo cáo Dùng khi

Chi tiết lệnh Maven: maven/06.

3. Báo cáo Surefire (TestNG)

Thư mục target/surefire-reports/:

File Nội dung Dùng cho
index.html Báo cáo TestNG đầy đủ Người đọc
emailable-report.html Bản gọn, để gửi mail Chia sẻ (🧩 bản mẫu ở ket-qua/emailable-report.html)
testng-results.xml Dữ liệu chi tiết Công cụ phân tích
TEST-TestSuite.xml JUnit XML CI đọc để hiển thị kết quả
TestSuite.txt Tóm tắt một dòng Script kiểm tra nhanh
*.dumpstream Log hạ tầng JVM Debug Surefire

Mở nhanh:

powershell
Start-Process target\surefire-reports\emailable-report.html

4. Báo cáo do chạy bằng code

AllExercisesTest (TestNG API) ghi vào test-output/ (có index.html, emailable-report.html, testng-failed.xml, Command line suite/...). Hai thư mục báo cáo khác nhau ⇒ đừng nhầm khi tìm kết quả.

5. Chạy lại test fail

test-output/testng-failed.xml (🧩 đang liệt kê Exercise07_InfiniteScrollTest từ lần chạy cũ) là bộ test tạo sẵn cho lần chạy lại. Dùng để biết lần trước fail gì; để chạy lại bằng Maven, cách đơn giản nhất là -Dtest=Exercise07_InfiniteScrollTest.

6. Báo cáo nâng cao (tổng quan)

Công cụ Đặc điểm Dùng khi
Báo cáo TestNG/Surefire mặc định Có sẵn, không cần thêm Học tập/nhỏ
ExtentReports HTML đẹp, ảnh chụp, bước chi tiết Báo cáo cho QA lead/khách hàng
Allure Báo cáo tương tác, lịch sử, phân nhóm Dự án lớn, CI
Báo cáo CI (JUnit XML) CI tự hiển thị GitHub Actions/Jenkins

Cách tích hợp chung: viết một ITestListener (onTestStart/Success/Failure) để ghi bước, chụp ảnh khi fail, đẩy vào công cụ báo cáo. Thêm thư viện vào pom.xml sau khi tra phiên bản ổn định và xem dependency:tree.

7. Chạy trên CI (ví dụ minh hoạ)

GitHub Actions (không có trong dự án, chỉ minh hoạ):

yaml
name: ui-tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
      - run: chmod +x mvnw
      - run: ./mvnw -B clean test
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: surefire-reports
          path: target/surefire-reports

Điều kiện cần cho CI Linux: test chạy headless (không có màn hình) ⇒ cần ChromeOptions --headless=new và --window-size; trong container đôi khi cần thêm --no-sandbox. Dự án hiện chưa có (xem selenium/01). Chú ý ví dụ YAML chỉ minh hoạ; hãy kiểm tra phiên bản action hiện hành khi áp dụng.

Điểm mạnh của Maven Wrapper trong CI: không cần bước cài Maven, chỉ cần JDK (./mvnw).

8. Danh sách kiểm tra sau mỗi lần chạy

  • Tests run = số test mong đợi.
  • Skipped: 0 (hoặc hiểu vì sao > 0).
  • Xem test fail trong emailable-report.html.
  • Phân loại: bug sản phẩm / bug test / môi trường / flaky.
  • Không commit target/, test-output/.

⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
Không thấy báo cáo Chạy bằng cách khác Maven Tìm đúng thư mục (target/surefire-reports vs test-output)
Báo cáo cũ Không clean clean test
Tests run: 0 Sai -Dtest/class maven/06
CI fail, local pass Headless/kích thước/Chrome khác Cấu hình headless; cố định --window-size

💼 Interview Corner

1. How do you read test results from a Maven run?

  • 🇻🇳 Dịch: Đọc kết quả test từ Maven?
  • Suggested answer (EN): I check Tests run, failures, errors and skipped counts, not only BUILD SUCCESS, and open the reports under target/surefire-reports.
  • Giải thích (VI): Zero tests still gives BUILD SUCCESS.
  • Follow-up: How do you guard in CI?

2. How would you run the suite in CI?

  • 🇻🇳 Dịch: Chạy suite trong CI?
  • Suggested answer (EN): Use the Maven Wrapper (./mvnw -B clean test) with JDK only, run headless, upload the surefire reports as artifacts, and fail if zero tests ran.
  • Giải thích (VI): Cần headless + window-size.
  • Follow-up: Why use the wrapper in CI?

📌 Lesson Summary

Kiến thức cần nhớ

  • Hai nơi báo cáo: target/surefire-reports (Maven) và test-output (chạy code)
  • Luôn đọc Tests run/Failures/Errors/Skipped
  • CI: headless + upload báo cáo + kiểm tra Tests run > 0

Method / lệnh cần biết

  • emailable-report.html, TEST-TestSuite.xml, testng-results.xml, TestSuite.txt

Điểm dễ nhầm lẫn

  • Surefire reports ≠ TestNG output
  • BUILD SUCCESS ≠ test pass
  • Failures ≠ Errors
