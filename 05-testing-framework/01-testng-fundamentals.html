TestNG Fundamentals

Liên quan: Mục lục · Sau: JUnit · Setup/Teardown · Phỏng vấn Phiên bản dự án: TestNG 7.10.2 (org.testng:testng, scope test).

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Giải thích TestNG làm gì so với Selenium
  • Nhớ thứ tự annotation và dùng @BeforeMethod/@AfterMethod

  • Hiểu vì sao <test> trong XML không phải một test method

📋 Prerequisites

  • Java Lambda & Generics (annotations)
  • Java Arrays (Object[][])

1. TestNG là gì?

TestNG (Test Next Generation) là framework kiểm thử cho Java lấy cảm hứng từ JUnit và NUnit, thêm nhiều tính năng hữu ích cho automation: nhóm test (groups), phụ thuộc (dependsOnMethods), @DataProvider, chạy song song, cấu hình bằng XML, báo cáo HTML.

Nó không điều khiển trình duyệt; nó tổ chức và chạy test, còn Selenium điều khiển trình duyệt. Hai thư viện bổ sung cho nhau.

2. Annotation chính

Annotation Chạy khi nào Dùng cho
@BeforeSuite / @AfterSuite 1 lần trước/sau cả suite Khởi tạo report, đọc config
@BeforeTest / @AfterTest Trước/sau thẻ <test> trong XML Hiếm dùng
@BeforeClass / @AfterClass 1 lần trước/sau mỗi class Mở browser dùng chung cho class
@BeforeMethod / @AfterMethod Trước/sau mỗi @Test 🧩 BaseTest.setup()/tearDown()
@Test Là một test
@DataProvider Cung cấp dữ liệu cho test Data-driven
@Parameters Nhận tham số từ testng.xml Browser, URL
@BeforeGroups / @AfterGroups Quanh nhóm

Thứ tự thực thi

text
@BeforeSuite
  @BeforeTest
    @BeforeClass
      @BeforeMethod   ← 🧩 mở Chrome
        @Test
      @AfterMethod    ← 🧩 quit()
      @BeforeMethod
        @Test
      @AfterMethod
    @AfterClass
  @AfterTest
@AfterSuite

3. Thuộc tính của @Test

java
@Test(priority = 1, groups = {"smoke", "login"}, description = "Đăng nhập đúng",
      enabled = true, timeOut = 60000, invocationCount = 1,
      dependsOnMethods = {"testOpenHerokuApp"})
public void testLoginSuccess() { ... }
Thuộc tính Ý nghĩa Lưu ý
priority Số nhỏ chạy trước (mặc định 0) Thứ tự test không nên là bắt buộc
groups Gắn nhãn Chạy theo nhóm
enabled=false Test không được chạy (thường không xuất hiện trong kết quả) Dùng cẩn thận: dễ quên và tạo "test ẩn"
dependsOnMethods Phụ thuộc test khác; nếu cái kia fail ⇒ test này skipped Tạo skipped; tránh lạm dụng
timeOut Quá thời gian (ms) ⇒ fail
invocationCount Chạy N lần Dùng thử flaky
expectedExceptions Mong đợi exception Test negative
description Mô tả trong báo cáo

🧩 Dự án chỉ dùng @Test trần; mỗi class đúng 1 @Test.

4. Thứ tự chạy test

  • Mặc định TestNG chạy method theo thứ tự bảng chữ cái (không phải thứ tự viết trong file) — không nên dựa vào đó.
  • Muốn thứ tự: priority, dependsOnMethods, hoặc testng.xml liệt kê method.
  • ✅ Nguyên tắc tốt: test độc lập, không cần thứ tự.

5. testng.xml

🧩 testng.xml của dự án:

xml
<suite name="Selenium Getting Started" verbose="1">
    <test name="Exercises 1-10">
        <classes>
            <class name="tests.Exercise01_LoginTest"/>
            ...
            <class name="tests.Exercise10_DynamicControlsTest"/>
        </classes>
    </test>
</suite>
Thẻ Ý nghĩa
<suite> Bộ gốc; name, verbose (0-10 mức log), parallel, thread-count
<test> Một nhóm test (không phải một method!)
<classes>/<class name="package.Class"> Class tham gia
<methods><include/><exclude/></methods> Chọn method
<groups><run><include name="smoke"/></run></groups> Chọn nhóm
<packages> Chọn theo package
<parameter name="..." value="..."/> Tham số
<listeners> Gắn listener

Ví dụ: chạy nhóm smoke

xml
<suite name="Smoke">
  <test name="Smoke tests">
    <groups><run><include name="smoke"/></run></groups>
    <packages><package name="tests"/></packages>
  </test>
</suite>

Tên <test> ≠ test method

Lỗi phổ biến của người mới: tưởng <test name="Exercises 1-10"> là một test case. Thực ra là một nhóm gồm nhiều class. Log Surefire thể hiện kết quả như Tests run: 10 (số method @Test).

6. Groups

java
@Test(groups = {"smoke"})   public void testLogin() {...}
@Test(groups = {"regression"}) public void testTable() {...}

Chạy: trong testng.xml (như trên). Dùng cho smoke / regression / sanity. Với Maven (Surefire): -Dgroups=smoke cũng được nhưng nếu suiteXmlFiles đã khai báo thì ưu tiên XML; khi dùng -Dtest thì XML bị bỏ qua (maven/06).

7. Data Provider (data-driven)

java
@DataProvider(name = "loginData")
public Object[][] loginData() {
    return new Object[][] {
        {"tomsmith", "SuperSecretPassword!", true,  "You logged into a secure area!"},
        {"tomsmith", "wrong",                 false, "Your password is invalid!"},
        {"nobody",   "x",                     false, "Your username is invalid!"}
    };
}

@Test(dataProvider = "loginData")
public void testLogin(String user, String pass, boolean ok, String expectedMessage) {
    driver.get("https://the-internet.herokuapp.com/login");
    driver.findElement(By.id("username")).sendKeys(user);
    driver.findElement(By.id("password")).sendKeys(pass);
    driver.findElement(By.cssSelector("button[type='submit']")).click();
    String msg = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash"))).getText();
    Assert.assertTrue(msg.contains(expectedMessage), "Thông báo thực tế: " + msg);
}
  • Mỗi hàng Object[] = một lần chạy test (kèm @BeforeMethod/@AfterMethod ⇒ mở/đóng Chrome mỗi hàng).
  • Nguồn dữ liệu: mảng, file CSV/JSON/Excel (đọc rồi trả Object[][]).
  • DataProvider có thể ở class khác: @Test(dataProvider = "x", dataProviderClass = TestData.class) (method static).
  • Muốn song song: @DataProvider(parallel = true).

⚠️ Thông báo thực tế của trang sai tài khoản là kiểm chứng trên trang chạy thật của bạn; chạy thử để lấy chuỗi chính xác, đừng chép mù.

8. Parameters từ testng.xml

xml
<suite name="Cross">
  <test name="Chrome">
    <parameter name="browser" value="chrome"/>
    <classes><class name="tests.Exercise01_LoginTest"/></classes>
  </test>
</suite>
java
@BeforeMethod
@Parameters("browser")
public void setup(@Optional("chrome") String browser) { ... }

@Optional cho giá trị mặc định nếu XML không có (hữu ích khi chạy -Dtest).

9. Chạy song song (Parallel)

xml
<suite name="Parallel" parallel="classes" thread-count="3">
parallel Chạy song song theo
methods Từng @Test
classes Từng class
tests Từng <test>
instances Từng instance

Điều kiện để an toàn: mỗi luồng có WebDriver riêng ⇒ không dùng static WebDriver; dùng ThreadLocal<WebDriver>:

java
private static final ThreadLocal<WebDriver> DRIVER = new ThreadLocal<>();
protected WebDriver driver() { return DRIVER.get(); }

🧩 Dự án chạy tuần tự, driver là field instance (đúng nhưng chỉ an toàn nếu mỗi instance một luồng). Chạy song song theo methods với cùng instance sẽ giẫm nhau. Surefire cũng có cấu hình parallel/threadCount riêng; nhưng với TestNG hãy ưu tiên cấu hình trong testng.xml.

10. Listener và retry

java
public class ScreenshotListener implements ITestListener {
    @Override public void onTestFailure(ITestResult result) { /* chụp ảnh */ }
}

Gắn: <listeners><listener class-name="listeners.ScreenshotListener"/></listeners> hoặc @Listeners(...). IRetryAnalyzer: thử lại test fail — chỉ dùng khi đã hiểu flaky (selenium/10).

11. TestNG tạo gì sau khi chạy?

Cách chạy Báo cáo
Surefire (mvnw test) target/surefire-reports/ (index.html, emailable-report.html, testng-results.xml, TEST-TestSuite.xml)
TestNG chạy bằng code/IDE (AllExercisesTest) test-output/ (có sẵn trong dự án: index.html, testng-failed.xml...)

testng-failed.xml liệt kê test fail để chạy lại. Dự án có bản cũ chứa Exercise07_InfiniteScrollTest.

✅ Best Practices

  1. Test độc lập; không dựa thứ tự.
  2. Dùng @BeforeMethod/@AfterMethod cho browser; @BeforeClass khi cần nhanh và test không phá trạng thái.
  3. Dùng groups cho smoke/regression.
  4. Dùng DataProvider cho dữ liệu lặp lại.
  5. Song song ⇒ ThreadLocal.
  6. enabled=false/dependsOnMethods dùng tiết chế vì tạo "test ẩn" hoặc skipped.

⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
Test không chạy Import org.junit.Test thay vì org.testng.annotations.Test Sửa import
ClassNotFoundException trong testng.xml Sai tên package/class tests.Exercise01_LoginTest (có package)
@BeforeMethod không chạy Method private/ không public; class không kế thừa public, extends BaseTest
DataProvider lỗi "provider not found" Sai tên/ không static khi ở class khác Kiểm tra name, static
Skipped bất ngờ dependsOnMethods của test trước fail Xem báo cáo
Song song mà trình duyệt "đánh nhau" static WebDriver ThreadLocal

💼 Interview Corner

1. What is TestNG and why use it with Selenium?

  • 🇻🇳 Dịch: TestNG là gì, vì sao dùng với Selenium?
  • Suggested answer (EN): TestNG organizes and runs tests with annotations, groups, data providers, parallel execution, XML suites and reports; Selenium controls the browser while TestNG manages lifecycle and results.
  • Giải thích (VI): Dự án: TestNG 7.10.2.
  • Follow-up: Can Selenium run without TestNG?

2. Explain the TestNG annotation order.

  • 🇻🇳 Dịch: Thứ tự annotation TestNG?
  • Suggested answer (EN): BeforeSuite, BeforeTest, BeforeClass, BeforeMethod, the test, AfterMethod, AfterClass, AfterTest, AfterSuite.
  • Giải thích (VI): BaseTest dùng BeforeMethod/AfterMethod.
  • Follow-up: When use BeforeClass?

📌 Lesson Summary

Kiến thức cần nhớ

  • Annotation: @Test, @BeforeMethod/@AfterMethod, @BeforeClass, @DataProvider, @Parameters
  • testng.xml: suite → test → classes/groups
  • Test nên độc lập, không dựa thứ tự

Method / lệnh cần biết

  • @Test(groups, dataProvider, priority, enabled), testng.xml, parallel, thread-count

Điểm dễ nhầm lẫn

  • <test> ≠ test method
  • @BeforeMethod ≠ @BeforeClass
  • dependsOnMethods có thể tạo skipped
