TestNG Fundamentals

Liên quan: Mục lục · Sau: JUnit · Setup/Teardown · Phỏng vấn Phiên bản dự án: TestNG 7.10.2 (org.testng:testng, scope test).

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Giải thích TestNG làm gì so với Selenium
  • Nhớ thứ tự annotation và dùng @BeforeMethod/@AfterMethod
  • Viết @DataProvider, groups, testng.xml
  • Hiểu vì sao <test> trong XML không phải một test method

📋 Prerequisites

  • Java Lambda & Generics (annotations)
  • Java Arrays (Object[][])

1. TestNG là gì?

TestNG (Test Next Generation) là framework kiểm thử cho Java lấy cảm hứng từ JUnit và NUnit, thêm nhiều tính năng hữu ích cho automation: nhóm test (groups), phụ thuộc (dependsOnMethods), @DataProvider, chạy song song, cấu hình bằng XML, báo cáo HTML.

Nó không điều khiển trình duyệt; nó tổ chức và chạy test, còn Selenium điều khiển trình duyệt. Hai thư viện bổ sung cho nhau.

2. Annotation chính — từng annotation làm gì

Annotation là nhãn dạng @Tên đặt trên method/class để nói với TestNG "method này dùng để làm gì". TestNG đọc nhãn rồi tự quyết định gọi method nào, lúc nào. Bạn không tự gọi các method này.

Cách đọc mỗi thẻ: Làm gì · Chạy mấy lần · Ví dụ · Lưu ý.

2.1. @Test

  • Làm gì: đánh dấu một method là một test case. TestNG chạy nó; ném exception (kể cả AssertionError từ Assert) = fail; chạy hết không lỗi = pass.
  • Chạy mấy lần: 1 lần mỗi method (nhiều hơn nếu có invocationCount hoặc dataProvider).
  • Ví dụ:
java
@Test
public void testLoginSuccess() { ... }
  • Lưu ý: method @Test phải public. Nếu đặt @Test trên class, mọi public method của class đó đều là test. Các thuộc tính của @Test ở mục 3.

2.2. @BeforeMethod / @AfterMethod

  • Làm gì: chạy trước / sau mỗi method @Test.
  • Chạy mấy lần: số lần = số @Test trong class.
  • Ví dụ: 🧩 BaseTest.setup() mở Chrome, tearDown() gọi quit().
java
@BeforeMethod public void setup()    { driver = new ChromeDriver(); }
@AfterMethod  public void tearDown() { if (driver != null) driver.quit(); }
  • Lưu ý: mỗi test có trình duyệt mới → test độc lập nhưng chậm hơn @BeforeClass. Method private hoặc class không kế thừa BaseTest thì không được gọi.

2.3. @BeforeClass / @AfterClass

  • Làm gì: chạy một lần trước test đầu tiên / sau test cuối cùng của class.
  • Chạy mấy lần: 1 lần mỗi class.
  • Ví dụ: mở một trình duyệt dùng chung cho cả class (nhanh hơn).
java
@BeforeClass public void openBrowser() { driver = new ChromeDriver(); }
@AfterClass  public void closeBrowser() { driver.quit(); }
  • Lưu ý: các test dùng chung trạng thái (cùng trình duyệt, cùng cookie). Test này có thể ảnh hưởng test kia → chỉ dùng khi test không phá trạng thái.

2.4. @BeforeTest / @AfterTest

  • Làm gì: chạy một lần trước / sau mỗi thẻ <test> trong testng.xml (không phải trước mỗi @Test!).
  • Chạy mấy lần: 1 lần mỗi thẻ <test>.
  • Lưu ý: tên dễ gây nhầm — đây không phải "trước mỗi test". Hiếm dùng; chủ yếu khi bạn chạy nhiều <test> với cấu hình khác nhau (browser khác nhau).

2.5. @BeforeSuite / @AfterSuite

  • Làm gì: chạy một lần trước mọi test / sau mọi test của cả suite (toàn bộ lần chạy).
  • Chạy mấy lần: 1 lần mỗi lần chạy suite.
  • Ví dụ: khởi tạo báo cáo, đọc file cấu hình, xoá thư mục ảnh chụp cũ.
  • Lưu ý: có thể đặt trong class bất kỳ thuộc suite; đừng mở trình duyệt ở đây nếu test chạy song song.

2.6. @BeforeGroups / @AfterGroups

  • Làm gì: chạy trước test đầu tiên / sau test cuối cùng thuộc một nhóm (groups) được chỉ định.
  • Ví dụ: @BeforeGroups("db") public void connectDb() {...}
  • Lưu ý: hiếm dùng; nhớ ghi tên nhóm trong annotation.

2.7. @DataProvider

  • Làm gì: đánh dấu method cung cấp dữ liệu cho test: mỗi hàng dữ liệu → TestNG gọi test một lần.
  • Trả về: Object[][] (mỗi Object[] là một bộ tham số) hoặc Iterator<Object[]> (tạo dần, hợp với dữ liệu lớn).
  • Thuộc tính: name (tên để test tham chiếu), parallel (chạy các hàng song song).
  • Ví dụ & lưu ý: xem mục 7.

2.8. @Parameters và @Optional

  • Làm gì: @Parameters("browser") đưa giá trị <parameter name="browser" value="..."/> từ testng.xml vào tham số của method. @Optional("chrome") đặt giá trị mặc định khi XML không khai báo.
  • Ví dụ & lưu ý: xem mục 8.

2.9. Thứ tự thực thi — có ví dụ

Hai class trong cùng một <test>: LoginTest có test a, b; TableTest có test c. Mỗi method in ra tên của nó.

java
public class LoginTest {
    @BeforeClass  public void bc() { log("LoginTest @BeforeClass"); }
    @BeforeMethod public void bm() { log("  @BeforeMethod"); }
    @Test         public void a()  { log("    test a"); }
    @Test         public void b()  { log("    test b"); }
    @AfterMethod  public void am() { log("  @AfterMethod"); }
    @AfterClass   public void ac() { log("LoginTest @AfterClass"); }
}
// TableTest tương tự với một test c

Kết quả theo quy tắc của TestNG (suite có @BeforeSuite/@BeforeTest ở class nào đó):

text
@BeforeSuite
@BeforeTest
LoginTest @BeforeClass
  @BeforeMethod
    test a
  @AfterMethod
  @BeforeMethod
    test b
  @AfterMethod
LoginTest @AfterClass
TableTest @BeforeClass
  @BeforeMethod
    test c
  @AfterMethod
TableTest @AfterClass
@AfterTest
@AfterSuite

Quy tắc ghi nhớ:

Muốn chạy… Dùng Số lần với 2 class, 3 test (a, b, c)
1 lần cả lần chạy @BeforeSuite 1
1 lần mỗi thẻ <test> @BeforeTest 1 (nếu một thẻ <test>)
1 lần mỗi class @BeforeClass 2
Trước mỗi test @BeforeMethod 3

Cặp @After... chạy theo thứ tự ngược (method → class → test → suite). Các @Before... của class cha chạy trước class con; @After... của class con chạy trước class cha.

text
Sơ đồ lồng nhau:
@BeforeSuite
  @BeforeTest
    @BeforeClass
      @BeforeMethod  ← 🧩 mở Chrome
        @Test
      @AfterMethod   ← 🧩 quit()
    @AfterClass
  @AfterTest
@AfterSuite

3. Thuộc tính của @Test

java
@Test(priority = 1, groups = {"smoke", "login"}, description = "Đăng nhập đúng",
      enabled = true, timeOut = 60000, invocationCount = 1,
      dependsOnMethods = {"testOpenHomePage"})
public void testLoginSuccess() { ... }

3.1. priority

  • Làm gì: quyết định thứ tự chạy giữa các test trong cùng class: số nhỏ chạy trước. Mặc định 0; cho phép số âm.
  • Ví dụ:
java
@Test(priority = 1) public void testOpenHome()  { ... }   // chạy trước
@Test(priority = 2) public void testLogin()     { ... }   // chạy sau
  • Lưu ý: các test cùng priority chạy theo thứ tự bảng chữ cái tên method. Dùng priority để ép thứ tự là dấu hiệu test phụ thuộc nhau — nên tránh.

3.2. groups

  • Làm gì: gắn nhãn nhóm cho test (một test có thể thuộc nhiều nhóm). Dùng để chạy riêng một nhóm.
  • Ví dụ: @Test(groups = {"smoke", "login"}); chọn nhóm bằng testng.xml (mục 6) hoặc -Dgroups=smoke.
  • Lưu ý: tên nhóm là chuỗi tự do — viết sai chính tả thì test không thuộc nhóm bạn muốn và không báo lỗi.

3.3. enabled

  • Làm gì: enabled = false → TestNG bỏ qua hoàn toàn test (thường không xuất hiện cả trong số lượng skipped).
  • Ví dụ: @Test(enabled = false) public void testFlaky() {...}
  • Lưu ý: dễ quên và tạo "test ẩn". Nếu tạm tắt, ghi lý do và ngày; hoặc chuyển sang groups rồi loại khỏi suite.

3.4. dependsOnMethods

  • Làm gì: test này chỉ chạy sau các method được liệt kê. Nếu method kia fail hoặc skip, test này bị SKIPPED (không chạy, không fail).
  • Ví dụ:
java
@Test public void testLogin() { ... }
@Test(dependsOnMethods = "testLogin") public void testLogout() { ... }
  • Lưu ý: tạo thứ tự và quan hệ phụ thuộc; một lỗi ở đầu chuỗi kéo theo hàng loạt test skipped, che mất lỗi gốc. Có alwaysRun = true để vẫn chạy kể cả khi phụ thuộc fail. Tương tự có dependsOnGroups cho cả nhóm.

3.5. timeOut

  • Làm gì: giới hạn thời gian chạy của test, đơn vị mili-giây. Chạy lâu hơn → test bị fail (TestNG chạy test trong luồng riêng và dừng nó).
  • Ví dụ: @Test(timeOut = 60000) — tối đa 60 giây.
  • Lưu ý: là thời gian của cả method, không phải của từng bước. Khác pageLoadTimeout hay WebDriverWait.

3.6. invocationCount

  • Làm gì: chạy cùng một test N lần liên tiếp (mỗi lần đều qua @BeforeMethod/@AfterMethod).
  • Ví dụ: @Test(invocationCount = 10) — chạy thử 10 lần để kiểm tra test có "flaky" không.
  • Lưu ý: kết quả hiển thị 10 lượt chạy; chỉ cần 1 lượt fail là có vấn đề cần xem.

3.7. expectedExceptions

  • Làm gì: test pass chỉ khi ném đúng loại exception chỉ định; fail nếu không ném gì hoặc ném loại khác.
  • Ví dụ:
java
@Test(expectedExceptions = NoSuchElementException.class)
public void testMissingElement() {
    driver.findElement(By.id("khong-ton-tai"));
}
  • Lưu ý: chỉ kiểm tra được cả method ném lỗi, không kiểm tra được "ném đúng dòng nào". Cần kiểm tra chặt hơn dùng Assert.assertThrows (Assertions).

3.8. description

  • Làm gì: thêm câu mô tả hiện trong báo cáo.
  • Ví dụ: @Test(description = "Đăng nhập đúng tài khoản")

3.9. dataProvider

  • Làm gì: nói với TestNG lấy dữ liệu từ @DataProvider có tên này; test chạy một lần cho mỗi hàng dữ liệu.
  • Ví dụ & lưu ý: mục 7.
Thuộc tính Có tác dụng Nếu dùng sai
priority Sắp thứ tự Test phụ thuộc thứ tự → dễ vỡ
groups Chọn test theo nhóm Sai chính tả → không báo lỗi
enabled=false Tắt test Thành "test ẩn"
dependsOnMethods Thứ tự + phụ thuộc Hàng loạt test skipped
timeOut Chặn test treo Đặt quá ngắn → fail oan
invocationCount Lặp N lần Chậm nếu N lớn
expectedExceptions Test negative Không chỉ rõ dòng nào ném lỗi

🧩 Dự án chỉ dùng @Test trần; mỗi class đúng 1 @Test.

4. Thứ tự chạy test

  • Mặc định TestNG chạy method theo thứ tự bảng chữ cái (không phải thứ tự viết trong file) — không nên dựa vào đó.
  • Muốn thứ tự: priority, dependsOnMethods, hoặc testng.xml liệt kê method.
  • ✅ Nguyên tắc tốt: test độc lập, không cần thứ tự.

5. testng.xml

🧩 testng.xml của dự án:

xml
<suite name="Selenium Getting Started" verbose="1">
    <test name="Exercises 1-10">
        <classes>
            <class name="tests.Exercise01_LoginTest"/>
            ...
            <class name="tests.Exercise10_DynamicControlsTest"/>
        </classes>
    </test>
</suite>
Thẻ Ý nghĩa
<suite> Bộ gốc; name, verbose (0-10 mức log), parallel, thread-count
<test> Một nhóm test (không phải một method!)
<classes>/<class name="package.Class"> Class tham gia
<methods><include/><exclude/></methods> Chọn method
<groups><run><include name="smoke"/></run></groups> Chọn nhóm
<packages> Chọn theo package
<parameter name="..." value="..."/> Tham số
<listeners> Gắn listener

Ví dụ: chạy nhóm smoke

xml
<suite name="Smoke">
  <test name="Smoke tests">
    <groups><run><include name="smoke"/></run></groups>
    <packages><package name="tests"/></packages>
  </test>
</suite>

Tên <test> ≠ test method

Lỗi phổ biến của người mới: tưởng <test name="Exercises 1-10"> là một test case. Thực ra là một nhóm gồm nhiều class. Log Surefire thể hiện kết quả như Tests run: 10 (số method @Test).

6. Groups

java
@Test(groups = {"smoke"})   public void testLogin() {...}
@Test(groups = {"regression"}) public void testTable() {...}

Chạy: trong testng.xml (như trên). Dùng cho smoke / regression / sanity. Với Maven (Surefire): -Dgroups=smoke cũng được nhưng nếu suiteXmlFiles đã khai báo thì ưu tiên XML; khi dùng -Dtest thì XML bị bỏ qua (maven/06).

7. Data Provider (data-driven)

java
@DataProvider(name = "loginData")
public Object[][] loginData() {
    return new Object[][] {
        {"tomsmith", "SuperSecretPassword!", true,  "You logged into a secure area!"},
        {"tomsmith", "wrong",                 false, "Your password is invalid!"},
        {"nobody",   "x",                     false, "Your username is invalid!"}
    };
}

@Test(dataProvider = "loginData")
public void testLogin(String user, String pass, boolean ok, String expectedMessage) {
    driver.get(BASE_URL + "/login");
    driver.findElement(By.id("username")).sendKeys(user);
    driver.findElement(By.id("password")).sendKeys(pass);
    driver.findElement(By.cssSelector("button[type='submit']")).click();
    String msg = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash"))).getText();
    Assert.assertTrue(msg.contains(expectedMessage), "Thông báo thực tế: " + msg);
}
  • Mỗi hàng Object[] = một lần chạy test (kèm @BeforeMethod/@AfterMethod ⇒ mở/đóng Chrome mỗi hàng).
  • Nguồn dữ liệu: mảng, file CSV/JSON/Excel (đọc rồi trả Object[][]).
  • DataProvider có thể ở class khác: @Test(dataProvider = "x", dataProviderClass = TestData.class) (method static).
  • Muốn song song: @DataProvider(parallel = true).

⚠️ Thông báo thực tế của trang sai tài khoản là kiểm chứng trên trang chạy thật của bạn; chạy thử để lấy chuỗi chính xác, đừng chép mù.

8. Parameters từ testng.xml

xml
<suite name="Cross">
  <test name="Chrome">
    <parameter name="browser" value="chrome"/>
    <classes><class name="tests.Exercise01_LoginTest"/></classes>
  </test>
</suite>
java
@BeforeMethod
@Parameters("browser")
public void setup(@Optional("chrome") String browser) { ... }

@Optional cho giá trị mặc định nếu XML không có (hữu ích khi chạy -Dtest).

9. Chạy song song (Parallel)

xml
<suite name="Parallel" parallel="classes" thread-count="3">

Giả sử suite có 2 class (LoginTest có test a, b; TableTest có test c), thread-count="3":

parallel Đơn vị đưa vào một luồng Ví dụ chạy Rủi ro
methods Từng @Test a, b, c chạy cùng lúc trên 3 luồng, kể cả a và b của cùng một class Cao nhất: các test cùng class dùng chung field (ví dụ driver)
classes Từng class LoginTest (a rồi b, tuần tự) song song với TableTest (c) Thấp hơn: các test trong 1 class vẫn tuần tự trên 1 luồng
tests Từng thẻ <test> trong XML Mỗi <test> một luồng Thấp nhất nếu các <test> độc lập
instances Từng đối tượng class (instance) Mỗi instance một luồng, các method của cùng instance tuần tự Dùng khi tạo nhiều instance bằng @Factory

Chọn classes thường là điểm bắt đầu an toàn nhất cho Selenium.

Điều kiện để an toàn: mỗi luồng có WebDriver riêng ⇒ không dùng static WebDriver; dùng ThreadLocal<WebDriver>:

java
private static final ThreadLocal<WebDriver> DRIVER = new ThreadLocal<>();
protected WebDriver driver() { return DRIVER.get(); }

🧩 Dự án chạy tuần tự, driver là field instance (đúng nhưng chỉ an toàn nếu mỗi instance một luồng). Chạy song song theo methods với cùng instance sẽ giẫm nhau. Surefire cũng có cấu hình parallel/threadCount riêng; nhưng với TestNG hãy ưu tiên cấu hình trong testng.xml.

10. Listener và retry

java
public class ScreenshotListener implements ITestListener {
    @Override public void onTestFailure(ITestResult result) { /* chụp ảnh */ }
}

Gắn: <listeners><listener class-name="listeners.ScreenshotListener"/></listeners> hoặc @Listeners(...). IRetryAnalyzer: thử lại test fail — chỉ dùng khi đã hiểu flaky (selenium/10).

12. So sánh nhanh với JUnit

Xem 02-junit-fundamentals.md.

✅ Best Practices

  1. Test độc lập; không dựa thứ tự.
  2. Dùng @BeforeMethod/@AfterMethod cho browser; @BeforeClass khi cần nhanh và test không phá trạng thái.
  3. Dùng groups cho smoke/regression.
  4. Dùng DataProvider cho dữ liệu lặp lại.
  5. Song song ⇒ ThreadLocal.
  6. enabled=false/dependsOnMethods dùng tiết chế vì tạo "test ẩn" hoặc skipped.

⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
Test không chạy Import org.junit.Test thay vì org.testng.annotations.Test Sửa import
ClassNotFoundException trong testng.xml Sai tên package/class tests.Exercise01_LoginTest (có package)
@BeforeMethod không chạy Method private/ không public; class không kế thừa public, extends BaseTest
DataProvider lỗi "provider not found" Sai tên/ không static khi ở class khác Kiểm tra name, static
Skipped bất ngờ dependsOnMethods của test trước fail Xem báo cáo
Song song mà trình duyệt "đánh nhau" static WebDriver ThreadLocal

  • D. Một nhóm các class
Xem đáp án

Đáp án: D. Số Tests run đếm method @Test.

Câu 4. Một class có 3 @Test, 1 @BeforeClass, 1 @BeforeMethod. Chạy class đó thì @BeforeClass và @BeforeMethod lần lượt chạy bao nhiêu lần?

  • A. 3 và 3
  • B. 1 và 3
  • C. 1 và 1
  • D. 3 và 1
Xem đáp án

Đáp án: B. @BeforeClass chạy một lần mỗi class; @BeforeMethod chạy trước mỗi @Test.

Câu 5. @Test(dependsOnMethods = "testLogin") và testLogin fail. Kết quả của test phụ thuộc?

  • A. Fail
  • B. Pass
  • C. Skipped
  • D. Vẫn chạy bình thường
Xem đáp án

Đáp án: C. Bị bỏ qua (skipped), không chạy. Thêm alwaysRun = true nếu vẫn muốn chạy.

Câu 6. parallel="classes" với thread-count="3": hai test trong cùng một class có chạy cùng lúc không?

  • A. Có
  • B. Không, chúng chạy tuần tự trên cùng một luồng
  • C. Tuỳ hệ điều hành
  • D. Chỉ khi dùng @DataProvider
Xem đáp án

Đáp án: B. classes đưa nguyên một class vào một luồng. Muốn các test cùng class song song phải dùng parallel="methods" (và driver riêng mỗi luồng).

💼 Interview Corner

1. What is TestNG and why use it with Selenium?

  • 🇻🇳 Dịch: TestNG là gì, vì sao dùng với Selenium?
  • Suggested answer (EN): TestNG organizes and runs tests with annotations, groups, data providers, parallel execution, XML suites and reports; Selenium controls the browser while TestNG manages lifecycle and results.
  • Giải thích (VI): Dự án: TestNG 7.10.2.
  • Follow-up: Can Selenium run without TestNG?

2. Explain the TestNG annotation order.

  • 🇻🇳 Dịch: Thứ tự annotation TestNG?
  • Suggested answer (EN): BeforeSuite, BeforeTest, BeforeClass, BeforeMethod, the test, AfterMethod, AfterClass, AfterTest, AfterSuite.
  • Giải thích (VI): BaseTest dùng BeforeMethod/AfterMethod.
  • Follow-up: When use BeforeClass?

📌 Lesson Summary

Kiến thức cần nhớ

  • Annotation: @Test, @BeforeMethod/@AfterMethod, @BeforeClass, @DataProvider, @Parameters
  • testng.xml: suite → test → classes/groups
  • Test nên độc lập, không dựa thứ tự

Method / lệnh cần biết

  • @Test(groups, dataProvider, priority, enabled), testng.xml, parallel, thread-count

Điểm dễ nhầm lẫn

  • <test> ≠ test method
  • @BeforeMethod ≠ @BeforeClass
  • dependsOnMethods có thể tạo skipped
