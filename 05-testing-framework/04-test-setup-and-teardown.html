1. Vì sao cần Setup/Teardown?

Mỗi test cần trạng thái ban đầu sạch (trình duyệt mới, chưa đăng nhập) và phải dọn dẹp sau cùng (đóng trình duyệt) dù pass hay fail. Đặt logic này ở một chỗ (BaseTest) để 10 class không lặp lại.

2. Phân tích BaseTest của dự án

java
public class BaseTest {
    protected WebDriver driver;          // field protected: class con dùng trực tiếp
    protected WebDriverWait wait;

    @BeforeMethod
    public void setup() {
        driver = new ChromeDriver();
        driver.manage().window().maximize();
        driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(30));
        wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }

    @AfterMethod
    public void tearDown() {
        if (driver != null) {
            driver.quit();
        }
    }
}
Dòng Giải thích Lý do thiết kế
protected Class con (package khác) truy cập được Không cần getter; vẫn không public
@BeforeMethod Chạy trước mỗi @Test Mỗi test một Chrome mới ⇒ độc lập
window().maximize() Tránh phần tử bị che do cửa sổ nhỏ Ổn định locator/hover
pageLoadTimeout(30s) get() không treo vô hạn Fail nhanh khi mạng hỏng
new WebDriverWait(..., 15s) Một Wait dùng chung Không cần tạo lại ở từng test
if (driver != null) setup() có thể fail trước khi gán Tránh NullPointerException che lỗi gốc
quit() Đóng cả session Không rò rỉ process

Không có Implicit Wait — cố ý (xem Javadoc trong file và selenium/05).

3. Kế thừa hoạt động thế nào?

java
public class Exercise01_LoginTest extends BaseTest {
    @Test
    public void testLoginSuccess() {
        driver.get(LOGIN_URL);      // dùng driver của BaseTest
        ...
    }
}

TestNG quét class con, thấy method kế thừa có @BeforeMethod/@AfterMethod ⇒ gọi tự động quanh testLoginSuccess. Class con không cần viết lại.

Luồng chạy Exercise01_LoginTest:

text
BaseTest.setup()  →  Exercise01_LoginTest.testLoginSuccess()  →  BaseTest.tearDown()

Vì vậy 10 test = 10 lần mở Chrome (≈ 91 giây cả bộ — target/surefire-reports/TestSuite.txt).

4. Hai cách chạy: TestNG và main()

Mỗi class có main():

java
public static void main(String[] args) {
    Exercise01_LoginTest test = new Exercise01_LoginTest();
    try {
        test.setup();                      // gọi tay vì không có TestNG
        test.testLoginSuccess();
    } finally {
        test.tearDown();                   // luôn dọn dẹp
    }
}
TestNG/Maven main()
Ai gọi setup/tearDown TestNG (annotation) Code gọi tay
try/finally Không cần (TestNG đảm bảo) Cần
Báo cáo Surefire/TestNG In ra console
Dùng khi mvnw test, CI Chạy nhanh bằng run-test.ps1/IDE

5. Các cấp độ Setup

Cấp Annotation Khi dùng Đánh đổi
Mỗi test @BeforeMethod Mặc định — độc lập Chậm (mở Chrome mỗi test)
Mỗi class @BeforeClass Nhiều test cùng trang, không phá trạng thái Nhanh hơn; test có thể ảnh hưởng nhau
Cả suite @BeforeSuite Khởi tạo report/config 1 lần
Mỗi nhóm @BeforeGroups Setup riêng cho nhóm

Ví dụ @BeforeClass (đổi trade-off):

java
@BeforeClass public void setupClass() { driver = new ChromeDriver(); ... }
@AfterClass  public void tearDownClass() { if (driver != null) driver.quit(); }
@BeforeMethod public void goHome() { driver.get(BASE_URL); }     // trả về trạng thái đầu

6. Vòng đời khi test fail

  • @AfterMethod vẫn chạy khi test fail (mặc định) ⇒ quit() luôn được gọi ⇒ không rò rỉ.
  • Nếu @BeforeMethod fail (ví dụ không khởi tạo được Chrome): các test sau trong class thường bị skipped (cấu hình method fail ⇒ skip), và @AfterMethod có thể vẫn chạy ⇒ vì vậy kiểm tra driver != null là cần thiết.
  • Chụp ảnh khi fail: nhận ITestResult trong @AfterMethod (selenium/10).

7. Thiết kế tốt hơn (đề xuất — không sửa dự án)

java
public abstract class BaseTest {
    private static final ThreadLocal<WebDriver> DRIVER = new ThreadLocal<>();
    protected WebDriverWait wait;

    protected WebDriver driver() { return DRIVER.get(); }

    @BeforeMethod(alwaysRun = true)
    @Parameters({"browser"})
    public void setup(@Optional("chrome") String browser) {
        DRIVER.set(DriverFactory.create(browser));          // Factory
        driver().manage().window().maximize();
        wait = new WebDriverWait(driver(), Duration.ofSeconds(Config.timeoutSeconds()));
    }

    @AfterMethod(alwaysRun = true)
    public void tearDown(ITestResult result) {
        if (driver() != null) {
            if (result.getStatus() == ITestResult.FAILURE) Screenshots.take(driver(), result.getName());
            driver().quit();
            DRIVER.remove();                                // tránh rò rỉ ThreadLocal
        }
    }
}
Cải tiến Lợi ích
ThreadLocal Chạy song song an toàn
DriverFactory Nhiều browser
Config Không hard-code timeout/URL
alwaysRun = true Teardown chạy cả khi group/ phụ thuộc bị bỏ qua
Screenshot khi fail Điều tra dễ
DRIVER.remove() Tránh rò rỉ bộ nhớ trong thread pool

Các thành phần này giải thích ở framework-design/.

✅ Best Practices

  1. Một nơi duy nhất tạo/đóng driver.
  2. Luôn kiểm tra null trước quit().
  3. quit() không close().
  4. Trạng thái ban đầu sạch cho mỗi test.
  5. Setup không chứa assertion nghiệp vụ.

⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
NullPointerException ở driver.get setup() không chạy (không kế thừa/ sai annotation) extends BaseTest, import đúng
Chrome không đóng tearDown không chạy / quên quit Kiểm tra annotation
Test sau dùng nhầm trạng thái của test trước Dùng @BeforeClass mà không reset Reset hoặc dùng @BeforeMethod
Song song bị hỏng static driver ThreadLocal

💼 Interview Corner

1. Explain your BaseTest.

  • 🇻🇳 Dịch: Giải thích BaseTest của bạn.
  • Suggested answer (EN): It owns the driver and the explicit wait, creates Chrome, maximizes the window and sets the page load timeout in @BeforeMethod, and quits it in @AfterMethod with a null check, so every test gets a clean browser.
  • Giải thích (VI): Không implicit wait.
  • Follow-up: How would you support parallel runs?

2. BeforeMethod vs BeforeClass for the browser?

  • 🇻🇳 Dịch: BeforeMethod hay BeforeClass cho browser?
  • Suggested answer (EN): BeforeMethod gives isolation but is slower; BeforeClass is faster but tests can affect each other, so state must be reset.
  • Giải thích (VI): Chọn theo nhu cầu.
  • Follow-up: What about failures in setup?

📌 Lesson Summary

Kiến thức cần nhớ

  • BaseTest: setup mở browser, teardown quit() có kiểm tra null
  • @BeforeMethod (độc lập) vs @BeforeClass (nhanh)
  • Teardown vẫn chạy khi test fail

Method / lệnh cần biết

  • @BeforeMethod, @AfterMethod(alwaysRun=true), ITestResult, ThreadLocal

Điểm dễ nhầm lẫn

  • Chụp ảnh sau quit() thì hỏng
  • static driver ≠ ThreadLocal
  • close ≠ quit
