JUnit Fundamentals (so sánh với TestNG)

Liên quan: Mục lục · Trước: TestNG · Sau: Assertions · Phỏng vấn ⚠️ Dự án Selenium1 không dùng JUnit. Tài liệu này để bạn hiểu và so sánh, vì nhiều công ty dùng JUnit 5. Ví dụ code không được biên dịch trong dự án; hãy thử trong thư mục thực hành riêng.

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Ánh xạ annotation TestNG ↔ JUnit 5
  • Viết @ParameterizedTest cơ bản
  • Nhớ thứ tự tham số assertEquals khác nhau
  • Biết dự án này không dùng JUnit

📋 Prerequisites

  • TestNG Fundamentals

1. JUnit là gì?

JUnit là framework kiểm thử đơn vị phổ biến nhất của Java. Hiện tại là JUnit 5 (JUnit Platform + Jupiter + Vintage). Package: org.junit.jupiter.api. JUnit 4 (package org.junit) vẫn còn trong nhiều dự án cũ.

Tọa độ Maven (JUnit 5, bạn tự tra phiên bản ổn định mới nhất và ghim trong <properties>):

xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>${junit.version}</version>
    <scope>test</scope>
</dependency>

Surefire (≥ 2.22) tự nhận JUnit Platform provider.

2. Annotation JUnit 5

JUnit 5 Ý nghĩa Tương đương TestNG
@Test Một test @Test
@BeforeEach / @AfterEach Trước/sau mỗi test @BeforeMethod / @AfterMethod
@BeforeAll / @AfterAll 1 lần trước/sau class (method static, trừ khi dùng @TestInstance(PER_CLASS)) @BeforeClass / @AfterClass
@Disabled Bỏ qua @Test(enabled=false)
@DisplayName("...") Tên hiển thị description
@Tag("smoke") Nhóm groups
@ParameterizedTest + nguồn Data-driven @DataProvider
@RepeatedTest(n) Lặp invocationCount
@Timeout Giới hạn thời gian timeOut
@Order + @TestMethodOrder Thứ tự priority
@ExtendWith Mở rộng/Listener ITestListener

2.1. Từng annotation làm gì (khác TestNG ở đâu)

Annotation Làm chính xác gì Khác TestNG
@Test Đánh dấu một method là test. Fail khi ném exception (gồm AssertionFailedError). Method không cần public TestNG bắt buộc public
@BeforeEach Chạy trước mỗi @Test = @BeforeMethod
@AfterEach Chạy sau mỗi @Test = @AfterMethod
@BeforeAll Chạy một lần trước test đầu tiên của class. Phải là method static (trừ khi class có @TestInstance(PER_CLASS)) = @BeforeClass, nhưng bắt buộc static
@AfterAll Chạy một lần sau test cuối của class; cũng static = @AfterClass
@Disabled("lý do") Bỏ qua test và báo là skipped kèm lý do enabled=false của TestNG thường không hiện trong báo cáo
@DisplayName("...") Tên hiển thị của test (cho phép tiếng Việt, dấu cách) = description
@Tag("smoke") Gắn nhãn nhóm; chọn nhóm khi chạy bằng Maven -Dgroups=smoke hoặc cấu hình Platform = groups
@ParameterizedTest + nguồn dữ liệu Chạy test một lần cho mỗi bộ dữ liệu = @DataProvider + dataProvider
@RepeatedTest(n) Chạy cùng một test n lần = invocationCount
@Timeout(value, unit) Test chạy quá thời gian → fail = timeOut (TestNG dùng ms)
@TestMethodOrder + @Order(n) Đặt thứ tự chạy; số nhỏ chạy trước = priority
@ExtendWith(...) Gắn "extension" (listener, tiêm tham số...) ≈ ITestListener/@Listeners

Khác biệt quan trọng về vòng đời: JUnit 5 tạo một đối tượng class test mới cho mỗi @Test (mặc định PER_METHOD). Vì vậy field driver của test này không còn nằm lại cho test khác. TestNG dùng một đối tượng cho cả class, nên field được giữ giữa các test — dễ dẫn đến test "phá" trạng thái nhau.

3. Ví dụ tương đương BaseTest (JUnit 5)

java
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;

public abstract class BaseJUnitTest {
    protected static final String BASE_URL = "https://example.com";   // đặt địa chỉ site demo của bạn
    protected WebDriver driver;
    protected WebDriverWait wait;

    @BeforeEach
    void setup() {
        driver = new ChromeDriver();
        driver.manage().window().maximize();
        wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }

    @AfterEach
    void tearDown() {
        if (driver != null) driver.quit();
    }
}

Test login:

java
class LoginJUnitTest extends BaseJUnitTest {
    @Test
    @DisplayName("Đăng nhập thành công hiển thị thông báo")
    void loginSuccess() {
        driver.get(BASE_URL + "/login");
        driver.findElement(By.id("username")).sendKeys("tomsmith");
        driver.findElement(By.id("password")).sendKeys("SuperSecretPassword!");
        driver.findElement(By.cssSelector("button[type='submit']")).click();
        String msg = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash"))).getText();
        assertTrue(msg.contains("You logged into a secure area!"), "Thực tế: " + msg);
    }
}

Điểm khác: method test không cần public (package-private được), dùng import static org.junit.jupiter.api.Assertions.*.

5. Assertions JUnit 5

java
assertEquals(expected, actual, "message");     // ⚠️ thứ tự (expected, actual) — NGƯỢC với TestNG
assertTrue(cond, "message");
assertAll("login", () -> assertEquals(...), () -> assertTrue(...));   // gom nhiều assertion (soft)
assertThrows(NoSuchElementException.class, () -> driver.findElement(By.id("x")));
Method JUnit 5 Làm chính xác gì Tương đương TestNG
assertEquals(expected, actual[, message]) So bằng equals(). Message có thể nằm cuối (tham số cuối cùng) assertEquals(actual, expected) — đảo thứ tự
assertNotEquals(unexpected, actual) Hai giá trị khác nhau assertNotEquals
assertTrue(cond[, message]) / assertFalse Điều kiện đúng / sai Giống
assertNull / assertNotNull Null / không null Giống
assertSame / assertNotSame Cùng / khác đối tượng (==) Giống
assertArrayEquals(exp, act) So hai mảng theo từng phần tử assertEquals cho mảng
assertIterableEquals(exp, act) So hai Iterable theo thứ tự assertEquals cho List
assertAll("tên nhóm", executables...) Chạy tất cả assertion trong nhóm, báo mọi lỗi cùng lúc SoftAssert + assertAll()
assertThrows(Class, Executable) Phải ném exception đó; trả về exception để kiểm tra thêm assertThrows / expectThrows
assertTimeout(Duration, Executable) Thực thi phải xong trong thời gian cho trước @Test(timeOut)
fail("message") Ép fail Assert.fail

Không cần nhớ thuộc lòng từng method: chỉ cần nhớ (1) thứ tự expected, actual, (2) assertAll = soft assert, (3) assertThrows trả exception.

6. So sánh TestNG và JUnit 5

Tiêu chí TestNG (🧩 dự án) JUnit 5
Package org.testng org.junit.jupiter.api
Setup mỗi test @BeforeMethod @BeforeEach
Setup 1 lần/class @BeforeClass @BeforeAll (static)
Suite/Test/Class cấp trên @BeforeSuite, @BeforeTest, testng.xml Không có khái niệm tương đương trực tiếp
Cấu hình suite testng.xml mạnh Không có file XML chuẩn; dùng @Suite/Platform Suite
Nhóm groups @Tag
Data-driven @DataProvider (linh hoạt, Object[][]) @ParameterizedTest (gọn)
Phụ thuộc test dependsOnMethods Không hỗ trợ trực tiếp (chủ ý)
Thứ tự priority, theo XML @Order
Song song Cấu hình sẵn trong XML Cấu hình qua junit-platform.properties
Thứ tự assertion assertEquals(actual, expected) assertEquals(expected, actual)
Soft assert SoftAssert assertAll
Báo cáo HTML mặc định Dựa vào Surefire/IDE
Phổ biến Rất phổ biến trong automation UI Chuẩn de-facto cho unit test; ngày càng nhiều dùng cho UI
Phù hợp Test E2E/UI có suite, parallel, data-driven Unit test, tích hợp Spring Boot

Kết luận thực tế: với Selenium nhiều team chọn TestNG vì testng.xml + DataProvider + parallel; một số team chọn JUnit 5 cho tính đồng nhất với unit test. Không có lựa chọn "đúng tuyệt đối" — quan trọng là nhất quán trong dự án. Khái niệm (setup/teardown, assert, data-driven) chuyển đổi dễ dàng.

7. Cẩn thận khi trộn

  • Không đặt cả TestNG và JUnit trong cùng module nếu không có lý do: Surefire có thể chọn provider không như ý.
  • import org.junit.Test (JUnit 4) ≠ org.junit.jupiter.api.Test (JUnit 5). Nhầm import ⇒ test không chạy.

Tóm tắt

  • Dự án dùng TestNG; biết JUnit 5 để thích nghi.
  • Bảng ánh xạ ở mục 2/6 là thứ cần thuộc cho phỏng vấn.
  • Chú ý thứ tự tham số assertEquals khác nhau giữa hai framework.

💼 Interview Corner

1. TestNG vs JUnit 5 — main differences?

  • 🇻🇳 Dịch: Khác biệt chính TestNG và JUnit 5?
  • Suggested answer (EN): TestNG has testng.xml suites, groups, dependsOnMethods and DataProvider; JUnit 5 has tags, parameterized tests and a modular platform; lifecycle names and the assertion argument order differ.
  • Giải thích (VI): Nhất quán trong dự án quan trọng hơn.
  • Follow-up: Which would you choose and why?

2. Can you mix TestNG and JUnit in one module?

  • 🇻🇳 Dịch: Trộn hai framework?
  • Suggested answer (EN): It is possible but risky because Surefire may select the wrong provider; avoid unless necessary.
  • Giải thích (VI): Chú ý import org.junit.Test nhầm.
  • Follow-up: What happens with a wrong import?

📌 Lesson Summary

Kiến thức cần nhớ

  • @BeforeEach/@AfterEach, @BeforeAll/@AfterAll, @ParameterizedTest, @Tag
  • Thứ tự assertEquals ngược nhau
  • Dự án dùng TestNG

Method / lệnh cần biết

  • assertEquals(expected, actual), assertAll, assertThrows

Điểm dễ nhầm lẫn

  • JUnit 4 (org.junit) ≠ JUnit 5 (org.junit.jupiter)
  • TestNG (actual, expected) ≠ JUnit (expected, actual)
  • @BeforeAll thường cần static
