1. Maven Wrapper và làm việc nhóm

1.1. Kịch bản từ đầu đến cuối

Giả sử bạn là Bảo (thành viên mới) và Selenium1 đã được đẩy lên GitHub.

Bước Hành động Lệnh Điều xảy ra bên dưới
1 Clone dự án git clone <url> rồi cd Selenium1 Bạn nhận pom.xml, mvnw, mvnw.cmd, .mvn/wrapper/, src/, testng.xml, .gitignore. Không có target/ hay .mvn/repository/
2 Kiểm tra JDK java -version Cần ≥ 21
3 Không cài Maven mvn -version ⇒ lỗi Bình thường, không sao
4 Xác nhận Wrapper chạy .\mvnw.cmd -version Tải Maven 3.9.16 vào ~/.m2/wrapper/dists/ (lần đầu)
5 Chạy test .\mvnw.cmd clean test Tải thư viện vào .mvn/repository (lần đầu chậm), biên dịch, chạy 10 test
6 Thêm thư viện mới (ví dụ slf4j-simple) Sửa pom.xml, thêm <dependency> Chưa tải gì cho đến khi chạy Maven
7 Kiểm chứng .\mvnw.cmd dependency:tree rồi .\mvnw.cmd clean test Maven tải thư viện mới vào Local Repository; test phải vẫn xanh
8 Cập nhật dependency Đổi <selenium.version>, chạy lại clean test Maven tải phiên bản mới; đọc kỹ kết quả test
9 Commit, push git add pom.xml → git commit → git push Chỉ pom.xml đổi; không có file jar nào được commit
10 Đồng đội pull git pull rồi .\mvnw.cmd test Máy họ tự tải thư viện mới do pom.xml chỉ định — không cần làm gì thêm

Điểm mấu chốt: thông tin duy nhất được chia sẻ qua Git là "dự án cần những gì" (pom.xml, maven-wrapper.properties). Còn "những file thực tế" (jar, Maven distribution) mỗi máy tự tải.

1.2. Trả lời các câu hỏi then chốt

Những file Wrapper nào cần commit? ✅ mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties (và maven-wrapper.jar nếu dự án dùng kiểu có jar). Đồng thời commit pom.xml. Nếu dùng .mvn/maven.config/.mvn/jvm.config (cấu hình chung của nhóm) cũng commit.

Có nên commit .mvn/wrapper? ✅ Có. Đây là nơi khoá phiên bản Maven. Không commit thì Wrapper không biết tải Maven nào và mvnw hỏng trên máy người khác.

Có nên commit target/? ❌ Không. Toàn bộ là file sinh ra (class, report, jar); khác nhau mỗi máy, nặng, gây xung đột Git. Dự án đã có target/ trong .gitignore.

Có nên commit thư viện trong Local Maven Repository? ❌ Không. Dự án này còn đặt Local Repository ngay trong .mvn/repository (123 jar) — tuyệt đối không commit, đã được .gitignore chặn bằng dòng .mvn/repository/. Hãy lưu ý: vì nó nằm dưới .mvn/, đừng nhầm lẫn và dùng lệnh git add .mvn (sẽ bị .gitignore chặn phần repository, nhưng thói quen này dễ gây lỗi ở dự án khác). Luôn git add .mvn/wrapper/ cụ thể.

Khi thêm dependency vào pom.xml, thành viên khác cần làm gì? Chỉ cần git pull rồi chạy Maven bất kỳ (.\mvnw.cmd test). Maven thấy dependency mới chưa có trong Local Repository ⇒ tự tải. Nếu IDE đang mở, bấm Reload Maven project.

Khi đổi phiên bản Maven cần cập nhật gì? Sửa một dòng distributionUrl trong .mvn/wrapper/maven-wrapper.properties (hoặc chạy mvnw wrapper:wrapper -Dmaven=<phiên bản> để sinh lại). Kiểm tra bằng .\mvnw.cmd -version, chạy clean test, rồi commit file properties (và các file wrapper nếu đổi). Mọi thành viên pull xong, lần chạy tiếp theo mvnw tự tải bản mới. Xem mục 4.

Vì sao các thành viên nên dùng cùng một Maven Wrapper? Để kết quả build giống nhau: cùng Maven ⇒ cùng cách giải quyết dependency, cùng hành vi plugin mặc định, ít lỗi "máy tôi chạy được".

Maven Wrapper có đảm bảo tất cả máy chạy giống nhau không? ❌ Không hoàn toàn. Wrapper chỉ khoá phiên bản Maven. Vẫn khác nhau ở:

Yếu tố Wrapper có kiểm soát?
Phiên bản Maven ✅
Phiên bản JDK (dự án --release 21, máy A dùng 21, máy B dùng 25) ❌ (chỉ hạn chế một phần nhờ release)
Phiên bản Chrome / ChromeDriver ❌ (Selenium Manager tải theo Chrome từng máy)
Hệ điều hành, độ phân giải, font ❌
Thư viện (nếu dùng version range hoặc SNAPSHOT) ❌ — nên ghim phiên bản cố định (dự án làm đúng)
Mạng, tốc độ website được test ❌
~/.m2/settings.xml cá nhân (mirror, proxy) ❌

Maven Wrapper có thay thế việc cài JDK không? ❌ Không. Maven là chương trình Java, vẫn cần JDK/JRE để chạy, và cần JDK (có javac) để biên dịch. Wrapper chỉ thay phần cài Maven.

2. Maven Wrapper và Git

2.1. Bảng quản lý file

File / thư mục Commit? Lý do
pom.xml ✅ Định nghĩa dependency, plugin
mvnw ✅ Script cho Linux/macOS/CI
mvnw.cmd ✅ Script cho Windows
.mvn/wrapper/ ✅ Khoá phiên bản Maven
.mvn/maven.config ✅ Tham số chung cả nhóm (ở dự án: đặt repo riêng)
testng.xml, src/ ✅ Mã nguồn
target/ ❌ Build output
test-output/ ❌ Report TestNG chạy ngoài Maven
.mvn/repository/ ❌ Local Repository riêng của dự án
~/.m2/... ❌ Nằm ngoài dự án

2.2. Kiểm tra trước khi commit

Hiện thư mục Selenium1 chưa là Git repository. Để thực hành, hãy làm trên một bản sao:

bash
git init
git status
git add pom.xml mvnw mvnw.cmd .mvn/wrapper/ .gitignore testng.xml src/
git status                      # xem chính xác thứ sẽ commit
git commit -m "Update Maven configuration"

Kiểm tra target/ và repository riêng đã bị bỏ qua:

bash
git check-ignore -v target .mvn/repository     # in ra dòng .gitignore khớp
git ls-files .mvn                               # chỉ nên thấy .mvn/wrapper/..., .mvn/maven.config

2.3. Bit thực thi của mvnw (quan trọng với Linux/macOS/CI)

✅ Đã tái hiện thật (Git 2.49.0, Windows): git add mvnw rồi git ls-files --stage mvnw cho 100644 (không thực thi). Sửa bằng git update-index --chmod=+x mvnw → 100755. Xem bài Git .gitignore và Maven.

Git lưu quyền thực thi. Trên Windows, đảm bảo mvnw được lưu là executable:

bash
git ls-files --stage mvnw                      # 100755 = executable, 100644 = không
git update-index --chmod=+x mvnw               # sửa nếu là 100644

Nếu thành viên dùng Linux/macOS gặp Permission denied, đây là nguyên nhân. Cách tạm: chmod +x mvnw.

2.4. Kết thúc dòng (line endings)

mvnw phải là LF. Nếu Git trên Windows tự đổi sang CRLF (core.autocrlf=true) thì Linux báo lỗi bad interpreter. Giải pháp phổ biến: thêm vào .gitattributes:

text
/mvnw            text eol=lf
/mvnw.cmd        text eol=crlf

2.5. Khi nào cần commit, khi nào không?

Tình huống Commit gì
Thêm/đổi dependency Chỉ pom.xml
Đổi phiên bản Maven .mvn/wrapper/maven-wrapper.properties (+ mvnw, mvnw.cmd nếu sinh lại bằng wrapper:wrapper)
Chạy test Không commit gì (đừng add target/, test-output/)
Tải thêm thư viện về máy Không commit gì
Đổi cấu hình chung Maven .mvn/maven.config

3. Các lỗi thường gặp

3.1. mvnw.cmd không chạy
Triệu chứng mvnw.cmd : The term 'mvnw.cmd' is not recognized... hoặc '.\mvnw.cmd' is not recognized
Nguyên nhân Đứng sai thư mục; quên .\ trong PowerShell; file bị xoá/không checkout
Kiểm tra Get-Location; Test-Path .\mvnw.cmd; git status
Khắc phục cd đến thư mục có pom.xml; gõ .\mvnw.cmd; git checkout -- mvnw.cmd nếu bị mất

Biến thể: PowerShell báo "running scripts is disabled" — mvnw.cmd là file .cmd nên không bị ExecutionPolicy của .ps1; nhưng script nhúng gọi powershell -noprofile sẽ vẫn chạy. Nếu bị chính sách công ty chặn PowerShell, Wrapper kiểu Windows sẽ không tải được Maven ⇒ cài Maven thủ công hoặc nhờ IT.

3.2. Không có quyền thực thi mvnw trên Linux/macOS
Triệu chứng bash: ./mvnw: Permission denied
Nguyên nhân File không có bit x (thường do commit từ Windows)
Kiểm tra ls -l mvnw; git ls-files --stage mvnw (100644?)
Khắc phục chmod +x mvnw; để vĩnh viễn: git update-index --chmod=+x mvnw rồi commit

Biến thể: /bin/sh^M: bad interpreter ⇒ CRLF; khắc phục bằng .gitattributes ở 2.4 và dos2unix mvnw.

3.3. Không tải được Maven Distribution
Triệu chứng Exception calling "DownloadFile"... Unable to connect to the remote server hoặc curl: Failed to fetch https://repo.maven.apache.org/...
Nguyên nhân Mất mạng, proxy/firewall, tường lửa công ty chặn repo.maven.apache.org, đồng hồ máy sai, distributionUrl sai (404)
Kiểm tra Mở URL trong distributionUrl bằng trình duyệt; MVNW_VERBOSE=true; kiểm tra proxy ($env:HTTPS_PROXY)
Khắc phục Sửa mạng/proxy; dùng mirror nội bộ qua MVNW_REPOURL; sửa URL; hoặc tải zip thủ công và giải nén vào đúng thư mục ~/.m2/wrapper/dists/apache-maven-3.9.16/<hash>/ (hash trùng với thư mục mà wrapper tính)

Nếu tải dở bị hỏng: xoá thư mục ~/.m2/wrapper/dists/apache-maven-3.9.16/ rồi chạy lại.

3.4. Lỗi kết nối Maven Central (tải thư viện)
Triệu chứng Could not transfer artifact ... from/to central, Connection timed out, Unknown host repo.maven.apache.org
Nguyên nhân Mất mạng/proxy/DNS; Central tạm lỗi; settings.xml có mirror hỏng
Kiểm tra ping repo.maven.apache.org; mở URL artifact trong trình duyệt; xem ~/.m2/settings.xml
Khắc phục Sửa mạng; cấu hình proxy trong settings.xml; thử lại; dùng -o nếu đã có cache đủ; cân nhắc -U để ép cập nhật sau khi sửa

3.5. Java version không tương thích
Triệu chứng Fatal error compiling: error: release version 21 not supported hoặc invalid target release: 21; UnsupportedClassVersionError
Nguyên nhân JDK trong PATH/JAVA_HOME thấp hơn 21
Kiểm tra java -version; javac -version; .\mvnw.cmd -version (dòng Java version: / runtime:)
Khắc phục Cài JDK ≥ 21 và đặt JAVA_HOME; PowerShell tạm thời: $env:JAVA_HOME="C:\...\jdk-21"; $env:Path="$env:JAVA_HOME\bin;$env:Path"

Ở chiều ngược lại — JDK mới hơn (25) chạy tốt, nhờ maven.compiler.release=21.

3.6. Dependency resolution failed
Triệu chứng Failed to execute goal ... Could not resolve dependencies for project ...: Could not find artifact ...
Nguyên nhân Gõ sai groupId/artifactId/version; phiên bản không tồn tại; mất mạng lần đầu; file trong repo bị hỏng; repository chứa artifact chưa được khai báo
Kiểm tra So tọa độ với trang tìm kiếm Maven Central; .\mvnw.cmd dependency:tree; xem file *.lastUpdated trong repo
Khắc phục Sửa tọa độ; kiểm tra mạng; xoá thư mục artifact lỗi trong .mvn/repository; chạy lại -U

Chi tiết: 08.

3.7. Maven build failed
Triệu chứng BUILD FAILURE
Nguyên nhân Rất nhiều loại: lỗi biên dịch, test fail, plugin lỗi, thiếu dependency
Kiểm tra Đọc dòng [ERROR] đầu tiên và dòng Failed to execute goal <plugin>:<goal>. Thêm -e (stacktrace) hoặc -X (debug)
Khắc phục Tuỳ plugin: compiler → sửa code; surefire → xem target/surefire-reports; dependency → mục 3.6

Nhận biết nhanh: compiler:testCompile fail = lỗi cú pháp/thiếu thư viện; surefire:test fail = test chạy nhưng sai; hai việc khác hẳn nhau.

3.8. Wrapper dùng Maven khác với môi trường cá nhân
Triệu chứng mvn -version ra 3.6.x nhưng mvnw -version ra 3.9.16; kết quả build khác nhau giữa IDE và dòng lệnh
Nguyên nhân IDE dùng "bundled Maven" hoặc Maven cài sẵn, còn dòng lệnh dùng Wrapper
Kiểm tra So hai lệnh version; xem thiết lập Maven trong IDE
Khắc phục Luôn dùng mvnw làm chuẩn; trong IDE chọn "Use Maven Wrapper" (IntelliJ: Settings → Build Tools → Maven → Maven home path: Use Maven wrapper)

Trường hợp thật của dự án (README của dự án, mục 7): ~/.m2 có .pom giả làm Maven cài sẵn bị lỗi maven-resources-plugin, còn mvnw.cmd không bị vì dùng repo riêng .mvn/repository.

3.9. JAVA_HOME chưa được cấu hình đúng
Triệu chứng The JAVA_HOME environment variable is not defined correctly, hoặc Maven chạy bằng JDK khác ý bạn
Nguyên nhân JAVA_HOME trỏ vào thư mục không tồn tại, trỏ vào bin, trỏ vào JRE, hoặc có dấu \ cuối/ngoặc kép thừa
Kiểm tra echo $env:JAVA_HOME; Test-Path "$env:JAVA_HOME\bin\javac.exe"; .\mvnw.cmd -version xem runtime:
Khắc phục Đặt lại đúng thư mục gốc JDK (chứa bin\javac.exe), mở terminal mới

🔎 Sự thật đã kiểm chứng: trên máy này JAVA_HOME trống vẫn chạy được: Maven dùng java có trong PATH. Tức JAVA_HOME không phải lúc nào cũng bắt buộc; nhưng nếu nó được đặt mà sai thì sẽ lỗi — nên hoặc đặt đúng, hoặc để trống hẳn.

4. Nâng cấp / đổi phiên bản Maven

Phần này chỉ để học; không thay đổi cấu hình của dự án hiện tại.

Cách 1 — sửa tay maven-wrapper.properties:

properties
distributionUrl=https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/<phiên bản mới>/apache-maven-<phiên bản mới>-bin.zip

Cách 2 — dùng goal của Maven (cần một Maven chạy được, ví dụ chính mvnw):

powershell
.\mvnw.cmd wrapper:wrapper "-Dmaven=<phiên bản mới>" "-Dtype=only-script"

Sau đó:

  1. .\mvnw.cmd -version — phải in phiên bản mới.
  2. .\mvnw.cmd clean test — mọi test phải xanh.
  3. Commit các file wrapper đã đổi; thông báo nhóm.

Tuỳ chọn tăng an toàn: thêm distributionSha256Sum=<hash> vào properties để Wrapper kiểm tra bản tải về (dự án hiện chưa có).

5. Tóm tắt

  • Wrapper = script trong dự án, tải và chạy đúng phiên bản Maven của dự án; không thay JDK.
  • Dự án: Wrapper 3.3.4, only-script, Maven 3.9.16, không có jar, không có checksum.
  • Commit: mvnw, mvnw.cmd, .mvn/wrapper/, pom.xml. Không commit: target/, Local Repository, test-output/.
  • Wrapper khoá Maven nhưng không khoá JDK, Chrome, mạng.
  • Windows: .\mvnw.cmd <goal>. Linux/macOS: ./mvnw <goal> + chmod +x.

💼 Interview Corner

1. Why should we commit mvnw and mvnw.cmd?

  • 🇻🇳 Dịch: Vì sao commit mvnw và mvnw.cmd?
  • Suggested answer (EN): So anyone who clones the repository, including CI, can build immediately with the same pinned Maven version without installing Maven.
  • Giải thích (VI): Cùng .mvn/wrapper/.
  • Follow-up: What must you not commit?

2. A teammate on Linux gets 'Permission denied: ./mvnw'. Why?

  • 🇻🇳 Dịch: Đồng đội Linux gặp Permission denied: ./mvnw?
  • Suggested answer (EN): The file was committed without the executable bit (mode 100644), typical when committed from Windows; fix with git update-index --chmod=+x mvnw and commit; also keep LF line endings via .gitattributes.
  • Giải thích (VI): Đã tái hiện: Git trên Windows commit mvnw mode 100644.
  • Follow-up: What error do you get when mvnw has CRLF?

📌 Lesson Summary

Kiến thức cần nhớ

  • Commit: pom.xml, mvnw, mvnw.cmd, .mvn/wrapper/, .mvn/maven.config
  • Không commit: target/, .mvn/repository/, test-output/
  • Wrapper khoá Maven, không khoá JDK/Chrome

Method / lệnh cần biết

  • git update-index --chmod=+x mvnw, git ls-files --stage, wrapper:wrapper

Điểm dễ nhầm lẫn

  • mvnw cần LF; mvnw.cmd CRLF
  • Mode 100644 vs 100755
  • Máy chạy giống nhau ≠ cùng Maven
