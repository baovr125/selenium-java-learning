Build và chạy Automation Test bằng Maven

Liên quan: Mục lục · Trước: Dependency · Sau: Maven trong team · TestNG · Báo cáo

⚠️ Nguyên tắc: không giả định mọi dự án giống nhau. Phần dưới đây dựa trên pom.xml thật của Selenium1: Surefire 3.5.2, TestNG provider tự phát hiện, suiteXmlFile = testng.xml, không có Failsafe.

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Chạy toàn bộ suite, một class, một method bằng Maven
  • Hiểu Surefire/Failsafe và -Dtest bỏ qua testng.xml
  • Đọc kết quả trong target/surefire-reports
  • Phân biệt 5 trạng thái: pass, skipped, fail, error, không có test

📋 Prerequisites

  • Maven Lifecycle
  • TestNG Fundamentals

1. Surefire làm gì?

maven-surefire-plugin chạy trong phase test. Nó:

  1. Dựng classpath (thư viện scope test + target/test-classes).
  2. Tự phát hiện provider (log thật: Using auto detected provider org.apache.maven.surefire.testng.TestNGProvider vì có TestNG).
  3. Tạo một JVM riêng ("forked") chạy test.
  4. Ghi kết quả vào target/surefire-reports/.
  5. Nếu có test fail ⇒ goal thất bại ⇒ BUILD FAILURE.

2. Test nào được chạy? (rất hay nhầm)

Điều kiện Surefire chạy gì
Có <suiteXmlFiles> (dự án này) và không có -Dtest Chỉ những class trong testng.xml (10 Exercise)
Có <suiteXmlFiles> và có -Dtest=... Bỏ qua testng.xml, chạy theo -Dtest
Không có suiteXmlFiles Quét class theo mẫu mặc định: **/Test*.java, **/*Test.java, **/*Tests.java, **/*TestCase.java

Kiểm chứng thật: EnvironmentCheckTest không có trong testng.xml, nhưng lệnh .\mvnw.cmd test "-Dtest=EnvironmentCheckTest" vẫn chạy 1 test và BUILD SUCCESS.

3. Các cách chạy

3.1. Toàn bộ test suite

powershell
.\mvnw.cmd test

Kết quả mong đợi (báo cáo lần chạy gần nhất): Tests run: 10, Failures: 0, Errors: 0, Skipped: 0, Time elapsed: 91.32 s.

3.2. Một Test Class

powershell
.\mvnw.cmd test "-Dtest=Exercise05_HoverTest"

3.3. Một Test Method

powershell
.\mvnw.cmd test "-Dtest=Exercise01_LoginTest#testLoginSuccess"

Cú pháp: Class#method. Có thể dùng wildcard và danh sách:

Mẫu Ý nghĩa
-Dtest=Exercise0* Mọi class bắt đầu Exercise0
-Dtest=Exercise01_LoginTest,Exercise02_CheckboxesTest Nhiều class
-Dtest=Exercise01_LoginTest#testLogin* Method theo mẫu
-Dtest=tests.Exercise01_LoginTest Có package
-Dtest='!Exercise09*' Loại trừ (chú ý nháy trong PowerShell)

3.4. Chạy theo file TestNG XML khác

Không thể "chạy testng.xml khác" chỉ bằng -Dtest. Có hai cách:

Cách A (dùng property trong POM): nếu POM khai báo <suiteXmlFile>${suiteFile}</suiteXmlFile> thì chạy -DsuiteFile=smoke.xml. Hiện Selenium1 ghi cứng testng.xml, nên đây chỉ là gợi ý cải tiến (xem ví dụ ở 02).

Cách B (tham số của Surefire): -Dsurefire.suiteXmlFiles=smoke.xml — tham số này được hỗ trợ bởi plugin, nhưng khi POM đã ghi cứng <suiteXmlFiles> trong <configuration>, giá trị trong POM thắng giá trị từ dòng lệnh; vì vậy với POM hiện tại cách B không đổi được suite. Hãy tự thử và đọc log Running ... để xác nhận.

3.5. Chạy bằng code (không qua Surefire)

AllExercisesTest.main() dùng API TestNG đọc testng.xml ⇒ phù hợp chạy trong IDE; không sinh báo cáo Surefire (báo cáo vào test-output/).

run-test.ps1 thì dùng javac + java -cp để chạy main() của một Exercise ⇒ cũng không qua Surefire.

Cách chạy Qua Maven/Surefire? Báo cáo ở
.\mvnw.cmd test ✅ target/surefire-reports/
.\run-test.ps1 -TargetClass AllExercisesTest ❌ test-output/
Nút Run trong IDE ❌ (tuỳ IDE) test-output/ hoặc console

3.6. Từng tham số cấu hình của Surefire

Cấu hình trong <plugin><artifactId>maven-surefire-plugin</artifactId><configuration>...</configuration></plugin> hoặc truyền bằng -D trên dòng lệnh.

<suiteXmlFiles> (-Dsurefire.suiteXmlFiles=...)

  • Làm gì: chỉ định file TestNG XML quyết định test nào chạy. 🧩 testng.xml.
  • Lưu ý: bị bỏ qua khi có -Dtest.

-Dtest=...

  • Làm gì: chọn test chạy theo tên class/method/mẫu (xem bảng mẫu ở mục 3.3).
  • Ví dụ: -Dtest=Exercise01_LoginTest#testLogin*.

<includes> / <excludes>

  • Làm gì: khai báo mẫu tên file của class được/không được chạy (khi không dùng suiteXmlFiles).
  • Ví dụ: <include>**/*Test.java</include>.
  • Mặc định: quét **/Test*.java, **/*Test.java, **/*Tests.java, **/*TestCase.java.

<groups> / <excludedGroups> (-Dgroups=smoke)

  • Làm gì: chỉ chạy (hoặc loại) test thuộc nhóm TestNG @Test(groups = "...").

<systemPropertyVariables>

  • Làm gì: đặt các system property cho JVM chạy test, để code đọc bằng System.getProperty(...).
  • Ví dụ: <browser>${browser}</browser>.
  • Lưu ý: Surefire chạy test trong JVM riêng; -D của Maven không phải lúc nào cũng tới được đó.

<argLine>

  • Làm gì: truyền tham số cho JVM chạy test (bộ nhớ, mã hoá).
  • Ví dụ: <argLine>-Xmx1g -Dfile.encoding=UTF-8</argLine>.

<skipTests> / <testFailureIgnore>

  • skipTests: true = không chạy test (như -DskipTests).
  • testFailureIgnore: true = test fail vẫn cho BUILD SUCCESS — nguy hiểm vì che lỗi; chỉ dùng có chủ đích.

<parallel> / <threadCount>

  • Làm gì: cấu hình chạy song song của Surefire. Với TestNG nên cấu hình trong testng.xml thay vì ở đây.
Muốn Dùng
Chọn test theo tên -Dtest=...
Chọn test theo file XML suiteXmlFiles
Chọn theo nhóm -Dgroups=...
Chuyển biến vào code test systemPropertyVariables
Đổi bộ nhớ/mã hoá của JVM test argLine

4. Failsafe (không có trong dự án)

maven-failsafe-plugin dành cho integration test (chạy ở phase integration-test, kiểm tra ở verify). Quy ước tên mặc định: *IT.java, IT*.java, *ITCase.java.

Vì sao có thể dùng cho Selenium? Test UI chậm, nên có nhóm tách riêng: test chạy unit test nhanh, verify chạy UI test. Cấu hình mẫu (minh hoạ, chưa áp dụng vào dự án):

xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-failsafe-plugin</artifactId>
    <version>3.5.2</version>
    <executions>
        <execution>
            <goals>
                <goal>integration-test</goal>
                <goal>verify</goal>
            </goals>
        </execution>
    </executions>
</plugin>

Chạy: .\mvnw.cmd verify. Dự án Selenium1 dùng Surefire cho cả UI test vì mục tiêu học tập, không cần tách.

5. Truyền tham số từ command line

5.1. Tham số cho Maven (-D)

-Dtên=giá_trị tạo system property. Có hai loại cần phân biệt:

Loại Ví dụ Ai đọc
Tham số của plugin -Dtest=..., -DskipTests Maven/Surefire
Property tuỳ ý -Dbrowser=firefox Chỉ có tác dụng trong test nếu được chuyển vào JVM test

Surefire chạy test trong JVM riêng; nó sao chép system property của Maven sang JVM test (hành vi mặc định của Surefire), nhưng để chắc chắn và rõ ràng nên khai báo qua systemPropertyVariables trong POM như ví dụ ở 02. Trong code:

java
String browser = System.getProperty("browser", "chrome");   // giá trị mặc định nếu không truyền

Dự án Selenium1 hiện không đọc system property nào; mọi thứ hard-code. Đây là hướng cải tiến ở framework-design/04.

5.2. Tham số TestNG qua testng.xml

xml
<suite name="Suite">
  <parameter name="browser" value="chrome"/>
  <test name="T1">...</test>
</suite>

Đọc bằng @Parameters("browser") — testing-framework/01.

6. Chạy với môi trường khác nhau

Kỹ thuật Ví dụ Dùng khi
Truyền URL qua -D -Dbase.url=https://staging... Ít môi trường
Maven Profile -Pstaging Mỗi môi trường kèm nhiều thiết lập
File properties theo môi trường config-staging.properties + -Denv=staging Quy mô vừa
Biến môi trường OS $env:BASE_URL=... CI

Ví dụ Profile (minh hoạ):

xml
<profiles>
  <profile>
    <id>staging</id>
    <properties><env>staging</env></properties>
  </profile>
</profiles>
powershell
.\mvnw.cmd test -Pstaging

Với Selenium1 có một môi trường duy nhất (site demo công khai).

7. Đọc kết quả trong target/

text
target/
├── classes/                  ← kết quả compile src/main (rỗng ở dự án này)
├── test-classes/             ← kết quả compile src/test
├── classpath.txt             ← do run-test.ps1 sinh, không phải Maven mặc định
├── maven-status/             ← cache biên dịch gia tăng
└── surefire-reports/
    ├── index.html, emailable-report.html     ← báo cáo TestNG (mở bằng trình duyệt)
    ├── TestSuite.txt                         ← tóm tắt 1 dòng: Tests run...
    ├── TEST-TestSuite.xml                    ← JUnit XML cho CI
    ├── testng-results.xml                    ← dữ liệu chi tiết TestNG
    └── *.dumpstream                          ← log JVM của Surefire (cảnh báo/ lỗi hạ tầng)

Thứ tự đọc khi có sự cố:

  1. Console Maven: dòng Tests run:, [ERROR].
  2. target/surefire-reports/TestSuite.txt.
  3. emailable-report.html (xem test nào fail và lý do).
  4. *.dumpstream nếu nghi vấn lỗi JVM/Surefire. Ví dụ file thật của dự án chứa: Boot Manifest-JAR contains absolute paths in classpath ... 'other' has different root + gợi ý <argLine>-Djdk.net.URLClassPath.disableClassPathURLCheck=true</argLine>. Nguyên nhân: dự án nằm ổ B:, còn Maven home/Surefire ở ổ C:. Đây chỉ là cảnh báo, 10 test vẫn pass.

8. Năm trạng thái cần phân biệt

"Build thành công" ≠ "test pass".

# Tình huống Dấu hiệu console BUILD Ý nghĩa
1 Test pass hoàn toàn Tests run: 10, Failures: 0, Errors: 0, Skipped: 0 SUCCESS Tốt
2 Test skipped Skipped: N (do enabled=false, dependsOnMethods fail, SkipException) SUCCESS Có test không được kiểm — phải điều tra
3 Test fail (assertion) Failures: N FAILURE Hành vi sai so với kỳ vọng
4 Test error (exception) Errors: N (hoặc exception chưa bắt, ví dụ NoSuchElementException) FAILURE Test không chạy đến cuối
5 Không có test nào Tests run: 0, Failures: 0, ... SUCCESS ⚠️ Maven coi là thành công!

Phân biệt Failure (assertion sai, AssertionError) và Error (exception khác). Với Surefire + TestNG, cả hai đều làm build fail; chỉ khác tên cột.

Bẫy "không có test nào"

Đã tái hiện trên dự án:

powershell
.\mvnw.cmd test "-Dtest=NoSuchTest"
# ...
# [INFO] Tests run: 0, Failures: 0, Errors: 0, Skipped: 0
# [INFO] BUILD SUCCESS

Gõ sai tên class vẫn BUILD SUCCESS. Trong CI, điều này có thể che giấu việc test không chạy. Cách phòng:

  • Kiểm tra số Tests run ≥ kỳ vọng (script CI).
  • ❌ Đã thử và KHÔNG hiệu quả: -Dsurefire.failIfNoSpecifiedTests=true kèm -Dtest=NoSuchTest vẫn cho Tests run: 0 ... BUILD SUCCESS với Surefire 3.5.2 + TestNG provider của dự án. Đừng dựa vào cờ này.
  • ✅ Kiểm tra log có dòng Running tests.<Class> và số Tests run: lớn hơn 0 (trong CI: đọc target/surefire-reports/TestSuite.txt hoặc testng-results.xml rồi fail nếu Tests run: 0).
  • ✅ Chạy bằng suite testng.xml (không dùng -Dtest) — tên class sai trong XML sẽ gây lỗi ClassNotFoundException rõ ràng.

9. Bỏ qua test

Mục đích Cách
Biên dịch nhưng không chạy test -DskipTests
Không biên dịch và không chạy -Dmaven.test.skip=true
Chạy tiếp dù có test fail -Dmaven.test.failure.ignore=true

10. Chạy lại test fail

TestNG tạo testng-failed.xml (dự án có sẵn bản cũ ở test-output/testng-failed.xml ghi nhận Exercise07_InfiniteScrollTest từng fail). Có thể chạy lại bằng cách trỏ suiteXmlFile tới file này, hoặc dùng -Dsurefire.rerunFailingTestsCount=2 (Surefire tự chạy lại test fail — cẩn thận: có thể che giấu flaky test; chỉ nên dùng khi đã hiểu).

11. Một số lệnh hữu ích khi vận hành

powershell
.\mvnw.cmd -q test                          # ít log
.\mvnw.cmd -B -e test                       # CI: batch + stacktrace
.\mvnw.cmd test-compile                     # kiểm tra cú pháp, không mở Chrome
.\mvnw.cmd clean test "-Dtest=Exercise10*"  # sạch + chạy một nhóm
Get-Content target\surefire-reports\TestSuite.txt
Start-Process target\surefire-reports\emailable-report.html

✅ Best Practices

  1. clean test trước khi push/CI.
  2. Luôn nhìn dòng Tests run: — đừng chỉ nhìn BUILD SUCCESS.
  3. Dùng -Dtest=Class#method khi debug một test.
  4. Giữ suite smoke nhỏ và suite regression đầy đủ trong các file XML riêng.
  5. Không dùng rerunFailingTestsCount để "xanh hoá" test flaky mà không điều tra.

⚠️ Lỗi thường gặp

Lỗi Gốc rễ
Tests run: 0 Sai -Dtest, sai tên class, sai thư mục, thiếu @Test
Chạy -Dtest=X nhưng test khác chạy Bạn nhầm: -Dtest bỏ qua testng.xml
Dấu # trong PowerShell Đặt cả tham số trong nháy kép
Test pass ở IDE, fail ở Maven Khác classpath/JDK/thư mục làm việc (ví dụ testng.xml tìm theo thư mục hiện tại)
Test chạy mà không mở Chrome Không có test nào được chạy thật (xem mục 8)

💼 Interview Corner

1. How do you run a specific test with Maven?

  • 🇻🇳 Dịch: Chạy một test cụ thể bằng Maven?
  • Suggested answer (EN): Use -Dtest=Class#method, e.g. mvnw test -Dtest=LoginTest#testLoginSuccess; with -Dtest Surefire ignores the suite XML.
  • Giải thích (VI): PowerShell cần đặt trong nháy.
  • Follow-up: What if the name is wrong?

2. Why can BUILD SUCCESS hide problems?

  • 🇻🇳 Dịch: Vì sao BUILD SUCCESS có thể che vấn đề?
  • Suggested answer (EN): Maven only fails when a goal fails; zero matching tests or skipped tests do not fail the build, so I always check the test counts.
  • Giải thích (VI): Đã tái hiện với -Dtest=NoSuchTest.
  • Follow-up: How do you guard in CI?

📌 Lesson Summary

Kiến thức cần nhớ

  • -Dtest=Class#method, wildcard *
  • Tests run/Failures/Errors/Skipped
  • Surefire cho test thường; Failsafe cho integration test (chưa dùng)

Method / lệnh cần biết

  • test, -Dtest, -DskipTests, -Dmaven.test.failure.ignore, target/surefire-reports

Điểm dễ nhầm lẫn

  • test-output/ (code TestNG) ≠ target/surefire-reports/ (Surefire)
  • Failure (assert) ≠ Error (exception)
  • Skipped không làm build fail
