1. pom.xml của dự án, đọc từng khối

xml
<modelVersion>4.0.0</modelVersion>

<groupId>com.fresher</groupId>
<artifactId>SeleniumPractice</artifactId>
<version>1.0-SNAPSHOT</version>
Thẻ Ý nghĩa Giá trị ở dự án Ghi chú
modelVersion Phiên bản cấu trúc POM 4.0.0 Luôn là 4.0.0 với Maven 3
groupId Nhóm/tổ chức, thường là tên miền đảo ngược com.fresher
artifactId Tên dự án SeleniumPractice Tên artifact sinh ra: SeleniumPractice-1.0-SNAPSHOT.jar
version Phiên bản dự án 1.0-SNAPSHOT -SNAPSHOT = bản đang phát triển, chưa phát hành
packaging Kiểu đóng gói không khai báo ⇒ mặc định jar Log [ jar ] khi build

Tổ hợp groupId:artifactId:version = tọa độ của chính dự án, giống như tọa độ của thư viện khác.

2. <properties> — biến dùng chung

xml
<properties>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>
    <maven.compiler.release>21</maven.compiler.release>
    <selenium.version>4.52.0</selenium.version>
    <testng.version>7.10.2</testng.version>
</properties>
Property Tác dụng
project.build.sourceEncoding Mã hoá file nguồn. Quan trọng vì code có comment tiếng Việt; thiếu thì có thể sinh cảnh báo/ lỗi ký tự trên Windows
project.reporting.outputEncoding Mã hoá báo cáo
maven.compiler.release Mức ngôn ngữ và API Java dùng khi biên dịch (tương đương javac --release 21)
selenium.version, testng.version Biến tự đặt, tham chiếu bằng ${selenium.version}

🔎 release khác source/target: --release 21 không chỉ chọn cú pháp mà còn giới hạn API về JDK 21, nên biên dịch bằng JDK 25 vẫn không vô tình dùng API chỉ có ở JDK 25. Đó là lý do máy dự án dùng JDK 25 nhưng vẫn khớp mức 21.

Ưu điểm biến phiên bản: đổi 4.52.0 ở một chỗ, mọi artifact Selenium cùng đổi.

3. <dependencies>

xml
<dependency>
    <groupId>org.seleniumhq.selenium</groupId>
    <artifactId>selenium-java</artifactId>
    <version>${selenium.version}</version>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testng</groupId>
    <artifactId>testng</artifactId>
    <version>${testng.version}</version>
    <scope>test</scope>
</dependency>
Dependency Cung cấp Ghi chú
selenium-java Gói tổng hợp: selenium-api, chrome-driver, support (WebDriverWait, ExpectedConditions, Select), remote-driver, selenium-manager... "Một dòng, ~40 jar"
testng @Test, Assert, TestNG... Kéo jcommander, slf4j-api, jquery webjar

Scope test nghĩa là: thư viện chỉ có trong classpath khi biên dịch và chạy test, không vào classpath src/main và không đóng gói theo artifact chính. Phù hợp vì toàn bộ code Selenium của dự án nằm ở src/test/java.

Scope Compile src/main Compile + chạy src/test Runtime Có trong artifact/WAR? Dùng cho
compile (mặc định) ✔ ✔ ✔ ✔ Thư viện sản phẩm
provided ✔ ✔ ✖ ✖ Servlet API... môi trường có sẵn
runtime ✖ ✔ ✔ ✔ JDBC driver
test ✖ ✔ ✖ ✖ Selenium, TestNG, JUnit, Mockito
system / import (hiếm) Tránh dùng system

⚠️ Nếu sau này bạn tạo BasePage/DriverFactory trong src/main/java, dòng <scope>test</scope> của selenium-java sẽ gây lỗi package org.openqa.selenium does not exist. Khi đó đổi sang compile, hoặc (tốt hơn) tiếp tục để mã framework trong src/test/java.

4. <build> và <plugins>

xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.13.0</version>
        </plugin>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-surefire-plugin</artifactId>
            <version>3.5.2</version>
            <configuration>
                <suiteXmlFiles>
                    <suiteXmlFile>testng.xml</suiteXmlFile>
                </suiteXmlFiles>
            </configuration>
        </plugin>
    </plugins>
</build>
Plugin Gắn vào phase Làm gì
maven-compiler-plugin 3.13.0 compile, test-compile Biên dịch src/main và src/test
maven-surefire-plugin 3.5.2 test Chạy test; tự nhận TestNG provider vì có testng trong classpath

<suiteXmlFiles> bảo Surefire chạy theo testng.xml thay vì tự quét *Test. Hậu quả đã kiểm chứng:

  • mvnw test chạy 10 class trong testng.xml, không chạy EnvironmentCheckTest.
  • Khi có -Dtest=..., Surefire bỏ qua suiteXmlFiles và chọn class/method theo -Dtest (06).

Plugin còn được dùng ngầm dù không khai báo: maven-resources-plugin 3.4.0 (copy src/test/resources), và maven-dependency-plugin 3.7.0 khi bạn gọi dependency:tree. Bản không khai báo do Super POM/Maven mặc định quyết định ⇒ thông tin này thể hiện trong log (--- resources:3.4.0:resources ---).

✅ Nên ghim phiên bản plugin như dự án đã làm với compiler và surefire để kết quả build lặp lại được.

4.1. Từ điển thẻ pom.xml — từng thẻ làm gì

Mỗi thẻ có dạng <tên>giá trị</tên>; thẻ lồng nhau tạo thành cây. Cách đọc thẻ: Làm gì · Nằm ở đâu · Ví dụ · Lưu ý.

<project>

  • Làm gì: thẻ gốc bao toàn bộ POM; chứa các khai báo namespace của Maven.
  • Lưu ý: mọi thẻ khác nằm bên trong nó.

<modelVersion>

  • Làm gì: phiên bản cấu trúc của file POM. Luôn là 4.0.0 với Maven 3.
  • Lưu ý: không phải phiên bản dự án của bạn.

<groupId>, <artifactId>, <version> (ở cấp <project>)

  • Làm gì: ba thẻ tạo tọa độ (GAV) của chính dự án: nhóm / tên / phiên bản.
  • Ví dụ: com.fresher / SeleniumPractice / 1.0-SNAPSHOT.
  • Lưu ý: -SNAPSHOT = bản đang phát triển. Cùng ba thẻ này đặt trong <dependency> thì chỉ thư viện được dùng.

<packaging>

  • Làm gì: kiểu đóng gói khi build (jar, war, pom).
  • Lưu ý: không khai báo → mặc định jar.

<properties>

  • Làm gì: khai báo biến dùng chung trong POM; mỗi thẻ con là một biến.
  • Ví dụ: <selenium.version>4.52.0</selenium.version> rồi dùng ${selenium.version}.
  • Lưu ý: một số tên có ý nghĩa đặc biệt với Maven (maven.compiler.release, project.build.sourceEncoding); tên khác do bạn tự đặt.

${tên}

  • Làm gì: thay thế bằng giá trị của biến tên (từ <properties>, -D trên dòng lệnh, hoặc project.*).
  • Lưu ý: -Dselenium.version=4.50.0 trên dòng lệnh đè giá trị trong <properties>.

<dependencies> và <dependency>

  • Làm gì: <dependencies> là danh sách thư viện cần; mỗi <dependency> là một thư viện, xác định bằng GAV.
  • Ví dụ:
xml
<dependency>
    <groupId>org.testng</groupId>
    <artifactId>testng</artifactId>
    <version>7.10.2</version>
    <scope>test</scope>
</dependency>
  • Lưu ý: Maven tải thêm cả các thư viện mà nó phụ thuộc (transitive).

<scope>

  • Làm gì: nói thư viện được dùng ở giai đoạn nào (biên dịch, test, chạy). Mặc định compile; test = chỉ cho src/test.
  • Ví dụ: Selenium và TestNG dùng test (code sản phẩm không cần).

<exclusions>

  • Làm gì: loại bỏ một thư viện kéo theo không mong muốn khỏi một dependency.
  • Dùng khi: thư viện con xung đột phiên bản.

<optional>true</optional>

  • Làm gì: đánh dấu dependency không truyền sang dự án khác dùng dự án của bạn. Hiếm gặp trong dự án test.

<build>

  • Làm gì: gom cấu hình quá trình build: thư mục, plugin.

<plugins> và <plugin>

  • Làm gì: <plugin> khai báo một công cụ (compiler, surefire) cùng phiên bản; <plugins> là danh sách.
  • Ví dụ: maven-surefire-plugin chạy test; maven-compiler-plugin biên dịch.
  • Lưu ý: nên ghim phiên bản plugin để build ổn định.

<configuration> (trong <plugin>)

  • Làm gì: truyền tham số cho plugin đó.
  • Ví dụ: trong Surefire: <suiteXmlFiles>, <systemPropertyVariables>.

<suiteXmlFiles> / <suiteXmlFile>

  • Làm gì: chỉ cho Surefire chạy test theo file TestNG XML (🧩 testng.xml).
  • Lưu ý: có -Dtest=... trên dòng lệnh thì file XML này bị bỏ qua.
Thẻ Trả lời câu hỏi
<groupId>/<artifactId>/<version> "Cái này là ai?" (tọa độ)
<properties> "Giá trị dùng chung ở đâu?"
<dependencies> "Dự án cần thư viện nào?"
<scope> "Thư viện dùng ở giai đoạn nào?"
<plugins> "Dùng công cụ nào để build/test?"
<configuration> "Cấu hình công cụ đó thế nào?"

5. Những thẻ KHÔNG có trong dự án (nhưng cần biết)

5.1. <dependencyManagement>

Khai báo phiên bản/scope trung tâm mà không thật sự thêm thư viện vào dự án. Hữu ích cho dự án nhiều module:

xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.testng</groupId>
            <artifactId>testng</artifactId>
            <version>7.10.2</version>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.testng</groupId>
        <artifactId>testng</artifactId>
        <!-- không cần <version>: lấy từ dependencyManagement -->
        <scope>test</scope>
    </dependency>
</dependencies>

Sau đó <dependency> con không cần ghi version. dependencyManagement còn ép phiên bản cho cả thư viện transitive (ví dụ ép guava về một bản cố định để xử lý xung đột — xem 05). Ngoài ra nó có thể import một BOM (<type>pom</type><scope>import</scope>), ví dụ junit-bom mà bạn thấy trong .mvn/repository/org/junit/junit-bom/.

Với một module như Selenium1, <properties> đã đủ; không cần thêm độ phức tạp này.

5.2. <repositories> và <pluginRepositories>

Mặc định Maven chỉ dùng Central. Thêm repository nội bộ công ty:

xml
<repositories>
    <repository>
        <id>company-nexus</id>
        <url>https://nexus.example.com/repository/maven-public/</url>
    </repository>
</repositories>

Trong dự án thực tế, URL, tài khoản thường đặt ở ~/.m2/settings.xml (không commit).

5.3. <profiles>

Cho phép cấu hình theo môi trường (-Pstaging). Ví dụ:

xml
<profiles>
    <profile>
        <id>staging</id>
        <properties><base.url>https://staging.example.com</base.url></properties>
    </profile>
</profiles>

Chạy: .\mvnw.cmd test -Pstaging. Xem practice/07.

5.4. <parent>

Kế thừa cấu hình từ POM cha (ví dụ Spring Boot parent). Dự án Selenium độc lập thường không dùng.

6. Ví dụ pom.xml mở rộng cho dự án Selenium Java (minh hoạ — KHÔNG phải cấu hình của dự án)

xml
<project ...>
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.fresher</groupId>
    <artifactId>SeleniumFramework</artifactId>
    <version>1.0-SNAPSHOT</version>

    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.release>21</maven.compiler.release>
        <selenium.version>4.52.0</selenium.version>
        <testng.version>7.10.2</testng.version>
        <slf4j.version>1.7.36</slf4j.version>
        <!-- cho phép chạy: mvnw test -Dbrowser=firefox -->
        <browser>chrome</browser>
        <suiteFile>testng.xml</suiteFile>
    </properties>

    <dependencies>
        <dependency>
            <groupId>org.seleniumhq.selenium</groupId>
            <artifactId>selenium-java</artifactId>
            <version>${selenium.version}</version>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.testng</groupId>
            <artifactId>testng</artifactId>
            <version>${testng.version}</version>
            <scope>test</scope>
        </dependency>
        <!-- Cho phép log, hết cảnh báo StaticLoggerBinder. Phải KHỚP slf4j-api 1.7.36 mà TestNG 7.10.2 kéo vào -->
        <dependency>
            <groupId>org.slf4j</groupId>
            <artifactId>slf4j-simple</artifactId>
            <version>${slf4j.version}</version>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
            </plugin>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-surefire-plugin</artifactId>
                <version>3.5.2</version>
                <configuration>
                    <suiteXmlFiles>
                        <suiteXmlFile>${suiteFile}</suiteXmlFile>
                    </suiteXmlFiles>
                    <systemPropertyVariables>
                        <browser>${browser}</browser>
                    </systemPropertyVariables>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>

Giải thích điểm mới:

  • systemPropertyVariables truyền browser vào JVM chạy test; trong Java đọc bằng System.getProperty("browser", "chrome").
  • ${suiteFile} cho phép .\mvnw.cmd test -DsuiteFile=smoke.xml.
  • SLF4J: TestNG 7.10.2 kéo slf4j-api 1.7.36 (đã thấy trong dependency tree thật). slf4j-simple phải cùng dòng 1.7.x để binding khớp (SLF4J 2.x dùng cơ chế khác, trộn hai dòng sẽ lại báo lỗi binding). Hãy chạy dependency:tree sau khi thêm để xác nhận chỉ có một phiên bản slf4j-api. Đây là ví dụ minh hoạ — bạn cần tự chạy kiểm chứng trước khi áp dụng vào dự án thật.

7. Xem POM "thực sự" mà Maven dùng

powershell
.\mvnw.cmd help:effective-pom

In ra POM sau khi cộng Super POM (mặc định của Maven) với pom.xml của bạn: bạn sẽ thấy repositories Central, thư mục src/main/java, target... dù không viết. (Plugin maven-help-plugin có thể cần tải lần đầu.)

8. Checklist đọc pom.xml của một dự án lạ

  1. groupId:artifactId:version, packaging.
  2. properties: phiên bản Java, phiên bản thư viện.
  3. dependencies: thư viện test (Selenium? TestNG hay JUnit?), scope.
  4. build/plugins: compiler, surefire/failsafe, có suiteXmlFiles/profiles không.
  5. profiles, parent, repositories.
  6. File phụ: .mvn/maven.config, .mvn/jvm.config, testng.xml.

💼 Interview Corner

1. What is the purpose of pom.xml?

  • 🇻🇳 Dịch: Mục đích của pom.xml?
  • Suggested answer (EN): It is the Project Object Model: coordinates, properties, dependencies and build plugins that tell Maven what to download and how to build.
  • Giải thích (VI): Nêu các khối chính.
  • Follow-up: Properties vs dependencyManagement?

2. Why pin plugin versions?

  • 🇻🇳 Dịch: Vì sao ghim phiên bản plugin?
  • Suggested answer (EN): To make builds reproducible; default plugin versions depend on the Maven version and can change behavior.
  • Giải thích (VI): Dự án ghim compiler 3.13.0 và surefire 3.5.2.
  • Follow-up: How do you see which plugin versions are used?

📌 Lesson Summary

Kiến thức cần nhớ

  • pom.xml = GAV + properties + dependencies + build/plugins
  • Scope test cho thư viện chỉ dùng trong test
  • Ghim phiên bản để build lặp lại được

Method / lệnh cần biết

  • validate, help:effective-pom, dependency:tree

Điểm dễ nhầm lẫn

  • properties ≠ dependencyManagement
  • release ≠ source/target
  • Plugin không khai báo vẫn được dùng ngầm (resources, jar...)
