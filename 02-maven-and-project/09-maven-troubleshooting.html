Troubleshooting

Liên quan: Mục lục · Wrapper & lỗi · Build & test · Phỏng vấn: troubleshoot

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Áp dụng phương pháp 5 bước để đọc lỗi Maven
  • Nhận diện nhóm lỗi theo plugin/goal
  • Tra bảng nguyên nhân – kiểm tra – khắc phục
  • Biết khi nào và xoá gì trong cache

📋 Prerequisites

  • Maven Lifecycle
  • Maven Wrapper

1. Phương pháp chung (5 bước)

  1. Đọc dòng [ERROR] đầu tiên (không phải dòng cuối). Dòng quan trọng nhất có dạng Failed to execute goal <plugin>:<version>:<goal> (id) on project ...: <nguyên nhân>.
  2. Xác định plugin/goal nào lỗi → biết lỗi thuộc nhóm nào:
Goal lỗi Nhóm
compiler:compile / testCompile Lỗi biên dịch (cú pháp, thiếu thư viện, sai Java version)
surefire:test Test fail/error hoặc Surefire không khởi động được
resources:... Lỗi copy tài nguyên/encoding
dependency:... Phân giải dependency
(không có goal, lỗi trước đó) pom.xml sai hoặc Wrapper/JDK
  1. Thu thập thêm thông tin: -e (stacktrace), -X (debug), -B -q, MVNW_VERBOSE=true.
  2. Thu hẹp: test-compile trước, rồi một test (-Dtest=Class#method), rồi cả suite.
  3. Làm sạch có chủ đích: clean; xoá artifact hỏng trong Local Repository; không xoá bừa.

2. Bảng lỗi: nguyên nhân – kiểm tra – khắc phục

4. Công cụ chẩn đoán

Lệnh Mục đích
.\mvnw.cmd -version Maven + Java + OS đang dùng
.\mvnw.cmd -X test Log debug (rất dài; lọc bằng Select-String)
.\mvnw.cmd -e test Stacktrace lỗi
.\mvnw.cmd help:effective-pom POM sau khi gộp
.\mvnw.cmd help:effective-settings settings.xml hiệu lực (proxy, mirror)
.\mvnw.cmd dependency:tree Cây phụ thuộc
$env:MVNW_VERBOSE="true" Debug Wrapper
Get-Content target\surefire-reports\*.dumpstream Lỗi hạ tầng Surefire

4.1. Từng công cụ chẩn đoán làm gì và khi nào dùng

.\mvnw.cmd -version

  • Làm gì: in Maven, Java (đường dẫn, nhà cung cấp) và hệ điều hành đang dùng.
  • Dùng khi: lỗi liên quan JDK (release 21 not supported, JAVA_HOME) — xem Maven thực sự chạy bằng JDK nào.

.\mvnw.cmd -e test

  • Làm gì: hiện stacktrace của lỗi build thay vì chỉ một dòng ngắn.
  • Dùng khi: thông báo lỗi chung chung ("Failed to execute goal ...").

.\mvnw.cmd -X test

  • Làm gì: bật log debug: thấy classpath, plugin, từng bước phân giải. Rất dài.
  • Mẹo: lọc bằng PowerShell: .\mvnw.cmd -X test | Select-String "ERROR|classpath".

.\mvnw.cmd help:effective-pom

  • Làm gì: in POM cuối cùng sau khi gộp thừa kế và profile.
  • Dùng khi: nghi ngờ một cấu hình được đặt ở nơi khác (parent, profile) đè giá trị bạn thấy.

.\mvnw.cmd help:effective-settings

  • Làm gì: in settings.xml hiệu lực (proxy, mirror, kho cục bộ).
  • Dùng khi: lỗi tải thư viện, nghi do proxy/mirror.

.\mvnw.cmd dependency:tree

  • Làm gì: in cây phụ thuộc.
  • Dùng khi: NoSuchMethodError, ClassNotFoundException, xung đột phiên bản. Thêm -Dverbose.

$env:MVNW_VERBOSE = "true"

  • Làm gì: bật log chi tiết của Wrapper (không phải của Maven).
  • Dùng khi: Wrapper không tải được Maven.

Get-Content target\surefire-reports\*.dumpstream

  • Làm gì: đọc file ghi lỗi hạ tầng Surefire (khi JVM test bị lỗi khởi động/kết thúc bất thường).
  • Dùng khi: Tests run không hiện hoặc log báo "The forked VM terminated".
Triệu chứng Công cụ đầu tiên
Lỗi JDK/Java -version
Lỗi build mơ hồ -e, sau đó -X
Cấu hình "lạ" help:effective-pom
Lỗi tải thư viện help:effective-settings, dependency:tree
Wrapper không tải được Maven MVNW_VERBOSE
JVM test chết bất thường *.dumpstream

5. Khi nào xoá cache?

Muốn làm Hành động Rủi ro
Xoá build cũ clean (xoá target/) Không
Tải lại một artifact hỏng Xoá thư mục artifact trong .mvn/repository/... Cần mạng để tải lại
Tải lại toàn bộ thư viện Xoá .mvn/repository Mất vài phút, không mất mã nguồn
Tải lại Maven của Wrapper Xoá ~/.m2/wrapper/dists/apache-maven-3.9.16 Tải lại ~9 MB

Quy tắc an toàn: xoá đúng phạm vi nhỏ nhất có thể; đọc kỹ đường dẫn trước khi Remove-Item -Recurse.

6. Cách viết báo lỗi tốt cho đồng đội/mentor

  1. Lệnh đã chạy (chính xác).
  2. .\mvnw.cmd -version (3 dòng đầu).
  3. Toàn bộ khối [ERROR] đầu tiên (không chụp màn hình cắt dở).
  4. Bạn đã thử gì.
  5. Thay đổi gần nhất (git diff).

💼 Interview Corner

1. How do you troubleshoot Maven build failures?

  • 🇻🇳 Dịch: Xử lý lỗi build Maven?
  • Suggested answer (EN): Read the first [ERROR], identify the failing plugin goal, rerun with -e/-X, narrow with test-compile or a single test, check java -version and mvnw -version, and clean only the broken artifacts.
  • Giải thích (VI): Quy trình 5 bước.
  • Follow-up: Where do you look for test failures?

2. Tests fail but the Maven log is unclear. Where next?

  • 🇻🇳 Dịch: Test fail nhưng log không rõ?
  • Suggested answer (EN): Open target/surefire-reports (emailable-report.html, TestSuite.txt, .dumpstream) for details.
  • Giải thích (VI): .dumpstream chứa cảnh báo hạ tầng.
  • Follow-up: What does the 'Boot Manifest-JAR' warning mean?

📌 Lesson Summary

Kiến thức cần nhớ

  • 5 bước: đọc lỗi → xác định goal → thu thập → thu hẹp → làm sạch có chủ đích
  • Nhóm lỗi: compiler / surefire / dependency / wrapper-JDK
  • Xoá cache ở phạm vi nhỏ nhất

Method / lệnh cần biết

  • -e, -X, -B, -U, -o, help:effective-pom, help:effective-settings

Điểm dễ nhầm lẫn

  • Lỗi biên dịch ≠ test fail
  • JAVA_HOME trống (OK) ≠ sai (lỗi)
  • -o thiếu cache gây lỗi tải
