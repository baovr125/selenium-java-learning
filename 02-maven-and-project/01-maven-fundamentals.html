Maven Fundamentals

📋 Prerequisites

  • Project Initialization

1. Maven là gì?

📘 Apache Maven là công cụ quản lý dự án và tự động hoá build cho Java. Nó làm ba việc chính:

  1. Quản lý thư viện (dependency management): bạn khai báo "tôi cần Selenium 4.52.0", Maven tự tải về cùng mọi thư viện mà Selenium cần.
  2. Chuẩn hoá build: mọi dự án Maven đều có cùng cấu trúc thư mục và cùng các lệnh (compile, test, package...).
  3. Chạy các tác vụ qua plugin: biên dịch, chạy test, đóng gói, sinh báo cáo.

Tên gọi hay gặp: POM (Project Object Model) là file pom.xml mô tả dự án.

2. Tại sao dự án Java dùng Maven?

Nhu cầu Không có Maven Có Maven
Lấy thư viện Tự tải từng file .jar từ web Khai báo 3 dòng trong pom.xml
Thư viện phụ thuộc Tự tìm và tải từng cái (Selenium cần ~40 jar!) Tự tải đệ quy (transitive)
Đổi phiên bản Xoá jar cũ, tải jar mới, sửa classpath Đổi một số trong <selenium.version>
Đưa code cho đồng nghiệp Gửi cả thư mục jar (hàng chục MB) Chỉ commit pom.xml; mỗi người tự tải
Chạy test Tự gõ javac, java -cp ... .\mvnw.cmd test
CI/CD Phải viết script riêng Một lệnh Maven chuẩn

🧩 Dự án có run-test.ps1 — một phiên bản "tự làm thủ công" của build: lấy classpath bằng Maven (dependency:build-classpath), rồi tự gọi javac và java. Nó chạy được nhưng chỉ phục vụ chạy nhanh một class trên máy Windows; mvnw test mới là chuẩn chung cho team và CI.

3. Maven hoạt động như thế nào?

text
pom.xml  ──đọc──►  Maven (core)  ──chạy──►  Lifecycle (các phase)  ──gọi──►  Plugin (goal)
   │                                                                     compiler, surefire, ...
   └─ khai báo dependency ──► tìm trong Local Repo ──(thiếu)──► tải từ Remote/Central ──► lưu vào Local Repo

Maven không tự biết biên dịch hay chạy test: plugin làm việc đó. Maven core chỉ điều phối: đọc pom.xml, giải quyết dependency, gọi đúng plugin ở đúng phase. Xem 04.

4. Tọa độ (coordinates) — "địa chỉ" của thư viện

Mỗi thư viện/plugin có địa chỉ gồm 3 phần chính (viết tắt GAV):

Thành phần Ý nghĩa Ví dụ trong dự án
groupId Tổ chức/nhóm org.seleniumhq.selenium
artifactId Tên sản phẩm selenium-java
version Phiên bản 4.52.0

Cùng tọa độ ⇒ cùng một file ở mọi máy. Đường dẫn file trong repository suy ra trực tiếp từ GAV:

text
org/seleniumhq/selenium/selenium-java/4.52.0/selenium-java-4.52.0.jar

Bạn có thể thấy đúng cấu trúc này trong .mvn/repository/org/seleniumhq/selenium/selenium-java/4.52.0/.

5. Maven Repository

📘 Repository là nơi lưu các artifact (jar, pom, plugin).

Loại Vị trí Vai trò
Local Repository Mặc định C:\Users\<tên>\.m2\repository Kho trên máy bạn; Maven luôn tìm ở đây trước
Central Repository https://repo.maven.apache.org/maven2 Kho công cộng chính thức, Maven mặc định kết nối
Remote Repository URL tuỳ ý (Nexus/Artifactory công ty, JitPack...) Khai báo trong <repositories> hoặc settings.xml

🧩 Khác biệt của dự án: file .mvn/maven.config chứa

text
-Dmaven.repo.local=.mvn/repository

Nghĩa là Local Repository của dự án này không nằm ở ~/.m2/repository mà ở thư mục .mvn/repository (hiện có 123 file .jar). Lý do được ghi trong README: máy từng có file .pom giả trong ~/.m2 làm Maven hỏng; repo riêng giúp cô lập. Đổi lại:

  • Mỗi lần clone mới, phải tải lại toàn bộ thư viện vào .mvn/repository.
  • Thư mục này không được commit (đã có .mvn/repository/ trong .gitignore).
  • Thư mục ~/.m2/wrapper/dists (nơi mvnw lưu bản Maven) vẫn dùng ~/.m2 — hai thứ này khác nhau: Maven distribution và Local Repository.

6. Quy trình Maven tải và quản lý dependency

Khi bạn chạy .\mvnw.cmd test, với mỗi dependency trong pom.xml:

  1. Đọc groupId:artifactId:version (ví dụ selenium-java:4.52.0).
  2. Tìm trong Local Repository. Có đủ .pom và .jar ⇒ dùng luôn, không cần mạng.
  3. Nếu thiếu, kết nối repository khai báo (mặc định Central) và tải file .pom trước để biết thư viện này phụ thuộc gì.
  4. Đệ quy: với mỗi dependency của dependency (transitive), lặp lại bước 2-3.
  5. Giải quyết xung đột phiên bản (nếu cùng thư viện xuất hiện nhiều phiên bản — "nearest wins").
  6. Tải .jar, kiểm tra checksum (.sha1 đi kèm — bạn thấy các file *.jar.sha1 trong .mvn/repository), lưu vào Local Repository.
  7. Lắp classpath từ các jar có scope phù hợp phase hiện tại rồi đưa cho compiler/Surefire.

Dấu hiệu quan sát được: lần đầu chạy, console in Downloading from central: ...; lần sau không có (đã cache). File _remote.repositories trong mỗi thư mục artifact ghi nhớ artifact lấy từ repository nào.

Kiểm chứng: sau khi tải xong, bạn có thể chạy offline bằng cờ -o: .\mvnw.cmd -o test-compile (đã chạy thật và thành công).

7. Build Tool trong dự án Automation Testing

Vai trò Ví dụ ở Selenium1
Quản lý thư viện test selenium-java, testng
Biên dịch code test maven-compiler-plugin → target/test-classes
Chạy test maven-surefire-plugin → đọc testng.xml
Sinh báo cáo target/surefire-reports/*.html, *.xml
Tích hợp CI CI chỉ cần gọi ./mvnw test
Chuẩn hoá giữa các thành viên pom.xml + Maven Wrapper

8. Cấu trúc thư mục chuẩn và đầu ra

Thư mục Nội dung Commit?
src/main/java Mã sản phẩm ✅
src/test/java Mã kiểm thử ✅
src/test/resources Config, dữ liệu test ✅
target/ Mọi thứ Maven sinh ra (class, report, jar) ❌
.mvn/repository/ Local Repository riêng của dự án ❌

9. Maven vs Gradle (tham khảo)

Maven Gradle
Cấu hình XML khai báo (pom.xml) Groovy/Kotlin script
Học Dễ, chuẩn hoá mạnh Linh hoạt, đường cong học cao hơn
Phổ biến trong automation test Rất phổ biến Có nhưng ít hơn
Dự án này ✅ ❌

✅ Best Practices

  1. Dùng Maven Wrapper để cả nhóm cùng phiên bản Maven (03).
  2. Không commit target/ và Local Repository.
  3. Cố định phiên bản trong <properties> (như selenium.version).
  4. Dùng clean khi nghi ngờ file build cũ.

⚠️ Lỗi thường gặp

Lỗi Gốc rễ
"Maven tải mãi không xong" Mạng chậm/proxy; lần đầu cần tải ~40 jar Selenium
"Hôm qua chạy được, hôm nay Could not resolve dependencies" Mất mạng và thiếu cache; hoặc đổi maven.repo.local
Thư viện bị hỏng trong repo Tải dở; xoá thư mục artifact đó trong repo rồi chạy lại

Câu 1. Maven tìm thư viện ở đâu trước tiên?

  • A. Local Repository
  • B. Central Repository

  • A. group, archive, vendor
  • B. git, api, version
  • C. groupId, artifactId, version
  • D. Không có
Xem đáp án

Đáp án: C. Tọa độ duy nhất của một thư viện.

Câu 3. .mvn/maven.config của dự án làm gì?

  • A. Đặt phiên bản Java

💼 Interview Corner

1. What is Maven and why do Java projects use it?

  • 🇻🇳 Dịch: Maven là gì, vì sao dự án Java dùng?
  • Suggested answer (EN): Maven is a build and dependency management tool: it downloads libraries from repositories, standardizes the build lifecycle and runs plugins for compile, test and package.
  • Giải thích (VI): Ba ý: dependency, chuẩn hoá build, plugin.
  • Follow-up: Maven vs Gradle?

2. Explain local, central and remote repositories.

  • 🇻🇳 Dịch: Giải thích local, central, remote repository.
  • Suggested answer (EN): The local repository is a cache on your machine, central is the public default repository, and a remote repository is any other server such as a company Nexus; Maven looks locally first.
  • Giải thích (VI): Dự án này dùng local repo riêng .mvn/repository.
  • Follow-up: How can you build offline?

📌 Lesson Summary

Kiến thức cần nhớ

  • Maven = quản lý thư viện + chuẩn hoá build + plugin
  • Local → (Remote/Central) khi thiếu
  • GAV là tọa độ thư viện

Method / lệnh cần biết

  • -o offline, dependency:tree, -Dmaven.repo.local

Điểm dễ nhầm lẫn

  • Local Repository ≠ thư mục Maven của Wrapper (~/.m2/wrapper/dists)
  • Repository ≠ dependency
  • Plugin ≠ dependency
