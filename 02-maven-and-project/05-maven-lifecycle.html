Commands và Build Lifecycle

Liên quan: Mục lục · Trước: Maven Wrapper · Sau: Dependency Management · Chạy test

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Liệt kê các phase của default lifecycle theo thứ tự
  • Phân biệt clean, compile, test, package, verify, install
  • Giải thích Maven thực thi phase theo thứ tự
  • Biết -DskipTests, -o, -q, -B

📋 Prerequisites

  • pom.xml

1. Ba khái niệm cần phân biệt

Khái niệm Là gì Ví dụ
Lifecycle Chuỗi các phase theo thứ tự cố định default, clean, site
Phase Một bước trong lifecycle compile, test, package
Plugin goal Việc cụ thể do plugin thực hiện, gắn vào phase compiler:compile, surefire:test

Khi gõ .\mvnw.cmd test, bạn yêu cầu chạy phase test và mọi phase đứng trước nó. Mỗi phase gọi các goal đã gắn vào nó.

2. Ba lifecycle có sẵn

  1. clean: dọn dẹp (pre-clean, clean, post-clean).
  2. default (build): mọi thứ từ biên dịch đến triển khai.
  3. site: sinh trang tài liệu (hiếm dùng trong dự án test).

3. Lifecycle default — các phase chính

text
validate → compile → test → package → verify → install → deploy

(Thực tế có nhiều phase chi tiết hơn: process-resources, test-compile, process-test-classes, prepare-package, pre-integration-test, integration-test, post-integration-test...)

Phase Làm gì Goal gắn mặc định (jar packaging) Trong Selenium1
validate Kiểm tra pom.xml hợp lệ, đủ thông tin — Luôn qua
process-resources Copy src/main/resources resources:resources Không có thư mục ⇒ bỏ qua
compile Biên dịch src/main/java → target/classes compiler:compile Nothing to compile (không có src/main)
process-test-resources Copy src/test/resources resources:testResources —
test-compile Biên dịch src/test/java → target/test-classes compiler:testCompile Biên dịch BaseTest, 10 Exercise...
test Chạy unit test surefire:test Chạy 10 test Selenium theo testng.xml
package Đóng gói jar/war jar:jar Tạo jar gần rỗng, cảnh báo JAR will be empty
verify Chạy kiểm tra chất lượng sau package (integration test với Failsafe nếu có) (failsafe:verify nếu cấu hình) Không có plugin ⇒ không làm gì thêm
install Copy artifact vào Local Repository install:install Cài vào .mvn/repository (vì maven.repo.local)
deploy Đẩy artifact lên Remote Repository deploy:deploy Cần cấu hình distributionManagement — không dùng

🧩 Log thật khi chạy package -DskipTests:

text
--- resources:3.4.0:resources (default-resources) ---
--- compiler:3.13.0:compile (default-compile) ---
--- resources:3.4.0:testResources (default-testResources) ---
--- compiler:3.13.0:testCompile (default-testCompile) ---
--- surefire:3.5.2:test (default-test) ---          ← "Tests are skipped."
--- jar:3.5.0:jar (default-jar) ---                  ← "JAR will be empty..."
BUILD SUCCESS

Chú ý: phase test vẫn chạy (goal surefire:test xuất hiện) nhưng -DskipTests bảo nó bỏ qua việc chạy test.

4. Quy tắc quan trọng nhất

Chạy một phase ⇒ Maven chạy tất cả các phase trước nó theo thứ tự.

Lệnh Các phase chạy
compile validate → … → compile
test validate → … → compile → … → test-compile → test
package … → test → package (có chạy test)
verify … → package → verify
install … → verify → install
clean chỉ lifecycle clean; không biên dịch hay test

Hệ quả thực tế: package hay install sẽ chạy cả 10 test Selenium (~90 giây). Nếu chỉ muốn đóng gói: -DskipTests.

5. Các lệnh cần biết

Lệnh (Windows) Ý nghĩa Khi nào dùng
.\mvnw.cmd clean Xoá target/ Nghi ngờ file build cũ; trước khi chạy CI
.\mvnw.cmd compile Biên dịch main Dự án có src/main
.\mvnw.cmd test-compile Chỉ biên dịch test Kiểm tra lỗi cú pháp nhanh, không mở Chrome
.\mvnw.cmd test Biên dịch + chạy test Hằng ngày
.\mvnw.cmd clean test Làm sạch rồi chạy test Chuẩn trước khi push, trong CI
.\mvnw.cmd package Test + đóng gói Cần artifact
.\mvnw.cmd verify + bước kiểm tra sau package Dự án có integration test (Failsafe)
.\mvnw.cmd install + cài vào Local Repo Dự án khác trên máy cần dùng artifact này
.\mvnw.cmd validate Kiểm tra POM Debug cấu hình

6. clean, test, package, verify, install khác nhau thế nào?

Lifecycle Biên dịch? Chạy test? Tạo jar? Cài vào Local Repo? Thời gian ở dự án này
clean clean ✖ ✖ ✖ ✖ ~1-2 s (lần đầu cần mạng để tải plugin)
test default ✔ ✔ ✖ ✖ ~90 s
package default ✔ ✔ ✔ ✖ ~90 s +
verify default ✔ ✔ ✔ ✖ (+ kiểm tra) ~90 s +
install default ✔ ✔ ✔ ✔ ~90 s +

Mẹo nhớ: clean là một lifecycle riêng, nên thường ghép với phase khác: clean test, clean install. Không ghép thì test không tự xoá build cũ (Maven chỉ biên dịch lại file thay đổi — compiler dùng cơ chế incremental; đôi khi cần clean để hết lỗi "ma").

7. Goal trực tiếp (không qua lifecycle)

Cú pháp plugin:goal, ví dụ:

Lệnh Tác dụng
.\mvnw.cmd dependency:tree In cây phụ thuộc (đã chạy thật)
.\mvnw.cmd dependency:build-classpath "-Dmdep.outputFile=cp.txt" Xuất classpath (cách run-test.ps1 dùng)
.\mvnw.cmd help:effective-pom POM hiệu lực
.\mvnw.cmd surefire:test Chạy riêng goal test (cần đã biên dịch)
.\mvnw.cmd wrapper:wrapper Tạo/cập nhật Maven Wrapper

8. Cờ thường dùng

Cờ Ý nghĩa
-q Quiet — chỉ in lỗi
-B Batch mode — không màu, không tiến trình tải (dùng trong CI)
-o Offline — không dùng mạng (thất bại nếu thiếu plugin/lib trong cache)
-U Ép cập nhật SNAPSHOT/metadata
-e / -X Stacktrace lỗi / log debug
-DskipTests Biên dịch test nhưng không chạy
-Dmaven.test.skip=true Không biên dịch cả test (mạnh hơn skipTests)
-Dtest=... Chọn test cần chạy (06)
-P<profile> Kích hoạt profile
-f <pom> Chọn file POM khác

9. Cách Maven thực thi phase theo thứ tự

  1. Bạn gõ test. Maven tra bảng binding của packaging jar để xác định danh sách phase từ validate đến test.
  2. Với mỗi phase, Maven chạy mọi goal đã gắn vào phase đó theo thứ tự: goal mặc định của packaging trước, rồi goal bạn khai báo trong pom.xml.
  3. Fail-fast: nếu một goal thất bại (ví dụ testCompile lỗi cú pháp), Maven dừng, không chạy phase sau, kết luận BUILD FAILURE.
  4. Với test fail, Surefire thất bại ⇒ phase test thất bại ⇒ package không chạy. (Có thể dùng -Dmaven.test.failure.ignore=true để tiếp tục — chỉ nên dùng khi biết rõ lý do.)

⚠️ Lỗi thường gặp

Nhầm lẫn Sự thật
"compile biên dịch test" Không. Test được biên dịch ở test-compile
"clean chạy test" Không. clean chỉ xoá
"package nhanh vì chỉ tạo jar" Nó chạy test trước ⇒ chậm
"BUILD SUCCESS nghĩa là test pass" Chưa chắc: test có thể skipped hoặc 0 tests. Xem 06
Gõ mvnw clean mà không có test rồi hỏi sao test không chạy clean đứng một mình

💼 Interview Corner

1. What is the Maven build lifecycle?

  • 🇻🇳 Dịch: Vòng đời build Maven là gì?
  • Suggested answer (EN): An ordered list of phases (validate, compile, test, package, verify, install, deploy); running a phase runs all earlier phases, and plugin goals are bound to phases.
  • Giải thích (VI): clean là lifecycle riêng.
  • Follow-up: Phase vs goal?

2. Difference between clean, test, package and install?

  • 🇻🇳 Dịch: Khác nhau clean/test/package/install?
  • Suggested answer (EN): clean deletes target; test compiles and runs tests; package also builds the jar; install also copies it to the local repository. Package and install run the tests too.
  • Giải thích (VI): Dùng -DskipTests nếu chỉ cần đóng gói.
  • Follow-up: What does verify add?

📌 Lesson Summary

Kiến thức cần nhớ

  • Chạy phase N = chạy mọi phase trước N
  • clean là lifecycle riêng
  • package/install chạy cả test

Method / lệnh cần biết

  • clean, compile, test-compile, test, package, verify, install, -DskipTests, -o, -q, -B

Điểm dễ nhầm lẫn

  • compile ≠ test-compile
  • skipTests ≠ maven.test.skip
  • Phase ≠ Goal
