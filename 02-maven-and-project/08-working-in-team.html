Quy trình làm việc với Maven trong team

Quy trình 9 bước từ clone đến khi đồng đội pull về chạy lại. Mỗi bước có lệnh, giải thích, kết quả mong đợi. Liên quan: Mục lục · Maven Wrapper · Troubleshooting · Git phỏng vấn

ℹ️ Thư mục Selenium1 hiện chưa phải Git repository. Các lệnh Git dưới đây là quy trình chuẩn bạn sẽ dùng khi dự án nằm trên GitHub/GitLab; hãy thực hành trên bản sao hoặc repo thử nghiệm.

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Thực hiện quy trình 9 bước từ clone đến khi đồng đội pull
  • Đọc nhanh một dự án Maven lạ
  • Thêm/cập nhật dependency an toàn
  • Dùng checklist trước khi push

📋 Prerequisites

  • Maven Wrapper
  • Git Fundamentals

Tổng quan

text
 ┌─ Bạn ──────────────────────────────────────────────────────────────┐   ┌─ Đồng đội ──────────────┐
 │ 1 clone → 2 kiểm tra JDK/mvnw → 3 đọc pom → 4 clean test →         │   │ 9 git pull              │
 │ 5 đọc kết quả → 6 thêm dependency → 7 test lại → 8 commit & push ──┼──►│   .\mvnw.cmd clean test │
 └────────────────────────────────────────────────────────────────────┘   └─────────────────────────┘

Bước 1. Clone dự án

powershell
git clone https://github.com/<tổ-chức>/<repo>.git
cd <repo>

Giải thích: clone tải toàn bộ mã nguồn và lịch sử. Kết quả mong đợi: có pom.xml, mvnw, mvnw.cmd, .mvn/wrapper/, src/, testng.xml. Không có target/, .mvn/repository/ (bị .gitignore).

Kiểm tra:

powershell
Get-ChildItem -Force | Select-Object Name

⚠️ Nếu thiếu mvnw.cmd hoặc .mvn/wrapper ⇒ Wrapper chưa được commit; báo nhóm (xem 03).

Bước 2. Kiểm tra Java và Maven Wrapper

powershell
java -version
javac -version
.\mvnw.cmd -version

Giải thích: java/javac xác nhận JDK; mvnw -version xác nhận Wrapper chạy được (lần đầu tải Maven, cần Internet). Kết quả mong đợi (máy tác giả):

text
java version "25.0.1" ...
Apache Maven 3.9.16 (...)
Maven home: C:\Users\<tên>\.m2\wrapper\dists\apache-maven-3.9.16\<hash>
Java version: 25.0.1 ...

Điều kiện: JDK ≥ 21 (theo maven.compiler.release=21). Không cần cài Maven.

Bước 3. Đọc pom.xml (và file cấu hình liên quan)

powershell
Get-Content pom.xml
Get-Content .mvn\wrapper\maven-wrapper.properties
Get-Content .mvn\maven.config
Get-Content testng.xml

Cần xác định: phiên bản Java (maven.compiler.release), Selenium (selenium.version), framework test (TestNG), suite nào được chạy (testng.xml), Local Repository ở đâu (.mvn/maven.config ⇒ .mvn/repository). Kết quả mong đợi: bạn trả lời được "dự án dùng gì, chạy thế nào" trong 2 phút — xem checklist ở 02.

Bước 4. Chạy clean test

powershell
.\mvnw.cmd clean test

Giải thích: clean xoá target/; test biên dịch và chạy toàn bộ suite. Lần đầu chậm vì tải ~40 jar vào .mvn/repository. Chrome mở/đóng lần lượt. Kết quả mong đợi:

text
[INFO] Tests run: 10, Failures: 0, Errors: 0, Skipped: 0
[INFO] BUILD SUCCESS

Nếu lỗi: tra 08.

Bước 5. Phân tích kết quả test

powershell
Get-Content target\surefire-reports\TestSuite.txt
Start-Process target\surefire-reports\emailable-report.html

Câu hỏi cần trả lời:

  1. Tests run có đúng 10 không? (0 = không chạy gì!)
  2. Skipped có bằng 0 không?
  3. Nếu fail: exception là gì (NoSuchElementException? TimeoutException? AssertionError)? Xem selenium/09.
  4. Lỗi do code của mình hay do website/mạng?

Kết quả mong đợi: 10/10 pass (khớp báo cáo mẫu ket-qua/emailable-report.html).

Bước 6. Thêm hoặc cập nhật dependency khi cần

Tạo nhánh riêng trước:

powershell
git checkout -b feature/add-logging

Sửa pom.xml (ví dụ thêm một thư viện test). Rồi:

powershell
.\mvnw.cmd dependency:tree

Giải thích: xem thư viện mới kéo thêm gì và có xung đột phiên bản không (05). Kết quả mong đợi: BUILD SUCCESS, thư viện mới xuất hiện trong cây; không có cảnh báo xung đột bất thường.

Cập nhật phiên bản có sẵn: đổi giá trị <selenium.version> — chỉ ở một chỗ.

Bước 7. Kiểm tra lại toàn bộ test

powershell
.\mvnw.cmd clean test

Giải thích: bảo đảm thay đổi không làm hỏng gì. Đặc biệt khi nâng Selenium: đọc kỹ cảnh báo deprecated khi biên dịch. Kết quả mong đợi: vẫn Tests run: 10, Failures: 0, Errors: 0, Skipped: 0.

Bước 8. Commit và push

powershell
git status
git add pom.xml
git diff --staged
git commit -m "Add slf4j-simple test dependency to enable logging"
git push -u origin feature/add-logging

Giải thích: - git status xem đã thay đổi gì — kiểm tra không có target/, .mvn/repository/ trong danh sách. - git add pom.xml thêm đúng file cần (tránh git add . bừa bãi). - git diff --staged đọc lại những dòng sẽ commit. - Thông điệp commit nêu vì sao.

Kết quả mong đợi: commit chỉ chứa pom.xml. Mở Pull Request; CI (nếu có) chạy ./mvnw clean test.

Nếu bạn đổi phiên bản Maven: commit thêm .mvn/wrapper/maven-wrapper.properties (+ mvnw, mvnw.cmd nếu được sinh lại) và nói rõ trong PR.

Bước 9. Đồng đội pull và chạy lại

powershell
git checkout main
git pull
.\mvnw.cmd clean test

Giải thích: pull mang về pom.xml mới. Khi chạy Maven, thấy dependency mới chưa có trong Local Repository ⇒ tự tải. Đồng đội không phải cài hay làm gì thêm. Nếu IDE đang mở: Reload Maven project. Kết quả mong đợi: BUILD SUCCESS; nếu có khác biệt với máy bạn (Chrome, JDK...) thì thảo luận trong PR.

Checklist "trước khi push"

  • .\mvnw.cmd clean test xanh (10/10, Skipped: 0).
  • git status không có target/, test-output/, .mvn/repository/.
  • Không commit thông tin nhạy cảm (mật khẩu thật, token).
  • Commit nhỏ, thông điệp rõ.
  • pom.xml đổi → ghi lý do trong PR.

Tình huống thường gặp trong nhóm

Tình huống Xử lý
"Máy tôi pass, CI fail" So phiên bản JDK/Chrome; xem log CI; chạy clean test cục bộ; xem 08
Xung đột khi merge pom.xml Giải quyết thủ công, giữ cả hai dependency hợp lệ; chạy dependency:tree; chạy lại clean test
Đồng đội báo Could not resolve dependencies sau khi pull Kiểm tra tọa độ bạn vừa thêm; mạng của họ; thử -U
Hai người cùng nâng Selenium Thống nhất một PR, không để hai phiên bản song song
Có người dùng IDE "bundled Maven" Yêu cầu dùng Maven Wrapper trong IDE
Ai đó vô tình commit target/ git rm -r --cached target rồi commit; đảm bảo .gitignore đúng

Vai trò của mỗi công cụ

Công cụ Giữ gì
Git Công thức: pom.xml, maven-wrapper.properties, mã nguồn
Maven Wrapper Đúng phiên bản Maven
Maven Tải và dựng theo công thức
CI Trọng tài chạy cùng lệnh trên máy sạch

✅ Knowledge Check

Câu 1. Lệnh nên chạy trước khi push?

  • A. mvnw clean test
  • B. mvnw clean
  • C. git add .
  • D. mvnw -version
Xem đáp án

Đáp án: A. Kiểm chứng toàn bộ trên môi trường sạch.

Câu 2. Khi đổi pom.xml, cần commit gì?

  • A. target/
  • B. pom.xml (và lý do trong PR)
  • C. .mvn/repository/
  • D. Mọi jar
Xem đáp án

Đáp án: B. Chỉ cấu hình/mã nguồn.

Câu 3. Ai chịu trách nhiệm tải thư viện mới khi pom.xml đổi?

  • A. Người đẩy code
  • B. CI duy nhất
  • C. Git
  • D. Mỗi máy tự tải khi chạy Maven
Xem đáp án

Đáp án: D. Git chỉ chia sẻ công thức; Maven tải thư viện.

💼 Interview Corner

1. Describe your workflow when you join a Maven Selenium project.

  • 🇻🇳 Dịch: Mô tả cách bạn bắt đầu với dự án Maven Selenium.
  • Suggested answer (EN): Clone, check the JDK, run mvnw -version, read pom.xml and the suite file, run mvnw clean test, read the report, then pick a small task on a branch.
  • Giải thích (VI): Có lệnh cụ thể cho từng bước.
  • Follow-up: What do you do if the first run fails?

2. How do you keep the team on the same environment?

  • 🇻🇳 Dịch: Giữ cả nhóm cùng môi trường?
  • Suggested answer (EN): Commit the wrapper, pin library and plugin versions, document the required JDK in the README and let CI run mvnw clean test on a clean machine.
  • Giải thích (VI): Wrapper chưa khoá JDK/Chrome.
  • Follow-up: How could you enforce the JDK version?

📌 Lesson Summary

Kiến thức cần nhớ

  • Quy trình 9 bước: clone → kiểm tra → đọc pom → clean test → phân tích → dependency → test lại → commit/push → đồng đội pull
  • Checklist trước khi push
  • CI là trọng tài trên máy sạch

Method / lệnh cần biết

  • git clone/pull/switch/add/commit/push, .\mvnw.cmd clean test, dependency:tree

Điểm dễ nhầm lẫn

  • git add . ≠ add từng file
  • Local pass ≠ CI pass
  • PR cần nêu cách kiểm chứng
