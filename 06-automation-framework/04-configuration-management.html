1. Mục tiêu

Một mã nguồn — nhiều cách chạy. Đổi browser, URL, timeout, headless mà không sửa code:

powershell
.\mvnw.cmd test "-Dbrowser=firefox" "-Dheadless=true" "-Dbase.url=https://staging.example.com"

3. Thiết kế Config

Xem mã đầy đủ ở testing-framework/05. Nguyên tắc:

text
ưu tiên (cao → thấp):
 -Dkey=value  >  biến môi trường  >  config-<env>.properties  >  config.properties  >  mặc định trong code

Ví dụ lớp bọc (Singleton đơn giản, bất biến):

java
public final class Config {
    public static String baseUrl()      { return get("base.url", "https://example.com"); }
    public static String browser()      { return get("browser", "chrome"); }
    public static boolean headless()    { return Boolean.parseBoolean(get("headless", "false")); }
    public static Duration timeout()    { return Duration.ofSeconds(Long.parseLong(get("timeout.seconds", "15"))); }
    // get(...) đọc theo thứ tự ưu tiên như trên
}

Dùng: new WebDriverWait(driver, Config.timeout()), driver.get(Config.baseUrl() + "/login").

4. Truyền cấu hình từ Maven sang JVM test

Surefire chạy test trong JVM riêng. -Dbrowser=firefox ở command line là property của Maven JVM; Surefire thường chuyển tiếp các user property sang JVM test, nhưng để rõ ràng/đảm bảo, khai báo trong POM:

xml
<plugin>
    <artifactId>maven-surefire-plugin</artifactId>
    <version>3.5.2</version>
    <configuration>
        <systemPropertyVariables>
            <browser>${browser}</browser>
            <base.url>${base.url}</base.url>
        </systemPropertyVariables>
    </configuration>
</plugin>

kèm giá trị mặc định trong <properties>:

xml
<properties>
    <browser>chrome</browser>
    <base.url>https://example.com</base.url>
</properties>

⇒ Không truyền gì thì dùng mặc định POM; truyền -Dbrowser=firefox thì đè. (Ví dụ minh hoạ; chạy thử và in giá trị ra để xác nhận.)

5. Maven Profile cho môi trường

xml
<profiles>
    <profile>
        <id>staging</id>
        <properties>
            <base.url>https://staging.example.com</base.url>
        </properties>
    </profile>
    <profile>
        <id>ci</id>
        <properties>
            <headless>true</headless>
        </properties>
    </profile>
</profiles>
powershell
.\mvnw.cmd test -Pstaging
.\mvnw.cmd test -Pci,staging

Khi nào dùng Profile vs file properties:

Profile config-<env>.properties
Nơi định nghĩa pom.xml src/test/resources
Phạm vi Cấu hình build + test Chủ yếu test
Dễ đọc với người không rành Maven Trung bình Cao
Lọc tài nguyên (resource filtering) ✅

Chọn một cách làm chủ đạo để nhóm khỏi lẫn.

  • ❌ Mật khẩu thật không vào Git.
  • ✅ System.getenv("TEST_PASSWORD").
  • ✅ CI secret.
  • ✅ File cấu hình cục bộ vào .gitignore.

🧩 Selenium1 chỉ dùng tài khoản demo công khai của trang luyện tập, nên chấp nhận được.

7. Cấu hình Maven Wrapper và .mvn/ như một phần của cấu hình

File Vai trò Commit?
.mvn/wrapper/maven-wrapper.properties Khoá phiên bản Maven ✅
.mvn/maven.config Tham số Maven mỗi lần chạy (🧩 đặt maven.repo.local) ✅
.mvn/jvm.config Tham số JVM của Maven (không có) ✅ nếu dùng
~/.m2/settings.xml Proxy/mirror cá nhân/ công ty ❌ (ngoài dự án)

Cẩn thận với .mvn/maven.config: nó áp dụng cho mọi lệnh Maven trong dự án và dễ bị quên. Khi hành vi Maven "lạ", đọc file này đầu tiên. Ví dụ của dự án đổi Local Repository sang .mvn/repository.

8. Checklist cấu hình tốt

  • Không hard-code URL/timeout/browser trong test.
  • Có giá trị mặc định để git clone rồi chạy được.
  • Ghi đè được bằng -D.
  • Bí mật không nằm trong Git.
  • Mọi file cấu hình chung của nhóm được commit và có tài liệu.
  • In cấu hình hiệu lực ở đầu lần chạy (log) để debug.

💼 Interview Corner

1. How do you run the same tests against different environments?

  • 🇻🇳 Dịch: Chạy cùng test trên nhiều môi trường?
  • Suggested answer (EN): Externalize the base URL and browser into properties overridable with -D, optionally grouped in Maven profiles, with defaults so the project runs after cloning.
  • Giải thích (VI): Một mã nguồn, nhiều cách chạy.
  • Follow-up: Profiles vs properties files?

2. What does .mvn/maven.config do?

  • 🇻🇳 Dịch: .mvn/maven.config làm gì?
  • Suggested answer (EN): It holds Maven command line options applied to every run; in this project it sets -Dmaven.repo.local=.mvn/repository.
  • Giải thích (VI): Dễ bị quên khi debug.
  • Follow-up: Should it be committed?

📌 Lesson Summary

Kiến thức cần nhớ

  • 4 tầng cấu hình
  • -D > env > file > default
  • Profile cho môi trường; bí mật ngoài Git

Method / lệnh cần biết

  • systemPropertyVariables, <profiles>, -P, -D

Điểm dễ nhầm lẫn

  • Property Maven ≠ property JVM test
  • Profile ≠ file properties
  • Cấu hình bí mật ≠ commit
