Page Object Model (POM)

Liên quan: Mục lục · Sau: Kiến trúc · Practice POM · Phỏng vấn POM 🔎 Selenium1 chưa dùng POM: locator và thao tác nằm ngay trong test (ví dụ Exercise01_LoginTest). Đây là điểm khởi đầu hợp lý cho người học, và cũng là chỗ POM sẽ phát huy tác dụng.

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Giải thích POM và lợi ích
  • Thiết kế Page Class (locator private, method nghiệp vụ, không assert)
  • Kết nối Page với Test qua driver
  • Nhận diện lỗi thiết kế POM

📋 Prerequisites

  • Java OOP Concepts
  • Explicit Wait

1. POM là gì?

Page Object Model là mẫu thiết kế: mỗi trang (hoặc thành phần UI) là một class Java. Class đó:

  • Che giấu locator (là private);
  • Cung cấp hành động có nghĩa nghiệp vụ (login(user, pass), getFlashMessage());
  • Không chứa assertion (hoặc rất ít) — assertion thuộc về test.

Test chỉ nói "làm gì", Page Object nói "làm thế nào".

2. Vì sao cần POM?

Giả sử website đổi id="username" thành id="user-name":

Không POM Có POM
Số chỗ phải sửa Mọi test dùng ô username 1 dòng trong LoginPage
Đọc test Đầy By.id(...), sendKeys Đọc như kịch bản: loginPage.login(...)
Tái sử dụng Copy-paste Gọi lại method
Rủi ro Sửa sót ⇒ test hỏng ngẫu nhiên Tập trung, dễ kiểm soát

3. Trước và sau khi áp dụng POM

Trước (kiểu của Exercise01, rút gọn)

java
public class Exercise01_LoginTest extends BaseTest {
    @Test
    public void testLoginSuccess() {
        driver.get(BASE_URL + "/login");
        WebElement usernameTextbox = driver.findElement(By.id("username"));
        usernameTextbox.clear();
        usernameTextbox.sendKeys("tomsmith");
        WebElement passwordTextbox = driver.findElement(By.name("password"));
        passwordTextbox.clear();
        passwordTextbox.sendKeys("SuperSecretPassword!");
        driver.findElement(By.xpath("//button[@type='submit']")).click();
        WebElement flash = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash")));
        Assert.assertTrue(flash.getText().contains("You logged into a secure area!"));
    }
}

Sau (đề xuất)

pages/LoginPage.java:

java
package pages;

public class LoginPage extends BasePage {
    private static final String PATH = "/login";

    private final By usernameInput = By.id("username");
    private final By passwordInput = By.id("password");
    private final By loginButton   = By.cssSelector("button[type='submit']");
    private final By flashMessage  = By.id("flash");

    public LoginPage(WebDriver driver) { super(driver); }

    public LoginPage open() {
        driver.get(BASE_URL + PATH);
        return this;
    }

    public SecureAreaPage loginAs(String username, String password) {
        type(usernameInput, username);
        type(passwordInput, password);
        click(loginButton);
        return new SecureAreaPage(driver);          // trang tiếp theo (fluent / chaining)
    }

    public LoginPage loginWithInvalid(String username, String password) {
        type(usernameInput, username);
        type(passwordInput, password);
        click(loginButton);
        return this;
    }

    public String getFlashMessage() { return text(flashMessage); }   // trang sai vẫn ở /login
}

✅ Bộ BasePage + LoginPage + SecureAreaPage + LoginPomTest ở mục này đã được biên dịch và chạy thật (2 test pass) trong một bản sao của dự án.

pages/SecureAreaPage.java:

java
public class SecureAreaPage extends BasePage {
    private final By flashMessage = By.id("flash");

    public SecureAreaPage(WebDriver driver) { super(driver); }

    public String getFlashMessage() { return text(flashMessage); }       // chờ visible rồi đọc
    public boolean isAtSecureArea() { return driver.getCurrentUrl().endsWith("/secure"); }
}

tests/LoginTest.java:

java
public class LoginTest extends BaseTest {
    @Test
    public void shouldLoginWithValidCredentials() {
        SecureAreaPage secure = new LoginPage(driver).open().loginAs("tomsmith", "SuperSecretPassword!");

        Assert.assertTrue(secure.getFlashMessage().contains("You logged into a secure area!"));
        Assert.assertTrue(secure.isAtSecureArea(), "URL phải kết thúc bằng /secure");
    }
}

Test giờ ngắn, đọc như tiếng người. Assertion ở test, locator ở page.

BasePage (xem 03):

java
public abstract class BasePage {
    protected static final String BASE_URL = "https://example.com";   // đặt địa chỉ site demo của bạn
    protected final WebDriver driver;
    protected final WebDriverWait wait;

    protected BasePage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }
    protected void click(By by) { wait.until(ExpectedConditions.elementToBeClickable(by)).click(); }
    protected void type(By by, String text) {
        WebElement el = wait.until(ExpectedConditions.visibilityOfElementLocated(by));
        el.clear();
        el.sendKeys(text);
    }
    protected String text(By by) { return wait.until(ExpectedConditions.visibilityOfElementLocated(by)).getText(); }
}

3.1. Đọc từng thành phần của một Page class

Thành phần (trong LoginPage) Làm chính xác gì Trả về Vì sao thiết kế vậy
private final By usernameInput = By.id("username") Lưu cách tìm ô username (chưa tìm gì cả). Nơi duy nhất biết locator — private để test không biết locator; By (không phải WebElement) để mỗi lần dùng đều tìm lại → ít stale
LoginPage(WebDriver driver) Nhận driver từ test rồi gọi super(driver) để BasePage giữ driver và wait đối tượng LoginPage Page không tự tạo trình duyệt; dùng chung driver của BaseTest
open() Mở URL của trang (driver.get(BASE_URL + "/login")) LoginPage (return this) Trả về chính trang này để nối chuỗi: new LoginPage(driver).open().loginAs(...)
loginAs(user, pass) Nhập tên, nhập mật khẩu, bấm nút (qua type/click của BasePage, đã có chờ) SecureAreaPage (return new ...) Đăng nhập thành công chuyển sang trang khác → trả về Page mới; test tiếp tục với trang đó
loginWithInvalid(user, pass) Cùng thao tác nhưng sai thông tin LoginPage (return this) Đăng nhập thất bại vẫn ở /login → trả về chính trang này
getFlashMessage() Chờ thông báo hiện rồi đọc chữ String Page trả dữ liệu, không assert: việc assertEquals là của test
isAtSecureArea() Kiểm tra URL kết thúc bằng /secure boolean Giúp test xác nhận "đã đúng trang" mà page không assert hộ

Quy tắc chọn kiểu trả về của một method trong Page:

Hành động trong method Kiểu trả về Ví dụ
Ở lại cùng trang chính class đó (return this) open(), loginWithInvalid(...), addElement()
Chuyển sang trang khác Page mới (return new NextPage(driver)) loginAs(...) → SecureAreaPage
Lấy dữ liệu để test assert String, int, boolean, List<...> getFlashMessage(), getRowCount()
Hành động độc lập, không có "bước kế tiếp" void closeModal() (hiếm)

3.2. @FindBy và PageFactory.initElements — từng phần làm gì

Đây là cách khai báo locator kiểu cũ (bạn sẽ gặp trong dự án có sẵn).

Thành phần Làm chính xác gì Lưu ý
@FindBy(id = "username") Gắn locator vào một field WebElement. Có thể dùng id, name, className, css, xpath, linkText, partialLinkText, tagName Mỗi @FindBy chỉ chọn một kiểu
private WebElement usernameInput; Field không chứa phần tử thật ngay: sau khi khởi tạo nó là một proxy Mỗi lần dùng (usernameInput.sendKeys(...)) proxy mới đi tìm phần tử
PageFactory.initElements(driver, this) Duyệt các field có @FindBy của this và gán proxy cho chúng. Phải gọi (thường trong constructor) Quên gọi → NullPointerException khi dùng field
@CacheLookup Tìm một lần rồi nhớ phần tử ⚠️ Gặp StaleElementReferenceException nếu DOM vẽ lại; thường không nên dùng
@FindBys / @FindAll Kết hợp nhiều locator theo kiểu AND (@FindBys) / OR (@FindAll) Hiếm dùng; khó đọc
java
public class LoginPage {
    @FindBy(id = "username") private WebElement usernameInput;
    @FindBy(id = "password") private WebElement passwordInput;

    public LoginPage(WebDriver driver) {
        PageFactory.initElements(driver, this);     // gán proxy cho các field @FindBy
    }
    public void typeUsername(String u) { usernameInput.sendKeys(u); }   // proxy tìm phần tử lúc gọi
}

4. Quy tắc thiết kế Page Class

Quy tắc Giải thích
1 trang/thành phần = 1 class LoginPage, SecureAreaPage, NavigationBar
Locator private Test không biết cách tìm
Method theo hành vi nghiệp vụ loginAs(...) chứ không typeUsername, clickLogin rời rạc (trừ khi cần)
Method trả về Page tiếp theo Chuỗi gọi mượt, dễ phát hiện luồng
Trả dữ liệu (String, int, List) để test assert Page không assert
Không có Thread.sleep; chờ nằm trong Page/BasePage Test sạch
Không giữ WebElement lâu; giữ By Tránh stale
Một phương thức "đã tải xong" (isLoaded) Xác nhận đang ở đúng trang

6. Kết nối Page Class với Test Class

text
Test class  ──new LoginPage(driver)──►  Page class  ──dùng──►  BasePage (wait/click/type)
   │ có driver từ BaseTest                                         │
   └─ assertion                                                    └─ WebDriver
  • BaseTest tạo driver ⇒ test truyền driver vào constructor Page.
  • Mỗi test tạo Page mới (nhẹ); Page không lưu trạng thái.

8. Lỗi thiết kế POM thường gặp

Lỗi Hậu quả Cách tránh
Assertion trong Page Page khó tái sử dụng, test kém rõ Page trả dữ liệu, test assert
Locator public Test lại đi tìm phần tử ⇒ mất ý nghĩa POM private
God Page (1 class cho cả site) Khó bảo trì Mỗi trang/component 1 class
Method quá thấp (clickButton1, clickButton2) Test lại là chuỗi click Method theo nghiệp vụ
Không trả Page tiếp theo Mất tính "luồng" return new NextPage(driver)
Thread.sleep trong Page Chậm + flaky Wait trong BasePage
Lưu WebElement làm field lâu dài Stale Lưu By
Page biết về test data Gắn chặt Truyền tham số
Lặp locator ở nhiều page Sửa nhiều chỗ Component (header, menu) dùng chung
Lạm dụng kế thừa sâu Rối Composition: Header là field của Page

✅ Best Practices

  1. Page: locator private + hành vi + trả dữ liệu/Page.
  2. Assertion ở test.
  3. Wait nằm trong BasePage.
  4. Đặt tên Page theo trang thật.
  5. Component dùng lại (header, footer, modal) tách class riêng.

💼 Interview Corner

1. What is the Page Object Model and why use it?

  • 🇻🇳 Dịch: POM là gì, vì sao dùng?
  • Suggested answer (EN): A design pattern where each page is a class holding its locators and exposing user actions; tests use those actions so a UI change is fixed in one class and tests stay readable.
  • Giải thích (VI): Dự án chưa dùng POM.
  • Follow-up: What are the disadvantages?

2. Should page objects contain assertions?

  • 🇻🇳 Dịch: Page có chứa assertion không?
  • Suggested answer (EN): Generally no; they return data or state and the test asserts, keeping pages reusable.
  • Giải thích (VI): isLoaded() nhỏ là chấp nhận được.
  • Follow-up: What about waits?

📌 Lesson Summary

Kiến thức cần nhớ

  • 1 trang = 1 class; locator private; method nghiệp vụ
  • Assertion ở test; wait trong BasePage
  • Trả Page tiếp theo hoặc dữ liệu

Method / lệnh cần biết

  • extends BasePage, new XxxPage(driver), loginAs(...)

Điểm dễ nhầm lẫn

  • God Page
  • Locator public
  • Lưu WebElement làm field → stale

public class DropdownPage extends BasePage {
    private final By dropdown = By.id("dropdown");

    public DropdownPage(WebDriver driver) { super(driver); }

    public DropdownPage open() {
        driver.get(BASE_URL + "/dropdown");
        return this;
    }

    public DropdownPage select(String visibleText) {
        new Select(waitVisible(dropdown)).selectByVisibleText(visibleText);
        return this;
    }

    public String getSelectedText() {
        return new Select(waitVisible(dropdown)).getFirstSelectedOption().getText().trim();
    }
}
