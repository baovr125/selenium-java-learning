Bài 1. Khởi tạo dự án Selenium Java

Mục tiêu: Dựng một dự án Maven mới có cấu trúc chuẩn và chạy được một test Selenium.

Kiến thức cần dùng: cấu trúc thư mục Maven (maven/01), BaseTest, TestNG @Test.

Yêu cầu:

  1. Tạo thư mục B:\Fresher\SeleniumLab (độc lập với Selenium1).
  2. Có src/test/java/base/BaseTest.java, src/test/java/tests/HomePageTest.java.
  3. Test mở https://the-internet.herokuapp.com/ và kiểm tra title bằng "The Internet".

Các bước:

powershell
mkdir B:\Fresher\SeleniumLab
cd B:\Fresher\SeleniumLab
mkdir src\test\java\base, src\test\java\tests, src\test\resources
  1. Tạo pom.xml (Bài 2).
  2. Tạo BaseTest và HomePageTest theo 04 mục 5-6.
  3. Chạy (sau khi có Wrapper ở Bài 3): .\mvnw.cmd test.

Code tham khảo: xem 04-project-initialization.md (đủ BaseTest và HomePageTest).

Kết quả mong đợi:

text
[INFO] Running tests.HomePageTest
[INFO] Tests run: 1, Failures: 0, Errors: 0, Skipped: 0
[INFO] BUILD SUCCESS

Lỗi thường gặp:

Lỗi Nguyên nhân Cách xử lý
Tests run: 0 Class không tên *Test, hoặc nằm ngoài src/test/java Đổi tên/vị trí
package org.testng does not exist Thiếu dependency Kiểm tra pom.xml
SessionNotCreatedException Chrome cũ/ mất mạng Cập nhật Chrome, kiểm tra mạng

Mở rộng: Thêm test thứ hai kiểm tra driver.getCurrentUrl() bằng https://the-internet.herokuapp.com/.

Bài 2. Cấu hình Maven (pom.xml)

Mục tiêu: Viết pom.xml đúng, hiểu từng khối, và so sánh với pom.xml của Selenium1.

Kiến thức cần dùng: groupId/artifactId/version, properties, dependencies, scope, plugins (maven/02).

Yêu cầu:

  1. groupId = com.fresher, artifactId = SeleniumLab, version = 1.0-SNAPSHOT.
  2. maven.compiler.release = 21, selenium.version = 4.52.0, testng.version = 7.10.2 (cùng phiên bản dự án gốc để so sánh).
  3. Hai dependency với scope test.
  4. maven-compiler-plugin 3.13.0, maven-surefire-plugin 3.5.2.
  5. Tự trả lời bằng văn bản (viết vào file ghi chú): vì sao scope test? Điều gì xảy ra nếu code Selenium đặt trong src/main?

Các bước: chép khung ở 04 mục 3, rồi đối chiếu từng dòng với pom.xml của dự án gốc; ghi lại điểm khác (ví dụ: bản gốc có suiteXmlFile).

Kiểm tra:

powershell
.\mvnw.cmd validate
.\mvnw.cmd dependency:tree

Kết quả mong đợi: BUILD SUCCESS; dependency:tree thấy selenium-java:4.52.0:test, testng:7.10.2:test và các transitive (selenium-support, guava, jcommander...).

Lỗi thường gặp:

Lỗi Nguyên nhân Cách xử lý
Non-parseable POM XML sai (thiếu đóng thẻ) Kiểm tra thẻ
Could not find artifact Sai tọa độ/ phiên bản So với pom.xml gốc
release version 21 not supported JDK < 21 Dùng JDK ≥ 21

Câu hỏi tự kiểm tra:

  1. ${selenium.version} được thay ở đâu?
  2. <scope>test</scope> ảnh hưởng gì tới compile?
  3. Vì sao ghim maven-surefire-plugin?
Đáp án gợi ý
  1. Maven thay biến bằng giá trị trong <properties> khi đọc POM.
  2. Thư viện không có trong classpath của src/main; chỉ có khi biên dịch/chạy test.
  3. Để build lặp lại được, không phụ thuộc phiên bản mặc định có thể đổi theo phiên bản Maven.
