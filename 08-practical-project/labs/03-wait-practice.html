Bài 8. Explicit Wait

Mục tiêu: Dùng WebDriverWait + ExpectedConditions; thấy tận mắt lỗi khi không chờ; so sánh với Thread.sleep.

Kiến thức cần dùng: visibilityOfElementLocated, elementToBeClickable, invisibilityOfElementLocated, textToBe, numberOfElementsToBe.

Yêu cầu: trên https://the-internet.herokuapp.com/dynamic_loading/1 (phần tử có sẵn nhưng ẩn cho đến khi bấm Start) và /dynamic_loading/2 (phần tử được thêm vào DOM sau khi bấm Start):

  1. Test không chờ → quan sát lỗi, ghi lại exception.
  2. Test chờ đúng bằng Explicit Wait.
  3. Đo thời gian chạy; so với Thread.sleep(10000).

Code tham khảo

java
package tests;

import base.BaseTest;
import org.openqa.selenium.By;
import org.openqa.selenium.NoSuchElementException;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.ui.ExpectedConditions;
import org.testng.Assert;
import org.testng.annotations.Test;

public class WaitPracticeTest extends BaseTest {

    private static final By START = By.cssSelector("#start button");
    private static final By FINISH = By.id("finish");

    // 1) Phần tử có trong DOM nhưng ẩn → presence ĐÚNG, visibility CHƯA
    @Test
    public void example1_hiddenElement_presenceVsVisibility() {
        driver.get("https://the-internet.herokuapp.com/dynamic_loading/1");
        WebElement finish = driver.findElement(FINISH);               // tìm được ngay (presence)
        Assert.assertFalse(finish.isDisplayed(), "Lúc đầu phần tử còn ẩn");
        Assert.assertEquals(finish.getText(), "", "Phần tử ẩn thì getText() rỗng");

        driver.findElement(START).click();
        wait.until(ExpectedConditions.visibilityOfElementLocated(FINISH));   // chờ hiện
        Assert.assertEquals(driver.findElement(FINISH).getText(), "Hello World!");
    }

    // 2) Phần tử chưa tồn tại trong DOM → phải chờ presence/visibility
    @Test
    public void example2_elementAddedLater() {
        driver.get("https://the-internet.herokuapp.com/dynamic_loading/2");
        driver.findElement(START).click();

        // KHÔNG chờ → thường ném NoSuchElementException ngay:
        // driver.findElement(FINISH);

        WebElement finish = wait.until(ExpectedConditions.visibilityOfElementLocated(FINISH));
        Assert.assertEquals(finish.getText().trim(), "Hello World!");
    }

    // 3) Chứng minh: tìm ngay sau click KHÔNG chờ sẽ lỗi
    @Test(expectedExceptions = NoSuchElementException.class)
    public void example3_noWait_failsFast() {
        driver.get("https://the-internet.herokuapp.com/dynamic_loading/2");
        driver.findElement(START).click();
        driver.findElement(FINISH);          // quá sớm → NoSuchElementException
    }

    // 4) Chờ biến mất: loading bar
    @Test
    public void example4_waitLoadingDisappears() {
        driver.get("https://the-internet.herokuapp.com/dynamic_loading/2");
        driver.findElement(START).click();
        wait.until(ExpectedConditions.invisibilityOfElementLocated(By.id("loading")));
        Assert.assertTrue(driver.findElement(FINISH).isDisplayed());
    }

    // 5) Đo thời gian: wait chỉ chờ đúng lượng cần thiết
    @Test
    public void example5_measureWait() {
        driver.get("https://the-internet.herokuapp.com/dynamic_loading/2");
        driver.findElement(START).click();
        long t0 = System.nanoTime();
        wait.until(ExpectedConditions.visibilityOfElementLocated(FINISH));
        long ms = (System.nanoTime() - t0) / 1_000_000;
        System.out.println("Đã chờ " + ms + " ms (timeout tối đa 15000 ms)");
        Assert.assertTrue(ms < 15_000);
    }
}

Kết quả mong đợi

  • example1, example2, example4, example5 pass; example3 pass (vì mong đợi exception).
  • example5 in thời gian chờ nhỏ hơn timeout rất nhiều ⇒ Explicit Wait không chờ thừa.

Thử nghiệm bắt buộc (rút ra bài học)

  1. Đổi Duration.ofSeconds(15) trong wait thành Duration.ofSeconds(1) ⇒ quan sát TimeoutException và đọc message (có điều kiện đang chờ).
  2. Thay chờ bằng Thread.sleep(10000) ⇒ đo tổng thời gian và so sánh.
  3. Bật implicitlyWait(10s) ở một test riêng rồi gọi driver.findElements(By.id("khong-co")) ⇒ đo: mất ~10 giây (lý do dự án cấm implicit).

getText() rỗng Phần tử còn ẩn Chờ visibility...

Bài 9. Xử lý Dynamic Web Elements

Mục tiêu: Xử lý phần tử thay đổi trạng thái, bị xoá/thêm, và thông báo cũ còn trên màn hình — chính xác tình huống của Exercise10.

Kiến thức cần dùng: textToBe, elementToBeClickable, invisibilityOfElementLocated, stalenessOf, custom wait.

Yêu cầu: trên /dynamic_controls:

  1. Bấm Remove → chờ "It's gone!" → xác nhận checkbox không còn.
  2. Bấm Add → chờ "It's back!" → xác nhận checkbox xuất hiện lại.
  3. Bấm Enable → chờ ô input được bật → nhập chữ → xác nhận.
  4. Bấm Disable → chờ ô input bị khoá lại.
  5. Không dùng Thread.sleep.

Code tham khảo

java
@Test
public void dynamicControls() {
    driver.get("https://the-internet.herokuapp.com/dynamic_controls");
    By message = By.id("message");

    // Remove
    driver.findElement(By.cssSelector("#checkbox-example button")).click();
    wait.until(ExpectedConditions.textToBe(message, "It's gone!"));
    Assert.assertTrue(driver.findElements(By.id("checkbox")).isEmpty(), "Checkbox phải biến mất khỏi DOM");

    // Add
    driver.findElement(By.cssSelector("#checkbox-example button")).click();
    wait.until(ExpectedConditions.textToBe(message, "It's back!"));
    Assert.assertEquals(driver.findElements(By.id("checkbox")).size(), 1);

    // Enable
    WebElement input = driver.findElement(By.cssSelector("#input-example input"));
    Assert.assertFalse(input.isEnabled());
    driver.findElement(By.cssSelector("#input-example button")).click();
    wait.until(ExpectedConditions.textToBe(message, "It's enabled!"));      // KHÔNG chỉ chờ visibility
    wait.until(ExpectedConditions.elementToBeClickable(input));
    input.sendKeys("Dynamic OK");
    Assert.assertEquals(input.getAttribute("value"), "Dynamic OK");

    // Disable
    driver.findElement(By.cssSelector("#input-example button")).click();
    wait.until(ExpectedConditions.textToBe(message, "It's disabled!"));
    Assert.assertFalse(driver.findElement(By.cssSelector("#input-example input")).isEnabled());
}

Thử thách: Bài học "thông báo cũ"

Thay textToBe(message, "It's enabled!") bằng visibilityOfElementLocated(message) rồi đọc getText(). Chạy nhiều lần: quan sát đọc nhầm "It's gone!"/"It's back!" (thông báo cũ). Viết 3 dòng giải thích bằng lời của bạn.

Kết quả mong đợi

  • Test xanh 5 lần liên tiếp.
  • Bạn giải thích được vì sao textToBe đúng hơn visibility ở bước 3-4.

Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
StaleElementReferenceException ở input Trang vẽ lại ô input Tìm lại input sau mỗi thao tác (dự án gốc dùng biến cũ vì trang giữ phần tử)
Đọc nhầm thông báo Chờ không đặc trưng textToBe
ElementNotInteractableException khi sendKeys Input chưa enabled elementToBeClickable

✅ Cả hai bài đã được chạy thật (Selenium 4.52.0, Chrome, JDK 25 với --release 21): 5 test của Bài 8 và 1 test của Bài 9 đều pass; các thông báo It's gone!, It's back!, It's enabled!, It's disabled! khớp trang thực tế tại thời điểm viết. Nếu trang đổi, hãy chạy thử và đối chiếu.
