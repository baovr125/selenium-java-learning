1. Khái niệm

Viết test xong mới là một nửa. Phần còn lại: chạy đúng cách, đọc kết quả đúng, điều tra lỗi có hệ thống, báo cáo cho người khác hiểu, và chia sẻ code an toàn.

2. Syntax: các lệnh then chốt

powershell
.\mvnw.cmd clean test                              # chạy toàn bộ suite
.\mvnw.cmd test "-DsuiteFile=smoke.xml"            # chỉ smoke (nếu POM dùng ${suiteFile})
.\mvnw.cmd test "-Dtest=LoginTest#shouldLoginWithValidCredentials"   # một test
Get-Content target\surefire-reports\TestSuite.txt  # tóm tắt
Start-Process target\surefire-reports\emailable-report.html          # báo cáo HTML

3. Ví dụ

3.1. Bước 9 — Đọc kết quả đúng

Dấu hiệu Ý nghĩa Hành động
Tests run: 12, Failures: 0, Errors: 0, Skipped: 0 + BUILD SUCCESS Tốt —
Skipped: N Có test không được kiểm Điều tra (config fail? dependsOnMethods?)
Tests run: 0 + BUILD SUCCESS Không chạy gì (bẫy) Kiểm tra tên/suite
Failures: N Assertion sai Xem message + dữ liệu thực tế
Errors: N Exception (không tìm thấy, timeout...) Xem stacktrace

3.2. Bước 10 — Quy trình debug 8 bước

  1. Đọc dòng [ERROR]/exception đầu tiên và dòng code của bạn trong stacktrace.
  2. Chạy lại một mình test đó (-Dtest=Class#method).
  3. Chạy lại 3–5 lần: lúc được lúc không ⇒ flaky ⇒ nghi đồng bộ hoá.
  4. Kiểm tra locator trong DevTools ($$(), $x()).
  5. Thu bằng chứng: screenshot, getPageSource(), log.
  6. Sửa nguyên nhân gốc (Wait đúng điều kiện), không vá bằng sleep hay tăng timeout vô tội vạ.
  7. Chạy lại nhiều lần.
  8. Ghi lại bài học vào progress.

Bảng triage nhanh:

Triệu chứng Nghi ngờ Xem
NoSuchElementException ngẫu nhiên Thiếu Wait / iframe Wait
StaleElementReferenceException DOM vẽ lại WebElement
ElementClickInterceptedException Overlay/spinner ExpectedConditions
Local pass, CI fail Headless/kích thước/JDK/Chrome Reports
Lỗi tải thư viện Mạng/tọa độ Troubleshooting

3.3. Bước 11 — Báo cáo

  • Báo cáo có sẵn: target/surefire-reports/index.html và emailable-report.html (gửi mail).
  • Cần ảnh khi fail: thêm Screenshots.take(...) trong @AfterMethod/Listener (Debugging).
  • Một bản tóm tắt bằng lời gửi người liên quan:
markdown
## Kết quả chạy 14/11/2026 — nhánh main, commit abc1234
- Môi trường: Windows 11, JDK 21, Chrome <phiên bản>, Maven 3.9.16 (Wrapper)
- Lệnh: .\mvnw.cmd clean test
- Kết quả: 12 chạy, 0 fail, 0 skipped (≈ 1m30s)
- Lỗi/ rủi ro: Ex7 (cuộn vô hạn) từng flaky — đang theo dõi
- Báo cáo: target/surefire-reports/emailable-report.html (đính kèm)

3.4. Bước 12 — Git cho dự án

bash
git init -b main
git add pom.xml mvnw mvnw.cmd .mvn/wrapper/ .mvn/maven.config .gitignore .gitattributes src/ *.xml README.md
git status                       # kiểm tra KHÔNG có target/, .mvn/repository/
git update-index --chmod=+x mvnw
git commit -m "Initial framework: Maven wrapper, BaseTest, POM, 12 tests"

Chi tiết (bit thực thi, line ending, .gitignore): Git và Maven project.

4. Ứng dụng với dự án Selenium Maven (Real-world) — Checklist nghiệm thu

  • .\mvnw.cmd clean test → Tests run ≥ 12, Failures 0, Errors 0, Skipped 0, chạy 3 lần liên tiếp đều xanh.
  • smoke.xml chạy đúng tập con.
  • Không Thread.sleep, không Implicit Wait; locator nằm trong Page.
  • README đủ để người lạ chạy chỉ với JDK + Internet.
  • git status sạch; commit chỉ gồm mã nguồn + cấu hình; mvnw mode 100755.
  • Có bản tóm tắt kết quả (mẫu ở 3.3).
  • Giải thích được kiến trúc trong 2 phút (phỏng vấn).

5. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
Chỉ nhìn BUILD SUCCESS Bỏ qua Tests run/Skipped Luôn đọc dòng tổng kết
Vá flaky bằng sleep Che nguyên nhân Tìm điều kiện chờ đặc trưng
Dùng retry tự động để "xanh hoá" Mất niềm tin vào bộ test Điều tra nguyên nhân trước
Báo cáo "fail" không kèm bằng chứng Người khác không tái hiện được Ảnh + lệnh + môi trường
Commit target/ hay mật khẩu thật Quên .gitignore/kiểm tra git status trước khi commit
Quên cập nhật README khi đổi cách chạy Đồng đội lúng túng Cập nhật cùng PR

✅ Knowledge Check

Câu 1. Tests run: 12, Skipped: 2, BUILD SUCCESS — kết luận?

  • A. Tốt
  • B. Có 2 test không được kiểm — cần điều tra
  • C. Lỗi Maven
  • D. Fail
Xem đáp án

Đáp án: B. Skipped không làm build fail.

Câu 2. Vá flaky bằng sleep hoặc retry vô tội vạ?

  • A. Nên
  • B. Không, che nguyên nhân
  • C. Bắt buộc
  • D. Tuỳ
Xem đáp án

Đáp án: B. Tìm điều kiện chờ đặc trưng.

Câu 3. Trước khi commit cần kiểm tra?

  • A. git status không có target/
  • B. Xoá .git
  • C. Đổi JDK
  • D. Không cần
Xem đáp án

Đáp án: A. Và không chứa bí mật.

💼 Interview Corner

1. How do you report test results to the team?

  • 🇻🇳 Dịch: Báo cáo kết quả cho nhóm?
  • Suggested answer (EN): I share the command, environment, counts of run/failed/skipped, risks such as known flaky tests, and attach the report; for failures I add evidence like screenshots.
  • Giải thích (VI): Có mẫu bản tóm tắt.
  • Follow-up: What do you include for a failure?

2. Walk me through delivering a framework to a team.

  • 🇻🇳 Dịch: Bàn giao framework cho nhóm?
  • Suggested answer (EN): A clean repository with wrapper, README, pinned versions, green clean test, correct .gitignore, executable mvnw, and a CI run on a clean machine.
  • Giải thích (VI): Checklist nghiệm thu.
  • Follow-up: What would you automate next?

📌 Lesson Summary

Kiến thức cần nhớ

  • Đọc Tests run/Skipped, không chỉ BUILD SUCCESS
  • Debug 8 bước; báo cáo có bằng chứng
  • Git sạch trước khi chia sẻ

Method / lệnh cần biết

  • mvnw clean test, TestSuite.txt, emailable-report.html, git status, update-index --chmod=+x

Điểm dễ nhầm lẫn

  • Vá ≠ sửa
  • Báo cáo thiếu môi trường/lệnh
  • Quên mode mvnw
