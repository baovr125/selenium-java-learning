1. Khái niệm

Bạn sẽ dựng một framework nhỏ theo từng mốc (milestone). Mỗi mốc kết thúc bằng .\mvnw.cmd clean test xanh và một commit Git (bước 12). Làm theo mốc giúp lỗi luôn nằm trong phạm vi nhỏ.

2. Syntax: cấu trúc đích

text
SeleniumFramework/
├── pom.xml
├── mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties
├── .gitignore, .gitattributes
├── smoke.xml, all.xml
├── README.md
└── src/test/
    ├── java/
    │   ├── base/BaseTest.java
    │   ├── core/DriverFactory.java
    │   ├── config/Config.java
    │   ├── pages/BasePage.java, LoginPage.java, SecureAreaPage.java, ...
    │   ├── utils/Screenshots.java
    │   └── tests/LoginTest.java, DynamicControlsTest.java, ...
    └── resources/config.properties

2.1. Từng file/thư mục trong cấu trúc đích — vai trò và bài học liên quan

Thành phần Làm chính xác gì Bài học liên quan
pom.xml Khai báo thư viện (Selenium, TestNG), phiên bản Java, plugin chạy test pom.xml
mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties Chạy đúng phiên bản Maven mà không cần cài Maven Wrapper
.gitignore, .gitattributes Chặn file sinh ra (target/), ép kết thúc dòng của mvnw .gitignore
smoke.xml, all.xml Hai bộ suite TestNG: chạy nhanh vs chạy đầy đủ TestNG
README.md Hướng dẫn cài, chạy, đọc báo cáo —
base/BaseTest.java Mở Chrome trước mỗi test, đóng sau; giữ driver, wait Setup/Teardown
core/DriverFactory.java Tạo WebDriver theo tên browser Reusable Components
config/Config.java Đọc cấu hình (-D > file > mặc định) Configuration
pages/BasePage.java Thao tác chung có sẵn Wait: click, type, text Reusable Components
pages/LoginPage.java... Mỗi trang một class: locator + hành vi nghiệp vụ Page Object Model
utils/Screenshots.java Chụp ảnh khi test fail Reusable Components
tests/LoginTest.java... Kịch bản + assert; không chứa locator Assertions
resources/config.properties Giá trị cấu hình mặc định (URL, browser, timeout) Test Data & Config

Thứ tự nên dựng (từ ít phụ thuộc đến nhiều): pom.xml + Wrapper → .gitignore → Config → DriverFactory → BaseTest → BasePage → Page → Test → suite XML → báo cáo.

3. Ví dụ: kế hoạch 6 mốc

Mốc Việc cần làm Kiểm chứng (Definition of Done)
M1 — Khung Thư mục, pom.xml (Java 21, Selenium 4.52.0, TestNG 7.10.2), Wrapper, BaseTest, 1 test mở trang .\mvnw.cmd -version → Maven 3.9.16; Tests run: 1, Failures: 0
M2 — Config config.properties, lớp Config, DriverFactory, ChromeOptions headless qua -D -Dheadless=true chạy không mở cửa sổ
M3 — POM BasePage (wait/click/type/text), LoginPage, SecureAreaPage + 2 test Test không chứa By./Thread.sleep
M4 — Mở rộng Page + test cho Checkboxes, Dropdown, Dynamic Controls, Add/Remove, Alerts Tests run ≥ 12, Skipped: 0
M5 — Wait & ổn định Mọi chỗ bất đồng bộ dùng Explicit Wait theo điều kiện; thử -Dtest= từng test 3 lần 3 lần chạy liên tiếp đều xanh
M6 — Suite & dữ liệu smoke.xml/all.xml, @DataProvider cho login -DsuiteFile=smoke.xml chạy tập con

Mẫu cấu hình tối thiểu cho M2

src/test/resources/config.properties:

properties
base.url=https://example.com
browser=chrome
headless=false
timeout.seconds=15

Đọc bằng Config (Test Data & Config); ghi đè bằng .\mvnw.cmd test "-Dheadless=true". Mã Config, DriverFactory, BasePage mẫu: Reusable Components (đã biên dịch thử).

Quy tắc viết Test Script (bước 7)

java
@Test(groups = {"smoke"}, description = "TC_LOGIN_01 Đăng nhập thành công")
public void shouldLoginWithValidCredentials() {
    SecureAreaPage secure = new LoginPage(driver()).open().loginAs("tomsmith", "SuperSecretPassword!");
    Assert.assertTrue(secure.getFlashMessage().contains("You logged into a secure area!"));
    Assert.assertTrue(secure.isAtSecureArea(), "URL phải kết thúc bằng /secure");
}

Quy tắc Wait (bước 8)

Tình huống Chờ
Đọc text visibilityOfElementLocated
Click elementToBeClickable (+ overlay invisibilityOfElementLocated)
Thông báo thay đổi textToBe (không chỉ visibility)
Phần tử biến mất invisibilityOfElementLocated/numberOfElementsToBe(by, 0)
Điều kiện đặc biệt Custom wait (lambda)
Không bao giờ Thread.sleep, Implicit Wait

4. Ứng dụng với dự án Selenium Maven (Real-world)

  • Đối chiếu từng mốc với dự án mẫu Selenium1: BaseTest ↔ M1, hằng URL/timeout ↔ M2, các Exercise ↔ M4, Wait ↔ M5.
  • Mỗi mốc là một Pull Request nhỏ (Git workflow).
  • Khi nâng phiên bản thư viện, tách PR riêng và dependency:tree trước.
  • README của dự án mới cần: yêu cầu môi trường, cách chạy, cấu trúc, cách thêm Page/Test mới.

5. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
package org.openqa.selenium does not exist Code ở src/main mà scope test Đặt code trong src/test/java
Tests run: 0 Sai tên/ vị trí/ sai suite Build & Test Execution
getResourceAsStream trả null config.properties sai chỗ src/test/resources
Phình to BasePage Nhét mọi thứ Tách Waits, JsUtils, component
Làm hết rồi mới chạy thử Lỗi dồn lại Chạy clean test sau mỗi mốc
Test phụ thuộc thứ tự Fail dây chuyền Độc lập, mỗi test tự mở browser

💼 Interview Corner

1. How do you structure a small automation project?

  • 🇻🇳 Dịch: Cấu trúc dự án automation nhỏ?
  • Suggested answer (EN): Maven with wrapper, base test and driver factory, config, page objects with a base page, tests with data providers, suites in XML files, reports from Surefire.
  • Giải thích (VI): Làm theo mốc.
  • Follow-up: How do you verify each step?

2. How do you keep tests stable?

  • 🇻🇳 Dịch: Giữ test ổn định?
  • Suggested answer (EN): Condition-based waits, independent tests, stable locators in pages, fixed window size and repeated runs before committing.
  • Giải thích (VI): Chạy 3 lần.
  • Follow-up: What if one still flakes?
