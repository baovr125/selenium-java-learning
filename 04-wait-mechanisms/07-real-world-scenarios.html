1. 15 tình huống thực tế

Mỗi tình huống: Hiện tượng → Lỗi nếu không chờ → Cách chờ đúng.

T1. Chuyển trang sau đăng nhập (🧩 Ex1)

  • Lỗi: driver.findElement(By.id("flash")) ngay sau click() ⇒ NoSuchElementException.
  • Đúng: wait.until(visibilityOfElementLocated(By.id("flash"))); kèm wait.until(urlContains("/secure")).

T2. Phần tử ẩn hiện sau hover (🧩 Ex5)

  • Lỗi: getText() trả "".
  • Đúng: actions.moveToElement(fig).perform(); wait.until(visibilityOf(caption));

T3. Nút "Delete" được sinh ra sau khi bấm Add (🧩 Ex6)

  • Đúng: wait.until(visibilityOfElementLocated(By.className("added-manually"))); xoá xong: wait.until(numberOfElementsToBe(by, 0)).

T4. Nội dung tải thêm khi cuộn (🧩 Ex7)

  • Lỗi: cuộn một lần rồi đếm ⇒ có thể không tăng.
  • Đúng: custom wait có cuộn lặp lại (xem Fluent Wait và Custom Wait).

T5. Modal quảng cáo hiện sau vài trăm ms rồi đóng (🧩 Ex8)

  • Đúng: visibilityOfElementLocated(By.id("modal")); đóng xong invisibilityOfElementLocated(By.id("modal")).

T6. Thông báo cũ vẫn còn trên màn hình (🧩 Ex10)

  • Lỗi: chờ visibilityOfElementLocated(#message) — thoả ngay vì "It's gone!" đang hiện ⇒ đọc nhầm.
  • Đúng: wait.until(textToBe(messageLocator, "It's enabled!")).

T7. Spinner/loading che nút

java
wait.until(ExpectedConditions.invisibilityOfElementLocated(By.cssSelector(".loading-spinner")));
wait.until(ExpectedConditions.elementToBeClickable(By.id("save"))).click();
  • Lỗi nếu bỏ: ElementClickInterceptedException: other element would receive the click.

T8. Bảng/danh sách được vẽ lại sau lọc (stale)

java
WebElement oldFirst = driver.findElement(By.cssSelector("#results li"));
driver.findElement(By.id("filter")).sendKeys("abc");
wait.until(ExpectedConditions.stalenessOf(oldFirst));
List<WebElement> items = wait.until(ExpectedConditions.presenceOfAllElementsLocatedBy(By.cssSelector("#results li")));
  • Lỗi nếu bỏ: StaleElementReferenceException hoặc đọc dữ liệu cũ.

T9. JS alert sau khi click

java
driver.findElement(By.cssSelector("button[onclick='jsAlert()']")).click();
Alert alert = wait.until(ExpectedConditions.alertIsPresent());
alert.accept();

T10. Mở tab mới

java
wait.until(ExpectedConditions.numberOfWindowsToBe(2));

T11. Iframe tải chậm

java
wait.until(ExpectedConditions.frameToBeAvailableAndSwitchToIt(By.id("mce_0_ifr")));

T12. Kết quả tìm kiếm AJAX theo số lượng

java
driver.findElement(By.id("search")).sendKeys("selenium");
wait.until(ExpectedConditions.numberOfElementsToBeMoreThan(By.cssSelector(".result"), 0));

T13. Trạng thái chữ đổi "Processing" → "Done"

java
wait.until(ExpectedConditions.textToBe(By.id("status"), "Done"));

T14. Nút bị khoá rồi mở khoá (disabled bị gỡ)

java
wait.until(ExpectedConditions.elementToBeClickable(By.id("submit")));   // enabled + visible
// 🧩 Ex10 dùng đúng cách này cho ô input được bật bởi nút Enable

T15. File tải xuống hoàn tất (không quan sát được bằng DOM)

java
Path file = Path.of(downloadDir, "report.xlsx");
new FluentWait<>(file).withTimeout(Duration.ofSeconds(60)).pollingEvery(Duration.ofSeconds(1))
        .until(p -> Files.exists(p) && !Files.exists(Path.of(p + ".crdownload")));

(Chrome ghi file tạm .crdownload khi đang tải.)

✅ Knowledge Check

Câu 1. Mẫu đúng để chờ DOM được vẽ lại?

  • A. Thread.sleep
  • B. Giữ phần tử cũ → hành động → stalenessOf(old) → tìm phần tử mới
  • C. Implicit lớn
  • D. Bỏ qua
Xem đáp án

Đáp án: B. Tránh đọc dữ liệu cũ.

Câu 2. getWindowHandles() ngay sau click có thể?

  • A. Luôn đủ
  • B. Mới có 1 handle (tab mở bất đồng bộ)
  • C. Ném lỗi
  • D. Trả null
Xem đáp án

Đáp án: B. Chờ numberOfWindowsToBe.

Câu 3. File tải xong không quan sát được bằng DOM thì dùng?

  • A. Implicit
  • B. FluentWait với điều kiện file
  • C. alertIsPresent
  • D. Không chờ
Xem đáp án

Đáp án: B. Custom condition.

💼 Interview Corner

1. The old message is still visible while I wait for a new message. What do you do?

  • 🇻🇳 Dịch: Thông báo cũ vẫn hiện, bạn làm gì?
  • Suggested answer (EN): Visibility passes immediately, so I wait for the exact new text with textToBe, or wait for the old element to be stale and read the new one.
  • Giải thích (VI): Điều kiện đặc trưng cho trạng thái mới.
  • Follow-up: Which exercise shows this?

2. How do you handle a spinner that blocks clicks?

  • 🇻🇳 Dịch: Spinner chặn click?
  • Suggested answer (EN): Wait for the spinner to be invisible and then for the button to be clickable before clicking.
  • Giải thích (VI): Tránh ElementClickInterceptedException.
  • Follow-up: What if the spinner may not appear?

📌 Lesson Summary

Kiến thức cần nhớ

  • 15 tình huống = 15 mẫu điều kiện chờ
  • Đọc dữ liệu mới: điều kiện đặc trưng
  • Alert/tab/iframe luôn chờ trước khi chuyển

Method / lệnh cần biết

  • alertIsPresent, numberOfWindowsToBe, frameToBeAvailableAndSwitchToIt, stalenessOf, textToBe

Điểm dễ nhầm lẫn

  • Thông báo cũ vs mới
  • invisibility pass sớm nếu chưa từng hiện
  • Handle cũ vs phần tử mới
