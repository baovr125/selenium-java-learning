Interview Cheatsheet — tóm tắt lý thuyết để ôn nhanh

Bản một trang để đọc lại trước ngày phỏng vấn. Mỗi mục trỏ về bài/bộ câu hỏi đầy đủ. Không thay thế việc hiểu bản chất. Quay lại: Interview README

1. Selenium

Chủ đề Cần nhớ
Kiến trúc Test code (client) → giao thức W3C WebDriver → browser driver (chromedriver…) → trình duyệt. Selenium Manager (4.6+) tự tìm/tải driver
close() vs quit() close() đóng cửa sổ hiện tại; quit() đóng tất cả, kết thúc session, dừng driver
findElement vs findElements Không thấy: ném NoSuchElementException vs trả danh sách rỗng
getText() vs getAttribute("value") Chữ hiển thị vs giá trị của input
isDisplayed/isEnabled/isSelected Hiển thị / cho thao tác / đã chọn (checkbox, radio, option)
Locator ưu tiên id → name → CSS → XPath; ổn định, duy nhất, dễ đọc; tránh XPath tuyệt đối và class tự sinh
CSS vs XPath CSS ngắn, nhanh, không chọn theo text/không đi lên cha; XPath mạnh hơn (text, axes parent/following-sibling/ancestor)
Tìm trong một element parent.findElement(...); XPath bắt đầu .// (không //)
Dropdown Select chỉ cho thẻ <select>; dropdown tự vẽ → click mở rồi click option
Alert switchTo().alert() → accept/dismiss/sendKeys/getText
iframe switchTo().frame(...) → parentFrame() / defaultContent()
Window/tab getWindowHandles(); lưu handle gốc; switchTo().window(handle)
Actions moveToElement, dragAndDrop, doubleClick…; phải .perform()
JavascriptExecutor Cuộn, lấy giá trị; dùng khi cần; không thay thế thao tác thật
Screenshot TakesScreenshot trước quit() (thường trong @AfterMethod/Listener)
Timeouts implicit · pageLoadTimeout · script timeout; pageLoadTimeout không phải wait theo điều kiện

2. Exceptions (đọc dòng đầu stacktrace)

Exception Nguyên nhân Hướng xử lý
NoSuchElementException Chưa có trong DOM / locator sai / sai frame Wait presence/visibility; kiểm tra locator & iframe
StaleElementReferenceException Handle cũ, DOM đã bị thay Tìm lại element; lưu By; stalenessOf/wait lại
ElementClickInterceptedException Có phần tử khác che (overlay, spinner, modal) Chờ che biến mất (invisibilityOf…) rồi elementToBeClickable
ElementNotInteractableException Ẩn/bị khoá/ngoài vùng Chờ visible/enabled; cuộn tới
TimeoutException Điều kiện của Wait không đạt kịp Đọc message mô tả điều kiện; xem locator/điều kiện
NoAlertPresentException Chưa có alert alertIsPresent
UnexpectedTagNameException Dùng Select trên thẻ không phải <select> Xử lý như dropdown tự vẽ

AssertionError (assert sai) ≠ exception của Selenium (script/page có vấn đề).

3. Wait

Implicit Explicit (WebDriverWait) Fluent
Phạm vi Toàn session, chỉ cho findElement(s) Một điều kiện, tại chỗ gọi Như Explicit + tuỳ biến polling/ignore/message
Điều kiện Chỉ "có trong DOM" Visible, clickable, text, URL, stale… Bất kỳ (lambda)
  • until() trả ngay khi đúng; timeout là giới hạn trên. Mặc định WebDriverWait: polling 500 ms, bỏ qua NotFoundException.
  • Presence (có trong DOM) ≠ Visibility (hiển thị) ≠ Clickability (hiển thị + enabled).
  • Không trộn Implicit + Explicit; findElements rỗng với implicit vẫn chờ hết giờ.
  • Thread.sleep: chờ cố định → chậm hoặc flaky; tránh.
  • Thông báo cũ còn hiển thị → chờ nội dung mới (textToBe), không chỉ visibility.
  • Spinner che nút → chờ invisibilityOfElementLocated rồi elementToBeClickable.
  • Flaky: lặp lại → đọc lỗi → điều kiện chờ đặc trưng trạng thái mới; không chỉ tăng timeout hay thêm retry.

4. Java (bản chất)

Chủ đề Ý chính
JDK/JRE/JVM JDK ⊃ JRE ⊃ JVM; JVM chạy bytecode
== vs equals Tham chiếu vs nội dung; chuỗi dùng equals
String Bất biến; StringBuilder nhanh, không an toàn luồng; StringBuffer đồng bộ
Overload vs override Cùng tên khác tham số (compile-time) vs lớp con ghi đè (runtime)
4 trụ cột OOP Đóng gói, kế thừa, đa hình, trừu tượng — luôn kèm ví dụ (WebDriver driver = new ChromeDriver(), extends BaseTest)
Interface vs abstract class Nhiều interface, một lớp cha; abstract có constructor/state; interface có default/static (Java 8)
final/finally/finalize Hằng/không ghi đè/không kế thừa · khối luôn chạy · hook GC (đã lỗi thời)
Checked vs unchecked Bắt buộc xử lý vs không; Selenium exception là unchecked
ArrayList vs LinkedList Mảng động (truy cập nhanh) vs danh sách liên kết (chèn/xoá tại vị trí)
HashMap hashCode → bucket, equals tìm key; hợp đồng equals/hashCode
List/Set/Map Có thứ tự & trùng / không trùng / cặp key-value
Wrapper Integer cache −128..127 → dùng equals
Pass-by-value Luôn tham trị; với object là bản sao tham chiếu
static Thuộc lớp; không dùng this; static WebDriver nguy hiểm khi song song
Lambda Cài functional interface; wait.until(d -> …)
ThreadLocal Mỗi luồng một bản (driver khi chạy song song), nhớ remove()

5. TestNG & POM

  • Thứ tự annotation: @BeforeSuite → @BeforeTest → @BeforeClass → @BeforeMethod → @Test → @AfterMethod → @AfterClass → @AfterTest → @AfterSuite.
  • testng.xml: <suite> ⊃ <test> ⊃ <class>; groups, parameter, parallel, thread-count.
  • @DataProvider trả Object[][] cho test nhiều bộ dữ liệu; hard assert dừng ngay, soft assert gom lỗi (assertAll).
  • TestNG assertEquals(actual, expected) — thứ tự ngược JUnit (expected, actual).
  • POM: locator private By trong Page; method nghiệp vụ (loginAs); Page không chứa assertion; trả về Page kế tiếp; lưu By không lưu WebElement; test độc lập.
  • BaseTest quản lý vòng đời driver; BasePage chứa wait/click/type dùng chung; DriverFactory tạo driver theo cấu hình; Config đọc config.properties và cho ghi đè bằng -D….

6. Maven & Wrapper

  • Lifecycle mặc định: validate → compile → test → package → verify → install → deploy; clean là lifecycle riêng.
  • Dự án chỉ có src/test/java ⇒ compile báo Nothing to compile; phải test-compile/test.
  • Scope test: thư viện chỉ có khi biên dịch/chạy test.
  • Wrapper: mvnw, mvnw.cmd, .mvn/wrapper/maven-wrapper.properties — commit cả ba; khoá phiên bản Maven; chạy không cần cài Maven (vẫn cần JDK); mvnw cần mode thực thi trên Linux/macOS (git update-index --chmod=+x).
  • Chạy test: .\mvnw.cmd clean test · một class -Dtest=Class · một method -Dtest=Class#method.
  • Bẫy: Tests run: 0 nhưng BUILD SUCCESS (gõ sai -Dtest, sai import @Test) — luôn đọc dòng Tests run.
  • Xung đột phiên bản: dependency:tree; NoSuchMethodError thường do xung đột.

7. Git

  • fetch tải về không gộp; pull = fetch + merge (hoặc rebase).
  • merge giữ lịch sử phân nhánh; rebase làm lịch sử thẳng (không rebase nhánh đã chia sẻ).
  • Không commit: target/, test-output/, .mvn/repository/, IDE files, mật khẩu thật. Commit: src/, pom.xml, mvnw*, .mvn/wrapper, testng.xml, .gitignore.
  • Conflict: mở file → chọn nội dung đúng → xoá dấu <<<<<<</=======/>>>>>>> → build kiểm chứng → git add → commit.
  • PR: mục đích, thay đổi, cách kiểm chứng; review test: không sleep, không XPath tuyệt đối, assertion có message.

8. Tư duy automation (nói được trong 1 câu)

Câu hỏi Một câu trả lời
Tự động hoá cái gì? Lặp lại, ổn định, giá trị cao, kết quả rõ ràng; không phải kiểm tra một lần/chủ quan
Test pyramid Nhiều unit/API, ít UI end-to-end
Vì sao flaky? Đồng bộ, locator, dữ liệu, thứ tự, môi trường
Retry? Biện pháp tạm, che nguyên nhân gốc
UI vs API Logic ở API, UI cho luồng người dùng; dùng API để chuẩn bị dữ liệu
Selenium vs Playwright Selenium: giao thức W3C, đa ngôn ngữ, hệ sinh thái lớn, tự chờ bằng explicit wait; Playwright: auto-wait, browser context, trace (kiểm chứng lại khi phỏng vấn)

9. 10 câu phải nói trôi chảy bằng tiếng Anh

  1. Tell me about yourself (30 s).
  2. Walk me through your project.
  3. Why explicit waits and not implicit waits?
  4. A test is flaky. How do you diagnose it?
  5. StaleElementReferenceException — cause and fix.
  6. What is the Page Object Model and why use it?
  7. What is Maven Wrapper and what do you commit?
  8. == vs equals().
  9. Why WebDriver driver = new ChromeDriver()?
  10. How do you decide what to automate?
