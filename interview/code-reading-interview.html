Code Reading — Interview (đọc code, tìm lỗi, nói output)

Dạng câu hỏi "Look at this code — what happens / what is wrong?" rất phổ biến ở vòng kỹ thuật. Không cần chạy máy: đọc đoạn code, trả lời thành tiếng bằng tiếng Anh, rồi đối chiếu. Quay lại: Interview README Cấu trúc: Code → Câu hỏi → Đáp án (EN) → Giải thích (VI). CR1–CR4 là Java, CR5–CR14 là Selenium/TestNG.

CR1. What does this print?

java
String a = "qa";
String b = "qa";
String c = new String("qa");
System.out.println(a == b);
System.out.println(a == c);
System.out.println(a.equals(c));

Answer: true, false, true. a and b are the same literal from the string pool, so == is true. c is a new object, so == is false, but the content is equal. Giải thích: == so tham chiếu, equals so nội dung. Xem Java Q12.

CR2. What does this print?

java
Integer x = 127, y = 127;
Integer p = 128, q = 128;
System.out.println(x == y);
System.out.println(p == q);
System.out.println(p.equals(q));

Answer: true, false, true. Integer values from -128 to 127 come from a cache, so == is true; 128 creates different objects, so == is false. Use equals(). Giải thích: Bẫy autoboxing. Xem Java Q21.

CR3. What is wrong here?

java
List<String> names = new ArrayList<>(List.of("a", "b", "c"));
for (String n : names) {
    if (n.equals("a")) names.remove(n);
}

Answer: It throws ConcurrentModificationException because the list is modified while the for-each iterator is running. Fix: use an Iterator and it.remove(), or names.removeIf(n -> n.equals("a")). Giải thích: Có trường hợp đặc biệt (xoá phần tử kế cuối) lại không ném lỗi — đừng dựa vào đó. Cũng chú ý List.of(...) bất biến nên phải bọc new ArrayList<>(...).

CR4. What does this print?

java
static int f() {
    try {
        return 1;
    } finally {
        System.out.println("cleanup");
    }
}
System.out.println(f());

Answer: cleanup then 1. The finally block runs before the method returns. If finally contained return 2, the method would return 2, which is why returning from finally is bad practice. Giải thích: Xem Java Q16, Q26.

CR5. The test fails intermittently. Why, and how do you fix it?

java
driver.findElement(By.cssSelector("#start button")).click();
String text = driver.findElement(By.id("finish")).getText();
Assert.assertEquals(text, "Hello World!");

Answer: The code reads the result immediately after the click, but the page loads it asynchronously. If the element is not in the DOM yet we get NoSuchElementException; if it exists but is hidden, getText() returns an empty string. Fix: wait for the specific condition, wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("finish"))), then read the text. Giải thích: Nguyên nhân flaky số 1: thiếu đồng bộ. Ca /dynamic_loading/1 (ẩn sẵn) và /2 (thêm vào DOM sau) cho hai triệu chứng khác nhau — xem Lab 03.

CR6. What exception occurs, and why?

java
List<WebElement> rows = driver.findElements(By.cssSelector("#table1 tbody tr"));
driver.navigate().refresh();
System.out.println(rows.get(0).getText());

Answer: StaleElementReferenceException. The WebElement handles refer to elements of the old page; after the refresh the DOM was rebuilt, so the references are invalid. Fix: find the elements again after the refresh, or store the By locator instead of the element, and wait for the page state you need. Giải thích: Stale = handle cũ trỏ vào DOM đã bị thay. Xem Selenium Exceptions.

CR7. The hover does nothing. Why?

java
Actions actions = new Actions(driver);
actions.moveToElement(figure);
String caption = figure.findElement(By.tagName("h5")).getText();

Answer: The action is only built, never executed: .perform() is missing. Also the caption becomes visible only after the hover, so I need actions.moveToElement(figure).perform(); followed by a wait for the caption to be visible. Giải thích: Quên .perform() là lỗi kinh điển; ca này khớp Exercise 5.

CR8. How long does this take, and what is the problem?

java
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));
List<WebElement> items = driver.findElements(By.className("does-not-exist"));
System.out.println(items.size());

Answer: It returns an empty list only after waiting the full 10 seconds, because the implicit wait applies to every find call. Mixing implicit and explicit waits makes total waiting time unpredictable, so I use only explicit waits. Giải thích: Đã đo thật trong tài liệu: 17 ms (không implicit) so với 3050 ms (implicit 3 s) — Implicit Wait.

CR9. Tests fail randomly when run in parallel. Why?

java
public class BaseTest {
    protected static WebDriver driver;

    @BeforeMethod
    public void setup() { driver = new ChromeDriver(); }

    @AfterMethod
    public void tearDown() { driver.quit(); }
}

Answer: driver is static, shared by all threads. One thread overwrites or quits the driver another thread is using. Fix: give each thread its own driver with ThreadLocal<WebDriver> and call remove() after the test, and make sure tests are independent. Giải thích: Xem Java Q30, TestNG parallel.

CR10. The build says BUILD SUCCESS but nothing ran. Why?

java
import org.junit.Test;          // <- note the import

public class LoginTest extends BaseTest {
    @Test
    public void shouldLogin() { /* ... */ }
}

Answer: The project uses TestNG, but the annotation comes from JUnit, so TestNG does not recognize the method as a test. Maven can finish with Tests run: 0 and still report BUILD SUCCESS. Fix: import org.testng.annotations.Test; and always read the Tests run line. (If JUnit is not on the classpath it may instead fail to compile.) Giải thích: Bẫy đã tái hiện trong dự án: -Dtest=NoSuchTest ⇒ Tests run: 0 nhưng thành công — Maven interview Q17.

CR11. This Page Object crashes on creation. Why?

java
public class LoginPage {
    private WebDriver driver;
    private WebElement username = driver.findElement(By.id("username"));

    public LoginPage(WebDriver driver) {
        this.driver = driver;
    }
}

Answer: Field initializers run before the constructor body, so driver is still null and NullPointerException occurs. Even if it worked, storing a WebElement at construction risks stale or missing elements. Fix: store the locator, private final By username = By.id("username");, and look the element up inside the page methods. Giải thích: Đúng quy tắc POM: lưu By, không lưu WebElement — POM.

CR12. What exception does this throw?

java
Select select = new Select(driver.findElement(By.id("custom-dropdown")));   // a <div>
select.selectByVisibleText("Option 2");

Answer: UnexpectedTagNameException — the Select class only works with a real <select> element. For a custom dropdown built from div/ul, click it to open and then click the desired option element. Giải thích: Dropdown "giả" rất phổ biến trên web thật.

CR13. Why is this a bad practice?

java
button.click();
try {
    Thread.sleep(5000);
} catch (InterruptedException e) {
    e.printStackTrace();
}
Assert.assertTrue(result.isDisplayed());

Answer: A fixed sleep always costs the full 5 seconds when the page is faster and is still not enough when it is slower, so the test is both slow and flaky. Replace it with an explicit wait for the condition, such as wait.until(ExpectedConditions.visibilityOf(result)). catch with only printStackTrace() also hides the interruption. Giải thích: Xem Wait: so sánh và Thread.sleep.

CR14. The failure message looks backwards. Why?

java
String expected = "You logged into a secure area!";
String actual = driver.findElement(By.id("flash")).getText();
Assert.assertEquals(expected, actual, "Wrong message");

Answer: TestNG's signature is assertEquals(actual, expected, message), the reverse of JUnit's (expected, actual). With the arguments swapped, the report prints the expected value as "actual" and misleads whoever reads it. The test still passes or fails correctly, but the message is confusing. Giải thích: Lỗi nhỏ nhưng người review hay bắt; chú ý khi chuyển giữa JUnit và TestNG.
