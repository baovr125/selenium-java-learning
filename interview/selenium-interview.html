Selenium (Fundamentals, Locators, Exceptions) — Interview

Song ngữ Anh–Việt. Cấu trúc mỗi câu: Câu hỏi → Dịch → Câu trả lời mẫu → Giải thích → Ví dụ thực tế → Câu hỏi đào sâu. Quay lại: Interview README

Phần 1 — Selenium Fundamentals

Q1. What is Selenium and what does it consist of?

Dịch: Selenium là gì, gồm những thành phần nào?

Sample answer: Selenium is an open-source suite for automating web browsers. Its main parts are Selenium WebDriver, which is the API to control browsers, Selenium Grid for running tests in parallel on many machines, and Selenium IDE for record and playback. I mostly use WebDriver with Java.

Giải thích: Nêu 3 thành phần; bổ sung Selenium Manager tự tải driver (từ 4.6). Selenium chỉ cho web, không phải mobile native.

Ví dụ: Dự án dùng selenium-java 4.52.0, chỉ WebDriver (không Grid/IDE).

Đào sâu: Can Selenium test desktop or mobile native apps? → Không (Appium cho mobile).

Q2. Explain the Selenium WebDriver architecture.

Dịch: Giải thích kiến trúc Selenium WebDriver.

Sample answer: The test code uses the Selenium client library, which sends commands as HTTP requests in JSON, following the W3C WebDriver protocol, to a browser driver such as chromedriver. The driver translates them into browser actions and returns the results the same way.

Giải thích: Chuỗi: Test (Java) → HTTP/JSON (W3C) → Browser Driver → Browser. Hệ quả: mỗi lệnh là một request; WebElement là handle chứ không phải bản sao DOM.

Ví dụ: driver.findElement(By.id("flash")) ⇒ POST /session/{id}/element.

Đào sâu: Why can a WebElement become stale? → handle trỏ phần tử đã bị thay trong DOM.

Q3. What is the difference between WebDriver, a browser driver and the browser?

Dịch: Khác nhau giữa WebDriver, browser driver và browser?

Sample answer: WebDriver is the API in my code. The browser driver, for example chromedriver, is an executable by the browser vendor that receives WebDriver commands. The browser, for example Chrome, is what actually renders pages and performs the actions.

Giải thích: Ba lớp riêng biệt, driver phải khớp phiên bản browser.

Ví dụ: Dự án không tải chromedriver thủ công; Selenium Manager làm điều đó.

Đào sâu: What if Chrome updates and the driver is old? → SessionNotCreatedException.

Q4. How does Selenium Manager work?

Dịch: Selenium Manager hoạt động thế nào?

Sample answer: Since Selenium 4.6, when I create new ChromeDriver(), Selenium Manager detects the installed Chrome version, downloads the matching driver and caches it, so I do not need WebDriverManager or manual downloads. It needs internet the first time.

Giải thích: Có trong selenium-manager-4.52.0.jar (dependency tree). Lỗi liên quan: NoSuchDriverException, SessionNotCreatedException.

Ví dụ: README dự án: "ChromeDriver được Selenium tự tải về".

Đào sâu: Do you still need WebDriverManager? → Không bắt buộc với Selenium ≥ 4.6.

Q5. What is the difference between close() and quit()?

Dịch: close() khác quit()?

Sample answer: close() closes only the current window or tab. quit() closes all windows of the session and ends the driver process. I use quit() in teardown; close() when I close a secondary tab and then switch back to the main window.

Giải thích: close() cuối cùng có thể để sót process driver ⇒ rò rỉ tài nguyên.

Ví dụ: BaseTest.tearDown() dùng quit() có kiểm tra driver != null.

Đào sâu: What happens if you call a command after close() of the only window? → NoSuchWindowException/session lỗi.

Q6. What is the difference between get() and navigate().to()?

Dịch: get() khác navigate().to()?

Sample answer: Functionally they are very similar: both load a URL and wait for page load. navigate() belongs to the Navigation interface, which also provides back(), forward() and refresh(), and to() accepts a URL object too.

Giải thích: Quy ước: get() mở lần đầu; navigate() cho lịch sử duyệt.

Ví dụ: Mọi Exercise dùng driver.get(URL).

Đào sâu: What happens to previously found elements after refresh()? → stale.

Q7. How do you handle browser options such as headless mode?

Dịch: Cấu hình trình duyệt (headless) thế nào?

Sample answer: I use ChromeOptions, for example options.addArguments("--headless=new", "--window-size=1920,1080"), and pass them to new ChromeDriver(options). I read values from configuration so the same code runs locally and in CI.

Giải thích: Headless cần đặt window-size vì maximize() không đáng tin.

Ví dụ: Dự án hiện dùng mặc định + maximize(); đây là điểm cải thiện cho CI.

Đào sâu: What is the page load strategy? → NORMAL/EAGER/NONE.

Q8. What are the different timeouts in Selenium?

Dịch: Selenium có những loại timeout nào?

Sample answer: Page load timeout for get(), implicit wait for element lookup, and script timeout for async JavaScript. Explicit waits are separate: they are controlled in the test code by WebDriverWait.

Giải thích: Đừng lẫn WebDriverWait với timeouts của manage().timeouts().

Ví dụ: BaseTest: pageLoadTimeout(30s) + WebDriverWait(15s); không implicit.

Đào sâu: What happens when page load timeout is exceeded? → TimeoutException.

Q9. How do you take a screenshot when a test fails?

Dịch: Chụp ảnh khi test fail thế nào?

Sample answer: Cast the driver to TakesScreenshot and call getScreenshotAs(OutputType.FILE), then copy the file to a folder like target/screenshots. I do this in a TestNG listener or in @AfterMethod using ITestResult, before calling quit().

Giải thích: Phải chụp trước quit().

Ví dụ: Gợi ý cải tiến cho BaseTest của dự án (selenium/10).

Đào sâu: Why target/? → không bị commit.

Q10. What are the limitations of Selenium?

Dịch: Giới hạn của Selenium?

Sample answer: It only automates web browsers, has no built-in reporting or test runner, can be slow compared with API tests, and UI tests can be flaky if synchronization is poor. It cannot natively handle things like OS dialogs or CAPTCHA. I combine it with TestNG or JUnit, and prefer API tests for logic that does not need the UI.

Giải thích: Thể hiện hiểu kim tự tháp kiểm thử: UI test ít, chậm; API/unit nhiều, nhanh.

Ví dụ: Suite 10 test của dự án mất ~91 giây vì mỗi test mở Chrome mới.

Đào sâu: How would you reduce the run time? → song song (ThreadLocal), setup qua API/cookie, @BeforeClass.

Phần 2 — Locators và WebElement

Q1. What locator strategies does Selenium support?

Dịch: Selenium hỗ trợ những locator nào?

Sample answer: Eight: ID, Name, ClassName, TagName, LinkText, PartialLinkText, CSS Selector and XPath. In Selenium 4 there are also relative locators like above and near.

Giải thích: Nêu đủ 8 + relative locators.

Ví dụ: Ex1 dùng id, name, className, xpath; Ex2/5/8 dùng cssSelector.

Đào sâu: Which is the fastest? → ID, nhưng chênh lệch thực tế nhỏ.

Q2. How do you choose a stable locator?

Dịch: Chọn locator ổn định thế nào?

Sample answer: I prefer a unique, meaningful ID or a dedicated test attribute like data-testid, then name, then a short CSS selector, then XPath on stable attributes or text. I avoid absolute XPath, deep nth-child and auto-generated class names, and I verify uniqueness in DevTools.

Giải thích: Ngắn, có nghĩa, không phụ thuộc cấu trúc. Thoả thuận với dev thêm data-testid.

Ví dụ: Nút Login không có id/name nên Ex1 dùng //button[@type='submit'] thay vì class radius chỉ mang tính giao diện.

Đào sâu: What if the ID is dynamic? → [id^='prefix'] hoặc thuộc tính khác.

Q3. CSS Selector vs XPath?

Dịch: CSS khác XPath?

Sample answer: CSS is shorter, readable and usually a bit faster, but it cannot select by text or go up to a parent. XPath is more powerful: it can use text, parent/ancestor and sibling axes, and positions, but it is longer and more fragile. I prefer CSS when it is enough.

Giải thích: Bảng so sánh ở selenium/02.

Ví dụ: Ex6 dùng XPath theo text //button[text()='Add Element']; Ex3 dùng XPath vị trí tr[last()-1].

Đào sâu: Write XPath for the last row of a table. → //table[@id='table1']/tbody/tr[last()].

Q4. What is the difference between findElement and findElements?

Dịch: findElement khác findElements?

Sample answer: findElement returns the first matching element and throws NoSuchElementException if none. findElements returns a list and returns an empty list if nothing matches. I use findElements(...).isEmpty() to check existence safely.

Giải thích: Với Implicit Wait, findElements rỗng vẫn chờ hết giờ.

Ví dụ: Ex2 findElements lấy 2 checkbox; Ex6 kiểm tra danh sách rỗng sau khi xoá.

Đào sâu: Which element does findElement return when many match? → phần tử đầu tiên theo thứ tự tài liệu.

Q5. What is a StaleElementReferenceException and how do you handle it?

Dịch: StaleElementReferenceException là gì, xử lý sao?

Sample answer: It happens when a stored WebElement is no longer attached to the DOM because the page refreshed or was re-rendered. I handle it by finding the element again, storing the By locator instead of the element, waiting with stalenessOf before reading new data, or a limited retry.

Giải thích: WebElement là handle chứ không phải bản sao.

Ví dụ: Ex4 lấy trước text/value dạng chuỗi để không phụ thuộc phần tử khi duyệt.

Đào sâu: Does PageFactory help? → proxy tìm lại mỗi lần gọi, nhưng khó debug.

Q6. How do you locate an element inside another element?

Dịch: Tìm phần tử bên trong phần tử khác?

Sample answer: I call findElement on the parent WebElement, which limits the search to its descendants. With XPath I must start with .// because // starts from the document root.

Giải thích: Lỗi kinh điển: //td trong row.findElement.

Ví dụ: Ex3 row.findElements(By.tagName("td")); Ex8 modalElement.findElement(By.cssSelector(".modal-title h3")).

Đào sâu: Why scope the search? → nhanh hơn, ít khớp nhầm.

Q7. What is the difference between getText() and getAttribute("value")?

Dịch: getText() khác getAttribute("value")?

Sample answer: getText() returns the visible text of an element and returns an empty string if it is hidden. An input field has no inner text, so I use getAttribute("value") or getDomProperty("value") for its content.

Giải thích: getDomAttribute = attribute trong HTML; getDomProperty = property hiện tại.

Ví dụ: Ex10: textInput.getAttribute("value") so với chuỗi đã gõ.

Đào sâu: How to get hidden text? → getAttribute("textContent").

Q8. What do isDisplayed(), isEnabled() and isSelected() return?

Dịch: Ba method này trả gì?

Sample answer: isDisplayed tells whether the element is visible. isEnabled is false for disabled controls. isSelected tells the state of checkboxes, radio buttons and options. They are instant checks, so for asynchronous changes I wait first and then assert.

Giải thích: Không dùng để "chờ".

Ví dụ: Ex2 isSelected, Ex10 isEnabled trước/sau, Ex4 lọc option disabled.

Đào sâu: How do you assert an element does not exist?

Q9. How do you handle a dropdown?

Dịch: Xử lý dropdown?

Sample answer: For a native <select>, I wrap it with the Select class and use selectByVisibleText, selectByValue or selectByIndex, and getFirstSelectedOption to verify. For custom dropdowns made of divs, I click to open, wait for the list and click the item.

Giải thích: Select chỉ cho <select>; ưu tiên visible text/value hơn index.

Ví dụ: Ex4 duyệt getOptions(), lọc isEnabled(), chọn từng mục.

Đào sâu: What happens if you pass a div to Select? → UnexpectedTagNameException.

Q10. How do you interact with elements that are hidden until hover?

Dịch: Phần tử chỉ hiện khi hover?

Sample answer: I use Actions.moveToElement(element).perform(), then wait for visibility of the revealed element before reading it. Forgetting perform() does nothing.

Giải thích: Actions là builder; perform() mới chạy.

Ví dụ: Ex5 hover từng ảnh rồi wait.until(visibilityOf(captionHeader)).

Đào sâu: How do you do drag and drop and what can go wrong? → dragAndDrop; HTML5 DnD có thể flaky (Ex9) — dùng clickAndHold/moveToElement/release hoặc JS dự phòng.

Phần 3 — Exception Handling

Q1. Name common Selenium exceptions and their causes.

Dịch: Kể tên các exception thường gặp và nguyên nhân.

Sample answer: NoSuchElementException for a missing or not yet loaded element; TimeoutException when a wait expires; StaleElementReferenceException when the element was re-rendered; ElementNotInteractableException for hidden or disabled elements; ElementClickInterceptedException when another element covers the target; InvalidSelectorException for a bad locator; NoSuchWindowException/NoSuchFrameException; SessionNotCreatedException for driver or browser mismatch.

Giải thích: Học theo cặp exception ⇒ nguyên nhân ⇒ cách xử lý (selenium/09).

Ví dụ: Ex1 tránh NoSuchElementException bằng cách chờ flash message.

Đào sâu: Are they checked or unchecked? → unchecked.

Q2. How do you fix NoSuchElementException?

Dịch: Sửa NoSuchElementException thế nào?

Sample answer: I check the locator in DevTools, make sure the element is not inside an iframe or shadow DOM, and add an explicit wait for the element, for example visibility, instead of searching immediately.

Giải thích: Ba nguyên nhân chính: locator sai / chưa tải / ngữ cảnh khác (iframe).

Ví dụ: wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash"))).

Đào sâu: What if the element is in an iframe? → frameToBeAvailableAndSwitchToIt.

Q3. How do you handle StaleElementReferenceException?

Dịch: Xử lý StaleElementReferenceException?

Sample answer: Find the element again, keep the locator rather than the element, wait for stalenessOf the old element and then locate the new one, or use a limited retry for transient cases.

Giải thích: Retry phải có giới hạn và ném lại sau lượt cuối.

Ví dụ: Ex4 đọc trước text/value dạng chuỗi.

Đào sâu: Show a retry loop.

Q4. When do you get ElementClickInterceptedException, and how do you fix it?

Dịch: Khi nào gặp ElementClickInterceptedException?

Sample answer: When another element, like a modal, spinner or banner, receives the click instead. I wait for the overlay to become invisible, close the popup, or scroll the element into view; I avoid forcing the click with JavaScript because it bypasses what a real user can do.

Giải thích: Message nêu rõ phần tử che.

Ví dụ: Ex8 modal quảng cáo che trang cho tới khi đóng.

Đào sâu: Why avoid JS click?

Q5. TimeoutException vs NoSuchElementException?

Dịch: Khác nhau?

Sample answer: NoSuchElementException is thrown immediately by findElement. TimeoutException is thrown when an explicit wait expires; inside the wait, NoSuchElementException is ignored and retried.

Giải thích: Một cái "ngay lúc này", một cái "hết thời gian chờ".

Ví dụ: Sai id trong visibilityOfElementLocated ⇒ TimeoutException.

Đào sâu: What do you read in the message? → điều kiện đang chờ + locator.

Q6. Is it good to catch Exception and continue?

Dịch: Có nên catch (Exception) rồi chạy tiếp?

Sample answer: No, usually. It hides failures and tests may pass falsely. I catch specific exceptions only for a clear purpose and either retry, log or rethrow.

Giải thích: Test fail đúng chỗ giúp debug.

Ví dụ: Dự án gần như không có catch; chỉ try/finally.

Đào sâu: Example of a legitimate catch? → banner cookie tuỳ chọn: catch (TimeoutException ignored).

Q7. How do you check that an element exists without exceptions?

Dịch: Kiểm tra tồn tại không dùng exception?

Sample answer: !driver.findElements(by).isEmpty(). It returns an empty list instead of throwing.

Giải thích: Nhưng nếu có Implicit Wait, vẫn chờ hết giờ.

Ví dụ: Ex6 xác nhận danh sách nút Delete rỗng.

Đào sâu: What if the element is added asynchronously? → chờ trước.

Q8. What is the difference between an assertion failure and a Selenium exception?

Dịch: AssertionError khác exception Selenium?

Sample answer: An AssertionError means the actual result differs from the expected one; the test ran to the end of that step. A Selenium exception means the test could not continue, for example the element was not found or not clickable. They need different investigation: application behavior versus locator, synchronization or environment.

Giải thích: Phân loại giúp tìm nguyên nhân nhanh.

Ví dụ: Ex3 sai dữ liệu bảng ⇒ AssertionError; sai XPath ⇒ NoSuchElementException.

Đào sâu: How is each shown in Surefire? → Failures vs Errors.

Q9. How do you make sure the browser closes even when a test fails?

Dịch: Đảm bảo đóng browser khi test fail?

Sample answer: In TestNG I use @AfterMethod which runs even after failures, with a null check before quit(). In a plain main I use try/finally.

Giải thích: alwaysRun = true giúp khi có phụ thuộc/nhóm.

Ví dụ: BaseTest.tearDown() và main() trong Exercise.

Đào sâu: What if setup() fails? → driver null ⇒ cần kiểm tra null.

Q10. How do you debug an unexpected exception?

Dịch: Debug exception bất ngờ?

Sample answer: I read the exception name and message, find the first line in my own code in the stack trace, reproduce it by running the single test, check the locator in DevTools, capture a screenshot and page source, and look at timing issues. Then I fix the root cause.

Giải thích: Quy trình có thứ tự.

Ví dụ: .\mvnw.cmd test "-Dtest=Exercise07_InfiniteScrollTest".

Đào sâu: How do you capture evidence automatically? → listener + TakesScreenshot.
