Git và Team Workflow — Interview

Song ngữ Anh–Việt. Cấu trúc mỗi câu: Câu hỏi → Dịch → Câu trả lời mẫu → Giải thích → Ví dụ thực tế → Câu hỏi đào sâu. Quay lại: Interview README

Q1. What is the difference between Git and GitHub?

Dịch: Git khác GitHub?

Sample answer: Git is a distributed version control system that runs locally. GitHub is a hosting platform for Git repositories with collaboration features such as pull requests, issues and CI.

Giải thích: Git = công cụ; GitHub/GitLab/Bitbucket = dịch vụ.

Ví dụ: Clone dự án từ GitHub rồi chạy .\mvnw.cmd clean test.

Đào sâu: What is a remote?

Q2. Explain the basic Git workflow.

Dịch: Quy trình Git cơ bản?

Sample answer: git clone, create a branch with git checkout -b feature/x, make changes, git status, git add <files>, git commit -m "...", git push -u origin feature/x, open a pull request, review, merge, then git pull on main.

Giải thích: Tránh commit thẳng vào main.

Ví dụ: Nhánh feature/add-logging chỉ sửa pom.xml.

Đào sâu: What does git pull do? → fetch + merge.

Q3. What should and should not be committed in a Selenium Maven project?

Dịch: Nên/không nên commit gì?

Sample answer: Commit source code, pom.xml, testng.xml, mvnw, mvnw.cmd, .mvn/wrapper/ and shared config, and .gitignore. Do not commit target/, test-output/, the local Maven repository, IDE files or secrets.

Giải thích: Đã có trong .gitignore của dự án.

Ví dụ: .gitignore: target/, test-output/, .mvn/repository/, .idea/, *.iml...

Đào sâu: What if someone committed target/ by mistake? → git rm -r --cached target.

Q4. What is .gitignore and how do you check it works?

Dịch: .gitignore là gì, kiểm tra thế nào?

Sample answer: It lists patterns of files Git should not track. I check with git status and git check-ignore -v <path> which prints the rule that matches.

Giải thích: .gitignore chỉ tác dụng với file chưa được track.

Ví dụ: git check-ignore -v .mvn/repository.

Đào sâu: Why is the file still tracked after adding to .gitignore? → git rm --cached.

Q5. How do you resolve a merge conflict in pom.xml?

Dịch: Giải quyết conflict ở pom.xml?

Sample answer: I open the conflicted file, read both sides between the markers, keep the valid changes from both, for example both new dependencies, remove the markers, run mvnw dependency:tree and mvnw clean test, and then commit the merge.

Giải thích: Kiểm chứng bằng build, không chỉ "hết dấu <<<<".

Ví dụ: Hai người cùng thêm dependency: giữ cả hai nếu hợp lệ.

Đào sâu: What if both changed the same version property? → thống nhất với nhóm.

Q6. What is a pull request and what do you check when reviewing test code?

Dịch: Pull request; review code test cần kiểm tra gì?

Sample answer: A PR proposes merging a branch and enables review and CI. In review I check assertions are meaningful, waits are condition-based without sleep, locators are stable, tests are independent, no hard-coded secrets, clean test is green with the right number of tests, and nothing generated is committed.

Giải thích: Checklist ở framework-design/05.

Ví dụ: PR thêm dependency cần kèm dependency:tree và kết quả test.

Đào sâu: What if CI fails but local passes?

Q7. Why should mvnw be executable in Git, and how do you set it?

Dịch: Vì sao mvnw cần quyền thực thi, đặt thế nào?

Sample answer: On Linux and macOS, ./mvnw needs the executable bit. Git stores it as mode 100755. On Windows I can check with git ls-files --stage mvnw and set it with git update-index --chmod=+x mvnw.

Giải thích: Lỗi Permission denied. Bổ sung .gitattributes để LF.

Ví dụ: CI Linux fail Permission denied: ./mvnw.

Đào sâu: Line endings? → LF cho mvnw.

Q8. How do you keep the team on the same Maven and library versions?

Dịch: Giữ cả nhóm cùng phiên bản?

Sample answer: Commit the Maven Wrapper so Maven is pinned, pin library and plugin versions in pom.xml properties, and avoid version ranges and SNAPSHOT for external libraries. The wrapper does not pin the JDK or Chrome, so the README states the required JDK, and CI uses a fixed JDK.

Giải thích: Wrapper khoá Maven, không khoá JDK/Chrome.

Ví dụ: selenium.version=4.52.0, testng.version=7.10.2, Maven 3.9.16.

Đào sâu: How to enforce JDK version? → Maven Enforcer plugin (tuỳ chọn).

Q9. A teammate cannot build after you pushed. How do you help?

Dịch: Đồng đội build lỗi sau khi bạn push?

Sample answer: Ask for the exact command, the first error and mvnw -version. Ask them to git pull, run mvnw clean test, and compare JDK and network. I try to reproduce it in a fresh clone. If a file was missing from the commit I add it.

Giải thích: Thu thập thông tin trước khi đoán.

Ví dụ: Quên commit mvnw.cmd hoặc .mvn/wrapper.

Đào sâu: How would you prevent it? → CI trên máy sạch.

Q10. What are good commit messages?

Dịch: Commit message tốt?

Sample answer: Short, imperative, explaining what and why, for example "Add explicit wait for modal in entry ad test". One logical change per commit.

Giải thích: Giúp review và git blame.

Ví dụ: "Update Maven configuration" là quá chung chung; nên nói rõ cấu hình nào.

Đào sâu: Conventional commits?
