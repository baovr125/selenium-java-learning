Scenario-based — Interview

Song ngữ Anh–Việt. Cấu trúc mỗi câu: Câu hỏi → Dịch → Câu trả lời mẫu → Giải thích → Ví dụ thực tế → Câu hỏi đào sâu. Quay lại: Interview README

S1. A test fails randomly: the element is sometimes not found. What do you do?

Dịch: Test lúc fail lúc pass vì không thấy phần tử.

Sample answer: I suspect synchronization. I rerun it several times, read the exception, check the locator in DevTools and see whether the element appears after an AJAX call or animation. I replace any sleeps with an explicit wait for a condition specific to the new state, for example visibility or exact text, then run it repeatedly. I do not just increase the timeout.

Giải thích: Quy trình có hệ thống; tăng timeout là phương án vá.

Ví dụ: Ex10: thông báo cũ vẫn hiện nên phải textToBe thay vì visibility.

Follow-up: What if the locator itself is unstable?

S2. The page has a spinner that blocks clicks. How do you handle it?

Dịch: Spinner chặn click.

Sample answer: Wait for the spinner to be invisible with invisibilityOfElementLocated, then wait for the button to be clickable, then click. If the spinner might not appear immediately, wait for it to appear first so I don't pass too early.

Giải thích: elementToBeClickable không biết có overlay.

Ví dụ: Ex8: modal phải đóng hoàn toàn (invisibilityOfElementLocated) trước khi thao tác tiếp.

Follow-up: What exception do you see otherwise? → ElementClickInterceptedException.

S3. You must verify a message that changes after an AJAX call, but an old message is still visible.

Dịch: Thông báo cũ vẫn hiện khi chờ thông báo mới.

Sample answer: Waiting for visibility passes immediately because the old text is visible. I wait for the exact new text with textToBe or textToBePresentInElement, or wait for the old element to become stale and then read the new one.

Giải thích: Điều kiện chờ phải đặc trưng cho trạng thái mới.

Ví dụ: Exercise10_DynamicControlsTest — wait.until(ExpectedConditions.textToBe(messageLocator, "It's enabled!")).

Follow-up: How do you wait for attribute change? → attributeToBe.

S4. Infinite scroll does not load new content in your test.

Dịch: Infinite scroll không tải thêm.

Sample answer: The page loads content on scroll events and may ignore events during a load. A single scroll can be lost. I scroll inside the wait condition, repeating until the number of items increases, and I also dispatch a scroll event.

Giải thích: Custom wait với hành động lặp.

Ví dụ: Ex7 — wait.until(d -> { scrollToBottom(js); return d.findElements(...).size() > before; }); test từng fail (testng-failed.xml).

Follow-up: Why not Thread.sleep(5000)?

S5. A drag-and-drop works manually but not with Selenium.

Dịch: Kéo thả thủ công được nhưng Selenium không.

Sample answer: The page may use HTML5 drag and drop which does not respond to the default synthesized mouse events in some browser versions. I try clickAndHold, moveToElement, release with small offsets, and as a last resort a JavaScript implementation that dispatches the drag events, documenting the reason. I verify the result by content, not just "no error".

Giải thích: Thao tác dễ flaky; luôn kiểm chứng kết quả.

Ví dụ: Ex9 dragAndDrop(columnA, columnB) rồi kiểm tra header đổi chỗ.

Follow-up: Why avoid JS first? → bỏ qua hành vi người dùng thật.

S6. You clone a project and nothing runs: Tests run: 0, BUILD SUCCESS.

Dịch: Tests run: 0 mà build thành công.

Sample answer: I check how tests are selected: -Dtest pattern typo, class naming, testng.xml content, @Test imports (TestNG vs JUnit), and the Surefire configuration in pom.xml. I look for the Running <Class> lines. In CI I add a check that fails when zero tests ran.

Giải thích: Bẫy thật của dự án: -Dtest=NoSuchTest ⇒ SUCCESS.

Ví dụ: Đã tái hiện bằng .\mvnw.cmd test "-Dtest=NoSuchTest".

Follow-up: Does failIfNoSpecifiedTests help? → Đã thử: không, với cấu hình này.

S7. Tests pass locally but fail in CI.

Dịch: Local pass, CI fail.

Sample answer: I compare JDK version, browser version, headless mode, window size, locale/timezone and network speed. I read the CI logs and artifacts such as screenshots and surefire reports, reproduce in a clean clone, and review waits because CI machines are slower.

Giải thích: Wrapper khoá Maven, chưa đủ để giống hệt môi trường.

Ví dụ: Dự án chưa có headless/--window-size: cần thêm cho CI Linux.

Follow-up: How do you get screenshots from CI? → upload artifact.

S8. Login is needed by 50 tests and it makes the suite slow. What do you do?

Dịch: 50 test cùng cần đăng nhập, suite chậm.

Sample answer: Keep one UI login test, and for others set up authentication faster, for example by reusing a session cookie or calling a login API and injecting the cookie, then navigate directly. Also consider parallel execution with ThreadLocal drivers.

Giải thích: Tư duy kim tự tháp kiểm thử và tối ưu thời gian.

Ví dụ: 10 test hiện mất ~91 s vì mỗi test mở Chrome mới.

Follow-up: What are the risks of shortcuts? → không kiểm thử luồng login thật nữa (nên giữ 1 test).

S9. A teammate adds a library and your build fails with NoSuchMethodError.

Dịch: Đồng đội thêm thư viện, bạn gặp NoSuchMethodError.

Sample answer: It is probably a version conflict. I run mvnw dependency:tree and look for a library, such as Guava, resolved to a different version than Selenium needs. I pin the version in dependencyManagement or exclude the transitive dependency, run clean test, and tell the team.

Giải thích: Quy tắc "nearest wins".

Ví dụ: Selenium cần guava 33.7.2-jre (dependency tree thật).

Follow-up: How to prevent? → xem dependency:tree trước khi merge.

S10. How would you decide what to automate?

Dịch: Quyết định tự động hoá cái gì?

Sample answer: I automate repetitive, stable, high-value and regression-prone scenarios, with clear expected results and data. I avoid automating one-off checks, rapidly changing UI and highly subjective checks. I start with a small smoke suite on critical flows like login and checkout and expand based on risk.

Giải thích: Tiêu chí: tần suất, ổn định, giá trị, chi phí bảo trì.

Ví dụ: Login (Ex1) là ứng viên smoke điển hình.

Follow-up: What is your automation ROI view?

S11. A locator breaks every sprint because the front-end changes. What do you do?

Dịch: Locator gãy mỗi sprint.

Sample answer: Move locators into page objects so there is one place to fix, prefer stable attributes, ask developers to add data-testid, avoid positional or long XPath, and review UI changes with the team. I also add a quick locator health check in smoke tests.

Giải thích: Vấn đề tổ chức + kỹ thuật.

Ví dụ: Nút Login không có id/name ⇒ dùng //button[@type='submit'].

Follow-up: What is a relative locator?

S12. You are asked to run the suite on Firefox and Chrome. How do you design it?

Dịch: Chạy trên Firefox và Chrome.

Sample answer: Use a DriverFactory that returns the right WebDriver from a browser parameter, passed via testng.xml <parameter> or -Dbrowser=firefox. Use ThreadLocal for parallel runs, and keep all browser-specific options in the factory. Selenium Manager handles the drivers.

Giải thích: Factory + cấu hình ngoài code.

Ví dụ: Hiện BaseTest ghi cứng new ChromeDriver(); đề xuất ở framework-design/03.

Follow-up: How do you run across many machines? → Selenium Grid.
