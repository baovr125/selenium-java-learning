Maven và Maven Wrapper — Interview

Song ngữ Anh–Việt. Cấu trúc mỗi câu: Câu hỏi → Dịch → Câu trả lời mẫu → Giải thích → Ví dụ thực tế → Câu hỏi đào sâu. Quay lại: Interview README

Phần A. 14 câu hỏi cốt lõi

Q1. What is Maven?

Dịch: Maven là gì?

Sample answer (EN): Maven is a build automation and dependency management tool for Java projects. It uses a pom.xml file to describe the project, downloads the libraries the project needs from repositories, and runs standard build steps like compile, test and package through plugins.

Giải thích: Ba ý: (1) quản lý thư viện, (2) chuẩn hoá build, (3) plugin thực hiện việc cụ thể. Nhấn mạnh "convention over configuration".

Ví dụ thực tế: Dự án khai báo Selenium và TestNG trong pom.xml; chạy .\mvnw.cmd test là Maven tải khoảng 40 jar, biên dịch và chạy 10 test.

Câu hỏi đào sâu: What is the difference between Maven and Gradle? (XML khai báo vs script, độ linh hoạt).

Q2. What is Maven Wrapper?

Dịch: Maven Wrapper là gì?

Sample answer: Maven Wrapper is a small set of scripts (mvnw, mvnw.cmd) and a properties file under .mvn/wrapper that live inside the project. When you run it, it downloads the exact Maven version the project specifies if it is not already on your machine, and then runs Maven with it. So everyone uses the same Maven version without installing Maven manually.

Giải thích: Wrapper "bao" Maven: người chạy không cần cài Maven. Phiên bản Maven khoá trong maven-wrapper.properties (commit lên Git).

Ví dụ: Selenium1 có mvnw.cmd; lệnh mvn -version báo không tìm thấy, nhưng .\mvnw.cmd -version in Apache Maven 3.9.16.

Đào sâu: Where does the wrapper store the downloaded Maven? → ~/.m2/wrapper/dists/apache-maven-3.9.16/<hash> (dùng chung cho các dự án cùng phiên bản).

Q3. What is the difference between Maven and Maven Wrapper?

Dịch: Khác nhau giữa Maven và Maven Wrapper?

Sample answer: Maven is the actual build tool. Maven Wrapper is just a launcher that makes sure the right Maven version is available and then calls it. With plain Maven you must install it and versions may differ between machines. With the wrapper, the version is pinned in the repository and downloaded automatically, but the wrapper does not replace the JDK.

Giải thích: Wrapper không làm thay việc của Maven; nó chỉ cung cấp đúng bản Maven. Bảng so sánh ở maven/03 mục 1.4.

Ví dụ: Lệnh mvn test cần Maven cài sẵn; .\mvnw.cmd test thì không.

Đào sâu: If both exist on my machine, which one should I use in a team project? → Wrapper, để khớp với CI và đồng đội.

Q4. What is the purpose of pom.xml?

Dịch: Mục đích của pom.xml?

Sample answer: pom.xml is the Project Object Model. It defines the project coordinates (groupId, artifactId, version), properties like the Java version, the dependencies, and the build plugins and their configuration. Maven reads it to know what to download and how to build.

Giải thích: Là "bản mô tả" của dự án. Nêu các khối: coordinates, properties, dependencies, build/plugins, (profiles).

Ví dụ: Trong pom.xml của dự án: maven.compiler.release=21, selenium.version=4.52.0, testng.version=7.10.2, và Surefire cấu hình suiteXmlFile = testng.xml.

Đào sâu: What is the difference between properties and dependencyManagement? (biến vs chuẩn hoá version cho nhiều module/transitive).

Q5. What is a Maven dependency?

Dịch: Dependency trong Maven là gì?

Sample answer: A dependency is an external library your project needs, identified by groupId, artifactId and version. Maven downloads it from a repository into the local repository and adds it to the classpath. Each dependency has a scope such as compile or test, and it can bring its own transitive dependencies.

Giải thích: GAV là "địa chỉ". Scope quyết định thư viện có mặt ở đâu. Transitive là thư viện phụ thuộc gián tiếp.

Ví dụ: selenium-java:4.52.0 với scope test; dependency:tree cho thấy nó kéo selenium-support, guava, opentelemetry...

Đào sâu: What does <scope>test</scope> mean? → chỉ có khi biên dịch/chạy test, không có trong src/main.

Q6. What is the Maven build lifecycle?

Dịch: Vòng đời build của Maven là gì?

Sample answer: The default lifecycle is an ordered list of phases: validate, compile, test, package, verify, install and deploy. When you run a phase, Maven runs all previous phases first. Plugin goals are bound to each phase, for example the compiler plugin to compile and Surefire to test. There are also the separate clean and site lifecycles.

Giải thích: Nhớ quy tắc "chạy phase N = chạy mọi phase trước N". clean là lifecycle riêng.

Ví dụ: Log thật: resources → compiler:compile → resources:testResources → compiler:testCompile → surefire:test → jar:jar.

Đào sâu: What is the difference between a phase and a goal? → phase là bước trong lifecycle; goal là việc cụ thể của plugin.

Q7. What is the difference between clean, test, package and install?

Dịch: Khác nhau giữa clean, test, package, install?

Sample answer: clean deletes the target directory and belongs to the clean lifecycle. test compiles and runs the tests. package runs everything up to test and then creates the jar. install goes further and copies the artifact into the local repository. So package and install also run the tests unless you skip them.

Giải thích: test < package < verify < install. Điều hay quên: package có chạy test.

Ví dụ: .\mvnw.cmd package -DskipTests đã chạy thật: tạo SeleniumPractice-1.0-SNAPSHOT.jar ~2 KB với cảnh báo JAR will be empty vì không có src/main.

Đào sâu: How do you skip tests? → -DskipTests (biên dịch test nhưng không chạy) vs -Dmaven.test.skip=true (không biên dịch).

Q8. Why should we commit mvnw and mvnw.cmd?

Dịch: Vì sao nên commit mvnw và mvnw.cmd?

Sample answer: Because they are part of the project's build setup. If they are committed together with .mvn/wrapper/maven-wrapper.properties, anyone who clones the repository, including CI, can build immediately and uses the same Maven version. If they are missing, each person needs to install Maven separately and may get different results.

Giải thích: Cũng cần commit .mvn/wrapper/. Với Linux, nhớ bit thực thi (git update-index --chmod=+x mvnw) và line ending LF.

Ví dụ: Thành viên mới clone, không cài Maven, chạy .\mvnw.cmd clean test là có kết quả 10/10.

Đào sâu: What should NOT be committed? → target/, Local Repository (.mvn/repository), test-output/.

Q9. Can we run a Maven project without installing Maven?

Dịch: Có chạy được dự án Maven mà không cài Maven không?

Sample answer: Yes, if the project contains the Maven Wrapper. mvnw or mvnw.cmd downloads and runs the required Maven automatically. You still need a JDK and, the first time, internet access.

Giải thích: Điều kiện: có Wrapper + JDK + mạng (lần đầu).

Ví dụ: Máy này không có mvn trong PATH nhưng chạy .\mvnw.cmd test bình thường.

Đào sâu: What if the machine is offline? → Nếu đã có Maven trong ~/.m2/wrapper/dists và thư viện trong repository thì chạy được với -o; nếu chưa thì không.

Q10. Does Maven Wrapper eliminate the need for JDK?

Dịch: Maven Wrapper có thay thế JDK không?

Sample answer: No. Maven itself is a Java program, so it needs a Java runtime, and compiling code needs a JDK that includes javac. The wrapper only removes the need to install Maven.

Giải thích: Hai thứ khác nhau: JDK (Java) vs Maven (build tool). Một số hiểu lầm: "có mvnw là khỏi cài gì".

Ví dụ: Dự án cần JDK ≥ 21 (maven.compiler.release=21). Máy dùng JDK 25.0.1 vẫn biên dịch được vì --release 21. Với JDK < 21 sẽ lỗi release version 21 not supported.

Đào sâu: Must JAVA_HOME be set? → Không phải lúc nào cũng bắt buộc: máy này JAVA_HOME trống vẫn chạy nhờ java trong PATH; nhưng nếu đặt thì phải đúng.

Q11. How do you run a specific test using Maven?

Dịch: Làm sao chạy một test cụ thể bằng Maven?

Sample answer: With the Surefire -Dtest parameter. For a class: mvnw test -Dtest=LoginTest. For a single method: -Dtest=LoginTest#testLoginSuccess. When -Dtest is used, Surefire ignores the suiteXmlFiles configuration and selects tests by that pattern.

Giải thích: PowerShell nên đặt tham số trong dấu nháy ("-Dtest=Class#method"). Wildcard * được hỗ trợ.

Ví dụ: .\mvnw.cmd test "-Dtest=EnvironmentCheckTest" chạy 1 test dù class này không có trong testng.xml (đã kiểm chứng).

Đào sâu: What happens if the class name is wrong? → Với dự án này: Tests run: 0 và BUILD SUCCESS. Nên kiểm tra số test đã chạy.

Q12. How do you resolve dependency conflicts?

Dịch: Giải quyết xung đột dependency thế nào?

Sample answer: First I detect it with mvn dependency:tree and look at which versions are chosen or omitted for conflict. Maven uses "nearest definition wins". To fix it I can pin the version in dependencyManagement, exclude the unwanted transitive dependency, or align the versions of the libraries. Then I re-run the full tests.

Giải thích: Triệu chứng: NoSuchMethodError, ClassNotFoundException. Quy trình: phát hiện → ghim/loại trừ → kiểm chứng bằng test.

Ví dụ: Nếu thêm thư viện kéo guava cũ, Selenium (cần guava 33.7.2-jre) có thể lỗi lúc chạy; ép phiên bản guava trong dependencyManagement.

Đào sâu: What is the difference between exclusion and dependencyManagement? → loại bỏ một nhánh vs ép phiên bản toàn dự án.

Q13. What happens when a dependency is added to pom.xml?

Dịch: Điều gì xảy ra khi thêm dependency vào pom.xml?

Sample answer: Nothing happens until Maven runs. At the next run Maven reads the POM, looks for the artifact in the local repository, and if it is missing it downloads the .pom and .jar from the remote repository, plus all transitive dependencies. It resolves version conflicts and builds the classpath, so the classes become available according to the scope.

Giải thích: IDE cần "Reload Maven project". Đồng đội chỉ cần git pull + chạy Maven.

Ví dụ: Dự án lưu thư viện trong .mvn/repository (123 jar); thư viện mới sẽ xuất hiện ở đó sau lần chạy đầu.

Đào sâu: What if the download fails? → Could not resolve dependencies: kiểm tra tọa độ, mạng, proxy, -U.

Q14. How do you troubleshoot Maven build failures?

Dịch: Xử lý lỗi build Maven thế nào?

Sample answer: I read the first [ERROR] line and identify which plugin goal failed — compiler, surefire, dependency or the wrapper itself. Then I rerun with -e or -X for more detail, narrow the scope with test-compile or a single test, check java -version and mvnw -version, and finally clean the specific broken artifacts. I also read target/surefire-reports for test failures.

Giải thích: Phương pháp: đọc lỗi → xác định plugin → thu hẹp → kiểm tra môi trường → làm sạch có chủ đích. Bảng lỗi: maven/08.

Ví dụ: -o clean thất bại với has not been downloaded from it before vì chưa từng tải maven-clean-plugin; bỏ -o là xong.

Đào sâu: Tests fail but the build log has no clear error. Where do you look? → target/surefire-reports (emailable-report.html, .dumpstream).

Phần B. Câu hỏi bổ sung

Q15. What is the difference between wrapperVersion and the Maven version in the wrapper properties?

Dịch: wrapperVersion khác gì phiên bản Maven?

Sample answer: wrapperVersion is the version of the wrapper scripts themselves, while the Maven version is part of distributionUrl. In our project the wrapper is 3.3.4 and it downloads Maven 3.9.16.

Giải thích: Hai con số dễ nhầm. Bỏ qua điểm này là lỗi hay gặp.

Ví dụ: .mvn/wrapper/maven-wrapper.properties: wrapperVersion=3.3.4, distributionUrl=...apache-maven-3.9.16-bin.zip.

Đào sâu: What does distributionType=only-script mean? → chỉ dùng script, không cần maven-wrapper.jar.

Q16. What is the local repository, and where is it in your project?

Dịch: Local repository là gì, ở đâu trong dự án của bạn?

Sample answer: It is the folder on your machine where Maven caches downloaded artifacts. By default it is ~/.m2/repository, but in my project .mvn/maven.config sets -Dmaven.repo.local=.mvn/repository, so the project has its own repository folder, which is excluded from Git.

Giải thích: Đây là chi tiết riêng của dự án — thể hiện bạn đã đọc kỹ cấu hình. Lý do: cô lập khỏi ~/.m2 bị hỏng.

Ví dụ: .gitignore có dòng .mvn/repository/.

Đào sâu: Pros and cons? → cô lập, tái lập; nhưng mỗi clone phải tải lại.

Q17. Why can BUILD SUCCESS still hide a problem in test execution?

Dịch: Vì sao BUILD SUCCESS vẫn có thể che giấu vấn đề?

Sample answer: Because Maven only fails when a goal fails. If no tests match, for example a wrong -Dtest name, Surefire reports Tests run: 0 and the build still succeeds. Skipped tests also do not fail the build. So I always check the test counts.

Giải thích: Đã tái hiện: -Dtest=NoSuchTest ⇒ Tests run: 0, BUILD SUCCESS; thêm failIfNoSpecifiedTests=true không giúp ở cấu hình này.

Ví dụ: Trong CI, đọc target/surefire-reports/TestSuite.txt và fail nếu Tests run: 0.

Đào sâu: How would you guard against it in CI? → script kiểm tra số test tối thiểu.

Phần C. 6 tình huống thực tế

S1. You clone the project and have no Maven installed. How do you run the tests?

Dịch: Clone dự án, không có Maven, chạy test thế nào?

Sample answer: I check Java with java -version (needs 21+), open PowerShell in the project root, run .\mvnw.cmd -version to confirm the wrapper downloads Maven, then .\mvnw.cmd clean test. The first run is slow because it downloads Maven and the libraries. Then I check Tests run and the report in target/surefire-reports.

Giải thích: Trình bày quy trình đúng thứ tự, nêu điều kiện (JDK, mạng), và cách kiểm chứng kết quả.

S2. .\mvnw.cmd says "not recognized". What do you check?

Dịch: Gõ .\mvnw.cmd báo "not recognized", bạn kiểm tra gì?

Sample answer: First I check I am in the folder that contains mvnw.cmd and that I typed the .\ prefix, because PowerShell does not run commands from the current folder without it. Then I check the file exists with Test-Path, and if it was not checked out, I restore it from Git.

Giải thích: 90% là sai thư mục/thiếu .\.

S3. A teammate on Linux gets "Permission denied: ./mvnw". Why?

Dịch: Đồng đội dùng Linux báo Permission denied: ./mvnw. Vì sao?

Sample answer: The file lacks the executable bit, usually because it was committed from Windows. Quick fix is chmod +x mvnw. The permanent fix is git update-index --chmod=+x mvnw and committing it. Also line endings must be LF; otherwise they get "bad interpreter".

Giải thích: Git lưu mode 100755 vs 100644; kiểm tra bằng git ls-files --stage mvnw.

S4. You added a dependency and your teammate's build fails after pulling. What do you do?

Dịch: Bạn thêm dependency, đồng đội pull về build lỗi. Làm gì?

Sample answer: I ask for the first error line. If it says it cannot resolve the artifact, I verify the coordinates and version exist, and whether their network or proxy blocks Maven Central. If it is a runtime error like NoSuchMethodError, I check dependency:tree for a conflict. I also confirm that everything needed was committed, meaning pom.xml, and that my own build was clean from a fresh state.

Giải thích: Tách hai loại lỗi: phân giải (mạng/tọa độ) và xung đột (runtime). Chạy clean test ở máy sạch để tái hiện.

S5. Tests pass on your machine but fail in CI. Where do you start?

Dịch: Máy bạn pass, CI fail. Bắt đầu từ đâu?

Sample answer: I compare the environment: JDK version, Chrome version, whether the browser runs headless, window size, and network. The wrapper makes the Maven version the same, but not these. I read the CI log and the surefire reports, run mvnw clean test locally in a fresh clone, and then check for synchronization problems that appear when the CI machine is slower.

Giải thích: Wrapper chỉ khoá Maven, không khoá JDK/Chrome/OS/mạng. Nguyên nhân thường gặp nhất: headless + kích thước cửa sổ + Wait thiếu.

S6. You need to upgrade Maven from 3.9.16 to a newer version for the whole team. How?

Dịch: Cần nâng Maven cho cả nhóm. Làm thế nào?

Sample answer: I change distributionUrl in .mvn/wrapper/maven-wrapper.properties, or regenerate the wrapper with mvnw wrapper:wrapper -Dmaven=<version>. I verify with mvnw -version, run clean test, and commit the changed wrapper files in a pull request. Teammates just pull, and the wrapper downloads the new Maven on their next run.

Giải thích: Nâng Maven chỉ cần sửa file được commit — đó là sức mạnh của Wrapper. Tuỳ chọn thêm distributionSha256Sum.
