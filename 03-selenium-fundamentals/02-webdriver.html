1. Interface WebDriver — từng method làm gì

WebDriver là interface (bản "hợp đồng"): nó khai báo các lệnh bạn có thể gửi cho trình duyệt. ChromeDriver, FirefoxDriver, EdgeDriver là các lớp thực hiện hợp đồng đó. Mọi lệnh bên dưới đều gọi qua biến driver, ví dụ driver.get(...).

Cách đọc các thẻ method: mỗi method có Làm gì · Trả về · Khi lỗi / trường hợp đặc biệt · Ví dụ · Lưu ý.

Nhóm Câu hỏi nhóm này trả lời Method Học kỹ ở
Điều hướng và thông tin trang "Mở trang nào? Đang ở đâu?" get(url), navigate(), getCurrentUrl(), getTitle(), getPageSource() mục 1.1 và 05
Tìm phần tử "Phần tử nào trên trang?" findElement(By), findElements(By) mục 1.2 và 03
Quản lý "Cấu hình cửa sổ, timeout, cookie" manage() → window(), timeouts(), cookie mục 4, 5, 6 bên dưới
Chuyển ngữ cảnh "Điều khiển iframe, tab, alert nào?" switchTo() → frame, window, alert, activeElement, defaultContent, newWindow mục 1.4 và 07
Cửa sổ "Đang có những cửa sổ nào?" getWindowHandle(), getWindowHandles() mục 1.5
Kết thúc "Đóng trình duyệt" close(), quit() mục 1.6

Các interface mở rộng mà ChromeDriver cũng implement: JavascriptExecutor, TakesScreenshot, HasDevTools, Interactive...

1.1. Điều hướng và thông tin trang

get(String url)

  • Làm gì: mở URL trong tab đang focus (như gõ URL vào thanh địa chỉ rồi Enter) và chờ trang tải xong theo PageLoadStrategy (mặc định chờ document.readyState = "complete").
  • Trả về: void.
  • Khi lỗi: quá pageLoadTimeout (🧩 30 s) → TimeoutException. URL thiếu giao thức ("google.com" thay vì "https://google.com") → thường là InvalidArgumentException (tên chính xác có thể khác nhẹ tuỳ driver/phiên bản).
  • Ví dụ:
java
driver.get("https://the-internet.herokuapp.com/login");   // dòng sau chỉ chạy khi trang đã tải xong
  • Lưu ý: URL phải có https:// hoặc http://. get() chặn (block) tới khi tải xong nhưng không chờ nội dung do JavaScript sinh ra sau đó — việc đó cần Wait.

navigate() → Navigation

  • Làm gì: navigate() không làm gì ngay; nó trả về một đối tượng Navigation có các lệnh điều khiển lịch sử duyệt web giống thanh công cụ trình duyệt.
  • Trả về: WebDriver.Navigation. Bốn lệnh của nó:
Lệnh Làm chính xác gì Tương đương
navigate().to(String url) Mở URL, chờ tải xong. Thêm một mục vào lịch sử get(url)
navigate().to(URL url) Như trên nhưng nhận đối tượng java.net.URL get(url.toString())
navigate().back() Quay lại trang trước trong lịch sử Nút Back
navigate().forward() Đi tới trang sau (chỉ có sau khi đã back()) Nút Forward
navigate().refresh() Tải lại trang hiện tại F5
  • Ví dụ:
java
driver.get(BASE_URL + "/login");
driver.findElement(By.cssSelector("button[type='submit']")).click();   // → /secure
driver.navigate().back();       // về /login
driver.navigate().forward();    // lại /secure
driver.navigate().refresh();    // tải lại /secure
  • Lưu ý: sau back(), forward(), refresh() mọi WebElement đã tìm đều stale (StaleElementReferenceException) — phải tìm lại. back()/forward() khi không có trang trước/sau thường không làm gì.

getCurrentUrl()

  • Làm gì: trả URL của tab đang focus, sau khi mọi lần chuyển hướng (redirect) đã xong; có cả phần ?query và #fragment.
  • Trả về: String.
  • Ví dụ:
java
String url = driver.getCurrentUrl();                 // "https://the-internet.herokuapp.com/secure"
Assert.assertTrue(url.endsWith("/secure"));          // 🧩 Ex1
  • Lưu ý: gọi ngay sau click() có thể ra URL cũ vì trang chưa kịp chuyển. Luôn chờ wait.until(ExpectedConditions.urlContains("/secure")) rồi mới đọc.

getTitle()

  • Làm gì: trả nội dung thẻ <title> của trang hiện tại (đã bỏ khoảng trắng thừa ở đầu/cuối).
  • Trả về: String (chuỗi rỗng nếu trang không có <title>).
  • Ví dụ:
java
Assert.assertEquals(driver.getTitle(), "The Internet");     // 🧩 EnvironmentCheckTest
  • Lưu ý: cùng bẫy "đọc quá sớm" với getCurrentUrl(). Title không phải tiêu đề <h1> trên trang.

getPageSource()

  • Làm gì: trả HTML hiện tại của DOM, tức là sau khi JavaScript đã sửa trang — không phải HTML gốc server gửi về.
  • Trả về: String (có thể rất dài).
  • Ví dụ:
java
boolean hasWelcome = driver.getPageSource().contains("Welcome");   // chủ yếu để debug
  • Lưu ý: chậm và dễ lệch nếu dùng làm cách chính để assert. Ưu tiên kiểm tra bằng locator.

Khác nhau giữa các method gần giống trong nhóm này:

get(url) navigate().to(url) getCurrentUrl() getTitle() getPageSource()
Là lệnh Hành động mở trang Hành động mở trang Đọc thông tin Đọc thông tin Đọc thông tin
Trả về void void URL hiện tại <title> Toàn bộ HTML của DOM
Thuộc WebDriver Navigation WebDriver WebDriver WebDriver
Dùng khi Mở trang đầu của test Chuỗi thao tác lịch sử (to → back → forward) Kiểm tra đã đúng trang Kiểm tra đúng trang bằng tiêu đề Debug, tìm chuỗi

get() và navigate().to() cùng tải URL và cùng chờ tải xong. Khác biệt chỉ là cách tổ chức API: quy ước thực tế là get() cho lần mở đầu, navigate() khi thao tác lịch sử.

1.2. Tìm phần tử

findElement(By by)

  • Làm gì: tìm trong trang hiện tại (hoặc frame đang chọn) và trả phần tử đầu tiên khớp locator, theo thứ tự xuất hiện trong DOM.
  • Trả về: WebElement.
  • Khi lỗi: không có phần tử nào khớp → NoSuchElementException (sau khi hết thời gian implicit wait nếu có bật).
  • Ví dụ:
java
WebElement username = driver.findElement(By.id("username"));
username.sendKeys("tomsmith");
  • Lưu ý: locator khớp nhiều phần tử thì chỉ lấy cái đầu tiên, không báo lỗi — dễ lấy nhầm nếu locator quá rộng.

findElements(By by)

  • Làm gì: tìm tất cả phần tử khớp locator.
  • Trả về: List<WebElement> (theo thứ tự DOM).
  • Khi lỗi: không ném NoSuchElementException; không có phần tử nào thì trả danh sách rỗng (size() == 0).
  • Ví dụ:
java
List<WebElement> rows = driver.findElements(By.cssSelector("table#table1 tbody tr"));
Assert.assertEquals(rows.size(), 4);

boolean hasError = !driver.findElements(By.id("error")).isEmpty();   // kiểm tra "có tồn tại không" mà không bắt exception
  • Lưu ý: khi có implicit wait, findElements vẫn chờ đủ thời gian rồi mới trả list rỗng — làm các bước "kiểm tra không tồn tại" chậm đi.
findElement findElements
Trả về 1 WebElement (đầu tiên khớp) List<WebElement> (mọi phần tử khớp)
Không thấy Ném NoSuchElementException Trả list rỗng
Dùng khi Thao tác với một phần tử Đếm, duyệt, hoặc kiểm tra "có/không có"

Xem cách viết By ở 03 - Locators.

1.3. Quản lý — manage()

  • Làm gì: manage() là cổng vào của nhóm cấu hình trình duyệt. Nó trả về WebDriver.Options; từ đó bạn gọi tiếp:
  • manage().window() → kích thước/vị trí cửa sổ (mục 5)
  • manage().timeouts() → giới hạn thời gian (mục 4)
  • manage().addCookie(...), getCookies(), deleteAllCookies()... → cookie (mục 6)
  • Trả về: WebDriver.Options.
  • Lưu ý: manage() bản thân không làm gì; chỉ có lệnh nối phía sau mới có tác dụng.

1.4. Chuyển ngữ cảnh — switchTo()

  • Làm gì: switchTo() trả về WebDriver.TargetLocator. Mặc định driver "đang nhìn" vào trang chính của tab đầu tiên. Iframe, tab khác, alert là những "thế giới" riêng; muốn tìm phần tử bên trong chúng phải chuyển sang trước, nếu không findElement ném NoSuchElementException.
Lệnh Làm chính xác gì Trả về Khi lỗi
switchTo().frame(int index) Vào iframe thứ index (đếm từ 0) WebDriver NoSuchFrameException
switchTo().frame(String nameOrId) Vào iframe theo name hoặc id WebDriver NoSuchFrameException
switchTo().frame(WebElement frame) Vào iframe là phần tử bạn đã tìm WebDriver NoSuchFrameException
switchTo().parentFrame() Ra một cấp (iframe lồng nhau) WebDriver —
switchTo().defaultContent() Ra thẳng trang chính (ngoài mọi iframe) WebDriver —
switchTo().window(String handle) Chuyển sang tab/cửa sổ có handle đó WebDriver NoSuchWindowException
switchTo().newWindow(WindowType) Mở tab/cửa sổ mới (TAB/WINDOW) và chuyển sang nó WebDriver —
switchTo().alert() Chuyển sang hộp thoại JS (alert/confirm/prompt) Alert NoAlertPresentException
switchTo().activeElement() Lấy phần tử đang được focus WebElement —
  • Ví dụ:
java
driver.switchTo().frame("mce_0_ifr");                    // vào iframe
driver.findElement(By.id("tinymce")).sendKeys("hello");  // tìm bên TRONG iframe
driver.switchTo().defaultContent();                      // ra ngoài trang chính

String main = driver.getWindowHandle();
driver.findElement(By.linkText("Click Here")).click();   // mở tab mới nhưng driver vẫn ở tab cũ
for (String h : driver.getWindowHandles()) if (!h.equals(main)) driver.switchTo().window(h);

driver.switchTo().newWindow(WindowType.TAB);             // Selenium 4: mở tab mới và tự chuyển sang
driver.get(BASE_URL + "/windows");

driver.findElement(By.id("search")).click();
WebElement focused = driver.switchTo().activeElement();  // chính là ô #search
focused.sendKeys("selenium");
  • Lưu ý:
  • Sau khi bấm link mở tab mới, driver không tự chuyển sang tab đó (khác newWindow(...) thì có) — phải switchTo().window(handle).
  • Quên defaultContent() sau khi làm việc trong iframe → phần tử ngoài iframe "biến mất".
  • alert() gọi khi chưa có hộp thoại → NoAlertPresentException; chờ bằng ExpectedConditions.alertIsPresent() (Phase 4).
  • Alert có 4 lệnh: getText(), accept() (OK), dismiss() (Cancel), sendKeys(String) (nhập vào prompt).

Chi tiết từng tình huống: 07 - Browser Interactions.

1.5. Cửa sổ — handle

getWindowHandle()

  • Làm gì: trả "mã định danh" (handle) của cửa sổ/tab đang focus. Handle là một chuỗi dạng CDwindow-1A2B3C..., không có ý nghĩa với con người, chỉ dùng để chuyển qua lại.
  • Trả về: String.
  • Ví dụ:
java
String main = driver.getWindowHandle();   // lưu lại để quay về

getWindowHandles()

  • Làm gì: trả handle của tất cả cửa sổ/tab đang mở trong session.
  • Trả về: Set<String>.
  • Ví dụ:
java
Set<String> all = driver.getWindowHandles();
System.out.println(all.size());     // 2 nếu đang có 2 tab
  • Lưu ý: thứ tự trong Set không đáng tin — không giả định "phần tử cuối là tab mới nhất"; hãy loại handle main ra. Ngay sau click() mở tab, có thể mới có 1 handle (tab mở bất đồng bộ) → chờ numberOfWindowsToBe(2).
getWindowHandle() getWindowHandles()
Trả về 1 String Set<String>
Phạm vi Cửa sổ đang focus Mọi cửa sổ
Dùng khi Lưu cửa sổ chính để quay về Tìm tab mới vừa mở

1.6. Kết thúc — close() và quit()

close()

  • Làm gì: đóng cửa sổ/tab đang focus (như bấm dấu ✕ của tab đó).
  • Trả về: void.
  • Lưu ý: session vẫn sống nếu còn cửa sổ khác. Sau close(), driver không tự chuyển sang cửa sổ còn lại — phải switchTo().window(main), nếu không lệnh sau ném NoSuchWindowException.

quit()

  • Làm gì: đóng toàn bộ cửa sổ, kết thúc session và dừng process chromedriver.
  • Trả về: void.
  • Lưu ý: sau quit() không dùng được driver nữa. 🧩 BaseTest.tearDown() dùng quit() (đúng).
close() quit()
Đóng Cửa sổ/tab đang focus Toàn bộ cửa sổ của session
Session Còn nếu còn cửa sổ khác Kết thúc
Process chromedriver Có thể còn chạy Dừng
Dùng khi Đóng tab phụ rồi switchTo().window(main) @AfterMethod / @AfterClass

2. Khởi tạo trình duyệt

🧩 Trong dự án (BaseTest.setup()):

java
driver = new ChromeDriver();                                   // 1. mở Chrome
driver.manage().window().maximize();                           // 2. phóng to
driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(30)); // 3. giới hạn load trang
wait = new WebDriverWait(driver, Duration.ofSeconds(15));      // 4. explicit wait

Điều gì xảy ra ở new ChromeDriver():

  1. Selenium Manager (nhúng trong selenium-manager-4.52.0.jar) xác định phiên bản Chrome đã cài, tải ChromeDriver tương ứng vào cache (~/.cache/selenium), trả đường dẫn driver.
  2. Khởi động process chromedriver.
  3. Gửi New Session → Chrome được mở với một profile tạm.
  4. Trả về đối tượng ChromeDriver giữ sessionId.

⚠️ Lần chạy đầu tiên có thể chậm hơn vì tải driver; thiếu Internet ⇒ SessionNotCreatedException/NoSuchDriverException.

Các trình duyệt khác

java
WebDriver driver = new FirefoxDriver();   // geckodriver
WebDriver driver = new EdgeDriver();      // msedgedriver

Chọn theo cấu hình ⇒ DriverFactory (framework-design/03).

3. Cấu hình Browser: ChromeOptions

java
import org.openqa.selenium.chrome.ChromeOptions;

ChromeOptions options = new ChromeOptions();
options.addArguments("--start-maximized");          // thay cho window().maximize()
options.addArguments("--headless=new");             // chạy không giao diện (Chrome mới)
options.addArguments("--window-size=1920,1080");    // headless nên đặt kích thước
options.addArguments("--disable-notifications");
options.addArguments("--incognito");
options.setPageLoadStrategy(PageLoadStrategy.EAGER);  // NORMAL (mặc định) | EAGER | NONE
WebDriver driver = new ChromeDriver(options);
Option Tác dụng Dùng khi

--window-size=W,H Kích thước cố định Headless; test responsive
--incognito Không dùng cache/cookie cũ Test độc lập
--disable-notifications Tắt popup xin quyền Trang đòi thông báo
PageLoadStrategy Khi nào get() coi là "xong" Trang tải chậm vì quảng cáo

4. Timeouts (3 loại) — từng method

driver.manage().timeouts() cấu hình 3 giới hạn thời gian khác nhau hoàn toàn. Tất cả nhận java.time.Duration.

4.1. pageLoadTimeout(Duration)

  • Làm gì: đặt thời gian tối đa chờ một trang tải xong cho get(), navigate().to(), refresh() và các click gây điều hướng.
  • Mặc định: 300 giây. 🧩 Dự án đặt 30 giây.
  • Khi vượt giới hạn: TimeoutException ném ra từ chính lệnh get() (trang có thể đã tải dở).
  • Ví dụ:
java
driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(30));   // 🧩 BaseTest
  • Lưu ý: mặc định 300 giây quá lâu cho CI, nên đặt giá trị hợp lý.

4.2. implicitlyWait(Duration)

  • Làm gì: bảo driver: mỗi lần findElement/findElements không thấy phần tử thì cứ thử lại tới hết thời gian này.
  • findElement: thấy là trả ngay; hết giờ vẫn không thấy → NoSuchElementException.
  • findElements: chờ tới khi có ít nhất 1 phần tử hoặc hết giờ, rồi trả list (rỗng nếu không có).
  • Mặc định: 0 (không chờ).
  • Ví dụ:
java
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));   // 🧩 dự án CỐ Ý KHÔNG dùng
  • Lưu ý: áp dụng cho mọi lần tìm phần tử trong cả session, nên các kiểm tra "không tồn tại" bị chậm. Không nên trộn với Explicit Wait (thời gian cộng dồn khó đoán). Xem Phase 4 - Implicit Wait.

4.3. scriptTimeout(Duration)

  • Làm gì: thời gian tối đa chờ một đoạn JavaScript bất đồng bộ (executeAsyncScript) gọi lại callback.
  • Mặc định: 30 giây.
  • Khi vượt giới hạn: ScriptTimeoutException.
  • Ví dụ:
java
driver.manage().timeouts().scriptTimeout(Duration.ofSeconds(10));
  • Lưu ý: không ảnh hưởng executeScript thường (đồng bộ).
Timeout Method Mặc định Giới hạn thời gian của Exception khi vượt Trong dự án
Page load pageLoadTimeout 300 s Tải trang (get(), navigate()) TimeoutException ✅ 30 s
Implicit wait implicitlyWait 0 Tìm phần tử (findElement(s)) NoSuchElementException (findElement) ❌ cố ý không dùng
Script scriptTimeout 30 s executeAsyncScript ScriptTimeoutException ❌ mặc định

WebDriverWait (15 s trong dự án) không phải loại timeout nào trong 3 loại trên: nó là cơ chế chờ ở phía test code. Xem Phase 4.

5. Quản lý cửa sổ — manage().window()

Các lệnh dưới đây thao tác cửa sổ trình duyệt (không phải trang web bên trong).

5.1. maximize()

  • Làm gì: phóng to cửa sổ kín vùng làm việc của màn hình (như bấm nút □), vẫn còn thanh tiêu đề.
  • Trả về: void.
  • Ví dụ: driver.manage().window().maximize(); 🧩 dự án dùng.
  • Lưu ý: trong headless có thể không có hiệu quả như mong đợi → dùng --window-size=W,H.

5.2. minimize()

  • Làm gì: thu cửa sổ xuống thanh taskbar.
  • Trả về: void.
  • Lưu ý: hiếm dùng trong test; cửa sổ thu nhỏ có thể làm một số thao tác UI lỗi.

5.3. fullscreen()

  • Làm gì: chuyển sang toàn màn hình (như phím F11): ẩn thanh tiêu đề và thanh địa chỉ.
  • Trả về: void.
  • Khác maximize(): maximize vẫn thấy thanh trình duyệt; fullscreen thì không.

5.4. setSize(Dimension) và getSize()

  • Làm gì: setSize đặt kích thước cửa sổ theo pixel; getSize đọc kích thước hiện tại.
  • Trả về: setSize → void; getSize → Dimension (có getWidth(), getHeight()).
  • Ví dụ:
java
driver.manage().window().setSize(new Dimension(1280, 720));   // test responsive
Dimension size = driver.manage().window().getSize();
System.out.println(size.getWidth() + "x" + size.getHeight());
  • Lưu ý: đây là kích thước cả cửa sổ (gồm thanh địa chỉ), nên vùng hiển thị trang nhỏ hơn một chút.

5.5. setPosition(Point) và getPosition()

  • Làm gì: đặt/đọc vị trí góc trên bên trái của cửa sổ trên màn hình (pixel).
  • Trả về: setPosition → void; getPosition → Point (có getX(), getY()).
  • Ví dụ: driver.manage().window().setPosition(new Point(0, 0));
Lệnh Hiệu ứng
maximize() Kín màn hình, còn thanh tiêu đề
fullscreen() Kín màn hình, ẩn cả thanh tiêu đề (như F11)
minimize() Thu xuống taskbar
setSize(...) Kích thước cố định theo pixel (headless/CI nên dùng)

6. Cookie — manage()

Cookie là dữ liệu nhỏ trình duyệt lưu theo từng website (thường chứa phiên đăng nhập). Ứng dụng: đăng nhập một lần rồi dùng lại cookie phiên cho các test sau (tránh login UI lặp lại).

6.1. addCookie(Cookie)

  • Làm gì: thêm một cookie vào trình duyệt cho website của trang đang mở.
  • Trả về: void.
  • Khi lỗi: cookie không thuộc domain của trang hiện tại (hoặc đang ở about:blank) → InvalidCookieDomainException.
  • Ví dụ:
java
driver.get(BASE_URL);                                    // PHẢI mở đúng website trước
driver.manage().addCookie(new Cookie("name", "value"));
driver.navigate().refresh();                             // tải lại để trang dùng cookie
  • Lưu ý: cookie có hiệu lực cho các request sau đó; trang đã tải sẽ không tự thay đổi.

6.2. getCookieNamed(String name)

  • Làm gì: lấy cookie theo tên.
  • Trả về: Cookie, hoặc null nếu không có cookie tên đó.
  • Ví dụ:
java
Cookie c = driver.manage().getCookieNamed("name");
if (c != null) System.out.println(c.getValue());
  • Lưu ý: nhớ kiểm tra null — không ném exception.

6.3. getCookies()

  • Làm gì: lấy tất cả cookie của website hiện tại.
  • Trả về: Set<Cookie> (rỗng nếu không có).
  • Ví dụ:
java
for (Cookie c : driver.manage().getCookies()) System.out.println(c.getName() + "=" + c.getValue());

6.4. deleteCookieNamed(String) và deleteCookie(Cookie)

  • Làm gì: xoá một cookie, theo tên hoặc theo đối tượng Cookie.
  • Trả về: void.
  • Lưu ý: cookie không tồn tại thì không báo lỗi.

6.5. deleteAllCookies()

  • Làm gì: xoá mọi cookie của website hiện tại.
  • Trả về: void.
  • Ví dụ: driver.manage().deleteAllCookies(); — dọn phiên đăng nhập giữa các test để chúng độc lập.

7. Browser Session

  • Session = một "cuộc hội thoại" giữa test và browser; giữ cookie, localStorage, cửa sổ, timeout.
  • driver.getSessionId() có trên RemoteWebDriver/ChromeDriver (không có trong interface WebDriver).
  • Mỗi new ChromeDriver() là một session và một process Chrome riêng ⇒ 10 test = 10 lần mở Chrome (🧩 @BeforeMethod).
  • Kết thúc session đúng cách: quit(). Nếu test bị kill giữa chừng thì process mồ côi — xem maven/08 #17.

8. Vòng đời đúng của driver trong test

java
@BeforeMethod  public void setup()   { driver = new ChromeDriver(); ... }
@Test          public void test()    { driver.get(...); ... }
@AfterMethod   public void tearDown(){ if (driver != null) driver.quit(); }
  • Kiểm tra null vì nếu setup() fail (ví dụ không tải được driver) thì driver vẫn null và tearDown sẽ ném NullPointerException, che mất lỗi gốc.
  • ⚠️ Không dùng static WebDriver rồi chạy song song: các test giẫm lên nhau. Dùng ThreadLocal.

9. Phiên bản và API cần cẩn thận (Selenium 4.x)

Cũ (đã bỏ/deprecated) Dùng thay thế
new WebDriverWait(driver, 10) (số giây long) new WebDriverWait(driver, Duration.ofSeconds(10)) ✅ (🧩 dự án)
implicitlyWait(10, TimeUnit.SECONDS) implicitlyWait(Duration.ofSeconds(10))
System.setProperty("webdriver.chrome.driver", "...") Không cần: Selenium Manager tự xử lý (vẫn dùng được nếu cần chỉ định cụ thể)
DesiredCapabilities cho Chrome ChromeOptions
findElementsBy... findElements(By...)
WebDriverManager.chromedriver().setup() Không bắt buộc từ Selenium 4.6+

10. Best Practices

  1. Khai báo WebDriver, khởi tạo trong setup, quit() trong teardown.
  2. Mỗi test độc lập; mở browser mới hoặc dọn cookie.
  3. Không Thread.sleep() thay cho Wait.
  4. Cấu hình browser qua Options, đọc từ file/-D.
  5. Đặt kích thước cửa sổ cố định khi chạy CI.

11. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý

💼 Interview Corner

1. How do you run Chrome in headless mode?

  • 🇻🇳 Dịch: Chạy Chrome headless thế nào?
  • Suggested answer (EN): Pass --headless=new and an explicit --window-size through ChromeOptions to new ChromeDriver(options).
  • Giải thích (VI): Cần cho CI.
  • Follow-up: Why set the window size?

2. What are the different timeouts in Selenium?

  • 🇻🇳 Dịch: Các loại timeout?
  • Suggested answer (EN): Page load, implicit wait and script timeouts in manage().timeouts(); explicit waits are separate and controlled by WebDriverWait.
  • Giải thích (VI): Dự án: pageLoad 30 s + WebDriverWait 15 s, không implicit.
  • Follow-up: What happens when page load times out?

📌 Lesson Summary

Kiến thức cần nhớ

  • WebDriver là interface; ChromeDriver là hiện thực
  • ChromeOptions cấu hình browser
  • 3 timeout + WebDriverWait là việc khác nhau

Method / lệnh cần biết

  • Điều hướng/thông tin: get, navigate().to/back/forward/refresh, getCurrentUrl, getTitle, getPageSource
  • Tìm: findElement (ném lỗi nếu không thấy), findElements (list rỗng nếu không thấy)
  • Quản lý: manage().window().maximize/setSize, manage().timeouts().pageLoadTimeout/implicitlyWait/scriptTimeout, manage().addCookie/getCookies/deleteAllCookies
  • Chuyển ngữ cảnh: switchTo().frame/parentFrame/defaultContent/window/newWindow/alert/activeElement
  • Cửa sổ: getWindowHandle, getWindowHandles
  • Kết thúc: close, quit; cấu hình: ChromeOptions

Điểm dễ nhầm lẫn

  • findElement (đầu tiên, ném lỗi) ≠ findElements (tất cả, list rỗng)
  • get ≈ navigate().to; back/forward/refresh chỉ có trong navigate()
  • getWindowHandle (1 cửa sổ đang focus) ≠ getWindowHandles (tất cả); bấm link mở tab không tự chuyển driver sang tab mới
  • close (tab hiện tại) ≠ quit (cả session)
  • pageLoadTimeout ≠ WebDriverWait
  • Số giây long (cũ) ≠ Duration
  • Không dùng var cho driver

Lời giải Exercise 3
java
public final class DriverFactory {
    private DriverFactory() {}

    public static WebDriver create(String browser, boolean headless) {
        return switch (browser.toLowerCase()) {
            case "chrome" -> {
                ChromeOptions o = new ChromeOptions();
                if (headless) o.addArguments("--headless=new", "--window-size=1920,1080");
                yield new ChromeDriver(o);
            }
            case "firefox" -> new FirefoxDriver();
            case "edge" -> new EdgeDriver();
            default -> throw new IllegalArgumentException("Không hỗ trợ: " + browser);
        };
    }
}
