1. Automation Testing và Selenium

📘 Automation Testing là dùng chương trình để thực hiện các bước kiểm thử mà tester thường làm tay: mở trang, nhập dữ liệu, bấm nút, so sánh kết quả.

Selenium là một bộ công cụ mã nguồn mở để tự động hoá trình duyệt web. Gồm nhiều thành phần:

Thành phần Vai trò Dự án có dùng?
Selenium WebDriver API (Java, Python, C#...) điều khiển trình duyệt ✅ trọng tâm
Selenium Grid Chạy test song song trên nhiều máy/trình duyệt ❌
Selenium IDE Tiện ích ghi/phát lại thao tác ❌
Selenium Manager Tự tìm/tải browser driver (từ 4.6) ✅ (ngầm định, trong selenium-manager-4.52.0.jar)

Selenium chỉ tự động hoá trình duyệt web. Nó không kiểm thử ứng dụng mobile native hay desktop (đó là Appium, WinAppDriver...).

2. Selenium WebDriver là gì?

📘 WebDriver là một interface (org.openqa.selenium.WebDriver) mô tả các hành động điều khiển trình duyệt: get(url), findElement(by), getTitle(), quit()... Mỗi trình duyệt có một class hiện thực: ChromeDriver, FirefoxDriver, EdgeDriver, SafariDriver.

🧩 Trong dự án, BaseTest.java khai báo kiểu interface nhưng khởi tạo bằng class cụ thể:

java
protected WebDriver driver;      // kiểu interface (đa hình)
driver = new ChromeDriver();     // đối tượng cụ thể

✅ Luôn khai báo biến kiểu WebDriver: sau này đổi sang Firefox chỉ sửa một dòng khởi tạo.

3. Kiến trúc Selenium WebDriver (Selenium 4)

text
┌──────────────────┐   W3C WebDriver Protocol    ┌────────────────┐   giao thức    ┌───────────┐
│ Test code (Java) │ ───── HTTP + JSON ────────► │ Browser Driver │ ─────────────► │  Browser  │
│  Selenium client │ ◄──────── response ──────── │ (chromedriver) │ ◄───────────── │  (Chrome) │
└──────────────────┘                             └────────────────┘                └───────────┘

Các bước khi bạn gọi driver.findElement(By.id("username")):

  1. Thư viện Selenium Java đóng gói yêu cầu thành HTTP request JSON theo chuẩn W3C WebDriver (POST /session/{id}/element).
  2. Gửi tới chromedriver (process chạy local, lắng nghe một cổng).
  3. chromedriver chuyển thành lệnh điều khiển Chrome.
  4. Chrome thực hiện, kết quả quay ngược lại: JSON → đối tượng WebElement (thực chất chứa một element id của browser).

Hệ quả quan trọng:

  • Mỗi lệnh Selenium là một request qua mạng/loopback ⇒ có chi phí; tránh gọi thừa.
  • WebElement không phải bản sao DOM; nó chỉ là "tay cầm" (handle) tới phần tử. Nếu DOM đổi, handle có thể hết hạn → StaleElementReferenceException.
  • Selenium không biết trang đã "xong" theo nghĩa nghiệp vụ (AJAX chưa chạy xong...) ⇒ cần Wait. Xem selenium/05.

Đó là lý do README ghi "cần Internet" và lỗi SessionNotCreatedException thường xuất hiện khi Chrome cũ hoặc mất mạng.

5. WebDriver và WebElement

  • WebDriver: đại diện cả cửa sổ/tab trình duyệt (điều hướng, tìm phần tử, quản lý cửa sổ, timeout).
  • WebElement: đại diện một phần tử trên trang (click, nhập chữ, đọc text, đọc thuộc tính).
java
WebDriver driver = new ChromeDriver();
driver.get(BASE_URL + "/login");        // thao tác cấp trình duyệt
WebElement user = driver.findElement(By.id("username"));       // thao tác cấp phần tử
user.sendKeys("tomsmith");

Chi tiết: selenium/02.

6. Khởi tạo và đóng trình duyệt, Browser Session

  • new ChromeDriver() làm 2 việc: khởi động process chromedriver và tạo một session (phiên) — mỗi session có sessionId, cookie, tab, timeout riêng.
  • driver.quit() kết thúc session, đóng mọi cửa sổ và dừng process driver.
  • driver.close() chỉ đóng cửa sổ/tab hiện tại. Nếu là cửa sổ cuối cùng thì trình duyệt đóng nhưng process driver có thể còn sống.
close() quit()
Phạm vi Cửa sổ/tab đang focus Toàn bộ session
Process chromedriver Có thể còn Dừng
Dùng khi Đóng tab phụ rồi switchTo().window(...) về tab chính Kết thúc test (@AfterMethod)

🧩 BaseTest.tearDown() dùng quit() và kiểm tra driver != null (BaseTest.java).

7. Một test Selenium tối giản

java
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class FirstTest {
    private static final String BASE_URL = "https://example.com";   // đặt địa chỉ site demo của bạn

    public static void main(String[] args) {
        WebDriver driver = new ChromeDriver();
        try {
            driver.get(BASE_URL + "/");
            System.out.println(driver.getTitle());   // in ra tiêu đề của trang chủ
        } finally {
            driver.quit();                            // luôn giải phóng dù lỗi
        }
    }
}

try/finally quan trọng: nếu có exception mà quên quit(), Chrome vẫn mở. Dự án giải quyết vấn đề này bằng @AfterMethod (TestNG luôn chạy nó kể cả khi test fail).

7.1. Từ điển thuật ngữ Selenium — từng khái niệm là gì

Thuật ngữ Là gì, nói đơn giản Ví dụ / Lưu ý
Selenium WebDriver Bộ thư viện (API) bạn gọi trong Java để ra lệnh cho trình duyệt: mở trang, tìm phần tử, click, gõ selenium-java-4.52.0.jar
Browser Driver Chương trình trung gian của hãng trình duyệt: nhận lệnh từ code của bạn và điều khiển trình duyệt thật chromedriver.exe cho Chrome
Selenium Manager Công cụ tự tìm và tải đúng bản Browser Driver cho trình duyệt bạn đang cài (Selenium 4.6+) Chạy ngầm khi new ChromeDriver() — bạn không phải tải chromedriver.exe
Session Một "phiên làm việc" giữa test và một trình duyệt; giữ cookie, cửa sổ, cấu hình Mỗi new ChromeDriver() mở một session mới; quit() kết thúc
W3C WebDriver protocol Giao thức chuẩn (qua HTTP) giữa thư viện Selenium và Browser Driver Nhờ chuẩn chung, cùng code chạy được trên Chrome/Firefox/Edge
DOM Cây phần tử HTML mà trình duyệt dựng ra; Selenium tìm phần tử trong cây này Phần tử JS thêm vào sau cũng nằm trong DOM
Locator Cách chỉ định phần tử cần tìm (id, css, xpath...) By.id("username")
WebElement Đối tượng đại diện một phần tử đã tìm được, để bạn click, đọc chữ driver.findElement(...) trả về WebElement
Headless Chạy trình duyệt không hiện cửa sổ Dùng trên CI/server không có màn hình
Selenium Grid Hệ thống chạy test song song trên nhiều máy/trình duyệt Không dùng trong dự án này
Selenium IDE Tiện ích trình duyệt ghi và phát lại thao tác Không dùng trong dự án này
Flaky test Test lúc xanh lúc đỏ dù code không đổi Nguyên nhân hàng đầu: thiếu đồng bộ hoá (Wait)

Luồng một lệnh driver.get(...): code Java → thư viện Selenium → (giao thức W3C qua HTTP) → chromedriver → Chrome mở trang.

9. ✅ Best Practices khởi đầu

  1. Khai báo WebDriver, không khai báo ChromeDriver.
  2. Luôn quit() trong teardown.
  3. Dùng Explicit Wait, không Thread.sleep() làm cách chờ chính.
  4. Locator ưu tiên id, name, CSS ổn định.
  5. Mỗi test độc lập, không phụ thuộc thứ tự chạy.

Tóm tắt

  • Selenium = bộ công cụ; WebDriver = API; Browser Driver = cầu nối; Browser = nơi thực thi.
  • Giao tiếp bằng chuẩn W3C qua HTTP/JSON.
  • WebElement là handle, có thể stale.
  • Dự án dùng Selenium 4.52.0 + Selenium Manager (không WebDriverManager).

💼 Interview Corner

1. Explain the Selenium WebDriver architecture.

  • 🇻🇳 Dịch: Giải thích kiến trúc Selenium WebDriver.
  • Suggested answer (EN): Test code uses the Selenium client library, which sends JSON over HTTP using the W3C WebDriver protocol to a browser driver like chromedriver; the driver controls the browser and returns results the same way.
  • Giải thích (VI): Mỗi lệnh = một request.
  • Follow-up: Why can an element become stale?

2. What does Selenium Manager do?

  • 🇻🇳 Dịch: Selenium Manager làm gì?
  • Suggested answer (EN): Since Selenium 4.6 it detects the installed browser, downloads the matching driver and caches it, so WebDriverManager or manual downloads are not needed.
  • Giải thích (VI): Cần Internet lần đầu.
  • Follow-up: What exception appears if the driver can't be obtained?

📌 Lesson Summary

Kiến thức cần nhớ

  • Selenium là bộ công cụ; WebDriver là API; driver là cầu nối; browser thực thi
  • W3C protocol qua HTTP/JSON
  • quit() trong teardown

Method / lệnh cần biết

  • new ChromeDriver(), get, getTitle, close, quit

Điểm dễ nhầm lẫn

  • WebDriver ≠ Browser Driver ≠ Browser
  • close() ≠ quit()
  • Selenium ≠ Appium/Grid
