1. JavascriptExecutor là gì?

Interface cho phép chạy JavaScript ngay trong trang đang mở. ChromeDriver implement nó nên bạn ép kiểu:

java
JavascriptExecutor js = (JavascriptExecutor) driver;     // 🧩 Ex7
Object result = js.executeScript("return document.title;");
Method Ý nghĩa
executeScript(String script, Object... args) Chạy đồng bộ, trả giá trị
executeAsyncScript(String script, Object... args) Chạy bất đồng bộ, kết thúc khi gọi callback cuối (chịu scriptTimeout)

2. Truyền tham số và nhận kết quả

  • Tham số trong script là arguments[0], arguments[1]...
  • Truyền WebElement được: Selenium chuyển thành phần tử DOM.
  • Giá trị trả về được ánh xạ: số → Long/Double, chuỗi → String, boolean → Boolean, WebElement → WebElement, mảng → List, đối tượng → Map.
java
WebElement el = driver.findElement(By.id("username"));
js.executeScript("arguments[0].style.border='3px solid red'", el);           // highlight để debug
String text = (String) js.executeScript("return arguments[0].textContent;", el);

⚠️ Kiểu số trả về thường là Long (hoặc Double): ép kiểu bằng Number:

java
long y = ((Number) js.executeScript("return window.scrollY;")).longValue();   // 🧩 Ex7 làm đúng như vậy

Ép thẳng (Long)/(int) có thể ném ClassCastException khi giá trị là Double.

3. Phân tích Exercise 7

java
// cuộn xuống đáy + phát lại sự kiện scroll (đảm bảo plugin jScroll nhận được)
js.executeScript("window.scrollTo(0, document.body.scrollHeight);"
               + "window.dispatchEvent(new Event('scroll'));");

// cuộn về đầu
js.executeScript("window.scrollTo(0, 0);");

// kiểm tra tiêu đề đang nằm trong vùng nhìn thấy
Boolean headingInViewport = (Boolean) js.executeScript(
    "var r = document.querySelector('h3').getBoundingClientRect();"
  + "return r.top >= 0 && r.bottom <= window.innerHeight;");

Vì sao dùng JS ở đây?

  • Cuộn là thao tác của trình duyệt, không có API chuẩn "scroll to bottom" trong WebDriver cũ.
  • Cần phát sự kiện scroll thủ công khi trang đã ở đáy (trình duyệt không tự sinh sự kiện thêm).
  • Cần đọc thông tin hình học (getBoundingClientRect, scrollY, innerHeight) mà WebElement không cung cấp trực tiếp.

4. Các thao tác JS hay dùng

Mục đích Script
Cuộn xuống đáy window.scrollTo(0, document.body.scrollHeight)
Cuộn lên đầu window.scrollTo(0, 0)
Cuộn tới phần tử arguments[0].scrollIntoView({block:'center'})
Click bằng JS arguments[0].click()
Đọc scrollY return window.scrollY;
Đọc trạng thái load return document.readyState;
Lấy text ẩn return arguments[0].textContent;
Gán giá trị input arguments[0].value='abc'
Highlight arguments[0].style.border='2px solid red'
Xoá thuộc tính readonly arguments[0].removeAttribute('readonly')

Chờ trang "load xong" bằng JS:

java
wait.until(d -> "complete".equals(((JavascriptExecutor) d).executeScript("return document.readyState")));

5. Khi nào nên / không nên dùng JS

✅ Nên ❌ Không nên
Cuộn, đọc geometry, scrollY Thay click()/sendKeys() vì lười Wait
Đọc thông tin mà Selenium không có Gán giá trị input thay cho gõ phím ⇒ bỏ qua sự kiện keydown/input, có thể bypass validation
Xoá overlay/banner chặn test (khi môi trường test cho phép) Che giấu lỗi thật của giao diện
Trường hợp đặc biệt đã thử cách chuẩn mà không được (có ghi chú) Dùng làm cách mặc định

Lý do: click() của Selenium kiểm tra phần tử có nhìn thấy/bấm được như người dùng thật. arguments[0].click() bỏ qua kiểm tra đó ⇒ test "pass" dù người dùng thật không bấm được (bị che, bị ẩn). Mất tác dụng kiểm thử.

6. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
JavascriptException: javascript error: ... Script sai cú pháp / null Thử trước trong Console của DevTools
ClassCastException Ép sai kiểu kết quả Dùng Number, kiểm tra instanceof
return bị quên ⇒ kết quả null executeScript chỉ trả giá trị khi script có return Thêm return
StaleElementReferenceException khi truyền arguments[0] Phần tử đã stale Tìm lại
ScriptTimeoutException (async) Quên gọi callback Gọi arguments[arguments.length-1]()

✅ Best Practices

  1. Dùng API Selenium trước; JS là phương án cuối, có chú thích lý do.
  2. Gói thao tác JS trong helper nhỏ (🧩 Ex7: scrollToBottom, getScrollY).
  3. Không dùng JS để "ép" thành công cho hành động mà người dùng thật không làm được.
  4. Dùng Number khi nhận số.

💼 Interview Corner

1. When would you use JavascriptExecutor?

  • 🇻🇳 Dịch: Khi nào dùng JavascriptExecutor?
  • Suggested answer (EN): For things WebDriver does not provide natively, such as scrolling, reading geometry or page state; not as a shortcut around waits or real user actions.
  • Giải thích (VI): Ví dụ Exercise 7.
  • Follow-up: Why is JS click risky?

2. Why does Exercise 7 scroll inside the wait condition?

  • 🇻🇳 Dịch: Vì sao Exercise 7 cuộn trong điều kiện chờ?
  • Suggested answer (EN): The page ignores scroll events while a load is in progress, so one scroll can be lost; repeating the scroll until the item count grows makes the test robust.
  • Giải thích (VI): Retry đến khi điều kiện đúng.
  • Follow-up: How would you document that side effect?

📌 Lesson Summary

Kiến thức cần nhớ

  • JS là phương án sau cùng, có chú thích
  • Số trả về dùng Number
  • Cuộn/geometry là ứng dụng hợp lý nhất

Method / lệnh cần biết

  • executeScript, window.scrollTo, scrollIntoView, getBoundingClientRect, document.readyState

Điểm dễ nhầm lẫn

  • executeScript ≠ executeAsyncScript
  • JS click ≠ click thật
  • Quên return

🔑 Reference Solutions

Chỉ mở sau khi đã tự làm bài tập ở trên.

Lời giải Exercise 1
java
// (đặt trong một @Test — có sẵn driver và wait từ BaseTest)
driver.get(BASE_URL + "/");
JavascriptExecutor js = (JavascriptExecutor) driver;
System.out.println(js.executeScript("return document.title;"));
Lời giải Exercise 2
java
// (đặt trong một @Test — có sẵn driver và wait từ BaseTest)
driver.get(BASE_URL + "/floating_menu");
JavascriptExecutor js = (JavascriptExecutor) driver;
js.executeScript("window.scrollTo(0, document.body.scrollHeight);");
long y = ((Number) js.executeScript("return window.scrollY;")).longValue();
Assert.assertTrue(y > 0);

✅ Đã kiểm chứng: /floating_menu cho scrollY = 4465. Còn /infinite_scroll lúc mới tải có document.body.scrollHeight = 707 nhỏ hơn window.innerHeight = 889 (cửa sổ maximize) nên scrollY vẫn 0 — vì vậy Exercise07 phải cuộn lặp trong custom wait để trang dài ra.

Lời giải Exercise 3
java
// (đặt trong một @Test — có sẵn driver và wait từ BaseTest)
driver.get(BASE_URL + "/infinite_scroll");
wait.until(ExpectedConditions.presenceOfElementLocated(By.className("jscroll-added")));
JavascriptExecutor js = (JavascriptExecutor) driver;
final int before = driver.findElements(By.className("jscroll-added")).size();
wait.until(d -> {
    js.executeScript("window.scrollTo(0, document.body.scrollHeight); window.dispatchEvent(new Event('scroll'));");
    return d.findElements(By.className("jscroll-added")).size() > before;
});

Plugin jScroll bỏ qua sự kiện scroll khi đang tải; một lần cuộn có thể "mất" → cuộn lặp trong điều kiện chờ.
