📋 Prerequisites

  • Locators
  • Java Collections

☕ Java ↔ Selenium

findElements trả List<WebElement> (Java Collections); getText() trả String; isDisplayed() trả boolean.

1. WebElement API — từng method làm gì

WebElement là "tay nắm" (handle) tới một phần tử cụ thể trên trang. Bạn lấy nó từ findElement(...), rồi gọi method của nó để thao tác (click, gõ), đọc (text, thuộc tính) hoặc kiểm tra trạng thái (hiển thị, bật, chọn).

Cách đọc thẻ: Làm gì · Trả về · Khi lỗi · Ví dụ · Lưu ý. Chi tiết các lệnh tương tác hơn ở 06 - Element Interactions.

1.1. Nhóm thao tác

click()

  • Làm gì: cuộn phần tử vào vùng nhìn (nếu cần) rồi click chuột trái vào tâm phần tử.
  • Trả về: void.
  • Khi lỗi: phần tử ẩn/bị khoá → ElementNotInteractableException; bị phần tử khác che → ElementClickInterceptedException; handle cũ → StaleElementReferenceException.
  • Ví dụ: driver.findElement(By.cssSelector("button[type='submit']")).click();
  • Lưu ý: cần phần tử hiển thị + enabled + không bị che.

sendKeys(CharSequence... keys)

  • Làm gì: gõ phím vào phần tử: chuỗi chữ hoặc phím đặc biệt (Keys.ENTER, Keys.TAB). Với <input type="file"> thì nhận đường dẫn file để upload.
  • Trả về: void.
  • Khi lỗi: phần tử ẩn/disabled → ElementNotInteractableException.
  • Ví dụ: username.sendKeys("tomsmith"); username.sendKeys(Keys.TAB);
  • Lưu ý: gõ nối vào chữ cũ, không thay thế — nên clear() trước.

clear()

  • Làm gì: xoá toàn bộ nội dung của ô nhập.
  • Trả về: void.
  • Khi lỗi: phần tử không phải ô nhập được → InvalidElementStateException.
  • Ví dụ: username.clear();
  • Lưu ý: chỉ cho input/textarea đang enabled.

submit()

  • Làm gì: gửi form chứa phần tử này (như nhấn Enter trong form).
  • Trả về: void.
  • Lưu ý: ít dùng; ưu tiên click() nút submit vì mô phỏng người dùng thật hơn.

1.2. Nhóm đọc nội dung

getText()

  • Làm gì: trả văn bản đang hiển thị của phần tử và các phần tử con (đã bỏ khoảng trắng thừa ở đầu/cuối).
  • Trả về: String; "" nếu phần tử đang ẩn.
  • Ví dụ: String msg = driver.findElement(By.id("flash")).getText();
  • Lưu ý: với <input> luôn trả "" (nội dung nằm trong thuộc tính value, xem getAttribute). Chữ hiển thị theo CSS (text-transform: uppercase → trả chữ HOA).

getAttribute(String name)

  • Làm gì: trả giá trị thuộc tính hoặc property có tên name. Ưu tiên property hiện tại; không có thì lấy attribute.
  • Trả về: String, hoặc null nếu không có. Với thuộc tính kiểu bật/tắt (disabled, checked) trả "true" hoặc null.
  • Ví dụ: input.getAttribute("value") → chữ người dùng đã gõ. link.getAttribute("href") → URL.
  • Lưu ý: tiện nhưng "gộp" hai khái niệm dễ gây nhầm; xem hai method kế tiếp.

getDomAttribute(String name) (Selenium 4)

  • Làm gì: chỉ trả attribute viết trong HTML (giá trị khởi tạo).
  • Trả về: String, null nếu HTML không có attribute đó.
  • Ví dụ: <input value="abc"> rồi người dùng gõ đè "xyz": getDomAttribute("value") vẫn là "abc".

getDomProperty(String name) (Selenium 4)

  • Làm gì: trả property của DOM — trạng thái hiện tại của phần tử trong trình duyệt.
  • Trả về: String.
  • Ví dụ: cùng ví dụ trên: getDomProperty("value") → "xyz".
getAttribute getDomAttribute getDomProperty
Đọc từ Property, nếu không có thì attribute Chỉ attribute trong HTML Chỉ property của DOM
<input value="abc"> sau khi gõ "xyz" "xyz" "abc" "xyz"
Dùng khi Cần nhanh, không phân biệt Cần giá trị gốc trong HTML Cần giá trị đang có

getCssValue(String property)

  • Làm gì: trả giá trị CSS đã tính toán (kết quả cuối cùng áp dụng cho phần tử).
  • Trả về: String; màu trả dạng rgba(...).
  • Ví dụ: el.getCssValue("background-color") → "rgba(0, 123, 255, 1)".
  • Lưu ý: dùng kiểm tra giao diện (màu, cỡ chữ), không nên so sánh quá chặt.

getTagName()

  • Làm gì: trả tên thẻ HTML.
  • Trả về: String chữ thường, ví dụ "input", "a".

1.4. Nhóm kiểm tra trạng thái

Cả ba trả boolean, không ném lỗi khi trạng thái là false (chỉ ném StaleElementReferenceException nếu handle đã cũ).

Method Trả true khi Trả false khi Dùng cho 🧩 Dự án
isDisplayed() Phần tử đang hiển thị trên trang display:none, visibility:hidden, kích thước 0, <input type="hidden"> Modal, thông báo có hiện không Ex 1, 5, 6, 8

1.5. Nhóm tìm phần tử con

findElement(By) / findElements(By) (gọi trên một WebElement)

  • Làm gì: tìm bên trong phần tử này (chỉ trong các phần tử con của nó), thay vì trên cả trang.
  • Trả về: WebElement / List<WebElement>; không thấy thì ném NoSuchElementException / trả list rỗng.
  • Ví dụ:
java
WebElement row = driver.findElement(By.cssSelector("tbody tr"));
WebElement firstCell = row.findElement(By.tagName("td"));    // chỉ tìm trong dòng này
  • Lưu ý: XPath tìm trong phần tử phải bắt đầu bằng . (.//td); thiếu dấu chấm sẽ tìm trên cả trang.

getText() vs getAttribute("value")

java
WebElement input = driver.findElement(By.cssSelector("#input-example input"));
input.sendKeys("Selenium");
input.getText();                  // ""        — input không có "text node"
input.getAttribute("value");      // "Selenium" — 🧩 Exercise10 dùng đúng cách này

isDisplayed / isEnabled / isSelected — dùng khi nào

Method Ví dụ thực tế 🧩 Trong dự án
isDisplayed() Modal, flash message có hiện không Ex 1, 5, 6, 8
isEnabled() Ô input bị khoá trước khi Enable Ex 4 (lọc option disabled), Ex 10
isSelected() Checkbox đã tick chưa Ex 2

isDisplayed() trả false nếu phần tử tồn tại nhưng ẩn; nhưng ném NoSuchElementException nếu phần tử không tồn tại (vì bạn phải findElement trước). Để kiểm tra "không tồn tại" hãy dùng findElements(by).isEmpty() hoặc invisibilityOfElementLocated.

2. findElement vs findElements

findElement findElements
Trả về 1 WebElement (đầu tiên) List<WebElement>
Không thấy NoSuchElementException List rỗng
Dùng khi Chắc chắn có đúng 1 Đếm, duyệt, kiểm tra tồn tại
🧩 Ex 1, 4... Ex 2, 3, 5, 6, 7

Kỹ thuật kiểm tra "có/không" an toàn:

java
boolean exists = !driver.findElements(By.id("flash")).isEmpty();

⚠️ Nếu có Implicit Wait, findElements rỗng vẫn chờ đủ thời gian implicit mới trả về — lý do dự án cấm Implicit Wait (comment trong BaseTest). Bạn có thể kiểm chứng: bật implicitlyWait(10s) rồi gọi findElements cho phần tử không tồn tại ⇒ mất 10 giây.

3. Stale Element

WebElement là handle. Nếu DOM bị thay (làm mới trang, AJAX vẽ lại), handle cũ hết hiệu lực ⇒ StaleElementReferenceException.

java
WebElement btn = driver.findElement(By.id("save"));
driver.navigate().refresh();
btn.click();                     // ❌ StaleElementReferenceException
btn = driver.findElement(By.id("save")); // ✅ tìm lại

Giải pháp: lưu By thay vì WebElement để tìm lại khi cần (cách POM chuẩn); hoặc wait.until(ExpectedConditions.stalenessOf(old)) rồi tìm lại. Xem 05, 09.

🧩 Exercise04_DropdownTest có chú thích: lấy trước text/value dạng chuỗi để "không phụ thuộc vào trạng thái phần tử khi duyệt" — chính là phòng tránh stale.

Lỗi thường gặp với WebElement

Lỗi Nguyên nhân Cách xử lý

getText() rỗng với phần tử ẩn getText() chỉ trả text đang hiển thị Chờ visible; hoặc getAttribute("textContent")

💼 Interview Corner

1. What is the difference between findElement and findElements?

  • 🇻🇳 Dịch: findElement khác findElements?
  • Suggested answer (EN): findElement returns the first match or throws NoSuchElementException; findElements returns a list and an empty list when nothing matches.
  • Giải thích (VI): Dùng isEmpty() kiểm tra tồn tại.
  • Follow-up: How does implicit wait affect findElements?

2. How do you handle StaleElementReferenceException?

  • 🇻🇳 Dịch: Xử lý StaleElementReferenceException?
  • Suggested answer (EN): Find the element again, store the By instead of the element, wait for stalenessOf the old one, or use a bounded retry.
  • Giải thích (VI): WebElement là handle.
  • Follow-up: What causes it?

📌 Lesson Summary

Kiến thức cần nhớ

  • findElement (1, có thể ném lỗi) vs findElements (list, rỗng nếu không thấy)
  • getText cho text hiển thị, getAttribute("value") cho input
  • isDisplayed/isEnabled/isSelected chỉ là trạng thái tức thời

Method / lệnh cần biết

  • click, sendKeys, clear, getText, getAttribute, getDomProperty, isDisplayed, isEnabled, isSelected

Điểm dễ nhầm lẫn

  • getText ≠ getAttribute("value")
  • Tồn tại ≠ hiển thị ≠ bấm được
  • Handle cũ ≠ phần tử mới
