Alert

Có 3 loại JavaScript popup (không thuộc DOM): alert (OK), confirm (OK/Cancel), prompt (nhập chữ).

java
driver.findElement(By.cssSelector("button[onclick='jsPrompt()']")).click();
Alert alert = wait.until(ExpectedConditions.alertIsPresent());     // chờ + lấy Alert
System.out.println(alert.getText());
alert.sendKeys("Xin chào");     // chỉ prompt
alert.accept();                 // OK
// alert.dismiss();             // Cancel
Method Ý nghĩa
driver.switchTo().alert() Chuyển sang alert (ném NoAlertPresentException nếu chưa có)
getText() Nội dung
accept() / dismiss() OK / Cancel
sendKeys(String) Nhập vào prompt

Lưu ý:

  • Khi alert đang mở, mọi lệnh khác (kể cả findElement) ném UnhandledAlertException.
  • Alert không phải HTML ⇒ không dùng locator được.
  • Luôn chờ alertIsPresent() thay vì switchTo().alert() thẳng (05).
  • Popup xác thực (basic auth) không phải alert: nhúng credential vào URL https://user:pass@host/... hoặc dùng cơ chế riêng.
  • Modal HTML (như 🧩 Ex8 Entry Ad) không phải alert — dùng locator bình thường.

Frame / iFrame

<iframe> chứa một tài liệu HTML riêng. Selenium chỉ "nhìn thấy" phần tử của frame hiện tại ⇒ muốn thao tác trong iframe phải chuyển ngữ cảnh.

java
driver.get("https://the-internet.herokuapp.com/iframe");
wait.until(ExpectedConditions.frameToBeAvailableAndSwitchToIt(By.id("mce_0_ifr")));  // chờ + vào
WebElement body = driver.findElement(By.id("tinymce"));
body.click();                                                        // focus vào editor
body.sendKeys(Keys.chord(Keys.CONTROL, "a"), "Noi dung trong iframe"); // chọn hết rồi gõ đè
driver.switchTo().defaultContent();                     // ra khỏi mọi iframe, về trang chính

✅ Đã kiểm chứng thật: với TinyMCE của the-internet, clear() + sendKeys() không ghi nhận chữ (ô vẫn rỗng); phải click() để focus rồi Ctrl+A và gõ. Editor WYSIWYG (contenteditable) cư xử khác <input>.

Method Ý nghĩa
switchTo().frame(int index) Theo chỉ số (mong manh)
switchTo().frame(String nameOrId) Theo name hoặc id
switchTo().frame(WebElement) Theo phần tử <iframe>
switchTo().parentFrame() Lên một cấp
switchTo().defaultContent() Về gốc

Frame lồng nhau: vào lần lượt từng cấp; ra bằng parentFrame()/defaultContent().

Lỗi Nguyên nhân Cách xử lý
NoSuchElementException dù phần tử có trong DevTools Phần tử nằm trong iframe switchTo().frame(...) trước
NoSuchFrameException Frame chưa tải / sai locator frameToBeAvailableAndSwitchToIt
Sau khi ra, phần tử trang chính "biến mất" Quên defaultContent() Luôn quay về
StaleElementReferenceException Frame bị nạp lại Chuyển lại frame, tìm lại phần tử

Window / Tab

Mỗi cửa sổ/tab có một window handle (chuỗi định danh).

java
String mainHandle = driver.getWindowHandle();                       // tab hiện tại
driver.findElement(By.linkText("Click Here")).click();              // /windows: mở tab mới

wait.until(ExpectedConditions.numberOfWindowsToBe(2));              // chờ tab mở
for (String handle : driver.getWindowHandles()) {                   // Set<String>
    if (!handle.equals(mainHandle)) {
        driver.switchTo().window(handle);                           // sang tab mới
        break;
    }
}
System.out.println(driver.getTitle());                              // "New Window"
driver.close();                                                     // đóng tab mới
driver.switchTo().window(mainHandle);                               // PHẢI quay lại tab chính
Method Ý nghĩa
getWindowHandle() Handle cửa sổ hiện tại
getWindowHandles() Set<String> mọi cửa sổ (không có thứ tự đảm bảo)
switchTo().window(handle) Chuyển
switchTo().newWindow(WindowType.TAB \| WINDOW) Selenium 4: mở & chuyển sang tab/cửa sổ mới
close() Đóng cửa sổ hiện tại (xem 03)

⚠️ Lỗi thường gặp:

Lỗi Nguyên nhân Cách xử lý
getWindowHandles() chỉ có 1 handle Tab chưa mở xong numberOfWindowsToBe(2)
NoSuchWindowException driver vẫn trỏ cửa sổ đã đóng switchTo().window(...)
Dựa vào thứ tự của Set Set không đảm bảo thứ tự So sánh với handle chính
Quên quay lại tab chính Lưu mainHandle từ đầu

✅ Best Practices

  1. Luôn chờ (alertIsPresent, frameToBeAvailableAndSwitchToIt, numberOfWindowsToBe) trước khi chuyển ngữ cảnh.
  2. Lưu mainHandle; sau khi xong luôn quay lại.
  3. Tách thành helper dùng lại: switchToNewWindow(), acceptAlert().
  4. Ưu tiên selectByVisibleText/selectByValue hơn selectByIndex.
  5. Mỗi lần chuyển frame nhớ thoát ra.

✅ Knowledge Check

Câu 1. Gọi switchTo().alert() quá sớm gây?

  • A. NoAlertPresentException
  • B. TimeoutException
  • C. Không gì
  • D. Pass
Xem đáp án

Đáp án: A. Dùng alertIsPresent().

Câu 2. Sau khi làm việc trong iframe, trở về trang chính bằng?

  • A. close()
  • B. switchTo().defaultContent()
  • C. quit()
  • D. refresh()
Xem đáp án

Đáp án: B. Hoặc parentFrame() lên một cấp.

Câu 3. getWindowHandles() trả về kiểu?

  • A. List<String>
  • B. Set<String>
  • C. String[]
  • D. Map
Xem đáp án

Đáp án: B. Set<String>: không đảm bảo thứ tự.

💼 Interview Corner

1. How do you handle multiple windows?

  • 🇻🇳 Dịch: Xử lý nhiều cửa sổ?
  • Suggested answer (EN): Save the main handle, wait with numberOfWindowsToBe, loop over getWindowHandles() to switch to the new one, and switch back to the main handle after closing.
  • Giải thích (VI): Không dựa vào thứ tự của Set.
  • Follow-up: What exception if you forget to switch back?

2. How do you handle an iframe?

  • 🇻🇳 Dịch: Xử lý iframe?
  • Suggested answer (EN): Switch into it with frameToBeAvailableAndSwitchToIt, work with its elements, and leave with switchTo().defaultContent().
  • Giải thích (VI): Phần tử trong iframe không thấy từ trang chính.
  • Follow-up: WYSIWYG editors need what extra step?

📌 Lesson Summary

Kiến thức cần nhớ

  • Alert không phải HTML: switchTo().alert()
  • iframe: vào → làm → defaultContent()
  • Window: lưu handle chính, chờ số cửa sổ, chuyển, quay lại

Method / lệnh cần biết

  • alertIsPresent, accept/dismiss/sendKeys, frameToBeAvailableAndSwitchToIt, getWindowHandles, switchTo().window/newWindow

Điểm dễ nhầm lẫn

  • Alert ≠ modal HTML
  • defaultContent ≠ parentFrame
  • close cửa sổ phụ rồi phải switch lại
