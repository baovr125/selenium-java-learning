1. Bảng method

Method Trả về Ý nghĩa 🧩 Trong dự án
get(String url) void Mở URL; chờ trang load theo PageLoadStrategy Tất cả Exercise

navigate().to(URL url) void Nhận đối tượng java.net.URL —

navigate().forward() void Tiến tới (nút Forward) —

2. get() vs navigate().to()

Về chức năng gần như giống nhau: cả hai tải URL và chờ load. Khác biệt:

get() navigate().to()
Thuộc WebDriver Navigation
Nhận String String hoặc URL
Dùng Mở trang ban đầu Khi chuỗi điều hướng (to → back → forward)
Hành vi Cùng cơ chế bên dưới

Quy ước thực tế: get() cho lần mở đầu; navigate() khi thao tác lịch sử.

3. Ví dụ chuỗi điều hướng

java
driver.get("https://the-internet.herokuapp.com/login");
driver.findElement(By.id("username")).sendKeys("tomsmith");
driver.findElement(By.id("password")).sendKeys("SuperSecretPassword!");
driver.findElement(By.cssSelector("button[type='submit']")).click();   // → /secure

driver.navigate().back();       // về /login
driver.navigate().forward();    // lại /secure
driver.navigate().refresh();    // tải lại /secure
System.out.println(driver.getCurrentUrl());   // .../secure

⚠️ Sau back()/refresh() mọi WebElement tìm trước đó đều stale (02) — phải tìm lại.

4. getTitle() và getCurrentUrl() — dùng để xác minh

🧩 EnvironmentCheckTest: Assert.assertEquals(driver.getTitle(), "The Internet"). 🧩 Exercise01: driver.getCurrentUrl().endsWith("/secure").

⚠️ Đọc getCurrentUrl()/getTitle() ngay sau click() có thể trả giá trị cũ nếu trang chưa chuyển. Đúng cách:

java
wait.until(ExpectedConditions.urlContains("/secure"));
wait.until(ExpectedConditions.titleIs("Secure Area"));

(Xem 05.)

5. getPageSource()

Trả HTML hiện tại của DOM (đã được JavaScript thay đổi), không phải HTML gốc server gửi. Dùng để debug, hoặc kiểm tra một chuỗi xuất hiện: driver.getPageSource().contains("Welcome"). Không nên dùng làm cách chính để assert (chậm, dễ lệch); ưu tiên locator.

6. close() vs quit()

close() quit()
Đóng Cửa sổ/tab đang focus Toàn bộ cửa sổ của session
Session Còn nếu còn cửa sổ khác Kết thúc
Process driver (chromedriver) Có thể còn chạy Dừng
Giải phóng tài nguyên Một phần Đầy đủ
Dùng khi Đóng tab phụ rồi switchTo().window(main) @AfterMethod/@AfterClass
Sau khi gọi Phải switchTo().window(...) sang cửa sổ còn lại, nếu không lệnh sau lỗi NoSuchWindowException Không dùng được driver nữa
java
String main = driver.getWindowHandle();
// ... mở tab mới, làm việc ...
driver.close();                          // đóng tab phụ
driver.switchTo().window(main);          // PHẢI chuyển lại
...
driver.quit();                           // cuối test

🧩 BaseTest.tearDown() dùng quit() (đúng). Nếu thay bằng close() khi chỉ có 1 cửa sổ, Chrome đóng nhưng process chromedriver.exe có thể sót lại trong Task Manager (rò rỉ tài nguyên khi chạy nhiều test).

7. Mở tab/cửa sổ mới (Selenium 4)

java
driver.switchTo().newWindow(WindowType.TAB);       // tab mới và tự chuyển sang
driver.get("https://the-internet.herokuapp.com/windows");

Chi tiết 06.

8. Page load và đồng bộ hoá điều hướng

  • get() chặn (block) đến khi load xong (mặc định NORMAL) hoặc đến pageLoadTimeout (🧩 30 s) ⇒ quá hạn ném TimeoutException.
  • Với SPA (React/Angular) chuyển trang bằng JS, trình duyệt không "load" lại ⇒ Selenium không biết đã xong ⇒ phải tự chờ bằng urlContains, visibilityOfElementLocated...
  • Click link gây điều hướng: Selenium (Chrome) thường chờ trang mới load khi click() thuộc dạng điều hướng, nhưng đừng dựa vào đó cho trang phức tạp.

9. ✅ Best Practices

  1. get() cho mở trang; chờ điều kiện (URL/element) sau khi điều hướng bằng click.
  2. Không Thread.sleep() sau get().
  3. Luôn quit() trong teardown.
  4. Sau back/refresh tìm lại phần tử.
  5. Dùng hằng số cho URL (🧩 private static final String LOGIN_URL).

10. ⚠️ Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
TimeoutException ở get() Trang chậm/ngoại lệ mạng Tăng pageLoadTimeout, PageLoadStrategy.EAGER, kiểm tra mạng
NoSuchWindowException Dùng driver sau khi close() cửa sổ switchTo().window()
Assert URL sai Đọc quá sớm wait.until(urlContains(...))
InvalidArgumentException: invalid argument URL thiếu https:// Dùng URL đầy đủ

💼 Interview Corner

1. What is the difference between close() and quit()?

  • 🇻🇳 Dịch: close() khác quit()?
  • Suggested answer (EN): close() closes the current window or tab; quit() closes all windows and ends the session and driver process. I use quit() in teardown.
  • Giải thích (VI): Sau close() phải switchTo().window(...).
  • Follow-up: What leaks if you only call close()?

2. Why not read getCurrentUrl() right after a click?

  • 🇻🇳 Dịch: Vì sao không đọc getCurrentUrl() ngay sau click?
  • Suggested answer (EN): Navigation may not have finished, so I wait with urlContains or titleIs before asserting.
  • Giải thích (VI): Đồng bộ hoá.
  • Follow-up: What about single-page apps?

📌 Lesson Summary

Kiến thức cần nhớ

  • get, navigate() (to/back/forward/refresh)
  • getTitle, getCurrentUrl, getPageSource
  • close đóng cửa sổ, quit kết thúc session

Method / lệnh cần biết

  • urlContains, titleIs, switchTo().newWindow, getWindowHandle

Điểm dễ nhầm lẫn

  • close ≠ quit
  • back/refresh làm phần tử cũ stale
  • getPageSource là HTML hiện tại, không phải HTML gốc
