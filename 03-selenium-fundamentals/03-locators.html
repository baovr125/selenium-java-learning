Selenium: Locators (cách tìm phần tử)

🎯 Learning Objectives

Sau bài này bạn có thể:

  • Viết 8 loại locator
  • Viết CSS Selector và XPath (tương đối, trục, vị trí)
  • Chọn locator ổn định, dễ bảo trì
  • Kiểm tra locator bằng DevTools

📋 Prerequisites

  • WebDriver

☕ Java ↔ Selenium

By là class tiện ích tạo locator; locator nên là private final By trong Page Object.

1. By và findElement

  • Locator (bộ định vị) mô tả cách tìm một phần tử trong DOM: By.id("username").
  • driver.findElement(by) → trả một WebElement (phần tử đầu tiên khớp) hoặc ném NoSuchElementException.
  • driver.findElements(by) → trả List<WebElement>; rỗng nếu không tìm thấy, không ném exception.
  • webElement.findElement(by) → tìm bên trong phần tử đó (phạm vi hẹp hơn).

🧩 Exercise01_LoginTest, Exercise03_WebTablesTest (dùng row.findElements(By.tagName("td"))).

2. Tám loại locator

Dựa trên HTML của trang login (site demo):

html
<input type="text" name="username" id="username">
<input type="password" name="password" id="password">
<button class="radius" type="submit"><i class="fa fa-2x fa-sign-in"> Login</i></button>
<div id="flash" class="flash success">You logged into a secure area!</div>
# Locator Ví dụ Điểm mạnh Điểm yếu
1 ID By.id("username") Nhanh, thường duy nhất, ổn định Không phải phần tử nào cũng có; ID sinh động (id="ember123") thì vô dụng
2 Name By.name("password") Ổn định với form Có thể trùng (radio button cùng name)
3 ClassName By.className("radius") Ngắn Chỉ nhận MỘT tên class (không có khoảng trắng); class hay đổi/không duy nhất
4 TagName By.tagName("td") Tốt để lấy danh sách (td, a, li) Quá chung chung cho một phần tử cụ thể
5 LinkText By.linkText("<chữ của liên kết>") Dễ đọc Chỉ cho <a>; khớp toàn bộ chữ, nhạy hoa/thường; đổi ngôn ngữ thì hỏng
6 PartialLinkText By.partialLinkText("Elemental") Linh hoạt Có thể khớp nhiều link
7 CSS Selector By.cssSelector("#checkboxes input[type='checkbox']") Mạnh, nhanh, ngắn, đọc được Không đi lên cha; không chọn theo text
8 XPath By.xpath("//button[@type='submit']") Mạnh nhất: đi lên/xuống, theo text, vị trí Dài, dễ gãy, chậm hơn CSS một chút

🧩 Dự án dùng: id, name, className, xpath, cssSelector, tagName. Chưa dùng linkText, partialLinkText.

2.1. Từng method By.* làm gì

Mỗi method By.xxx(...) chỉ tạo một "bản mô tả cách tìm" (đối tượng By) — chưa tìm gì. Việc tìm thật chỉ xảy ra khi bạn đưa nó cho findElement/findElements.

By.id(String id)

  • Làm gì: khớp phần tử có thuộc tính id bằng đúng chuỗi này.
  • Khớp phần tử: <input id="username"> ← By.id("username").
  • Lưu ý: id lý thuyết là duy nhất trong trang, nên đây là lựa chọn đầu tiên nên thử. Không dùng được với id sinh tự động (id="ember123" đổi mỗi lần tải).

By.name(String name)

  • Làm gì: khớp phần tử có thuộc tính name bằng đúng chuỗi.
  • Khớp phần tử: <input name="password"> ← By.name("password").
  • Lưu ý: nhiều phần tử có thể cùng name (nhóm radio) → findElement lấy cái đầu tiên; dùng findElements để lấy cả nhóm.

By.className(String className)

  • Làm gì: khớp phần tử có một class bằng đúng chuỗi (phần tử có thể còn class khác).
  • Khớp phần tử: <div class="flash success"> ← By.className("flash") và By.className("success").
  • Lưu ý: không nhận nhiều class có khoảng trắng ("flash success" → InvalidSelectorException). Cần cả hai class → By.cssSelector(".flash.success").

By.tagName(String tag)

  • Làm gì: khớp theo tên thẻ HTML.
  • Khớp phần tử: By.tagName("td") khớp mọi <td>.
  • Lưu ý: gần như luôn dùng với findElements hoặc để tìm trong một phần tử đã có (row.findElements(By.tagName("td")) — 🧩 Ex3).

By.linkText(String text)

  • Làm gì: khớp thẻ <a> có chữ hiển thị bằng đúng chuỗi (không phân biệt khoảng trắng đầu/cuối, phân biệt hoa thường).
  • Khớp phần tử: <a href="/abtest">A/B Testing</a> ← By.linkText("A/B Testing").
  • Lưu ý: chỉ cho link; website đổi ngôn ngữ thì hỏng.

By.partialLinkText(String text)

  • Làm gì: như linkText nhưng chỉ cần chữ hiển thị của link chứa chuỗi.
  • Khớp phần tử: By.partialLinkText("Elemental") khớp <a>Elemental Selenium</a>.
  • Lưu ý: có thể khớp nhiều link; dùng chuỗi đủ đặc trưng.

By.cssSelector(String css)

  • Làm gì: khớp theo CSS selector — cùng cú pháp bạn dùng để định kiểu CSS (mục 3).
  • Khớp phần tử: By.cssSelector("#checkboxes input[type='checkbox']").
  • Lưu ý: cú pháp sai → InvalidSelectorException. Không đi lên phần tử cha, không chọn theo chữ.

By.xpath(String xpath)

  • Làm gì: khớp theo biểu thức XPath (mục 4) — duyệt cây DOM lên/xuống, theo text, theo vị trí.
  • Khớp phần tử: By.xpath("//button[text()='Add Element']").
  • Lưu ý: mạnh nhất nhưng dài và dễ gãy khi DOM đổi.
Muốn khớp Dùng Ghi nhớ
Một phần tử có id By.id Nhanh, ổn định nhất
Nhóm cùng name (radio) By.name + findElements
Phần tử có một class By.className Nhiều class → CSS
Nhiều class cùng lúc By.cssSelector(".a.b")
Mọi thẻ cùng loại By.tagName + findElements
Link theo chữ đầy đủ By.linkText
Link theo một phần chữ By.partialLinkText
Quan hệ cha-con, thuộc tính By.cssSelector Ưu tiên
Theo text, đi lên cha, vị trí By.xpath Khi CSS không đủ

⚠️ Cạm bẫy của className

java
By.className("flash success");   // ❌ InvalidSelectorException: compound class names not permitted
By.className("flash");           // ✅
By.cssSelector(".flash.success") // ✅ cách đúng để khớp cả hai class

3. CSS Selector — cú pháp cần thuộc

Mục đích CSS Ví dụ
Theo id #id #username
Theo class .class .radius
Nhiều class .a.b .flash.success
Theo tag tag td
Theo thuộc tính [attr='v'] input[type='checkbox']
Chứa chuỗi [attr*='v'] a[href*='download']
Bắt đầu / kết thúc [attr^='v'] / [attr$='v'] img[src$='.png']
Con trực tiếp A > B #checkbox-example > button
Hậu duệ A B #checkboxes input
Phần tử thứ n :nth-child(n) table tr:nth-child(2)
Phần tử cuối :last-child tr:last-child

🧩 Ví dụ trong dự án: #checkboxes input[type='checkbox'], .figcaption h5, #input-example button, .modal-title h3.

4. XPath — cú pháp cần thuộc

Mục đích XPath
Tuyệt đối (tránh) /html/body/div[2]/...
Tương đối //input[@id='username']
Theo text chính xác //button[text()='Add Element'] 🧩
Chứa text //a[contains(text(),'Elemental')] hoặc //a[contains(.,'Elemental')]
Chứa thuộc tính //div[contains(@class,'flash')]
Nhiều điều kiện //input[@type='text' and @name='username']
Vị trí (//input)[2], //tr[1], //tr[last()], //tr[last()-1] 🧩
Đi lên cha //input[@id='username']/.. hoặc /parent::div
Anh em kế tiếp //label[text()='Name']/following-sibling::input
Tổ tiên //td/ancestor::table
Bên trong phần tử đã tìm .//td (có dấu chấm)

🧩 Exercise03: //table[@id='table1']/tbody/tr[last()-1].

⚠️ Lỗi XPath kinh điển: trong row.findElement(By.xpath("//td")), dấu // bắt đầu từ gốc tài liệu, không phải từ row. Phải viết .//td.

⚠️ contains(text(), '...') chỉ xét text node trực tiếp đầu tiên; khi text bị tách bởi thẻ con, contains(., '...') an toàn hơn.

5. Selenium 4: Relative Locators

java
import static org.openqa.selenium.support.locators.RelativeLocator.with;

WebElement pwd  = driver.findElement(By.id("password"));
WebElement user = driver.findElement(with(By.tagName("input")).above(pwd));

Các method (gọi nối sau with(By)):

Method Làm chính xác gì Ví dụ
with(By) Bắt đầu: chọn loại phần tử muốn tìm (thường By.tagName) with(By.tagName("input"))
above(WebElement \| By) Phần tử nằm phía trên phần tử tham chiếu Ô username nằm trên ô password
below(WebElement \| By) Phần tử nằm phía dưới phần tử tham chiếu Nút Login dưới ô password
toLeftOf(WebElement \| By) Phần tử nằm bên trái phần tử tham chiếu Nhãn bên trái ô nhập
toRightOf(WebElement \| By) Phần tử nằm bên phải phần tử tham chiếu Nút bên phải ô tìm kiếm
near(WebElement \| By) Phần tử gần phần tử tham chiếu (mặc định trong khoảng 100 px) near(el, 50) đổi khoảng cách

Có thể nối nhiều điều kiện: with(By.tagName("input")).above(pwd).toRightOf(label). Dùng khi phần tử không có thuộc tính tốt nhưng vị trí tương đối với phần tử khác ổn định. Không thay thế CSS/XPath tốt.

7. Chọn locator ổn định và dễ bảo trì

Thứ tự ưu tiên khuyến nghị:

  1. id ổn định (không sinh ngẫu nhiên)
  2. thuộc tính dành cho test: data-testid, data-test, data-qa (nhờ dev thêm — tốt nhất)
  3. name
  4. CSS có nghĩa: form#login button[type='submit']
  5. XPath theo thuộc tính/text ổn định
  6. ❌ Tránh: XPath tuyệt đối, nth-child sâu, class do framework sinh (css-1x2y3z), locator theo vị trí khi dữ liệu có thể đổi thứ tự

Nguyên tắc:

Nguyên tắc Lý do
Ngắn nhất mà vẫn duy nhất Ít gãy khi DOM đổi
Dựa vào ý nghĩa, không dựa vào cấu trúc Layout đổi thường xuyên
Kiểm tra tính duy nhất trong DevTools ($$("css"), $x("xpath")) Tránh khớp nhầm
Gom locator vào một chỗ (Page Object) Sửa 1 nơi
Tránh text hiển thị nếu web đa ngôn ngữ Text đổi theo locale

🧩 So sánh trong dự án: By.xpath("//button[text()='Add Element']") rất dễ đọc, nhưng gãy nếu đổi nhãn nút; một data-testid sẽ bền hơn.

8. Kiểm tra locator bằng DevTools

  1. F12 → tab Elements → Ctrl+F gõ CSS hoặc XPath → xem "1 of 1".
  2. Console: $$("#checkboxes input") (CSS, trả mảng), $x("//button") (XPath).
  3. Phải trả về đúng số phần tử bạn muốn.

✅ Best Practices

  1. Ưu tiên id/data-testid; CSS trước XPath.
  2. Locator duy nhất, ngắn, có nghĩa.
  3. Lưu By, không lưu WebElement lâu.
  4. Kiểm tra locator trong DevTools trước khi đưa vào code.
  5. Dùng findElements(...).isEmpty() để kiểm tra tồn tại.

💼 Interview Corner

1. How do you choose a stable locator?

  • 🇻🇳 Dịch: Chọn locator ổn định thế nào?
  • Suggested answer (EN): Prefer a unique ID or data-testid, then name, a short CSS selector, then XPath on stable attributes; avoid absolute XPath and generated class names, and verify uniqueness in DevTools.
  • Giải thích (VI): Gom locator vào Page Object.
  • Follow-up: What if IDs are dynamic?

2. CSS vs XPath?

  • 🇻🇳 Dịch: CSS khác XPath?
  • Suggested answer (EN): CSS is shorter and usually faster but cannot select by text or go to a parent; XPath can use text, axes and positions but is longer and more fragile.
  • Giải thích (VI): Ưu tiên CSS khi đủ dùng.
  • Follow-up: Write an XPath for the last table row.

📌 Lesson Summary

Kiến thức cần nhớ

Method / lệnh cần biết

  • By.id/name/className/tagName/linkText/partialLinkText/cssSelector/xpath

Điểm dễ nhầm lẫn

  • className không nhận khoảng trắng
  • //td ≠ .//td
  • Relative locator (above, near) không thay CSS/XPath tốt
