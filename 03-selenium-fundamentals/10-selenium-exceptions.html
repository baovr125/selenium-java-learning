1. Cây exception của Selenium

Tất cả đều là unchecked (kế thừa RuntimeException), nên Java không bắt buộc try/catch.

text

 ├─ ElementClickInterceptedException
 ├─ InvalidSelectorException
 ├─ TimeoutException
 ├─ SessionNotCreatedException
 ├─ UnhandledAlertException
 └─ JavascriptException ...

Cấu trúc cụ thể có thể khác chút giữa các phiên bản; hãy dùng tên lớp để tra Javadoc của 4.52.0.

2.1. Một dòng code tái hiện cho từng exception

Học bằng cách gây ra lỗi có chủ đích: biết dòng code nào sinh ra lỗi nào, bạn sẽ nhận ra nó ngay khi gặp.

Exception Dòng code gây lỗi (tình huống) Lỗi do ai
NoSuchElementException driver.findElement(By.id("khong-ton-tai")) Locator sai, hoặc phần tử chưa xuất hiện
TimeoutException wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("khong-ton-tai"))) Điều kiện không đạt trong thời gian chờ
StaleElementReferenceException el = findElement(...); driver.navigate().refresh(); el.click(); Dùng handle cũ sau khi DOM đổi
ElementNotInteractableException driver.findElement(By.id("hidden-input")).sendKeys("x") (phần tử đang display:none) Phần tử có nhưng không tương tác được
ElementClickInterceptedException click() nút khi có modal/overlay đang che Có phần tử khác nhận click
InvalidSelectorException By.className("a b") hoặc XPath sai cú pháp Viết locator sai
NoSuchWindowException driver.close(); driver.getTitle(); (chỉ có một cửa sổ, vừa đóng) Dùng cửa sổ đã đóng
NoSuchFrameException driver.switchTo().frame("khong-co") Tên/id iframe sai hoặc iframe chưa tải
NoAlertPresentException driver.switchTo().alert() khi chưa có popup Gọi quá sớm
UnhandledAlertException Có popup đang mở mà gọi driver.findElement(...) Chưa xử lý popup
SessionNotCreatedException new ChromeDriver() khi Chrome và driver không tương thích Môi trường
JavascriptException js.executeScript("return abc.def;") (biến abc không tồn tại) Script sai

Một số dòng trên (ví dụ driver.close(); driver.getTitle();) có thể ra loại exception khác nhau tuỳ driver/phiên bản; mục đích là nhớ tình huống gây lỗi.

⚠️ Bẫy import: NoSuchElementException bị "ambiguous"

Cả java.util và org.openqa.selenium đều có class tên NoSuchElementException. Nếu bạn dùng import kiểu * cho cả hai, trình biên dịch báo:

text
error: reference to NoSuchElementException is ambiguous
  both class java.util.NoSuchElementException and class org.openqa.selenium.NoSuchElementException match

(Lỗi này đã gặp thật khi kiểm tra các ví dụ của tài liệu.) Cách xử lý: import tường minh class của Selenium và tránh import java.util.*; song song với org.openqa.selenium.*:

java
import org.openqa.selenium.NoSuchElementException;   // đúng class cần dùng
import java.util.List;                                // import từng class của java.util

Dự án Selenium1 tránh được vì import từng class (ví dụ import java.util.List;).

4. TimeoutException vs NoSuchElementException

NoSuchElementException TimeoutException
Nguồn findElement ngay lúc gọi wait.until(...) hết giờ (hoặc get() quá hạn)
Ý nghĩa "Bây giờ không thấy" "Đã chờ đủ lâu mà điều kiện không đúng"
Bên trong Wait WebDriverWait nuốt và thử lại Ném khi hết giờ (nguyên nhân gốc là NoSuchElement... có trong "caused by")
Hướng sửa Thêm Wait/ sửa locator Điều kiện/locator/timeout

5. Nên try/catch khi nào?

java
// ❌ Nuốt lỗi — test pass giả
try { driver.findElement(By.id("x")).click(); } catch (Exception e) { }

// ✅ Có mục đích: phần tử tuỳ chọn (banner cookie có thể không xuất hiện)
try {
    new WebDriverWait(driver, Duration.ofSeconds(3))
        .until(ExpectedConditions.elementToBeClickable(By.id("accept-cookies"))).click();
} catch (TimeoutException ignored) {
    // banner không xuất hiện — bình thường
}

// ✅ Retry khi stale
for (int i = 0; i < 3; i++) {
    try {
        driver.findElement(By.id("save")).click();
        break;
    } catch (StaleElementReferenceException e) {
        if (i == 2) throw e;      // hết lượt thử thì ném lại
    }
}

// ✅ Kiểm tra tồn tại mà không dùng exception
boolean has = !driver.findElements(By.id("flash")).isEmpty();

Quy tắc:

  1. Chỉ bắt loại exception cụ thể, tránh catch (Exception e) rỗng.
  2. Bắt thì phải có hành động: thử lại, ghi log, ném lại, hoặc đường đi thay thế có chủ ý.
  3. Không dùng exception thay if. Ưu tiên findElements(...).isEmpty().
  4. Trong test, để exception lan ra để TestNG ghi nhận fail; Assert có message rõ ràng.

🧩 Dự án gần như không catch — chỉ có try/finally trong main() để tearDown(); cách tiếp cận đúng cho test.

6. try/finally trong main() (🧩)

java
try {
    test.setup();
    test.testLoginSuccess();
} finally {
    test.tearDown();      // luôn dọn dẹp dù fail
}

Khi chạy bằng TestNG/Maven, @AfterMethod đảm nhận việc này (TestNG gọi tearDown kể cả test fail). Mặc định @AfterMethod vẫn chạy khi test fail (trừ khi cấu hình khác).

7. Assertion Error khác Exception Selenium

AssertionError (TestNG Assert) Exception Selenium
Ý nghĩa Kết quả sai so với kỳ vọng Test không thể tiếp tục (không thấy/không bấm được...)

8. Xử lý các tình huống điển hình

Tình huống Mô tả Giải pháp
Flaky NoSuchElementException Lúc có lúc không Wait đúng điều kiện
StaleElement sau AJAX Lưu By; stalenessOf; retry có giới hạn
Click bị chặn Có overlay Chờ overlay biến mất
Phần tử trong iframe frameToBeAvailableAndSwitchToIt
Shadow DOM Locator thường không xuyên qua element.getShadowRoot().findElement(...) (Selenium 4)
Alert bất ngờ UnhandledAlertException ⇒ xử lý alert

✅ Best Practices

  1. Biết exception nào ⇒ nguyên nhân nào.
  2. Fail nhanh, thông báo rõ (Assert có message — 🧩 dự án làm tốt).
  3. Không nuốt exception.
  4. Retry chỉ cho lỗi tạm thời đã hiểu (stale), có giới hạn lượt.
  5. Chụp ảnh màn hình khi fail để điều tra (10).

💼 Interview Corner

1. TimeoutException vs NoSuchElementException?

  • 🇻🇳 Dịch: Khác nhau?
  • Suggested answer (EN): NoSuchElementException is thrown immediately by findElement; TimeoutException is thrown when an explicit wait runs out; inside a wait NoSuchElementException is ignored and retried.
  • Giải thích (VI): Một cái "ngay lúc này", một cái "đã chờ đủ lâu".
  • Follow-up: How would you debug a timeout?

2. Should you catch exceptions in tests?

  • 🇻🇳 Dịch: Có nên catch trong test?
  • Suggested answer (EN): Rarely: only for a clear purpose such as an optional element or a bounded retry; never an empty catch that hides failures.
  • Giải thích (VI): Để test fail đúng chỗ.
  • Follow-up: Give a legitimate example.

📌 Lesson Summary

Kiến thức cần nhớ

  • Mọi exception Selenium là unchecked
  • Biết cặp exception ⇒ nguyên nhân ⇒ cách xử lý
  • catch chỉ khi có mục đích

Method / lệnh cần biết

  • NoSuchElementException, TimeoutException, StaleElementReferenceException, ElementClickInterceptedException, ElementNotInteractableException

Điểm dễ nhầm lẫn

  • Timeout ≠ NoSuchElement
  • Failure (assert) ≠ Error (exception)
  • Bẫy import ambiguous
