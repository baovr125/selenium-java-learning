1. Khái niệm

Branch cho phép làm một việc tách biệt khỏi main. Xong thì gộp (merge) lại.

text
main:      A ── B ───────── M          M = merge commit (3-way)
                 \         /
feature/login:    C ── D ─┘
Cách gộp Kết quả Khi dùng
Merge Giữ nguyên lịch sử, thêm một commit gộp (hoặc fast-forward nếu main không đổi) Mặc định, an toàn
Rebase Viết lại commit của bạn lên đầu nhánh đích → lịch sử thẳng Làm gọn nhánh cá nhân trước khi chia sẻ

Quy tắc vàng của rebase: không rebase nhánh đã push và người khác đang dùng (viết lại lịch sử sẽ làm đồng đội hỏng).

2. Syntax

bash
git branch                        # liệt kê nhánh
git switch -c feature/add-logging # tạo và chuyển sang nhánh mới (hoặc: git checkout -b ...)
git switch main                   # chuyển nhánh
git merge feature/add-logging     # gộp nhánh vào nhánh HIỆN TẠI
git rebase main                   # đặt commit của nhánh hiện tại lên đầu main
git branch -d feature/add-logging # xoá nhánh đã gộp
git push -u origin feature/add-logging

Quy ước tên nhánh: feature/<mô-tả>, fix/<mô-tả>, chore/<mô-tả> (ví dụ feature/page-object-login, fix/stale-element-ex10).

3. Ví dụ (đã chạy thật)

Ví dụ 1 — Nhánh phân kỳ

Từ commit đầu 26ba9ac, nhánh feature/a và main cùng sửa một dòng pom.xml:

bash
git log --oneline --graph --all
text
* cf8c370 Bump selenium to 4.54.0 (main)
| * fd28a31 Bump selenium to 4.53.0 (A)
|/
* 26ba9ac Initial commit: Maven project with wrapper

Ví dụ 2 — Merge sinh conflict

bash
git checkout main
git merge feature/a
text
Auto-merging pom.xml
CONFLICT (content): Merge conflict in pom.xml
Automatic merge failed; fix conflicts and then commit the result.

Cách xử lý: xem Pull Request và Conflicts. Nếu muốn huỷ gộp và quay lại trạng thái cũ: git merge --abort.

Ví dụ 3 — Rebase cũng có thể conflict

bash
git checkout feature/a
git rebase main
text
Could not apply fd28a31... Bump selenium to 4.53.0 (A)
interactive rebase in progress; onto cf8c370

Khi rebase dừng vì conflict: sửa file → git add <file> → git rebase --continue; hoặc bỏ cuộc: git rebase --abort.

Ví dụ 4 — Luồng làm việc nhóm thường dùng

bash
git switch main && git pull                 # 1. main mới nhất
git switch -c feature/page-object-login     # 2. nhánh riêng
# ... code, .\mvnw.cmd clean test ...
git add src/ && git commit -m "Add LoginPage and LoginPomTest"
git push -u origin feature/page-object-login
# 3. mở Pull Request, review, merge vào main
git switch main && git pull && git branch -d feature/page-object-login

4. Ứng dụng với dự án Selenium Maven (Real-world)

  • Mỗi thay đổi pom.xml (nâng Selenium, thêm thư viện) nên một nhánh/PR riêng — dễ review, dễ hoàn tác.
  • Conflict phổ biến nhất của team automation: pom.xml (hai người cùng thêm dependency hoặc đổi selenium.version) và testng.xml (cùng thêm class). Cách giải quyết ở bài kế.
  • Sau merge luôn chạy .\mvnw.cmd clean test để chắc kết quả gộp vẫn xanh.
  • Không commit trực tiếp lên main khi có CI/branch protection.

5. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
Commit nhầm lên main Quên tạo nhánh git switch -c feature/x (giữ commit), sau đó đưa main về lại bằng cách hỏi mentor/git reset cẩn thận
Your local changes would be overwritten by merge Có thay đổi chưa commit commit hoặc git stash trước
Rebase nhánh đã push rồi push bị từ chối Lịch sử bị viết lại Chỉ rebase nhánh cá nhân; nếu buộc, git push --force-with-lease và báo cả nhóm
Quên đang ở nhánh nào git branch --show-current, git status -sb
Merge xong test đỏ Hai thay đổi đúng riêng, sai khi gộp clean test sau mỗi merge
Nhánh sống quá lâu Conflict khổng lồ Merge/rebase main thường xuyên

💼 Interview Corner

1. Merge vs rebase?

  • 🇻🇳 Dịch: Merge hay rebase?
  • Suggested answer (EN): Merge keeps history and adds a merge commit, rebase rewrites my commits on top of the target for linear history; I rebase only my own unpublished branches.
  • Giải thích (VI): Quy tắc vàng.
  • Follow-up: What if a rebase conflicts?

2. Why use feature branches?

  • 🇻🇳 Dịch: Vì sao dùng nhánh tính năng?
  • Suggested answer (EN): They isolate work, enable review through pull requests and keep main stable.
  • Giải thích (VI): CI chạy trên PR.
  • Follow-up: How long should a branch live?

📌 Lesson Summary

Kiến thức cần nhớ

  • Nhánh tách việc; merge giữ lịch sử; rebase làm thẳng lịch sử
  • Không rebase nhánh đã chia sẻ
  • Sau merge luôn clean test

Method / lệnh cần biết

  • switch -c, branch, merge, rebase, merge --abort, rebase --abort

Điểm dễ nhầm lẫn

  • Merge vào nhánh hiện tại
  • Rebase viết lại lịch sử
  • Nhánh sống lâu → conflict lớn
