1. Khái niệm

Git là hệ thống quản lý phiên bản phân tán: mỗi máy có đầy đủ lịch sử. GitHub/GitLab là dịch vụ lưu repository trên mạng (khác với Git).

text
 Working tree ──git add──► Staging area (index) ──git commit──► Local repository ──git push──► Remote (origin)
   (file bạn sửa)           (chọn thứ sẽ commit)                (lịch sử trên máy)             ◄──git fetch/pull──
Khái niệm Ý nghĩa
Commit Một "ảnh chụp" (snapshot) có thông điệp, tác giả, mã băm
Branch Nhánh phát triển (con trỏ tới một commit)
Remote Bản repo ở server, thường tên origin
HEAD Vị trí bạn đang đứng (nhánh/commit hiện tại)

2. Syntax

bash
git config --global user.name  "Ten Ban"          # một lần trên máy
git config --global user.email "ban@example.com"

git clone <url>                  # tải repo về
git status                       # tình trạng thay đổi
git add pom.xml                  # đưa file vào staging (chọn CỤ THỂ)
git diff                         # xem thay đổi chưa staged
git diff --staged                # xem thay đổi đã staged
git commit -m "Thông điệp rõ ràng"
git log --oneline --graph        # lịch sử gọn
git push -u origin <nhánh>       # đẩy lên remote (-u: nhớ nhánh upstream)
git fetch                        # tải thông tin mới, KHÔNG gộp
git pull                         # fetch + merge vào nhánh hiện tại
Lệnh Ghi nhớ
fetch Chỉ xem có gì mới (an toàn)
pull fetch + gộp (có thể sinh conflict)
add <file> Tránh git add . bừa bãi (dễ kéo theo target/)

2.1. Từng lệnh Git làm gì

Cách đọc thẻ: Làm gì · Thay đổi gì · Mức an toàn · Ví dụ · Lưu ý. Mức an toàn: 🟢 chỉ đọc/xem · 🟡 thay đổi nhưng hoàn tác được · 🔴 có thể mất dữ liệu.

Ba "vùng" cần nhớ khi đọc các lệnh bên dưới: working tree (file đang sửa trên đĩa) → git add → staging (danh sách sẽ đưa vào commit) → git commit → repository (lịch sử commit).

git config --global user.name "…" và user.email "…"

  • Làm gì: ghi tên và email sẽ gắn vào mọi commit của bạn. --global = áp dụng cho cả máy; bỏ --global thì chỉ cho repo hiện tại.
  • An toàn: 🟡. Lưu ý: chưa đặt thì commit báo Author identity unknown. Xem cấu hình: git config --list.

git init

  • Làm gì: biến thư mục hiện tại thành repo Git (tạo thư mục ẩn .git).
  • An toàn: 🟡.

git clone <url>

  • Làm gì: tải toàn bộ repo (code + lịch sử) từ remote về máy, đặt remote tên origin.
  • An toàn: 🟢 (chỉ tạo thư mục mới). Ví dụ: git clone https://github.com/user/Selenium1.git.

git status

  • Làm gì: cho biết file nào đã sửa, file nào đã staged, file nào chưa được theo dõi, bạn đang ở nhánh nào.
  • An toàn: 🟢. Dùng: trước mọi lần add/commit. Bản gọn: git status -sb.

git add <file>

  • Làm gì: đưa thay đổi của file vào staging (chọn thứ sẽ có trong commit kế tiếp).
  • An toàn: 🟡 (hoàn tác bằng git restore --staged).
  • Biến thể: git add . đưa mọi thứ trong thư mục (kể cả target/ nếu chưa ignore) → tránh; git add -p chọn từng đoạn thay đổi.

git diff / git diff --staged

  • Làm gì: git diff hiện thay đổi chưa staged; --staged hiện thay đổi đã staged (sẽ vào commit).
  • An toàn: 🟢. Lưu ý: git diff trống không có nghĩa là không có thay đổi — có thể đã add hết, hãy xem --staged.

git commit -m "thông điệp"

  • Làm gì: chụp một snapshot của mọi thứ trong staging thành commit mới, kèm thông điệp, tác giả, mã băm.
  • An toàn: 🟡. Lưu ý: commit chỉ nằm ở máy bạn cho tới khi push. Thông điệp nên nói cái gì và vì sao.
  • Biến thể: git commit --amend sửa commit cuối (🔴 nếu đã push — làm đổi lịch sử).

git log --oneline --graph

  • Làm gì: xem lịch sử: --oneline mỗi commit một dòng, --graph vẽ nhánh.
  • An toàn: 🟢. Biến thể: git log --oneline -- <file> chỉ lịch sử của một file.

git show <commit>

  • Làm gì: xem nội dung một commit (thông điệp + thay đổi). 🟢.

git blame <file>

  • Làm gì: hiện mỗi dòng của file do ai, commit nào sửa lần cuối. 🟢. Dùng tìm "vì sao dòng này có".

git remote -v

  • Làm gì: liệt kê remote và URL fetch/push. 🟢. Dùng kiểm tra đang đẩy lên đâu.

git push -u origin <nhánh>

  • Làm gì: gửi commit của nhánh lên remote origin. -u ghi nhớ nhánh remote tương ứng để lần sau chỉ cần git push.
  • An toàn: 🟡 (người khác sẽ thấy). Lưu ý: bị rejected ... non-fast-forward khi remote có commit mới mà bạn chưa có → pull trước.
  • --force / --force-with-lease: 🔴 ghi đè lịch sử remote; --force-with-lease an toàn hơn (từ chối nếu người khác vừa đẩy). Không dùng trên main.

git fetch

  • Làm gì: tải thông tin commit mới từ remote về nhưng không gộp vào nhánh của bạn.
  • An toàn: 🟢. Dùng khi muốn xem trước có gì mới.

git pull

  • Làm gì: fetch rồi gộp (merge) commit mới vào nhánh hiện tại. git pull --rebase thì dùng rebase thay merge (lịch sử thẳng hơn).
  • An toàn: 🟡 — có thể sinh conflict. Nên commit/stash thay đổi dở trước.
git fetch git pull
Tải commit mới ✅ ✅
Gộp vào nhánh hiện tại ❌ ✅
Có thể sinh conflict Không Có

git restore <file>

  • Làm gì: bỏ thay đổi chưa staged của file, đưa nó về như commit gần nhất.
  • An toàn: 🔴 — thay đổi bị bỏ không lấy lại được. Cần chắc chắn hoặc stash trước.
  • Biến thể: git restore --staged <file> chỉ bỏ khỏi staging (file vẫn giữ nội dung đã sửa) — 🟡.

git reset

  • Làm gì: di chuyển nhánh về một commit khác. Ba chế độ:
Lệnh Commit Staging File trên đĩa An toàn
git reset --soft HEAD~1 Bỏ commit cuối Giữ thay đổi đã staged Giữ 🟡
git reset HEAD~1 (--mixed) Bỏ commit cuối Bỏ staged Giữ 🟡
git reset --hard HEAD~1 Bỏ commit cuối Bỏ Mất thay đổi 🔴
  • Lưu ý: không reset các commit đã push.

git stash / git stash pop / git stash list

  • Làm gì: git stash cất thay đổi chưa commit vào "ngăn kéo" và đưa thư mục về sạch; git stash pop lấy ra và áp lại; git stash list xem những gì đang cất.
  • An toàn: 🟡. Dùng khi cần chuyển nhánh/pull mà đang sửa dở.
Tôi muốn Lệnh
Xem đang có gì thay đổi git status
Xem chi tiết thay đổi git diff / git diff --staged
Chọn file vào commit git add <file>
Chốt thay đổi git commit -m "..."
Gửi lên server git push
Lấy thay đổi người khác (an toàn) git fetch
Lấy và gộp git pull
Bỏ thay đổi một file git restore <file> (🔴)
Cất tạm git stash

3. Ví dụ (đã chạy thật trên repo thử)

Ví dụ 1 — Khởi tạo, commit đầu tiên, đẩy lên remote

bash
git init -b main
git config user.name "Lab" && git config user.email "lab@example.com"
git add pom.xml mvnw mvnw.cmd .mvn/wrapper/ .mvn/maven.config .gitignore
git status --short

Kết quả (rút gọn):

text
A  .gitignore
A  .mvn/maven.config
A  .mvn/wrapper/maven-wrapper.properties
A  mvnw
A  mvnw.cmd
A  pom.xml
bash
git commit -m "Initial commit: Maven project with wrapper"
git remote add origin <url>
git push -u origin main

target/ và .mvn/repository/ không nằm trong danh sách vì .gitignore đã chặn (bài .gitignore).

Ví dụ 2 — Vòng lặp làm việc hằng ngày

bash
git pull                              # 1. cập nhật mã mới nhất
# ... sửa code, chạy .\mvnw.cmd clean test ...
git status                            # 2. xem đã đổi gì
git add src/test/java/tests/LoginTest.java
git diff --staged                     # 3. đọc lại thứ sẽ commit
git commit -m "Add invalid login cases with DataProvider"
git push                              # 4. đẩy lên

Ví dụ 3 — Hoàn tác an toàn

bash
git restore src/test/java/tests/LoginTest.java     # bỏ thay đổi CHƯA staged của file (không hoàn lại được!)
git restore --staged pom.xml                        # bỏ khỏi staging, giữ nguyên nội dung file
git stash                                           # cất tạm thay đổi
git stash pop                                       # lấy lại
git commit --amend -m "Thông điệp đã sửa"           # sửa commit CUỐI (chỉ khi CHƯA push)

5. Lỗi thường gặp

Lỗi Nguyên nhân Cách xử lý
fatal: not a git repository Đứng sai thư mục / chưa git init cd đúng chỗ; git init
Commit nhầm target/ git add . khi chưa có .gitignore git rm -r --cached target + sửa .gitignore
Author identity unknown Chưa git config user.name/email Cấu hình
rejected ... non-fast-forward khi push Remote có commit mới git pull (hoặc pull --rebase) rồi push
git add . kéo theo file nhạy cảm Không kiểm tra git status, add từng file
Mất thay đổi sau git restore Lệnh bỏ thay đổi không hoàn lại Cẩn thận; stash nếu chưa chắc
Thông điệp commit "update" Mơ hồ Viết rõ cái gì và vì sao

💼 Interview Corner

1. What is the difference between Git and GitHub?

  • 🇻🇳 Dịch: Git khác GitHub?
  • Suggested answer (EN): Git is a distributed version control tool; GitHub is a hosting service for Git repositories with pull requests, issues and CI.
  • Giải thích (VI): Git chạy cục bộ.
  • Follow-up: What is a remote?

2. Explain the basic Git workflow.

  • 🇻🇳 Dịch: Quy trình Git cơ bản?
  • Suggested answer (EN): Pull, create a branch, edit, add specific files, commit, push, open a pull request, review and merge.
  • Giải thích (VI): Không commit thẳng vào main.
  • Follow-up: What does git pull do exactly?

📌 Lesson Summary

Kiến thức cần nhớ

  • Working tree → staging → local repo → remote
  • fetch (xem) vs pull (gộp)
  • Add từng file, commit rõ ràng

Method / lệnh cần biết

  • clone, status, add, commit, diff, log, push, fetch, pull, restore, stash

Điểm dễ nhầm lẫn

  • fetch ≠ pull
  • diff ≠ diff --staged
  • restore không hoàn lại được
