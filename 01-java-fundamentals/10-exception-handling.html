1. Khái niệm

Exception là sự kiện bất thường làm chương trình dừng luồng bình thường (không thấy phần tử, chia cho 0, file không tồn tại...). Bạn có thể bắt (catch) để xử lý, hoặc để nó lan ra (test fail).

text
Throwable
 ├─ Error                      (lỗi nghiêm trọng của JVM: OutOfMemoryError — không bắt)
 └─ Exception
     ├─ Checked    (IOException, InterruptedException…) → BẮT BUỘC try/catch hoặc throws
     └─ RuntimeException (Unchecked: NullPointerException, IllegalArgumentException,
                          mọi exception của Selenium…) → không bắt buộc

Quan trọng: mọi exception của Selenium là unchecked (NoSuchElementException, TimeoutException...). Tài liệu chi tiết cho Selenium: Selenium Exceptions.

2. Syntax

java
try {
    // code có thể lỗi
} catch (NumberFormatException e) {       // bắt loại cụ thể
    // xử lý
} catch (IllegalStateException | IllegalArgumentException e) {   // multi-catch
    // xử lý chung
} finally {
    // LUÔN chạy (dọn dẹp)
}

throw new IllegalArgumentException("thông báo");   // chủ động ném
void read() throws IOException { ... }              // khai báo method có thể ném checked exception
try (Scanner sc = new Scanner(file)) { ... }        // try-with-resources: tự đóng tài nguyên
Thành phần Ý nghĩa
catch (X e) Bắt exception loại X (và con của nó); e.getMessage() cho thông báo
finally Chạy dù có lỗi hay không (đóng browser, đóng file)
throw Ném một exception (câu lệnh)
throws Khai báo trên method: "method này có thể ném..."
Thứ tự catch Từ cụ thể đến chung; Exception để cuối

3. Ví dụ code

Ví dụ 1 — try/catch/finally

java
public class Main {
    public static void main(String[] args) {
        try {
            int value = Integer.parseInt("abc");
            System.out.println("không in dòng này " + value);
        } catch (NumberFormatException e) {
            System.out.println("Lỗi: " + e.getMessage());
        } finally {
            System.out.println("finally luôn chạy");
        }
        System.out.println("chương trình tiếp tục");
    }
}
output
Lỗi: For input string: "abc"
finally luôn chạy
chương trình tiếp tục

Ví dụ 2 — Nhiều catch, thứ tự quan trọng

java
public class Main {
    static void run(String input) {
        try {
            int n = Integer.parseInt(input);
            System.out.println(10 / n);
        } catch (NumberFormatException e) {
            System.out.println("Không phải số: " + input);
        } catch (ArithmeticException e) {
            System.out.println("Chia cho 0");
        } catch (Exception e) {                 // chung nhất — để cuối
            System.out.println("Lỗi khác: " + e);
        }
    }

    public static void main(String[] args) {
        run("5");
        run("x");
        run("0");
    }
}
output
2
Không phải số: x
Chia cho 0

Ví dụ 3 — throw và throws

java
public class Main {
    static String browserFor(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("browser không được rỗng");   // unchecked
        }
        return name.toLowerCase();
    }

    static void mightFail() throws Exception {    // checked: khai báo throws
        throw new Exception("lỗi checked");
    }

    public static void main(String[] args) {
        System.out.println(browserFor("CHROME"));
        try {
            browserFor(" ");
        } catch (IllegalArgumentException e) {
            System.out.println("bắt được: " + e.getMessage());
        }
        try {
            mightFail();
        } catch (Exception e) {
            System.out.println("bắt được: " + e.getMessage());
        }
    }
}
output
chrome
bắt được: browser không được rỗng
bắt được: lỗi checked

Ví dụ 4 — try-with-resources và custom exception

java
public class Main {
    static class Session implements AutoCloseable {
        final String name;
        Session(String name) { this.name = name; System.out.println("mở " + name); }
        @Override public void close() { System.out.println("đóng " + name); }
    }

    static class TestDataException extends RuntimeException {   // custom exception
        TestDataException(String msg) { super(msg); }
    }

    public static void main(String[] args) {
        try (Session s = new Session("browser")) {
            System.out.println("đang dùng " + s.name);
            throw new TestDataException("dữ liệu thiếu cột email");
        } catch (TestDataException e) {
            System.out.println("lỗi: " + e.getMessage());
        }
    }
}
output
mở browser
đang dùng browser
đóng browser
lỗi: dữ liệu thiếu cột email

Tài nguyên được đóng tự động trước khi vào catch — cùng tinh thần với driver.quit() trong finally/@AfterMethod.

Ví dụ 5 — Retry bắt exception cụ thể

java
public class Main {
    static int attempts = 0;

    static void flakyClick() {
        attempts++;
        if (attempts < 3) throw new IllegalStateException("stale (lần " + attempts + ")");
        System.out.println("click OK ở lần " + attempts);
    }

    public static void main(String[] args) {
        for (int i = 1; i <= 3; i++) {
            try {
                flakyClick();
                break;
            } catch (IllegalStateException e) {
                System.out.println("thử lại: " + e.getMessage());
                if (i == 3) throw e;           // hết lượt thì ném lại, không nuốt lỗi
            }
        }
    }
}
output
thử lại: stale (lần 1)
thử lại: stale (lần 2)
click OK ở lần 3

4. Ứng dụng trong Selenium (Real-world)

Kiến thức Ví dụ trong dự án / thực tế
try/finally dọn dẹp main() của mọi Exercise: try { setup(); test(); } finally { tearDown(); }
@AfterMethod thay finally BaseTest.tearDown() luôn chạy kể cả test fail, có if (driver != null)
Unchecked Selenium exceptions NoSuchElementException, TimeoutException, StaleElementReferenceException
catch có mục đích catch (TimeoutException ignored) cho banner cookie tuỳ chọn
Retry khi stale Mẫu Ví dụ 5
throws Hàm đọc file dữ liệu: csvLogin() throws IOException (File Handling)
AssertionError Assert.assertEquals(...) ném khi sai → test fail

⚠️ Không viết catch (Exception e) { } rỗng: test sẽ "pass giả". Chỉ bắt khi có hành động rõ ràng (thử lại, ghi log, ném lại).

5. Lỗi thường gặp

Lỗi Nguyên nhân Cách sửa
unreported exception ... must be caught or declared to be thrown Gọi method ném checked exception try/catch hoặc thêm throws
exception X has already been caught catch (Exception) đặt trước catch cụ thể Đặt cụ thể trước
catch rỗng Nuốt lỗi Ghi log/ném lại
NullPointerException Gọi method trên null Kiểm tra null; khởi tạo; Objects.requireNonNull
Mất lỗi gốc khi bọc exception throw new RuntimeException("x") throw new RuntimeException("x", e) giữ cause
Quên đóng tài nguyên Mở file/driver không close/quit try-with-resources / finally
Dùng exception thay if Chậm, khó đọc Dùng findElements(...).isEmpty()

💼 Interview Corner

1. Checked vs unchecked exceptions?

  • 🇻🇳 Dịch: Checked khác unchecked?
  • Suggested answer (EN): Checked exceptions such as IOException must be caught or declared; unchecked ones extend RuntimeException, like NullPointerException and all Selenium exceptions, and need not be declared.
  • Giải thích (VI): Vì vậy code test Selenium ít try/catch.
  • Follow-up: Is TimeoutException checked?

2. When is it acceptable to catch an exception in a test?

  • 🇻🇳 Dịch: Khi nào được catch trong test?
  • Suggested answer (EN): Only for a clear purpose: an optional element like a cookie banner, a bounded retry for a transient error, or cleanup in finally; never an empty catch that hides failures.
  • Giải thích (VI): Luôn ném lại ở lượt thử cuối.
  • Follow-up: How would you rethrow with the original cause?

📌 Lesson Summary

Kiến thức cần nhớ

  • try/catch/finally, throw, throws
  • Checked (bắt buộc xử lý) vs unchecked (Selenium)
  • try-with-resources tự đóng tài nguyên

Method / lệnh cần biết

  • e.getMessage(), throw new X(...), throws X, try (res) {...}

Điểm dễ nhầm lẫn

  • throw (ném) ≠ throws (khai báo)
  • catch cụ thể trước, chung sau
  • Không catch rỗng
