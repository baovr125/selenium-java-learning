1. Biến và kiểu dữ liệu

Kiểu Ví dụ Dùng trong Selenium
int int total = 4; Đếm số dòng bảng, số phần tử
long long y = 0L; Giá trị window.scrollY trả từ JavaScript
boolean boolean ok = el.isDisplayed(); Trạng thái phần tử
String String text = el.getText(); Văn bản, URL, locator
double double due = 50.00; Dữ liệu số tiền (thực tế nên dùng BigDecimal)
Kiểu tham chiếu WebElement, List<WebElement> Đối tượng Selenium

🧩 Exercise01_LoginTest.java:

java
private static final String LOGIN_URL = BASE_URL + "/login"; // hằng số
String actualMessage = successMessageElement.getText();                              // biến cục bộ
  • final: gán một lần, không đổi. static final + UPPER_SNAKE_CASE = hằng số.
  • ⚠️ So sánh chuỗi bằng .equals(), không dùng == (so sánh tham chiếu).
  • var (Java 10+): var driver = new ChromeDriver(); suy luận kiểu ChromeDriver ⇒ mất lợi ích khai báo kiểu WebDriver. Tránh với driver.

2. Method và tham số

java
private List<String> getRowData(By rowLocator) { ... }   // nhận By, trả về List<String>
  • Tham số: dữ liệu đầu vào. Java truyền theo giá trị (với đối tượng là giá trị của tham chiếu).
  • Giá trị trả về: void nếu không trả gì.
  • Varargs: WebElement... others (Exercise01 assertSameElement) cho phép truyền số lượng phần tử tuỳ ý.
  • Overload: cùng tên, khác tham số. Ví dụ sendKeys(CharSequence...); By.xpath(String).

✅ Method nhỏ, một việc, tên là động từ (getRowData, clickAndVerifyToggled). Đây là nền của Reusable Methods và Page Methods.

3. Class và Object

  • Class = bản thiết kế. Object = thực thể tạo từ new.
  • ChromeDriver là class; driver là object. BaseTest là class; mỗi test chạy trên một đối tượng của class con.
java
WebElement button = driver.findElement(By.id("login"));   // button là object

Trong POM, mỗi trang web là một class (LoginPage), mỗi hành động là một method (login(user, pass)), mỗi phần tử là một field.

4. Constructor

Constructor khởi tạo đối tượng khi new. Trong POM nó nhận WebDriver:

java
public class LoginPage {
    private final WebDriver driver;
    private final By usernameInput = By.id("username");

    public LoginPage(WebDriver driver) {   // constructor
        this.driver = driver;              // this: field của đối tượng hiện tại
    }
}
  • Nếu không viết constructor, Java sinh sẵn constructor mặc định không tham số.
  • new WebDriverWait(driver, Duration.ofSeconds(15)) — gọi constructor của WebDriverWait.
  • ⚠️ Constructor không có kiểu trả về; nếu thêm void nó trở thành method thường.

5. Inheritance (kế thừa)

🧩 Đây là cơ chế cốt lõi của dự án: Exercise01_LoginTest extends BaseTest.

java
public class Exercise01_LoginTest extends BaseTest { ... }

Class con thừa hưởng field driver, wait (vì protected) và các method có annotation @BeforeMethod/@AfterMethod. TestNG tự gọi setup() trước từng @Test của class con, dù class con không viết lại.

  • super(...) gọi constructor cha; super.method() gọi method cha.
  • Java chỉ đơn kế thừa class, nhưng đa kế thừa interface.
  • ✅ Dùng kế thừa cho quan hệ "là một" (LoginPage là một BasePage). Đừng lạm dụng.

6. Encapsulation (đóng gói)

Giấu dữ liệu nội bộ, chỉ lộ ra hành vi cần thiết:

java
public class LoginPage {
    private final By usernameInput = By.id("username");   // locator ẩn khỏi test
    public void login(String u, String p) { ... }          // test chỉ biết "login"
}

Lợi ích POM: khi website đổi id, chỉ sửa một chỗ trong LoginPage; test không đổi. Xem framework-design/01.

7. Polymorphism (đa hình)

Cùng một kiểu tham chiếu, nhiều hiện thực:

java
WebDriver driver = new ChromeDriver();   // đổi thành new FirefoxDriver() chỉ sửa dòng này
driver.get(url);                          // gọi ChromeDriver.get() ở runtime
  • Overriding (đa hình runtime): class con viết lại method của cha, ví dụ @Override.
  • Overloading (compile time): cùng tên khác tham số.

8. Interface và Abstract Class

Interface Abstract class
Mục đích Hợp đồng "làm được gì" Khung chung + một phần hiện thực
Field Chỉ hằng public static final Field thường
Kế thừa Implement nhiều interface Chỉ extend một
Constructor Không Có
Ví dụ Selenium WebDriver, WebElement, JavascriptExecutor, TakesScreenshot, Alert BasePage, BaseTest (thường abstract)

🧩 WebDriver là interface. ChromeDriver còn implement JavascriptExecutor — vì vậy dự án mới ép kiểu được:

java
JavascriptExecutor jsExecutor = (JavascriptExecutor) driver;   // Exercise07_InfiniteScrollTest

Ví dụ abstract class cho POM:

java
public abstract class BasePage {
    protected final WebDriver driver;
    protected final WebDriverWait wait;
    protected BasePage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
    }
    public abstract boolean isLoaded();     // mỗi trang tự định nghĩa
}

9. Static và Non-static

static non-static (instance)
Thuộc về Class Từng đối tượng
Gọi ClassName.method() object.method()
Ví dụ Assert.assertEquals(...), Duration.ofSeconds(15), By.id(...) driver.get(...), element.click()

🧩 main(String[] args) trong các test class là static nên phải tự new đối tượng rồi gọi setup():

java
Exercise01_LoginTest test = new Exercise01_LoginTest();
test.setup();

⚠️ Dùng static WebDriver driver khiến mọi test dùng chung một driver và không an toàn khi chạy song song. Dự án dùng field instance — đúng hướng. Muốn song song, dùng ThreadLocal<WebDriver>.

10. List, Set, Map

java
List<WebElement> checkboxes = driver.findElements(By.cssSelector("#checkboxes input[type='checkbox']"));
WebElement first = checkboxes.get(0);          // có thứ tự, cho phép trùng
Collection Đặc điểm Dùng khi
List (ArrayList) Có thứ tự, trùng được Kết quả findElements, các dòng bảng
Set (HashSet) Không trùng getWindowHandles() trả Set<String>
Map (HashMap) Cặp key-value Dữ liệu form: Map<String,String>; cấu hình
java
Set<String> handles = driver.getWindowHandles();     // các tab đang mở
Map<String, String> user = Map.of("username", "tomsmith", "password", "SuperSecretPassword!");

🧩 Exercise03_WebTablesTest dùng List<String> và Arrays.asList(...) để so sánh cả hàng.

⚠️ findElements trả danh sách rỗng, không ném exception, nếu không tìm thấy; findElement mới ném NoSuchElementException.

11. Exception Handling

java
try {
    test.setup();
    test.testLoginSuccess();
} finally {
    test.tearDown();      // luôn chạy
}
Khái niệm Ý nghĩa
try / catch / finally Bắt và xử lý lỗi; finally luôn chạy
Checked exception Phải khai báo/bắt (ví dụ IOException, InterruptedException của Thread.sleep)
Unchecked (RuntimeException) Không bắt buộc. Mọi exception Selenium (NoSuchElementException, TimeoutException...) là unchecked
throw / throws Ném / khai báo

✅ Chỉ catch khi bạn có hành động hợp lý (thử lại, ghi log). Đừng nuốt lỗi bằng catch (Exception e) {} — test sẽ "pass giả". Xem selenium/09.

12. Lambda Expressions

Lambda là cách viết ngắn một hàm ẩn danh để truyền như tham số. Selenium dùng nhiều nhất trong Wait vì Wait.until(Function<? super T, V>).

🧩 Exercise07_InfiniteScrollTest:

java
wait.until(d -> {
    scrollToBottom(jsExecutor);
    return d.findElements(PARAGRAPH_LOCATOR).size() > countBeforeScroll;
});
  • d là tham số (kiểu WebDriver, do compiler suy ra).
  • until gọi lại hàm này theo chu kỳ (mặc định mỗi 500 ms) cho đến khi trả về giá trị truthy (khác null/false) hoặc hết timeout.
  • ⚠️ Biến cục bộ dùng trong lambda phải là final hoặc effectively final — vì vậy code dự án khai báo final int countBeforeScroll = currentCount;.

Lambda khác: list.forEach(e -> System.out.println(e.getText())), Stream: elements.stream().map(WebElement::getText).toList().

13. Generics

Generics cho phép khai báo kiểu tham số hoá, bắt lỗi kiểu tại compile time.

java
List<WebElement> items;            // chỉ chứa WebElement
Wait<WebDriver> wait;              // Wait làm việc với kiểu WebDriver
FluentWait<WebDriver> fluent = new FluentWait<>(driver);   // <> diamond

WebDriverWait extends FluentWait<WebDriver>. until có chữ ký <V> V until(Function<? super T, V> isTrue) — kết quả có kiểu V tuỳ điều kiện: visibilityOfElementLocated trả WebElement, invisibilityOfElementLocated trả Boolean.

java
WebElement flash = wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("flash")));
Boolean gone     = wait.until(ExpectedConditions.invisibilityOfElementLocated(By.id("modal")));

(mặc định) ✔ ✔ ✖ ✖

🧩 Trong dự án:

  • protected WebDriver driver; — BaseTest nằm package base, test nằm package tests. Class con khác package vẫn truy cập được nhờ protected (nếu để mặc định thì không).
  • private static final String LOGIN_URL — chỉ riêng class dùng.
  • public void setup() — public để main() và TestNG gọi được.

Bài tập tự kiểm tra

  1. Vì sao driver khai báo kiểu WebDriver mà không phải ChromeDriver?
  2. Nếu đổi protected thành private trong BaseTest, chuyện gì xảy ra ở Exercise01_LoginTest?
  3. Vì sao biến countBeforeScroll phải final?
  4. findElement và findElements khác nhau thế nào khi không tìm thấy?
  5. Viết BasePage có constructor nhận WebDriver và method protected WebElement waitVisible(By by).
Gợi ý đáp án
  1. Đa hình, dễ đổi browser, không bị buộc vào API riêng của ChromeDriver.
  2. Lỗi biên dịch: class con khác package không truy cập được driver/wait.
  3. Lambda chỉ capture biến final / effectively final.
  4. findElement ném NoSuchElementException; findElements trả List rỗng.
  5. Xem mục 8, thêm protected WebElement waitVisible(By by) { return wait.until(ExpectedConditions.visibilityOfElementLocated(by)); }.
