5. Kiến trúc test

text
   testng.xml  ──(surefire đọc)──►  10 class tests.ExerciseXX_*Test
                                              │ extends
                                              ▼
                                    base.BaseTest
                          @BeforeMethod setup()  → new ChromeDriver(), maximize, pageLoadTimeout(30s), WebDriverWait(15s)
                          @AfterMethod  tearDown() → driver.quit()
  • Mỗi @Test = một lần mở Chrome mới (vì @BeforeMethod). An toàn (test độc lập) nhưng chậm: cả bộ 10 test mất ~91 giây (xem target/surefire-reports/TestSuite.txt).
  • driver và wait là field protected của BaseTest → class con dùng trực tiếp.
  • Không dùng Implicit Wait (có chú thích lý do ngay trong BaseTest). Mọi chờ đợi đi qua wait (Explicit Wait, 15 giây).
  • Mỗi Test Class còn có main() để chạy trực tiếp từ IDE bằng cách gọi thủ công setup() → test → tearDown().

6. Phân tích từng class và method quan trọng

Với mỗi mục: Chức năng · Mục đích · Cách hoạt động · API liên quan · Khi nào dùng · Lỗi thường gặp · Cách cải thiện.

6.1. BaseTest.java

Thành phần Phân tích
Chức năng Lớp cha dùng chung: quản lý vòng đời WebDriver và WebDriverWait.
Mục đích Tránh lặp code khởi tạo/đóng trình duyệt ở 10 class. Đảm bảo mỗi test có trình duyệt sạch.
setup() (@BeforeMethod) (1) new ChromeDriver() — Selenium Manager tìm/tải ChromeDriver khớp phiên bản Chrome; (2) window().maximize(); (3) pageLoadTimeout(30s) để get() không treo vô hạn; (4) new WebDriverWait(driver, Duration.ofSeconds(15)).
tearDown() (@AfterMethod) if (driver != null) driver.quit() — quit() đóng toàn bộ cửa sổ + kết thúc session + dừng process chromedriver.
API liên quan ChromeDriver, WebDriver.manage().window().maximize(), Timeouts.pageLoadTimeout(Duration), WebDriverWait, @BeforeMethod, @AfterMethod. Xem selenium/01, testing-framework/04.
Khi nào dùng Mọi dự án TestNG cần một nơi quản lý driver.
Lỗi thường gặp Quên quit() → process chrome.exe/chromedriver.exe mồ côi. Nếu new ChromeDriver() ném exception thì driver vẫn null — code đã xử lý bằng if (driver != null).
Cải thiện (a) Tách DriverFactory để hỗ trợ nhiều browser; (b) ThreadLocal<WebDriver> nếu muốn chạy song song; (c) đọc timeout/URL từ file cấu hình; (d) chụp ảnh khi fail (ITestResult trong @AfterMethod); (e) cân nhắc @BeforeClass nếu muốn chạy nhanh hơn (đổi lại các test phụ thuộc nhau hơn). Xem framework-design.

6.2. Exercise01_LoginTest.java

  • Chức năng: đăng nhập tomsmith/SuperSecretPassword!, xác minh flash message và URL /secure.
  • Điểm hay: hàm assertSameElement(...) chứng minh By.id, By.name, By.xpath, By.className cùng trỏ về một WebElement (so sánh equals — RemoteWebElement.equals dựa trên element id nội bộ của browser). Đây là cách học Locator rất trực quan.
  • API: findElement, clear, sendKeys, click, getText, isDisplayed, getCurrentUrl, ExpectedConditions.visibilityOfElementLocated.
  • Lỗi thường gặp: đọc #flash ngay sau click() khi trang chưa load xong → NoSuchElementException; dự án tránh bằng wait.until(visibilityOfElementLocated).
  • Cải thiện: username/password hard-code → chuyển ra config; tách thành LoginPage (POM). Xem framework-design/01.

6.3. Exercise02_CheckboxesTest.java

  • Chức năng: đảm bảo cả 2 checkbox ở trạng thái checked.
  • Bài học: checkbox 2 mặc định đã tick, nên "click" mù sẽ bỏ tick. Hàm clickAndVerifyToggled kiểm tra isSelected() trước và sau click → test không thể "pass giả".
  • API: findElements(By.cssSelector("#checkboxes input[type='checkbox']")), isSelected(), click().
  • Cải thiện: viết helper setChecked(WebElement, boolean) — chỉ click khi trạng thái hiện tại khác trạng thái mong muốn (idempotent).

6.4. Exercise03_WebTablesTest.java

  • Chức năng: đọc 4 dòng (đầu, hai, kế cuối, cuối) của #table1 bằng XPath vị trí [1], [2], [last()-1], [last()].
  • API: By.xpath, findElements(...).size(), row.findElements(By.tagName("td")) (tìm con của một element), getText().trim().
  • Lỗi thường gặp: XPath bắt đầu bằng // bên trong row.findElement sẽ tìm toàn trang (không phải trong row); nên dùng .//td. Dự án dùng By.tagName("td") nên an toàn.
  • Cải thiện: dữ liệu kỳ vọng hard-code → dùng @DataProvider hoặc file JSON; trang web đổi dữ liệu là test fail.

6.5. Exercise04_DropdownTest.java

  • Chức năng: chọn từng option bằng class Select, kiểm tra text và value.
  • API: new Select(WebElement), getFirstSelectedOption(), getOptions(), selectByVisibleText(), getAttribute("value"). Select chỉ dùng được với thẻ <select> thật.
  • Điểm hay: duyệt getOptions() rồi lọc isEnabled() để bỏ placeholder disabled, không hard-code.
  • Lưu ý: file target/surefire-reports/tests.Exercise04_DropdownTest.txt còn sót từ lần chạy trước (11/11) — là báo cáo cũ, không phải lỗi hiện tại.

6.6. Exercise05_HoverTest.java

  • Chức năng: hover từng ảnh, đọc h5 ("name: user1"...).
  • API: Actions.moveToElement(el).perform(), ExpectedConditions.visibilityOf(WebElement).
  • Bài học: caption luôn có trong DOM nhưng ẩn (CSS). findElement thành công ngay, nhưng getText() trả chuỗi rỗng nếu chưa hiển thị → phải chờ visibilityOf. Đây là ví dụ thực tế về khác biệt Presence vs Visibility.
  • Lưu ý: actions.moveToElement(...) quên .perform() là lỗi kinh điển: không có gì xảy ra.

6.7. Exercise06_AddRemoveElementsTest.java

  • API: By.xpath("//button[text()='Add Element']"), By.className("added-manually"), numberOfElementsToBe(locator, 0).
  • Bài học: để chứng minh element biến mất hãy chờ numberOfElementsToBe(locator, 0) (hoặc invisibilityOfElementLocated) thay vì findElements rồi so sánh ngay. Comment trong code giải thích đúng: không dùng Implicit Wait để khỏi chờ thừa.

6.8. Exercise07_InfiniteScrollTest.java

  • Chức năng: cuộn xuống 3 lần, mỗi lần đảm bảo có thêm đoạn jscroll-added; cuộn về đầu trang.
  • Kỹ thuật nâng cao: đặt scrollToBottom bên trong wait.until(d -> {...}) — vừa cuộn lặp vừa kiểm tra điều kiện (Custom Wait bằng lambda). Lý do được ghi trong Javadoc: plugin jScroll bỏ qua sự kiện scroll nếu đang tải dở; cuộn đúng 1 lần có thể "mất" sự kiện. Có sẵn file test-output/testng-failed.xml ghi nhận Exercise07 từng fail — bài học thật về flaky test.
  • API: JavascriptExecutor.executeScript, window.scrollTo, window.dispatchEvent(new Event('scroll')), getBoundingClientRect(), Wait.until(Function).
  • Lưu ý: wait.until(d -> {scrollToBottom(); return ...}) có side effect trong điều kiện chờ — chấp nhận được ở đây vì có chủ đích, nhưng nên ghi chú rõ.

6.9. Exercise08_EntryAdModalTest.java

  • API: visibilityOfElementLocated, invisibilityOfElementLocated, tìm element con modal.findElement(By.cssSelector(".modal-title h3")).
  • Lưu ý: dùng toUpperCase() khi so tiêu đề vì CSS có thể đổi hoa/thường nhưng getText() trả về văn bản như đang hiển thị (kể cả text-transform). So sánh không phân biệt hoa-thường là quyết định thực tế hợp lý.

6.10. Exercise09_DragAndDropTest.java

  • API: Actions.dragAndDrop(source, target).perform().
  • Rủi ro: trang dùng HTML5 Drag & Drop; Actions.dragAndDrop thường hoạt động trên Chrome hiện đại, nhưng đây là loại thao tác dễ flaky giữa các phiên bản browser. Phương án dự phòng: clickAndHold → moveToElement → release, hoặc JavaScript mô phỏng sự kiện dragstart/drop. Xem selenium/07.

6.11. Exercise10_DynamicControlsTest.java

  • Chức năng: Remove checkbox, Enable input; chờ AJAX.
  • API: visibilityOfElementLocated, invisibilityOfElementLocated, elementToBeClickable, textToBe(locator, "It's enabled!").
  • Bài học then chốt (có chú thích trong code): sau khi Enable, thông báo #message vẫn đang hiển thị "It's gone!" của bước trước, nên chờ "visible" sẽ qua ngay và đọc nhầm. Phải chờ nội dung đúng bằng textToBe. Đây là một trong những lỗi đồng bộ hoá phổ biến nhất ngoài đời.

6.12. AllExercisesTest.java, EnvironmentCheckTest.java

  • AllExercisesTest.main() dùng API lập trình org.testng.TestNG: setTestSuites(List.of("testng.xml")), run(), System.exit(getStatus()) (exit code ≠ 0 khi fail — tốt cho CI).
  • EnvironmentCheckTest không nằm trong testng.xml; chỉ chạy qua run-test.ps1 hoặc -Dtest=EnvironmentCheckTest.

6.13. run-test.ps1

Script tự viết: tìm JDK 21+ → mvnw dependency:build-classpath ra target\classpath.txt (cache, chỉ tạo lại khi pom.xml mới hơn) → javac → java -cp ... tests.<Class>. Đây không phải Maven Surefire: không sinh report surefire, không đọc testng.xml (trừ khi chạy AllExercisesTest). Ghi chú: file cố ý để ASCII vì PowerShell 5.1 đọc sai UTF-8 không BOM.

9. Điểm mạnh của dự án

  1. Dùng Maven Wrapper only-script + .gitignore đúng (không commit target/, .mvn/repository/).
  2. Quy ước nhất quán: Explicit Wait, không Implicit Wait, có giải thích.
  3. Test tự kiểm chứng (kiểm tra cả trạng thái trước khi click, kiểm tra element biến mất).
  4. Javadoc/comment tiếng Việt chi tiết, có assert message rõ ràng.
  5. Có testng.xml là nguồn duy nhất cho danh sách test (dùng chung cho Maven và AllExercisesTest).
  6. Có báo cáo mẫu 10/10 đạt trong ket-qua/.

10. Vấn đề phát hiện được và đề xuất

Theo yêu cầu, chỉ ghi nhận và đề xuất — không sửa source code.

# Phát hiện Mức độ Đề xuất
1 README.md (mục 7) nói mvnw.cmd "dùng JAVA_HOME". Thực tế trên máy này JAVA_HOME trống nhưng mvnw.cmd vẫn chạy bằng Java trong PATH. Với only-script, JAVA_HOME không bắt buộc để tải Maven; Maven (mvn.cmd) tự tìm java trong PATH nếu không có JAVA_HOME. Thấp (tài liệu) Sửa câu: "nên đặt JAVA_HOME; nếu thiếu, Maven dùng java trong PATH". → Đã sửa trong README.md gốc (14/11/2026, sau đánh giá).
2 -Dtest= gõ sai tên → Tests run: 0, BUILD SUCCESS (đã tái hiện). Đã thử thêm -Dsurefire.failIfNoSpecifiedTests=true — vẫn SUCCESS, cờ này không cứu được. Trung bình (bẫy CI) Trong CI, đọc target/surefire-reports/TestSuite.txt và fail nếu Tests run: 0; đọc log có dòng Running tests.<Class>.
3 target/surefire-reports/*.dumpstream cảnh báo: Boot Manifest-JAR contains absolute paths ... 'other' has different root. Nguyên nhân: dự án ở ổ B: còn Local Repository mặc định/Maven home ở ổ C:. Chỉ là cảnh báo. Thấp Gợi ý của chính Surefire: <argLine>-Djdk.net.URLClassPath.disableClassPathURLCheck=true</argLine>.
4 Cảnh báo SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder". Thấp Thêm slf4j-simple (scope test) nếu muốn log; hoặc bỏ qua.
5 Credentials và dữ liệu kỳ vọng hard-code trong test. Trung bình config.properties / @DataProvider — xem testing-framework/05.
6 Không có Page Object Model; locator rải trong test. Trung bình (bảo trì) Tách Page Class — xem practice/06.
7 Mỗi test mở 1 Chrome (@BeforeMethod). Chạy 10 test ≈ 91 s. Thấp Chấp nhận để test độc lập; hoặc parallel + ThreadLocal.
8 Mỗi test có main() lặp lại cùng mẫu. Khi chạy bằng TestNG, main() không dùng. Thấp Chấp nhận (phục vụ học tập/IDE); dự án thật thường bỏ.
9 EnvironmentCheckTest không nằm trong testng.xml. Thông tin Cố ý (smoke check môi trường).
10 Không khai báo distributionSha256Sum trong maven-wrapper.properties. Thấp Thêm checksum nếu cần bảo mật chuỗi cung ứng.
11 .mvn/maven.config đặt Local Repository vào .mvn/repository (123 jar). Có lợi: cô lập khỏi ~/.m2 bị hỏng (xem README mục 7). Bất lợi: thư mục lớn, mỗi clone phải tải lại. Thông tin Giữ nguyên; chỉ cần chắc .mvn/repository/ nằm trong .gitignore (đã có).
12 Thư mục chưa là Git repo. Thông tin git init khi bắt đầu làm việc nhóm.

11. Những gì dự án CHƯA có

Không có không phải lỗi — đây là danh sách việc để học tiếp:

  • Page Object Model, BasePage, DriverFactory, ConfigReader.
  • Logging (Log4j2/SLF4J), Reporting (Extent/Allure), Screenshot khi fail, TestNG Listener.
  • Data-driven (@DataProvider), TestNG Groups, chạy song song.
  • Failsafe plugin / Maven Profile / chạy đa môi trường.
  • CI (GitHub Actions), headless mode, đa trình duyệt, Selenium Grid.
